先看结论

  • 权重优化改的是模型本身，也就是模型的权重（模型内部的参数）。最基本的办法是监督微调（supervised fine-tuning，简称 SFT）：给模型一批「输入和应有的输出」，训练它在每个位置上把正确的下一个 token 的概率提高。token 是模型处理文字的最小单位，大致是一个词或半个词。
  • agent 指能自己调用工具、分很多步去完成任务的语言模型系统。给 agent 做监督微调时，训练数据是运行轨迹（trajectory，一次运行里每一步的动作和看到的结果的完整记录）。做法是让一个强的教师模型去做任务，把轨迹收集起来，训练一个更小的学生模型去复现教师的每一步。
  • OpenThoughts-Agent 这项研究用 10 万条轨迹微调 Qwen3-32B 这个模型，七个 agent 基准测试（benchmark，一组题目加一个打分的办法）的平均成绩从 22.8% 升到 44.8%。它的对照实验显示：任务从哪里来对结果的影响最大，基准测试成绩最好的模型不一定是最好的教师。
  • FireAct 这项研究只用 500 条 GPT-4 的轨迹微调小模型 Llama-2-13B，它在多步问答数据集 HotpotQA 上的成绩是 34.4，比不微调、只靠 prompt（发给模型的那段输入文字）来引导的 GPT-3.5 的 31.4 高出 3.0 个百分点。成绩是答案和标准答案完全一致的题所占的百分比。粗略估算，这个差距只有大约一个标准误（标准误量的是一个成绩的不确定程度），还谈不上确定的领先。
  • 监督微调有两个局限。学生只见过教师遇到过的局面，它自己出了错之后该怎么办，训练数据里没有。训练目标只是写得和教师一样，任务最后有没有做成不在目标里。

微调时模型在学什么：交叉熵损失

fine-tuning（微调）指在已有模型的基础上用新数据继续训练，更新它的权重。监督微调教给模型的是一件很具体的事：在同样的上文之后，写出和训练数据一样的下一个 token。这一节看这件事是怎样写成一个训练目标的。

token 是模型处理文字的最小单位，大致是一个词或半个词。语言模型在每个位置上做的事，是给词表（模型认识的全部 token 的清单）里的每个 token 一个概率，表示模型认为下一个 token 是这个 token 的可能性有多大。

要让模型写出和训练数据一样的 token，就要提高它给这个 token 的概率。监督微调用的训练目标叫交叉熵损失（cross-entropy loss），它量的就是这个概率有多低，和预训练时用的训练目标一样。预训练指最初在大量文字上训练模型接着往下写的那个阶段。

{{fig 72 | 一个位置上的交叉熵损失。求和遍历词表里的每一个 token，词表大小是 V。对其中每一个 token，y 说明它是不是数据里实际出现的那个 token：是就取 1，其他的都取 0。p 是模型给它的概率，log(p) 是这个概率的对数。}}

公式写成一行是 L = − Σ yi log(pi)。因为 y 只在一个 token 上是 1，求和里只剩下一项：

一个位置上的损失，等于模型给「数据里实际出现的那个 token」的概率，取对数再取负号。

模型给正确的 token 的概率是 1 时，损失是 0。给的概率越低，损失越大。把一条训练样本里所有位置的损失加起来，再朝着让它变小的方向调整权重，就是一步训练。

先例：指令微调

监督微调最有名的应用是指令微调（instruction finetuning）。预训练出来的模型只会接着往下写，不一定会照指令办事。把很多个数据集都改写成「一条指令加一个应有的回答」的形式，用它们微调模型，模型就学会了按指令回答，包括训练时没见过的任务。

{{fig 73 | 上半部分是微调：把很多任务写成指令的形式，一部分只要求回答，一部分要求先一步一步推理，一共约 1,800 个任务，用来训练同一个语言模型。虚线下面是使用时：模型在没见过的任务上也能按要求先推理再回答。图片来源：Chung 等，2022。}}

Chung 等人 2022 年的论文用 1,836 个任务做指令微调，这些任务来自 473 个数据集。论文的结果有三点。

  • 效果。论文把没有参加训练的几组评测上的六项成绩归一化（换算到同一个尺度上）之后取平均。按这个平均分，经过指令微调的 Flan-PaLM 540B 比没有微调的 PaLM 540B 高 9.4 个百分点。名字里的 540B 指模型有约 5400 亿个参数。
  • 任务数量。任务越多效果越好，但大部分提高在 282 个任务时已经得到。
  • 代价很小。指令微调用了 14 亿个 token，是预训练所用 token 数的 0.2%。论文的解释是，微调带来的提高主要来自模型学会了把预训练时已经掌握的知识更好地表达出来。

把 agent 的监督微调放在这个背景下看，就容易理解了：做法完全一样，只是训练数据从「指令和回答」换成了「任务和运行轨迹」。

用在 agent 上：让学生照着教师的轨迹学

agent 指能自己调用工具、分很多步去完成任务的语言模型系统。给 agent 做监督微调，流程是三步：教师模型去做任务，留下做成了的运行轨迹，再用这些轨迹微调学生模型。

{{fig 74 | 右边是流程：教师模型去做任务，留下做成了的运行轨迹，用这些轨迹微调学生模型。左边是四个要点。}}

这个流程有四点要注意。

  • 让教师去做任务。教师是一个强的模型，通常更大、更贵。把教师在一个任务上从头到尾跑一次叫一次 rollout。
  • 在教师做完的任务上训练学生。教师每做完一个任务，留下一条运行轨迹，训练用的就是这些轨迹。是全部留下还是只留做成了的，下面讲收集轨迹的那一段会说。这种在预训练之后进行的训练，也叫 post-training。
  • 重点是任务和环境的多样性。环境指 agent 做任务时所处的那套系统，比如下面例子里的终端和里面的文件。学生将来要面对各种任务，训练数据要覆盖得足够广。
  • 学生学到的是怎样执行任务。包括什么时候调用哪个工具，看到结果之后下一步做什么，什么时候算完成。
{{fig 75 | 一条运行轨迹的例子。任务是找出当前目录下所有名字以 .example.com 结尾的文件，忽略 beta 子目录，并把命令的输出存进一个指定的文件。标着 AGENT 的是 agent 每一步的想法和它发出的命令，标着 TERMINAL 的是终端返回的结果。最后一步 agent 确认文件存在、内容符合预期，宣布任务完成。}}

训练时，这条轨迹被当成一段很长的文字。学生要学的是标着 AGENT 的那些部分：给定任务和到目前为止的全部记录，写出教师在这一步写的想法和命令。终端返回的内容是环境给的，只作为上文。

收集轨迹时要决定哪些轨迹留下来。可以全部留下，也可以用某种办法检查教师的输出，只留通过检查的。上面的流程图画的是后一种，检查的内容是任务有没有做成。这种生成很多、只留下通过检查的那一部分的做法叫拒绝采样，第二部分讲的 STaR 这种方法用的也是它。

检查什么没有统一的答案，本页后面的两个例子做法就不同。FireAct 只留答对的轨迹。OpenThoughts-Agent 的筛选条件里没有「教师是否把任务做成」这一条，它去掉的是不到 5 轮的轨迹。一轮指模型作出一次回应，也就是上面例子里标着 AGENT 的一步。

让学生模型学习教师模型的行为，统称蒸馏（distillation），这里的做法是其中最简单的一种。它只用到教师输出的文字，所以教师可以是只能通过 API 调用的模型。能拿到教师给每个 token 的概率时还有别的做法，比如第五部分的 on-policy 蒸馏。on-policy 指训练用的数据由被训练的模型自己产生：这种蒸馏让学生自己写，再让教师给它写下的每个 token 打分。

OpenThoughts-Agent：一份数据是怎么做出来的

OpenThoughts-Agent（Raoof 等，2026 年 6 月）研究的问题是：给编程和终端类的 agent 做监督微调，训练数据应该怎么造。它把造数据的过程拆成六个环节，做了 100 多组对照实验，每次只改一个环节。

{{fig 76 | 造数据的六个环节：找任务的来源，混合不同来源的任务，筛选任务，生成运行轨迹，筛选运行轨迹，以及选教师模型。最右边是最终的配方（final recipe），指论文根据各环节的对照结果最后定下来的那一套造数据的做法。图片来源：Raoof 等，2026。}}

默认的设置是：教师是 GLM-4.7，放在 terminus-2 这个运行框架里，在隔离的沙箱中做任务。运行框架（harness）是包在模型外面、给它工具并管理多轮对话的程序。沙箱是和外界隔开的运行环境，agent 在里面执行命令不会影响别的系统。

对照实验里，每份数据是 1 万条轨迹，用来微调 Qwen3-8B。名字里的 8B 指模型有约 80 亿个参数，32B 是约 320 亿个。

下面的表列出其中五个环节的主要发现。「生成运行轨迹」这一环节按上面的默认设置进行，表里没有单独的一行。

对照实验用三个基准测试来比成绩。SWE-bench Verified 考的是修真实代码仓库里的 bug，实验用的是它的一个 100 题子集。Terminal-Bench 2.0 考的是在终端里完成任务。第三个 OT-TBLite 有 100 个任务，题型和 Terminal-Bench 一样，四档难度的任务数量均衡，用来快速估计模型在完整的 Terminal-Bench 2.0 上的成绩。

最终的配方用对照实验里排在最前面的 4 种任务来源。SWE-smith 和 IssueTasks 是自动生成的任务，内容是解决代码仓库里报告的问题。StackExchange SuperUser 是人写的系统管理类问题，StackExchange Tezos 是人写的加密货币问答，论文把这两种都归为人写的电脑使用问题。

轨迹由 GLM-4.7 生成，去掉不到 5 轮的，一共 10 万条。论文正文提到的筛选条件里，没有「教师是否把任务做成」这一条。

对照实验里每份数据是 1 万条，最终的配方要把数据扩大到 10 万条。扩大用了两个办法。

  • 给同一个任务生成多条轨迹。每个任务至少生成一条，剩下的条数按上面表里「筛选任务」一行的难度信号来分：模型做这个任务时写出的回答越长，这个任务分到的轨迹越多。最终的配方没有按难度去掉任务，「筛选任务」这一环节在这里用来决定每个任务生成几条轨迹。
  • 改写任务的描述。4 种来源里任务最少的是 StackExchange Tezos，论文把它的任务描述改写成了更多种说法。为什么要改写，见下面「结果」一节里「数据越多越好」那一点。

读这组结果时有三点值得留意。

  • 微调的收益很大。同一个 32B 的模型，平均成绩差不多翻了一倍。8B 的模型也一样：论文报告它的平均成绩从 10.2% 升到 27.4%。

基准测试成绩最好的模型不一定是最好的教师。用教师的轨迹微调确实有效，上面的表说明了这一点。但论文的对照实验同时表明，教师自己的基准测试成绩越好，训练出来的学生不一定越好：成绩最好的 GPT-5.3-Codex 是五个教师里最差的一个，较旧、成绩较低的 GLM-4.7 是最好的一个。选教师时要实际试，不能只看排行榜。

论文只报告了这个结果，没有给出原因。一种可能的解释是能力差距：教师比学生强太多时，它的做法学生不容易学会。图像分类的蒸馏研究里报告过类似的现象：Mirzadeh 等人 2019 年的论文发现，学生和教师的规模差距很大时，学生的成绩会下降。

这个解释只对得上这里的一部分数据。对得上的是 GPT-5.3-Codex：它的基准测试成绩最好，训练出来的学生最差。对不上的有两个教师。Kimi K2.5 的基准测试成绩高于 GLM-4.7，按这个解释它训练出来的学生应该差一些，实际几乎一样好。GLM-4.6 是和 GLM-4.7 同一系列里更早的版本，如果更早的版本能力较弱，按这个解释它训练出来的学生不该更差，实际却差得多。

FireAct：500 条轨迹能带来多少

FireAct（Chen 等，2023）是较早系统地研究 agent 微调的工作。它的主要实验用的是 HotpotQA 这个数据集：回答需要多步推理和查资料的问题，agent 手里有一个 Google 搜索工具，成绩按答案和标准答案是否完全一致（exact match，下面简称 EM）计算。

{{fig 78 | 方法的示意图。上半部分是微调：问题可以来自多个问答数据集，配上多种 prompt 写法（CoT、ReAct、Reflexion），交给一个强模型（比如 GPT-4）带着工具去做，只留下答对的轨迹，统一改写成 ReAct 的格式，用来微调一个小模型（比如 Llama2）。下半部分是使用时：微调后的模型不需要示例，自己决定用哪种方式推理。图片来源：Chen 等，2023。}}

图里的三种写法是三种让模型推理的方式。CoT 是先写一段推理再给答案。ReAct 是「想一步、做一个动作、看结果」反复进行。Reflexion 是在做了若干步之后停下来回顾，再继续。

默认的做法比图里画的简单：只用 HotpotQA 一个数据集的问题，让 GPT-4 用 ReAct 的方式做题，取 500 条答对的轨迹，微调各个模型。

{{fig 79 | 左表是只用 prompt 时的成绩：GPT-4 和 GPT-3.5 各用 IO、CoT、ReAct 三种方式，IO 指不写推理、直接给答案。右表比较每个模型用 ReAct 的 prompt 和微调之后的成绩，最后一列是提高的绝对值和相对比例。图片来源：Chen 等，2023。}}

论文自己写出的一个结论是：微调之后的 Llama-2-13B 是 34.4，超过了 GPT-3.5 用任何一种 prompt 方式的成绩，其中最高的是 31.4。一个可以自己部署的小模型，学了 500 条强模型的轨迹，就比一个只靠 prompt 的、更强的商用模型做得好。

这个结论要带着三个限定来读。

  • 差距不大。标准误（standard error）量的是一个成绩的不确定程度：换一批同样多的题来测，成绩通常会在正负一两个标准误的范围里变动。论文附录给出这两个成绩的标准误都在 2.1 左右。粗略估算，两个成绩之差的标准误约是 3.0，算的办法是把两个 2.1 各自平方、相加再开方。两个成绩相差 3.0 个百分点，只等于一个这样的标准误，谈不上确定的领先。
  • 更强的模型成绩仍然更高。微调后的 GPT-3.5 是 39.2，高于微调后的 Llama-2-13B 的 34.4。GPT-4 没有微调，只用 prompt 时 IO、CoT、ReAct 三种方式的成绩依次是 37.2、45.0、42.0，也都高于微调后的 Llama-2-13B。
  • 只有问答这一类任务、搜索这一个工具。论文自己把这一点列为局限。

下面三条都是微调后的 GPT-3.5 和只用 prompt 的 GPT-3.5 比。

  • 更快。微调后的模型不需要在 prompt 里放示例，答一道题花的时间从 9.0 秒降到 2.7 秒。
  • 工具出错时成绩下降得更少。让搜索工具有一半的时候什么都不返回。只用 prompt 时 EM 从 31.4 降到 20.8，微调后从 39.2 降到 33.6。
  • 换一个数据集，成绩仍然高一些。Bamboogle 是另一个多步问答数据集，有 125 道题。在这个数据集上，微调后是 44.0，只用 prompt 是 40.8，相差 3.2 个百分点。题数比 HotpotQA 的 500 道少得多，按题数粗略判断，成绩的不确定程度更大，这个差距同样谈不上确定的领先。

论文还试了把 ReAct、CoT、Reflexion 这三种方式的轨迹混在一起训练，让模型在使用时自己决定用哪一种。结果有好有坏。以 GPT-3.5 为例，只用 ReAct 的轨迹是 39.4，ReAct 加 CoT 的混合是 41.0，再加上 Reflexion 是 40.0，反而略低。这里的 39.4 和前面表里的 39.2 是同一个模型的成绩，论文的两张表略有出入。

论文的结论是，混合更多的方式不一定更好，最好的配比取决于被微调的模型。它举的例子是：ReAct 加 CoT 的混合对 GPT-3.5 和 Llama-2 有帮助，对 CodeLlama 的几个模型反而有害。

数据量方面，GPT-3.5 只要 100 条轨迹，EM 就能到 35 左右。Llama 系列用 100 或 200 条连 ReAct 的格式都学不会，要到 500 条才学会。前面表里 Llama-2-7B 的 26.2 和 Llama-2-13B 的 34.4 就是用 500 条得到的。

监督微调的局限

监督微调有两个内在的局限，下一部分的两种方法分别针对它们。

  • 学生只见过教师遇到过的局面。训练时，每一步的上文都来自教师的运行轨迹，里面的想法和命令是教师写的。使用时，上文里的想法和命令是学生自己写的。学生一旦在前面犯了一个教师不会犯的错，就进入了训练数据里没有出现过的局面，之后离训练时见过的局面越来越远。训练数据不是由被训练的模型自己产生的，这种情况叫 off-policy。
  • 训练目标是模仿教师。交叉熵损失只看学生写的和教师写的是否一样，任务最后有没有做成不在目标里。教师的轨迹里如果有多余的步骤，学生也会照学。教师做不到的事，学生从这些数据里也学不到。

下一部分讲让学生自己去做任务的两种办法：强化学习直接按任务有没有做成给奖励，on-policy 蒸馏让教师在学生自己走到的局面里给它逐个 token 的反馈。
