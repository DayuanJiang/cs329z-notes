先看结论

  • 优化（optimization）指的是：用数据和评估说明你想要什么，再让算法自动去改系统，让它在评估上的分数变高。
  • 做优化要同时有三样东西：数据，一个可以改的系统或模型，一个能打分的评估指标。缺一样都做不了。
  • 通用的模型越来越强，优化仍然有用：你的场景有自己的数据、规定和偏好，优化把通用的模型调到适合这个具体的场景。
  • 系统里能改的东西主要有两样。一样是上下文，也就是放进模型输入里的文字，主要是 prompt 里的指令和示例。另一样是模型的权重，也就是模型内部的参数。第二到第五部分按这两样分开讲，第六部分讲让 agent 来做优化，第七部分讲两样怎么选。

  • 哪一句更好，很难凭直觉猜出来。B 和 C 都是算法搜出来的，C 的句子更长、用词更讲究，分数却比 B 低 5.7 个百分点。要知道哪句好，只能拿数据去测。

优化是什么

优化的做法是：人用数据和评估告诉算法想要什么，算法照着去改系统。

平时改进一个语言模型系统的办法是人去读输出、猜原因、改 prompt、再试。上面的小测验说明这种办法靠不住：人猜不准哪句话更好。优化换了一种分工。人负责准备两样东西：一批有代表性的输入（数据），和一个能给输出打分的办法（评估）。剩下的事交给算法：它提出改法，在数据上跑，看分数，保留分数高的。

用数据和评估来说明想要什么，是因为很多要求很难用文字在 prompt 里写全，比如「回答要像我们公司的客服那样说话」。给出一百个好的回答和一个能分辨好坏的评估，往往比写一页说明更准确地表达了你想要什么。

第 5 讲讲过的从邮件里提取日程的任务是一个具体的例子。交给模型的指令只有一句「Extract event details from an email.」（从邮件里提取日程的信息）。要把这件事做对，还有一些这句话没有写的要求。邮件里的日期不管是哪种写法，比如「12/7/2026」或「20 November 2026」，都要读对并统一成 YYYY-MM-DD 的格式。用文字写的时长，比如「two-hour session」，要换算成 120 分钟，不能留空。

这些要求体现在带标准答案的数据和评估里：日期、开始时间、时长三项都和标准答案一致才算对。优化之后的指令里，写进去的正是这样的规则。优化做的事，就是从数据和评估里把这些没写出来的要求找出来，放进系统。

模型越来越强，还需要调 prompt 吗

模型越来越强，自然会想到两个问题：现在还用得着花时间调 prompt 吗？模型规模再大一些，它自己不就变好了吗？

回答分两层：逐字推敲 prompt 的措辞很可能越来越不必要，优化仍然需要。

先说措辞。第三部分要讲的优化方法 GEPA，它的作者在论文里说，近来的模型遵循指令的能力变强了。照这个说法，一条要求只要写进了指令，模型大多能照着做，用哪个词来写就没有那么要紧。所以随着模型变强，逐字推敲措辞很可能越来越不必要。

再说优化。优化仍然需要，因为模型和优化解决的是两个不同的问题。

  • 模型提供的是一个很好的通用方案。它解决了大部分的问题，对所有人都一样。
  • 优化针对的是具体的场景。知道了你确切的使用环境，包括你的数据、你的工具、你对输出的要求，就可以把系统调到适合这个环境。

可以这样理解：模型变强之后，不做优化时的成绩会更高，但你的场景里那些只有你知道的要求，仍然要有办法告诉系统。一种办法是靠人把每一条要求都写进 prompt 或系统的其他部件。另一种是前面说的办法：先建一个评估，它的含义是「系统在这上面拿到满分，就说明它理解了要做的事」，再让算法把系统往这个评估上调。优化指的是后一种。

只改放进模型输入里的文字、不动模型本身的那一类优化，这一讲统称上下文优化（context optimization）。这里的上下文和 prompt 指同一样东西，都是每次调用时放进模型输入里的全部文字。论文里通常把这一类方法叫 prompt 优化，两个词指的是同一类方法。

这一讲改用「上下文优化」这个名字，是因为「prompt 优化」容易让人想到反复改措辞，上面小测验里的「深吸一口气」就属于这一类。现在的方法主要做的是另一件事：把场景里没写出来的要求补进上下文。第三部分的小结会回到这一点。

优化能带来什么

优化带来的好处有五项，其中容易被忽略的一项是可以换用更小的模型。先看一个例子，再看完整的清单。

第 5 讲讲过的例子里，只改 prompt 就让一个更小的模型达到了同样的成绩。原来用的 gpt-5.4-nano 靠一句话的指令，20 封测试邮件全对。换成更小的模型 Gemma 3 12B，同一句指令只对 11 封，优化指令之后也是 20 封全对。测试集只有 20 封，这个结果只说明方向。

Gemma 3 12B 是权重公开的模型，可以放在自己的硬件上运行。换用它是否更省钱，取决于怎样部署。这个例子说明的是：优化指令之后，更小的模型达到了同样的成绩，20 封全对。

第四部分里的做法是同一个方向：让一个小模型学会大模型的做法，用小模型得到接近大模型的效果。

最后一项在换模型时最明显。一个系统是针对某一代模型调好的，新一代模型发布之后，只要数据和评估还在，重新跑一遍优化，就能得到针对新模型调好的系统，不需要人从头再调一遍。

后面各部分讲什么：改什么，谁来改

一个语言模型系统里能改的东西主要有两样，对应两大类优化。

  • 上下文优化。前面已经说过，它只改放进模型输入里的文字，模型本身不动。这些文字里能优化的主要是两部分：用文字说明任务的指令（instruction），和做好了的例子，也就是示例。
  • 权重优化（weight optimization）。权重是模型内部的参数。这一类优化用新的数据继续训练模型，改的是模型本身。这种做法叫 fine-tuning（微调）。

另外还有一个角度：优化的过程由谁来执行。可以是一个人写好的固定算法，也可以是一个会写代码的 agent。

读表之前先交代四个词。

  • token 是模型处理文字的最小单位，大致是一个词或半个词。
  • 教师模型是一个更强的、已经能把任务做好的模型。要训练的那个模型叫学生模型。
  • 蒸馏指让学生模型学习教师模型的行为。
