先看结论

  • 优化（optimization）指的是：用数据和评估说明你想要什么，再让算法自动去改系统，让它在评估上的分数变高。
  • 做优化要同时有三样东西：数据，一个可以改的系统或模型，一个能打分的评估指标。缺一样都做不了。
  • 通用的模型越来越强，优化仍然有用：你的场景有自己的数据、规定和偏好，优化把通用的模型调到适合这个具体的场景。
  • 系统里能改的东西主要有两样：上下文（prompt 里的指令和示例）和模型的权重。第二到第五部分按这两样分开讲，第六部分讲让 agent 来做优化，第七部分讲两样怎么选。

一个小测验：三句 prompt 哪一句最好

先看一个例子。prompt 是发给语言模型的那段输入文字。下面三句话分别接在同一批数学应用题的后面，作为模型回答的开头，让同一个模型去解题。三句话的用意差不多，都是提示模型有条理地解题。哪一句的准确率最高？

答案是 B。这个例子说明三件事。

  • 措辞上的小差别，分数上的差别可以很大。A 和 B 都是让模型一步一步地解题，B 多了「深吸一口气」，后半句的说法也略有不同，准确率高了 8.4 个百分点。
  • 哪一句更好，很难凭直觉猜出来。B 和 C 都是算法搜出来的，C 的句子更长、用词更讲究，分数却比 B 低 5.7 个百分点。要知道哪句好，只能拿数据去测。
  • 这个结果只对这个模型和这批题成立。80.2% 是 PaLM 2-L 在 GSM8K 上的成绩。换一个解题的模型或换一类题，最好的那句话很可能就变了。第三部分会讲这三句话是怎么搜出来的。

B 这句话里的两个模型不要混在一起。PaLM 2-L-IT 是负责想出新 prompt 的模型，论文把它叫作优化器（optimizer）。拿着这句 prompt 去解数学题、得到 80.2% 的，是另一个模型 PaLM 2-L，论文把它叫作评分器（scorer）。所以准确的说法是：这句话对 PaLM 2-L 最好，它是由 PaLM 2-L-IT 找到的。

优化是什么

优化让我们可以用数据和评估来说明意图，并据此改进系统。

平时改进一个语言模型系统的办法是人去读输出、猜原因、改 prompt、再试。上面的小测验说明这种办法靠不住：人猜不准哪句话更好。优化换了一种分工。人负责准备两样东西：一批有代表性的输入（数据），和一个能给输出打分的办法（评估）。剩下的事交给算法：它提出改法，在数据上跑，看分数，保留分数高的。

这里的「说明意图」值得多说一句。很多要求很难用文字在 prompt 里写全，比如「回答要像我们公司的客服那样说话」。给出一百个好的回答和一个能分辨好坏的评估，往往比写一页说明更准确地表达了你想要什么。

模型越来越强，还需要调 prompt 吗

常有人问两个问题：现在还用得着花时间调 prompt 吗？模型规模再大一些，它自己不就变好了吗？

回答是：仍然需要，因为模型和优化解决的是两个不同的问题。

  • 模型提供的是一个很好的通用方案。它解决了大部分的问题，对所有人都一样。
  • 优化针对的是具体的场景。知道了你确切的使用环境，包括你的数据、你的工具、你对输出的要求，就可以把系统调到适合这个环境。

可以这样理解：模型变强之后，不做优化时的成绩会更高，但你的场景里那些只有你知道的要求，仍然要靠你的数据和评估告诉系统。

优化能带来什么

第三条容易被忽略：优化的目标可以是省钱。第四部分里的做法就是让一个小模型学会大模型的做法，用小模型的价钱得到接近大模型的效果。

这一讲的地图：改什么，谁来改

一个语言模型系统里能改的东西主要有两样，对应两大类优化。

  • 上下文优化（context optimization）。上下文是每次调用时放进模型输入里的全部文字，其中人能控制的主要是 prompt 里的两部分：用文字说明任务的指令（instruction），和做好了的例子，也就是示例。这一类优化只改这些文字，模型本身不动。
  • 权重优化（weight optimization）。权重是模型内部的参数。这一类优化用新的数据继续训练模型，改的是模型本身。这种做法叫 fine-tuning（微调）。

另外还有一个角度：优化的过程由谁来执行。可以是一个人写好的固定算法，也可以是一个会写代码的 agent。
