先看结论

  • prompt 是发给语言模型的那段输入文字。指令（instruction）是 prompt 里用文字说明任务的那一段。优化指令的办法是让一个语言模型来写新的指令。各种方法的差别在于：写之前给它看什么，写出来的候选怎么挑。
  • OPRO 给它看以往的指令和各自的分数。MIPROv2 给它看程序的说明、数据的特点和做成的例子，再用一个统计模型搜索指令和示例的最好组合。
  • TextGrad 和 GEPA 给它看的是系统实际运行的记录和对结果的文字评价，让它分析哪里出了问题再改。
  • GEPA 另外做了一件事：保留在不同题目上各自最好的多个候选，轮流在它们的基础上改。在六个任务上，它相对于不优化的提高幅度是 MIPROv2 的两倍多。

让语言模型来写指令

上一部分优化的是 prompt 里的示例。prompt 里还有一段指令，比如「根据花瓣和花萼的尺寸预测鸢尾花的品种」。指令是一段自由的文字，可能的写法无穷多，没法像示例那样从一个现成的集合里挑。

这一部分的四种方法都用同一个办法解决这个问题：让一个语言模型来提出新的指令，再用数据检验。它们的差别在两点：写新指令之前给语言模型看什么，写出来的候选怎么挑。

后两种方法都先把系统跑一遍，让语言模型读运行的结果、分析哪里可以改进，再把分析的结论写进 prompt。这个「读结果、找原因、再改」的过程，英文叫 reflection，这里译作反思。这类让语言模型看着结果来改 prompt 的做法，统称反思式优化（reflective optimization）。

OPRO：把以往的指令和分数给模型看

OPRO（Optimization by PROmpting，Yang 等，ICLR 2024）的想法很直接：把语言模型当作优化器。告诉它以往试过哪些指令、各得了多少分，请它写一条新的、分数更高的。

{{fig 24 | 左上是循环：优化器模型生成新的方案，评估程序给它们打分，方案和分数一起写回 meta-prompt。右边是 meta-prompt 的内容：开头说明下面是一些文字和它们的分数，按分数从低到高排列；中间是以往的指令和分数；然后是几道例题，说明指令会被放在什么位置；最后一句要求写一条和以往都不同、分数尽可能高的新文字。图片来源：Yang 等。}}

这里有两个模型，分工不同。负责写新指令的叫优化器（optimizer）。拿着指令去做题、用来算分数的叫评分器（scorer）。交给优化器的那段输入叫 meta-prompt，意思是「用来生成 prompt 的 prompt」。论文在数学应用题数据集 GSM8K 上的具体做法如下。

  • 每一步。把 meta-prompt 交给优化器 8 次，得到 8 条新指令。每条新指令在训练数据上算出准确率，连同分数加入历史。
  • meta-prompt 里放什么。到目前为止分数最高的 20 条指令，按分数从低到高排；再加 3 道从训练集里随机取的例题。
  • 用多少数据。从 GSM8K 的训练集里随机取 3.5%。训练集有 7,473 道题，粗略估算是 260 道左右。优化结束后，在全部 1,319 道测试题上评估。
  • 跑多久。默认 200 步。
  • 分数怎样才可比。评估时评分器的温度设为 0，每一步都取概率最高的 token，同一条指令的分数不带采样的随机波动。优化器的温度设为 1.0，让它写出多样的指令。

OPRO 靠把评分器的温度设为 0 去掉了评估里的随机性。做不到这一点时，比如模型的 API 不保证输出可重复，通常的做法是同一条 prompt 多跑几次，按分数波动的幅度来判断两条 prompt 的差别是否可信。

{{fig 25 | 评分器都是 PaLM 2-L，表里是用不同的优化器找到的、测试集准确率最高的指令。上面三行是对照：两条人写的指令，以及不加任何指令。图片来源：Yang 等的表 1。}}

四个优化器找到的指令风格各不相同：PaLM 2-L-IT 找到的是「深吸一口气，一步一步地解这道题」，准确率 80.2%；PaLM 2-L 找到的只有三个词「Break this down」，79.9%；GPT-3.5 和 GPT-4 找到的是更长的句子，78.5% 和 74.5%。人写的「Let's think step by step」是 71.8%。论文摘要里的说法是：OPRO 找到的最好的 prompt，在 GSM8K 上比人设计的高出最多 8%，在 Big-Bench Hard 的任务上高出最多 50%。对照论文的正文，这两个数说的都是准确率之差，单位是百分点：GSM8K 上是 80.2% 和 71.8% 相差的 8.4 个百分点；Big-Bench Hard 上，论文比较的是每个任务上的准确率之差。

「深吸一口气」这一条是在第 107 步找到的。它只是对 PaLM 2-L 这个评分器最好。论文换成另一个评分器 text-bison 之后，找到的最好的指令是另外的句子，最高的准确率是 68.5%。

i
OPRO 的局限。优化器看到的只有指令和一个总分。它不知道一条指令在哪些题上错了、错在哪里，只能从「哪种措辞分数高」里找规律。后面三种方法给它看的东西一个比一个多。

MIPROv2：指令和示例一起优化

MIPROv2 针对的是由多个模块组成的语言模型程序。程序里每一次对语言模型的调用是一个模块，每个模块有自己的指令和示例。MIPROv2 为每个模块同时选指令和示例。它分三步。

{{fig 26 | 三步的示意。第一步：对每个模块生成候选示例。第二步：对每个模块提出候选指令，输入是程序的概括、数据的概括、示例和一条提示。第三步：用贝叶斯搜索找指令和示例的最好组合，右边的百分比是各个组合的分数。图片来源：Opsahl-Ong 等，2024。}}
i
名字。Opsahl-Ong 等人 2024 年的论文里，这个算法叫 MIPRO（Multi-prompt Instruction PRoposal Optimizer）。MIPROv2 是它在 DSPy 这个库里的实现的名字。后来的论文引用时两个名字都用，指的是同一种方法。下面的默认数值来自 DSPy 现在的文档，旧版本可能不同。

下面用一个很小的例子走一遍。程序只有一个模块：输入花瓣和花萼的长宽四个数，输出鸢尾花的品种，共三种。最初的指令是「Given the petal and sepal dimensions in cm, predict the iris species.」。这个分类任务也是 MIPRO 论文的七个测试任务之一。

第一步：生成候选示例

这一步就是上一部分的 bootstrap：拿训练集里的输入去跑程序，输出通过指标检查的那些运行，把输入、推理和输出记下来。

{{figs 33 34 | 左：一条训练输入进入程序，程序给出品种的预测、推理和输出，指标判为通过，这条记录保留。右：保留下来的一条记录，包括四个输入、模型写的推理过程和答案 setosa。}}

这样重复很多次，得到若干套候选示例。DSPy 的默认设置是每套最多 4 个由程序生成的示例，另加最多 4 个直接取自训练集的示例。

第二步：让一个语言模型提出候选指令

直接让语言模型「写一条更好的指令」，它对任务一无所知，只能泛泛地改写。MIPROv2 先收集关于任务的四样背景，再交给负责写指令的模型。论文把这叫作 grounding，意思是让它写的东西有所依据。

{{fig 45 | 四样输入交给一个语言模型，输出是一批候选指令。}}

写作提示的作用是让候选指令彼此不同。论文附录里的列表有六项：不给提示；大胆发挥创意；保持简洁清楚；写得详细、信息充分；包含一个事关重大的情境；给模型一个和任务有关的身份，比如「你是一名……」。这份列表是针对当时的模型写的。一般认为，「事关重大的情境」这一类写法在当时的模型上比较有效，对现在的模型很可能没有那么必要。

{{fig 47 | 写出来的三条候选指令。第一条和第三条用了「事关重大的情境」那条提示，说这是为了拯救一个濒临灭绝的品种。第二条列出了三个品种的名字，并要求一步一步给出推理。}}

第三步：搜索指令和示例的最好组合

现在每个模块有 N 条候选指令和 N 套候选示例。所有组合都在全部数据上评估一遍太贵。MIPROv2 的办法是维护一个统计模型，记录目前对「每条指令、每套示例有多好」的估计，然后重复下面的循环。

{{figs 50 62 | 左：循环开始时。每条指令和每套示例旁边的横条是目前对它的估计，这时都一样。红框标出这一轮抽中的是指令 1 和示例集 2。右：若干轮之后。横条里绿色的部分越长，表示估计越好。指令 1 和示例集 1 的估计变高了，指令 2 的估计变低了。}}
  1. 按目前的估计抽一个组合，比如指令 1 配示例集 2。估计好的更容易被抽中，还没怎么试过的也有机会。
  2. 把抽中的指令和示例填进程序。
  3. 从数据里随机抽一小批，用填好的程序跑一遍，得到一个分数。DSPy 的默认设置是一小批 35 条。
  4. 按这个分数更新对这条指令和这套示例的估计。
  5. 每隔几轮，把到目前为止平均分最高的组合在全部数据上完整评估一次，确认它在小批数据上的高分不是偶然。默认是每 5 轮一次。

循环结束后，返回完整评估里分数最高的组合。这种「用一个统计模型代替昂贵的真实评估来指导搜索」的做法叫贝叶斯优化，那个统计模型叫代理模型（surrogate model）。MIPRO 用的是 Optuna 这个库里的 Tree-structured Parzen Estimator。用小批数据评估会让单次的分数有噪声，论文的理由是贝叶斯优化对噪声比较稳健。可以把这一步理解成一个多臂老虎机（multi-armed bandit）问题：有很多个选项，每试一次得到一个带噪声的分数，要用有限的尝试次数找出最好的那个。

{{fig 63 | 优化的结果。上面是最初的指令。下面是优化后这个模块的 prompt：一条新的指令，后面跟着一个带推理过程的示例。}}

在这个例子里，最后选中的是那条「拯救濒危品种」的指令，加一个由程序自己生成的示例。这条指令读起来有些奇怪，但它是在数据上测出来分数最高的。这和第一部分的小测验是同一个道理。

论文的结果和三条经验

论文用 Llama-3-8B 做执行任务的模型，在七个多步骤的语言模型程序上测试。摘要的结论是：MIPRO 在其中五个上超过了作为对照的几种优化器，准确率最多高出 13%。对照论文的结果表，这个数应当是准确率之差，单位是百分点：在带条件规则的那个 HotPotQA 任务上，MIPRO 的测试成绩是 23.3，只优化示例的随机搜索是 10.4，相差 12.9 个百分点。论文总结了五条经验，前三条是：

  • 优化示例是拿到最好成绩的关键。在多数任务上，只优化由程序生成的示例，明显好于只优化指令。
  • 指令和示例一起优化，总体上最好。有三个任务例外。
  • 指令在一种情况下最重要。任务里有带条件的规则，这些规则模型不容易自己看出来，又没法靠几个示例表达清楚。

TextGrad：把文字反馈往回传

TextGrad（Yuksekgonul 等，2024）借用了训练神经网络时的做法。训练神经网络时，先算出输出离目标有多远，再把这个差距沿着网络一层一层往回传，算出每个参数该怎么调，这叫反向传播，传回去的量叫梯度。TextGrad 把一个语言模型系统也看成一张由若干步骤连成的图，往回传的是文字。

{{fig 64 | 左边是一个系统的例子：prompt、查询和工具的 prompt 分别进入语言模型、搜索引擎和工具调用，中间的输出再进入后面的语言模型，最后得到一个评价。紫色的箭头是往回传的文字反馈，写着「这个回答可以这样改进」「这个 prompt 可以这样改进」。右边是一个优化前后的例子。图片来源：Yuksekgonul 等，2024。}}
  • 往前跑。系统正常运行，得到最后的输出。再用一个语言模型按评估的要求给这个输出写评价，相当于神经网络里的损失。
  • 往回传。从最后一步开始，让语言模型针对每一个中间结果写出「它应该怎样改，最后的评价才会变好」。这段文字批评传给上一步，上一步再据此写出对自己的输入的批评，一直传到最前面的 prompt。论文把这些文字叫作 textual gradients（文本梯度），并说明「梯度」在这里是一个类比。
  • 更新。把 prompt 和针对它的批评一起交给语言模型，让它写出改过的 prompt。

整个过程里没有数值上的求导，每一步传的都是语言模型写的文字。TextGrad 的接口照着深度学习库 PyTorch 来设计，论文摘要的说法是沿用 PyTorch 的语法和抽象，所以损失、梯度、反向传播这些词在这里指的都是文字版本的对应物。

图右边的例子是数物体个数的任务（Big-Bench Hard 里的 Object Counting）。执行任务的是 gpt-3.5-turbo，写反馈的是 gpt-4o。最初的 prompt 只说「一步一步地想，最后一行按固定格式给出答案」，准确率 77.8%。优化后的 prompt 要求逐项列出物品和数量、直接按列表求和、检查每一项是否和问题有关、最后再核对一遍总数，准确率 91.9%。这次优化只用了 12 轮，每轮 3 道训练题。论文的同一组实验里，带 8 个示例的 DSPy bootstrap 是 84.9%。

TextGrad 能优化的不限于 prompt。论文里还用它直接改进某一道题的解答、一段代码、一个分子的结构。摘要里的两个数字是：GPT-4o 在 GPQA 这组研究生水平的理科选择题上不带示例的准确率从 51% 升到 55%；在 LeetCode 难题上的成绩相对提高 20%。这篇论文后来以另一个标题发表在 2025 年的《Nature》上。

GEPA：反思，加上保留多个各有所长的候选

GEPA（Genetic-Pareto，Agrawal 等，ICLR 2026）把两件事合在一起：让语言模型读运行记录来改指令，以及用进化的方式管理一群候选。它优化的也是由多个模块组成的系统，每次只改其中一个模块的指令。

{{fig 65 | GEPA 的流程。左下是候选池和分数表：每一列是一个候选，每一行是一道题，对勾表示这个候选在这道题上是最好的。中间按「每道题上最好的候选」筛出帕累托前沿。右边是提出新候选的两种办法：反思式的修改，和把两个候选合并。上方是接受新候选的检查：先在一小批题上比较，变好了才在全部验证题上评估并加入候选池。图片来源：Agrawal 等。}}

一轮里发生什么

  1. 选一个候选。候选池一开始只有最初的系统。选法见下一小节。
  2. 选一个模块。系统里的模块轮流来。
  3. 跑一小批。从训练数据里随机抽一小批题，论文的实验里是 3 道。用选中的候选跑一遍，记下这个模块的输入、输出和推理。同时调用反馈函数：它除了返回分数，还返回评估过程中产生的文字，比如编译器的报错、没有满足的评分项。
  4. 反思并改写。把当前的指令、运行记录、分数和文字反馈交给一个语言模型，让它判断成功和失败分别和指令里的哪些内容有关，再写出一条新的指令。
  5. 先小范围检查。换上新指令，在同样这一小批题上再跑一遍。分数没有提高就丢弃。
  6. 通过了再完整评估。分数提高了，就把它加入候选池，记下它是从谁改来的，并在全部验证题上逐题评估。

预算用完后，返回验证题上平均分最高的候选。预算按 rollout 计：把系统在一道题上从头到尾跑一次，算一次 rollout。

候选怎么选：帕累托前沿

最简单的选法是每次都在平均分最高的候选上接着改。论文指出这样容易卡住：找到一个不错的策略之后，搜索会反复在它上面小修小补，改不出更好的，预算就用完了。

GEPA 的选法是按题来看。对每一道验证题，记下哪些候选在这道题上得分最高。只要在至少一道题上是最好的，这个候选就有可取之处。然后去掉多余的候选，论文把它们叫作被严格支配（strictly dominated）的候选。可以这样理解：如果候选 B 最好的那些题上，候选 A 也都是最好的，A 还在别的题上最好，B 就是多余的。剩下的这一组候选叫帕累托前沿（Pareto frontier）。从里面随机抽一个，被抽中的概率和它在几道题上最好成正比。

看上面图里的例子。第 1 题上最好的是 P3，第 2 题上是 P1 和 P2，第 3 题上是 P2。P0 和 P4 在哪一题上都不是最好的，不参加。P1 只在第 2 题上最好，而 P2 在第 2 题上同样最好，在第 3 题上也是最好的，所以 P1 被去掉。前沿上剩下 P2 和 P3。按论文的算法推算，P2 在两道题上最好，P3 在一道题上最好，P2 被抽中的机会是 P3 的两倍。

前沿上有多少个候选，由验证题决定：一个候选要留在前沿上，至少要在一道验证题上得分最高。所以可供选择的候选数量大致受验证题数量的限制。遗传算法通常靠维持一个很大的群体来保持多样性，GEPA 的多样性来自题目之间的差别；验证题少，或者一个候选在大多数题上都领先时，前沿上就只有很少的几个候选。另外，搜索从最初的一个系统出发，候选池里的所有候选都是它一步步改出来的，结果仍然可能受这个起点的影响。

另一种提出新候选的办法是合并：两个候选来自同一个祖先，各自改好了不同的模块，就各取改好的那个模块拼成一个新候选。论文把带这一步的版本叫 GEPA+Merge。

一个例子：保护隐私的委托

PAPILLON（Li Siyan 等）是一个由两个模块组成的系统。场景是：用户的问题里有隐私信息，本地有一个可信但较弱的模型，远程有一个更强但不可信的模型。

{{fig 66 | 左边是 PAPILLON 的流程：用户的问题先交给本地的「Prompt Creator」模块，改写成一个不含隐私信息的请求，发给远程的模型；远程模型的回答和用户原来的问题一起交给本地的「Information Aggregator」模块，由它写出最后的回答。右边是 GEPA 论文里给这两个模块用的最初的指令。左图来源：Li Siyan 等。}}

评分同时看两件事：最后的回答质量有多高，以及有多少隐私信息泄露给了远程模型。GEPA 得到的文字反馈就是这两项各自的得分。第一个模块最初的指令只有两句话：给定一个包含隐私的用户问题，为一个强大的外部模型写一个保护隐私的请求；这个模型可以提供帮助，但不应得知用户的隐私信息。第二个模块最初的指令也只有两句：回答用户的问题；作为参考，附上一个发给外部模型的相关请求和它的回答。中间发给远程模型的那一步没有可以优化的指令，远程模型收到的就是第一个模块写出的请求。

{{fig 67 | GEPA 在这个任务上的一次优化过程。每个圆是一个候选，括号里是它的分数，连线表示谁是从谁改来的。红色箭头标出从最初的指令（0 号，82.26）到最好的指令（11 号，97.6）的路径，旁边的方框概括了这一步的指令增加了什么。图片来源：Agrawal 等。}}

沿着红色的路径，指令一步步变具体。2 号（90.99）加上了怎样识别和概括隐私信息的详细指导，并要求分析问题的意图。4 号（94.44）规定输出分成「推理」和「请求」两部分，明确禁止出现姓名和代号。5 号（94.67）要求写明隐私处理的理由。11 号（97.6）变成一套严格的步骤：逐项抽象隐私信息和专有信息，不允许只遮掉一部分，不容许任何泄露。这棵树来自用 GPT-4.1 Mini、带合并步骤的那次运行。图上的分数很可能是验证题上的分数，论文的图注没有写明；它们和下面表里的测试分数不是同一批题。

这个例子显示了反思式优化的一个特点：最后的指令里写的是从失败的例子里总结出来的具体规则，人可以读懂，也可以检查。

论文在两个模型、六个任务上，把 GEPA 和几种 prompt 优化方法作了比较。先看 GPT-4.1 Mini 上的结果。

{{fig 68 | 以 GPT-4.1 Mini 为执行任务的模型，各种 prompt 优化方法在六个任务上的测试分数。Aggregate 是六个任务的平均，Improvement 是比不做优化高多少。最后一行是把用 Qwen3-8B 优化出来的 prompt 原样拿给 GPT-4.1 Mini 用的结果。图片来源：Agrawal 等的表 2。}}

从论文里可以读出四点。

  • 只优化指令的 GEPA，超过了同时优化指令和示例的 MIPROv2。这和 MIPRO 论文的第一条经验方向相反。GEPA 的作者认为主要原因是，近来的模型遵循指令和反思的能力变强了。
  • prompt 更短。因为不带示例，GEPA 得到的 prompt 的长度，最短时只有 MIPROv2 的 9.2 分之一，每次调用更便宜。
  • 可以跨模型用。用较弱的 Qwen3-8B 优化出来的 prompt，原样拿给 GPT-4.1 Mini 用，平均分比不优化高 9.00 个百分点，高于直接在 GPT-4.1 Mini 上跑 MIPROv2 和 TextGrad 的结果。
  • 合并这一步不总是有帮助。在 GPT-4.1 Mini 上，GEPA+Merge 的平均分更高。在 Qwen3-8B 上，它的平均分反而比不合并的 GEPA 低，其中一个任务上还低于不优化的分数。

GEPA 的论文题目说的是它能超过强化学习。这个比较放在第七部分，和权重优化一起看。

上下文优化的小结

第二、第三部分合起来是上下文优化。两条主要的经验：

  • 优化示例。让程序自己生成带推理和输出的示例，再搜索有用的组合，是一种很有效的做法。
  • 反思式优化。先把任务跑一遍，分析该改什么，再把结论写进 prompt，也是一种很有效的做法。按帕累托前沿的改进来进化 prompt，还能进一步提高。这样做的 GEPA 已经收进 DSPy 这个库，DSPy 的入门文档用它来示范怎样优化 prompt。

改写 prompt 为什么能提高分数，早期和现在的解释不同。

  • 早期：找到模型更熟悉的说法。OPRO 那个时期，改动主要在措辞上。当时流行的一种解释是：模型自己写出来的 prompt 更接近它训练时见过的文字，模型在这样的文字上表现更好，搜索的过程就是在找更接近训练数据的说法。没有查到专门检验这个解释的实验，只能把它当作一种直观的理解。
  • 现在：把没写出来的要求补进去。一种常见的看法是，模型变强之后措辞的影响变小，优化主要用来补全任务的要求。比如指令里忘了写日期要用 ISO 8601 格式（一种国际标准的日期写法，形如 2026-11-19），系统跑一遍之后，反思的那一步能从失败的记录里看出「日期的格式不对」，再把这条要求写进指令。上面 GEPA 在 PAPILLON 上得到的指令，就是这样一步步变具体的。

这些方法有一个共同的前提：模型的权重不动。所以它们对只能通过 API 调用的模型同样适用，每次优化要跑的次数也相对少。它们的上限是模型已有的能力：指令写得再好，也教不会模型它本来不会的事。下一部分开始讲另一条线：改模型的权重。
