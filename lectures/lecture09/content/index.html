先看结论

优化就是用数据和评估说明你想要什么，再让算法去改系统。这里的评估指给输出打分的办法，后面几部分也写作评估指标。

能改的主要有两样。一样是上下文，也就是每次调用时放进模型输入里的全部文字。这段文字也叫 prompt，其中能优化的主要是指令（用文字说明任务的那一段）和示例（做好了的例子）。另一样是模型的权重，也就是模型内部的参数。

改 prompt 便宜、快，适合先做。它不够用时再改权重。不管用哪一种，算法只会把你给的那个评估分数做高，所以评估本身最要紧。

两类优化放在一起比

只改 prompt、不动模型本身的一类叫上下文优化，论文里常叫 prompt 优化。改权重的一类叫权重优化。下面的表把这两类优化并排放在一起。表里有七个词先交代一下。

  • token 是模型处理文字的最小单位，大致是一个词或半个词。
  • 运行指把系统在一道题上从头到尾跑一次。
  • 运行轨迹是一次运行里每一步的动作和看到的结果的完整记录，表里也简称轨迹。
  • 教师模型是一个更强的、已经能把任务做好的模型。照着它学的那个模型叫学生模型。
  • 蒸馏指让学生模型学习教师模型的行为。
  • on-policy 指训练用的数据由学生模型自己产生。
  • agent 是能自己调用工具、分很多步去完成任务的语言模型系统。

 第二部分优化示例：放哪些例子，按什么顺序放
