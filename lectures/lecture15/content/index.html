先看结论

判定 agent 交出的结果对不对的那段逻辑叫评分器。评分器本身是一个测量工具，它会判错，所以也要被检验。能用代码检查的用代码，代码判不了的交给语言模型评审，也就是让一个语言模型来判断结果好不好。评审的判定要和人的判定对照过才可信。agent 每次运行的结果不同，所以报分数时还要写明跑了几次、用哪种汇总办法。

第 13 讲把基准测试的任务定义拆成问题描述、环境、验证三样。环境是 agent 执行任务的地方，里面有它能读写的东西，比如代码仓库、数据库和文件。验证判定 agent 交出的结果算不算通过。

这一讲的前六个部分讲两件事。第一件是一次运行的结果判得准不准，这属于验证。第二件是多次运行的结果怎么汇总，第 13 讲把它归在评估协议里，也就是跑分时每题跑几次、结果怎么汇总这类规定。下表把两件事并排来看。

最后的第七部分讲把任务交给 agent 去跑、调用评分器并汇总结果的那套程序，以及搭一套评估的步骤。

第二、三、四部分讲的是用语言模型当评审的三个阶段。这一讲按被评的东西来分：第一个阶段评一段生成的文字，第二个阶段判断人更喜欢哪个回答，第三个阶段评 agent 的动作和结果。

表里有四个词先说明一下。校准指拿语言模型评审的判定和人的判定对照，让两者保持一致。文本指标指用程序给一段文字自动算分的办法。G-Eval 是让语言模型按评分标准给文字打分的一种方法，表里的数是用 GPT-4 得到的。WebVoyager 是一个在真实网站上完成任务的 agent，它的论文用一个能看图的模型当评审，判断任务是否完成。

第 13 讲的结论是没有哪一个基准测试能说明一切。这一讲的结论接着往下说：单看一个基准测试给出的分数，也要在评分器经过检验、汇总办法写明之后，才知道它说明了什么。对语言模型评审来说，检验就是拿它的判定和人的判定对照。
