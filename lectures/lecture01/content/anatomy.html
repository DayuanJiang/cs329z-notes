先看结论

  • 一个 LLM agent 有五个部件：LLM 核心、规划和推理、记忆、工具、环境。前四个在 agent 里面，环境在外面。
  • 它们在一个循环里配合。每一轮里，LLM 先想下一步该做什么，再通过工具做一个动作，环境返回一个观察结果，这个结果记进记忆，然后开始下一轮。
  • 和一次普通的 LLM 调用相比，区别有三点：会动手改变外部的东西，会看到动作的结果，做几步、做到什么时候停由模型自己决定。
  • LLM agent 的拆法有别的版本，用词不同，指的是同一个结构：一个 LLM 在环境里循环地推理、记忆、使用工具和行动。

它们怎样配合：一个循环

五个部件靠一个循环连在一起：想一步，做一步，看结果，再想。这个循环叫 agent loop。把它写成代码只有十来行。

history = [task]                               # memory: everything so far
while True:
    step = llm(instructions, tools, history)   # LLM core: reason, then decide
    history.append(step)
    if step.is_final_answer:                   # the model decides when to stop
        return step.text                       # action: respond to the user
    result = run_tool(step.tool, step.args)    # action: act on the environment
    history.append(result)                     # observation goes into memory

逐行对照五个部件：

  • llm(…) 是 LLM 核心。每一轮调用一次模型，交给它三样东西：一段说明（它是谁、要遵守什么），可用的工具清单，以及到目前为止的全部记录。
  • 模型的输出里包含推理。它可以先写一段想法，再写要调用哪个工具。
  • history 是最简单的一种记忆。每一步做了什么、看到了什么，都追加在后面，下一轮原样交给模型。
  • run_tool(…) 是工具。模型只负责写出「用哪个工具、参数是什么」，真正去执行的是模型外面的程序。
  • 工具作用的对象是环境。读文件、点网页、查数据库，结果作为观察返回。

包在模型外面的这段程序，也就是这个循环本身，加上工具的实现和对记录的管理，叫运行框架（harness，也叫 scaffold）。同一个模型放进不同的运行框架，表现可以差很多。

循环里有一行值得多看一眼：if step.is_final_answer。什么时候停，是模型自己说的。这是 agent 和 workflow 的分界：workflow 里每一步做什么、什么时候结束，由事先写好的代码规定，agent 里由模型决定。第六部分专门讲这个区别。

LLM 核心：模型越强，agent 越强

agent 建立在大语言模型之上。一般来说，模型越强，agent 越好：推理更准，犯的错更少，编造内容（常叫幻觉，hallucination）更少，能应付的任务也更长。第一部分的两张图分别画了模型和 agent 这几年的进步。

这也带来一个一直在争论的问题：想让 agent 更好，是该去训练一个更适合当 agent 的模型，还是该把力气花在运行框架和别的改进上。图里的每个方框都可以单独调整：换一个模型，换一种推理的办法，换一种记忆的设计，增减工具。大家都想找到最好的那一组配置，所以运行框架和优化在后面各讲里占了很大的分量，第 9 讲专门讲优化。

工具：模型自己做不到的事

一个能解很难的数学题的模型，被问到「今天下午的讲座在校园的哪间教室」时，是答不出来的。这个信息不在它的训练数据里。类似的情况很多。

第二行有一个具体的数。2023 年的一篇论文测过，不给例子、直接提问时，GPT-4 做三位数乘三位数的乘法只对了 59%，ChatGPT 是 55%。四位数乘四位数时，GPT-4 的正确率降到 4%。有了工具，agent 的动作才能建立在事实和确定的计算上，前后也更一致。

出处：Dziri 等，2023，《Faith and Fate: Limits of Transformers on Compositionality》。模型怎样学会用工具、一次工具调用里发生了什么，见第五部分。

环境：动作作用在哪里

环境是 agent 之外的世界。图里列了五种：桌面操作系统、网页浏览器、手机应用、游戏、数据库。上面例子里的 ALFWorld 属于游戏这一类。

环境决定了两件事。第一，agent 能做哪些动作：在网页里是点击和输入，在终端里是执行命令，在代码仓库里是读写文件和运行测试。第二，agent 能看到什么：一段文字、一张屏幕截图、一条命令的输出。agent 和环境之间就是这两个方向的往来，动作过去，观察回来。

agent 出了问题，后果也发生在环境里。一次普通的 LLM 调用答错了，错的是一段文字。agent 做错了，可能是一封已经发出去的邮件、一个已经删掉的文件。第七部分讲的安全问题，大多出在 agent 和环境之间。

别的拆法：用词不同，结构相同

什么算 agent、什么不算，有过很多争论。五个部件这种拆法也只是其中一种。把几种常被引用的拆法放在一起，可以看到同样的几块反复出现。

{{fig 31 | 两种别的拆法。左：Lilian Weng 2023 年的图，agent 在中间，周围是工具、记忆、规划和动作。右：CoALA 框架的图，方框里是记忆、推理，以及读记忆的检索和写记忆的学习，方框外是环境，两者之间是观察和动作。图片来源：Weng，2023；Sumers 等，2024。}}

前两种说法的词汇不一样，指向的是同一个结构：一个 LLM 在它的环境里，循环地推理、记忆、使用工具并行动。Russell 和 Norvig 的定义更宽，不要求里面有 LLM，强化学习的 agent 也符合；它说的感知和行动，对应这个结构里的观察和动作。这里不去争论哪个定义最准确，后面看到任何一个 LLM agent，都可以拿这五个部件去对。

CoALA 的拆法解释了一个容易困惑的地方。「读写记忆」在五个部件的表里列在工具那一行，记忆自己又是一个单独的部件。按 CoALA 的说法就清楚了：记忆是存东西的地方，检索和学习是读它、写它的动作。对模型来说，查记忆和查网页是同一种操作，都是发出一个调用、拿回一段文字，所以读写记忆常常就做成工具。

这一部分的小结

  • agent 的基本结构是五个部件：LLM 核心负责想和决定，规划和推理让它想得更好，记忆让它记得之前发生过什么，工具让它能动手，环境是它动手的地方。
  • 把它们连起来的是一个循环。循环本身很简单，十来行代码就能写出来。
  • 不同的 agent，差别在于每个方框是怎么实现的，以及这几块配合得好不好。
