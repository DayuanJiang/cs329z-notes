先看结论

  • 这一讲说的 agent 全称是 LLM agent，指由 LLM 自己一步一步决定做什么、调用工具去完成任务的系统。它可以拆成五个部件：LLM 核心、规划和推理、记忆、工具、环境。这里的工具指模型可以调用的外部功能。
  • 前四个部件组成 agent 本身。环境指 agent 之外、它的动作作用在上面的那个世界，这一讲把它和前四个放在一起，合称五个部件。
  • 它们在一个循环里配合。每一轮里，LLM 先想下一步该做什么，再通过工具做一个动作，环境返回一个观察结果，这个结果记进记忆，然后开始下一轮。
  • 和一次普通的 LLM 调用相比，agent 的区别有五点。前三点是：要做很多轮，会改变外部的东西，会看到动作的结果。第四点是下一步做什么、什么时候给出最终回答由模型自己决定，一共做几步事先不固定。第五点是 agent 交出来的是一个被改动过的环境和每一步的完整记录。
  • agent 的拆法有别的版本，用词不同，指的是同一个结构：一个 LLM 在环境里循环地推理、记忆、使用工具和行动。

五个部件

表里前两行说的是同一个模型做的事。agent 的每一个决定，都是 LLM 核心在它生成的文字里做出的。规划和推理指这些文字里先于动作写出来的分析和打算，比如上面记录里「想」后面的内容，它也是 LLM 核心生成的。

图的最下面还有一行「agent 的动作」，列了三种：调用工具（tool call），交互（interaction），回复用户（response to users）。

调用工具是动作里的一种。前面例子里的「去 3 号台面」「拿起胡椒瓶」都是这一种动作，调用的工具分别是「去某处」和「拿起」这两条命令。一个环境里有哪些操作可做、其中哪些做成了工具，环境一节再讲。

交互这一种，配图上只写了 interaction 一个词，没有说明和谁交互。这一讲里和它有关的例子在第七部分：一个 agent 在信息不够的时候自己做了假设，没有回头问人，那里把这类失败归到和人的交互上。

回复用户也算一种动作。一个 agent 做完任务后说「已经改好了」，和它中途调用一次搜索，在这张图里是同一类东西：都是 LLM 生成的一段输出，被送到了 agent 的外面。

它们怎样配合：一个循环

五个部件靠一个循环连在一起：想一步，做一步，看结果，再想。这个循环叫 agent loop。把它写成代码不到十行。

history = [task]                               # memory: everything so far
while True:
    step = llm(instructions, tools, history)   # LLM core: reason, then decide
    history.append(step)
    if step.is_final_answer:                   # the model decides when to stop
        return step.text                       # action: respond to the user
    result = run_tool(step.tool, step.args)    # action: act on the environment
    history.append(result)                     # observation goes into memory

逐行对照五个部件：

  • llm(…) 是 LLM 核心。每一轮调用一次模型，交给它三样东西：一段说明（它是谁、要遵守什么），可用的工具清单，以及到目前为止的全部记录。
  • 模型的输出里包含推理。它可以先写一段想法，再写要调用哪个工具。
  • history 是最简单的一种记忆。每一步做了什么、看到了什么，都追加在后面，下一轮原样交给模型。
  • run_tool(…) 是工具。模型只负责写出「用哪个工具、参数是什么」，真正去执行的是模型外面的程序。
  • 工具作用的对象是环境。读文件、点网页、查数据库，结果作为观察返回。

包在模型外面的这段程序，也就是这个循环本身，加上工具的实现和对记录的管理，叫运行框架（harness，也叫 scaffold）。

同一个模型放进不同的运行框架，成绩会不一样。第七部分引的一项审计里，Claude Opus 4.6 这一个模型分别放在 OpenClaw 和 Claude Code 两个运行框架里，任务完成率是 0.74 和 0.82，满分是 1。

这个循环里，每一轮做什么都由模型决定。llm(…) 那一行返回的 step 是模型写出的这一步，内容是调用哪个工具、参数是什么，或者是最终回答。if step.is_final_answer 那一行检查它是不是最终回答，所以什么时候停，也由模型自己决定。

这是 agent 和 workflow 的分界。workflow 里每一步做什么、什么时候结束，由事先写好的代码规定，agent 里由模型决定。第六部分专门讲这个区别。

上面说的停，指模型判断任务已经做完、给出最终回答。检查到最终回答并结束循环的这行代码属于运行框架，运行框架也可以另设结束的条件，比如规定步数的上限。第七部分讲安全时说整个执行过程什么时候终止由运行框架决定，指的是这一层。

LLM 核心：模型越强，agent 一般也越强

agent 建立在大语言模型之上。一般来说，模型越强，agent 越好：推理更准，犯的错更少，编造内容（常叫幻觉，hallucination）更少，能应付的任务也更长。第一部分的两张图分别画了模型和 agent 这几年的进步。模型怎样生成文字、上下文里该放什么，是第 2 讲的内容。

这也带来一个一直在争论的问题：想让 agent 更好，是该去训练一个更适合当 agent 的模型，还是该把力气花在运行框架和别的改进上。第 9 讲专门讲优化，讨论的是一个相近的选择：改 prompt 和上下文，还是改模型的权重（模型内部由训练定下来的那些数值，也叫参数）。

五个部件那张图里，agent 里面的四个部件都可以单独调整：换一个模型，换一种推理的办法，换一种记忆的设计，增减工具。搭 agent 的人都想找到让 agent 表现最好的那一组配置，所以运行框架和优化在后面各讲里占了很大的分量。

工具：模型自己做不到的事

一个能解很难的数学题的模型，被问到「今天下午的讲座在校园的哪间教室」时，是答不出来的。这个信息不在它的训练数据里。类似的情况很多，下表列出三种。

第二行有实测的结果。2023 年的一篇论文测过，不给例子、直接提问时，三位数乘三位数的乘法，GPT-4 只做对了 59%，ChatGPT（gpt-3.5-turbo）只做对了 55%。四位数乘四位数时，GPT-4 的正确率降到 4%。出处：Dziri 等，2023，《Faith and Fate: Limits of Transformers on Compositionality》。

有了工具，agent 的动作才能建立在事实和确定的计算上，前后也更一致。拿乘法来说，同一道题交给计算器，每次算出的结果都相同。

模型怎样学会用工具、一次工具调用里发生了什么，见第五部分。

环境：动作作用在哪里

环境是 agent 之外的世界。五个部件那张图里举了五种：桌面操作系统、网页浏览器、手机应用、游戏、数据库，后面还写着「等等」。终端和代码仓库不在这五种里，也是常见的环境。上面例子里的 ALFWorld 是文字游戏，属于游戏这一类。

环境决定了两件事。第一，在它里面可以做哪些操作：在网页里是点击和输入，在终端里是执行命令，在代码仓库里是读写文件和运行测试。第二，agent 能看到什么：一段文字、一张屏幕截图、一条命令的输出。agent 和环境之间就是这两个方向的往来：agent 向环境发出动作，环境把观察结果返回给 agent。

环境决定的是有哪些操作可做。其中哪些做成工具交给模型、每个工具允许做什么，由运行框架决定，见第五部分。调用工具这一种动作，就是通过工具对环境做一次这样的操作。

agent 出了问题，后果也发生在环境里。一次普通的 LLM 调用答错了，错的是一段文字。agent 做错了，后果可能是一封邮件已经发了出去、一个文件已经被删掉。第七部分讲的安全问题，大多出在 agent 和环境之间。

别的拆法：用词不同，结构相同

什么算 agent、什么不算，有过很多争论。一个 agent 怎么拆也有几种说法，五个部件只是其中一种。把几种常被引用的拆法放在一起，可以看到同样的几个部件反复出现。

下面的图里是其中两种。左边的图出自 Lilian Weng 2023 年 6 月的博客文章《LLM Powered Autonomous Agents》，她当时是 OpenAI 的研究员。右边的 CoALA 是 2023 年一篇论文提出的一套描述 LLM agent 的框架，名字是论文标题 Cognitive Architectures for Language Agents 的缩写。

{{fig 31 | 两种别的拆法。左：Lilian Weng 2023 年的图，agent 在中间，周围是工具、记忆、规划和动作。右：CoALA 框架的图，方框里是记忆、推理，以及读记忆的检索和写记忆的学习，方框外是环境，两者之间是观察和动作。图片来源：Weng，2023；Sumers 等，2024。}}

下表把这两种拆法和五个部件对上，最后一行另外列出 Russell 和 Norvig 的教科书给 agent 下的定义，作为对照。表里有两个词先说明一下。向量数据库是把文字转成一串数字来保存、能按意思相近来查找的数据库。工作记忆是 CoALA 的用词，指 agent 当前这一轮做决定时手头可以直接用的信息，和它相对的长期记忆存在别处，用到时再取。

表里前两种拆法用的词不一样，指向的是同一个结构：一个 LLM 在它的环境里，循环地推理、记忆、使用工具并行动。后面看到任何一个 agent，都可以用这五个部件逐个对照。

Russell 和 Norvig 的定义更宽，不要求里面有 LLM，靠试错和奖励训练出来的强化学习 agent 也符合。它说的感知和行动，对应这个结构里的观察和动作。

CoALA 的拆法解释了一个容易困惑的地方。「读写记忆」在五个部件的表里列在工具那一行，记忆自己又是一个单独的部件。按 CoALA 的说法就清楚了：记忆是存东西的地方，检索和学习是读它、写它的动作。对模型来说，查记忆和查网页的做法相同，都是发出一个调用、拿回一段文字，所以读写记忆常常就做成工具。

这一部分的小结

  • agent 的基本结构是五个部件：LLM 核心负责想和决定，规划和推理让它想得更好，记忆让它记得之前发生过什么，工具让它能做光靠生成文字做不到的事，环境是它的动作作用的地方。
  • 把它们连起来的是一个循环。循环本身很简单，不到十行代码就能写出来。
  • 不同的 agent，差别在于每个部件是怎么实现的，以及这几个部件配合得好不好。
