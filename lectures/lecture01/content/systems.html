先看结论

  • 复合 AI 系统（compound AI system）指用多个互相配合的部件来完成任务的系统：多次调用模型，再加上检索器、外部工具这类部件。实际的 AI 产品几乎都是这样的系统，单独一个模型只是其中一个部件。
  • 复合 AI 系统里有一个关键的设计选择：下一步做什么由谁决定。由事先写好的代码决定，叫 workflow；由 LLM 自己决定，叫 agent。
  • workflow 可以很强。AlphaCode 2 的步骤是固定的：生成最多一百万个候选程序，再过滤、聚类、打分。它在编程竞赛里的成绩估计超过 85% 的参赛者。
  • 检索增强生成（RAG）是用得最广的一种 workflow：先检索，再把检索到的内容拼进 prompt，最后生成回答。
  • agent 工程可以分成三层：系统、数据、评估。agent 表现不好时，先问问题出在哪一层。

复合 AI 系统是什么

第二部分把一个 agent 拆成了五个部件。真实的产品里，LLM 总是和别的部件组合在一起用。这种组合有一个名字，叫复合 AI 系统。

这个词出自 Matei Zaharia 等 11 位作者 2024 年 2 月发表在伯克利 BAIR 博客上的文章。文章的定义是：复合 AI 系统用多个互相配合的部件来完成 AI 任务，包括多次调用模型、检索器或外部工具。与之相对的是 AI 模型，它只是一个统计模型，比如一个预测下一个 token（模型处理文字的最小单位，大致是一个词或半个词）的 Transformer。

文章的主要判断是：最好的 AI 成果越来越多地来自由多个部件组成的系统，单靠一个模型拿到的越来越少。它举了下面这些例子。

workflow 和 agent：下一步由谁决定

workflow 和 agent 都是复合 AI 系统，都是一个 LLM 加上别的部件。它们的区别只有一条：下一步做什么，是代码定的，还是 LLM 定的。

两个例子都来自修真实代码仓库里的 bug 这个任务。

  • Agentless。它的论文标题就点明了立场：不让 LLM 决定后面的动作，也不让它操作复杂的工具。流程固定为三个阶段：定位（找出要改的文件和位置）、修复（生成补丁）、验证补丁（用测试挑出最可信的一个）。论文报告它在 SWE-bench Lite 上修对了 300 道题里的 96 道（SWE-bench 是一个修真实代码仓库里的 bug 的基准测试，Lite 是它的一个子集），也就是 32.00%，平均每道题花费 0.70 美元，当时比所有开源的 agent 方案成绩都高，花费也低。
  • SWE-agent。它给模型一套专门设计的命令（论文叫 agent-computer interface），用来浏览仓库、查看和编辑文件、运行测试。用哪条命令、按什么顺序用，由模型决定。论文报告它在完整的 SWE-bench 上解决了 12.5% 的题。
i
这两个数不能直接比。32.00% 是在 SWE-bench Lite 上测的，12.5% 是在完整的 SWE-bench 上测的，题目不同，用的模型和时间也不同。这里列出它们只是为了说明两种设计都拿得出成绩。出处：Xia 等，2024；Yang 等，2024。
+
这两个词的出处。Zaharia 等人的文章提出了这个问题，但没有用 workflow 这个词。原文问的是：系统的控制逻辑，应该用传统的代码来写（比如调用 LLM 的 Python 代码），还是由 AI 模型来驱动（比如会调用外部工具的 LLM agent）。把前一种叫 workflow、后一种叫 agent 的说法，常被引用的出处是 Anthropic 2024 年 12 月的文章《Building effective agents》。它的定义是：workflow 是通过预先定义的代码路径来编排 LLM 和工具的系统；agent 是由 LLM 动态地指挥自己的过程和工具使用、自己掌握怎样完成任务的系统。两类合起来，那篇文章统称为 agentic systems。出处：Anthropic，2024。

workflow 的步骤由代码规定，每次运行的步数仍然可以不同：代码里可以有条件分支、重试和循环。只要走哪条路是按写好的规则判断的，它就还是 workflow。这条界线在实际系统里也是一段连续的范围。很多系统大体上是固定的流程，只在其中一两步让模型自己决定要不要多查一次、多试一次。判断一个系统更接近 workflow 还是更接近 agent，就看有多少步是由模型决定的。

workflow 可以很强：AlphaCode 2

既然 agent 更灵活，为什么还要 workflow？因为在步骤可以事先想清楚的任务上，workflow 能做到非常好的成绩。AlphaCode 2 是一个例子。

{{fig 56 | 横轴是参赛者的百分位，纵轴是按每场比赛的最高分折算后的平均得分，黑线是人类参赛者。蓝色的点是 AlphaCode 2，灰色的点是上一代 AlphaCode 的估计值。图片来源：AlphaCode 2 技术报告。}}

AlphaCode 2 是 Google DeepMind 2023 年 12 月发布的编程竞赛系统。它解一道题的步骤是固定的，一共四步。

四步的顺序写死在代码里。LLM 在第一步和第四步里干活，它不决定接下来该聚类还是该再采样一批。

报告的评测是在 Codeforces 上做的：选了 12 场参赛人数超过 8,000 的近期比赛，一共 77 道题。AlphaCode 2 在 10 次提交以内解出了 43% 的题，上一代 AlphaCode 是 25%。按比赛排名折算，报告估计它平均处在第 85 百分位，也就是成绩好于 85% 的参赛者。上一代大致是中位数的水平。

!
87% 还是 85%。有的介绍说 AlphaCode 2 超过了 87% 的参赛者，这个数来自上面那张图横轴上的标注。报告正文和摘要给出的估计都是第 85 百分位，Zaharia 等人的文章引用的也是 85。报告里没有找到对这 2 个百分点差别的解释。引用时用正文的 85% 更稳妥。

这个例子也说明了复合 AI 系统的第一条理由：同样的底层模型，直接让它写一个答案，和让它写一百万个再筛选，成绩差得很远。代价是算力，一道题最多一百万次采样的花费远高于一次调用。

RAG：用得最广的一种 workflow

检索增强生成（Retrieval-Augmented Generation，简称 RAG）在回答问题时把 LLM 和外部的知识来源连起来。模型的参数里没有的知识、训练之后才出现的知识、只存在于某家公司内部的知识，都可以用这个办法接进来。

三步的顺序是固定的，每个问题都先检索再生成，所以基本的 RAG 是一个 workflow。它在工业界用得很广，和开放域问答（不限定主题、需要查资料才能回答的问答任务）的研究关系很深。

+
RAG 这个名字的来历。这个名字出自 Lewis 等人 2020 年的论文。那篇论文里的 RAG 是一个要一起 fine-tuning 的模型：一个生成模型加一个检索器，检索的对象是维基百科的稠密向量索引（把每段文字变成一个向量，按向量的相似度来找）。现在说的 RAG 范围宽得多，通常不训练模型，只是在调用 LLM 之前加一步检索。检索该怎么做、检索到的内容怎么排序、常见的失败方式，是第 3 讲的内容。出处：Lewis 等，2020。

RAG 也可以做成 agent 的样子：把「检索」做成一个工具交给模型，由模型自己决定要不要查、查什么、查几次。第三部分里 ReAct 回答问题的例子就是这样做的，模型连续搜索了三次才找到答案。

什么时候用哪一种

Anthropic 的那篇文章给了一条简单的建议：先找最简单的办法，只在需要时才增加复杂度，这可能意味着根本不用搭 agent 式的系统。理由是 agent 式的系统通常是拿更长的耗时和更高的花费去换更好的任务表现，要想清楚这笔交换值不值。

把 workflow 的几种常见模式和 agent 的设计模式逐个展开，是第 6 讲的内容。

agent 工程的三层：系统、数据、评估

一个 agent 有 LLM、推理、记忆、工具、环境这么多部件，做起工程来容易顾此失彼。可以把所有的工作分成三层来想。

指标本身要仔细选。选错了指标，一个弱的 agent 也能显得不错。第七部分会看到几个例子。

这三层最直接的用处是查问题。agent 表现不如预期时，先问问题出在哪一层：是架构不对（系统），是给它的例子和上下文不对（数据），还是量的办法不对、它其实没有那么差或者没有那么好（评估）。

+
复合 AI 系统自己的三个难题。Zaharia 等人的文章从另一个角度列了三个难题，可以和这三层对着看。第一是设计空间太大：哪怕只是 RAG，也要选检索器、选模型、决定要不要重排、决定时间和花费的预算怎么分给各个部件。第二是优化：一个模型可以从头到尾用梯度来训练，复合系统里有搜索引擎、代码解释器这类没法求梯度的部件，需要新的优化办法，文章举的例子是 DSPy。第三是运维：一个 agent 每次运行的步数都不一样，怎样记录、分析和调试它的运行轨迹（trajectory，每一步的动作和看到的结果的完整记录），怎样保证安全，都是新问题。出处：Zaharia 等，2024。

这一部分的小结

  • 复合 AI 系统是多个部件配合完成任务的系统。四个理由让它成为主流：有些任务靠系统设计更容易提高，系统可以接上最新的数据，系统更好控制，系统可以按应用的需要调整质量和花费。
  • workflow 和 agent 的区别在于谁决定下一步。代码决定的是 workflow，LLM 决定的是 agent。
  • workflow 在步骤固定的任务上可以很强，例子是 AlphaCode 2 和 RAG。能用简单的办法做好时，就不必用 agent。
  • agent 工程分系统、数据、评估三层，查问题时先定位到层。后面各讲也大体按这三层排列。
