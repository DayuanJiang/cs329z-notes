先看结论

  • agent 这个概念比 LLM 早得多。这个词在 15 世纪末进入英语，意思是「行动的人」。AI 领域从 1970 年代起就在用它，1990 年代有了几个流传至今的定义。
  • 强化学习时代的 agent 已经能在围棋和电子游戏里赢过顶尖的人，但每一个都是为一项特定的任务训练出来的。
  • LLM 带来了两样东西：一步一步推理的能力，和使用工具的能力。两样合在一起，是现在的 agent 能出现的前提。
  • 2022 年 10 月到 2023 年 3 月的半年里，ReAct、ChatGPT、GPT-4、BabyAGI 的前身、AutoGPT 先后出现，agent 这个词大致从这时起进入日常用语。
  • 之后底层的模型和 agent 的成绩都在快速提高。在 SWE-bench Verified 上，由同一家机构统一测出的准确率（解决的题目占的比例），2024 年 11 月发布的模型是 31.0%，2026 年 4 月发布的模型是 83.5%。

1990 年以前：这个词和最早的几个想法

agent 现在是一个很热的词。它背后的想法已经发展了五六十年。

Hewitt 等人的这篇论文常被当作 AI 文献里较早使用 agent 一词的例子。它是不是最早的一处，没有核对到。agent 这个词在全文里只出现了一次，就是表里引的那一句。

1990 年代：给 agent 下定义

到了 1990 年代，越来越多的软件系统被叫作 agent，研究者开始认真回答「什么算 agent」。

{{fig 21 | 三份 1990 年代的文献。左：Pattie Maes 编的《Designing Autonomous Agents》。中：Wooldridge 和 Jennings 的综述《Intelligent agents: theory and practice》。右：Russell 和 Norvig 的教科书《Artificial Intelligence: A Modern Approach》，图上的封面是后来的第四版。}}

Wooldridge 和 Jennings 的四条性质

这篇 1995 年的综述说，agent 这个词最一般的用法，是指一个具有下面四条性质的计算机系统，通常是软件。

Russell 和 Norvig 的定义

很多人最熟悉的定义来自 Russell 和 Norvig 1995 年出版的教科书：agent 是任何可以看作通过传感器感知环境、并通过执行器作用于环境的东西。

这个定义很宽。书里举的例子是人：眼睛、耳朵是传感器，手、腿、嘴是执行器。它只要求两件事：能感知，能行动。第二部分的五个部件里，「观察」和「动作」这两条线就是从这里来的。

i
图上有两处和原书有出入。第一，Maes 编的这本书，图上写的年份是 1994。MIT 出版社的页面写的出版日期是 1991 年 2 月，图书馆的记录是 1990 年，它是一份期刊 1990 年两期合刊的重印本。没有查到 1994 年的版本。第二，图上把 Russell 和 Norvig 1995 年的定义写成 sensors 和 actuators。1995 年的第一版用的词是 effectors，actuators 是后来版本里的写法，第四版的原句用的是 actuators。两个词在这里是同一个意思，都译作执行器。出处：MIT 出版社；教科书第四版第 2 章。第一版的原句读自一份大学镜像，原始页面没能打开。

强化学习时代：很强，但只会一件事

接下来的阶段，agent 这个词主要出现在强化学习（reinforcement learning，简称 RL）里。强化学习研究的是一个 agent 怎样通过试错，学会在环境里拿到尽可能多的奖励。

{{fig 22 | 左上：强化学习里 agent 和环境的循环。agent 根据当前的状态和奖励选一个动作，环境收到动作后给出下一个状态和奖励。右：DQN 的网络结构，输入是游戏画面，输出是手柄上每个动作的价值。左下：AlphaGo 和 OpenAI Five 的图标。}}

图左上的循环出自 Sutton 和 Barto 1998 年的教科书。书里的说法是：做学习和决策的叫 agent，agent 之外的一切叫环境；两者不断地交互，agent 选动作，环境对动作做出回应，并把新的情况交给 agent。这个循环和第二部分里 LLM agent 的循环是同一个形状，多出来的只有奖励这个信号。

这些系统说明这条路可以走到超过人的水平。它们都是真正的 agent，但每一个都是为一项特定的任务训练出来的。下围棋的 AlphaGo 不会打 Dota，换一个任务就要从头训练。改变这一点的是大语言模型。

LLM 带来了什么：推理和使用工具

第一步：不用训练就能学新任务

{{fig 23 | 左：Transformer 的结构图，GPT 系列模型建立在这种结构上。右：GPT-3 论文里 few-shot 的例子。第一行是任务说明「把英语翻译成法语」，中间三行是例子，最后一行只给出英语单词 cheese，等模型续写。图片来源：Brown 等，2020。}}

LLM 第一个让人印象深刻的能力是 in-context learning（上下文学习）：在 prompt（交给模型的输入文字）里说明任务，再给几个例子，模型就能照着做。给几个例子的做法叫 few-shot。2020 年的 GPT-3 论文展示了这一点。图里的例子是翻译：给了三对英语和法语的词，模型就能把第四个词译出来。

和前面强化学习的系统相比，关键的不同是整个过程没有任何梯度更新，也就是模型的权重一点没变。换一个任务，只要换一段 prompt。

第二步：一步一步推理，以及用工具

prompt 能做的不止是教模型一个新任务。后来发现，模型可以一步一步地推理，还可以借助工具去做它自己做不了的事。

{{fig 24 | 左：chain-of-thought 的例子。prompt 里的示范在答案之前写出了推导过程，模型在回答新问题时也先写推导（绿色部分），算出食堂还剩 9 个苹果。中间叠着的是 WebGPT 文章的标题。右：MRKL 系统的结构，输入先交给语言模型，再分发给下面的各个专家模块，比如天气接口、货币换算、维基百科接口、日历、数据库、计算器。}}

到这里，两块关键的东西齐了：模型能一步一步推理，模型能使用工具。能想，又能通过工具动手，这是 agent 出现的两个前提。

2022 年 10 月到 2023 年 3 月：agent 出现

{{fig 25 | 半年里的五件事。下面一行从左到右：ReAct 论文里的一段运行记录，ChatGPT 和 GPT-4 的图标，BabyAGI 的流程图，AutoGPT 的图标。}}

最后两行的日期有两个细节。3 月 28 日发布的是 Yohei Nakajima 的一条推文和一篇文章，标题是《Task-Driven Autonomous Agent》；BabyAGI 这个名字和它的代码仓库是 4 月 3 日才有的。AutoGPT 的代码仓库建于 3 月 16 日，3 月 30 日是它公开发布的日期。

回头看，这两个项目的想法在当时很超前。实际上它们当时都不太好用。但它们吸引了大量的注意，让人看到了可能性。agent 这个词大致也是从这时候起进入日常用语的。

2023 年以后：模型和 agent 都在变强

底层的模型

{{fig 26 | 三代 GPT 模型在几个基准测试（benchmark，一组题目加一个打分的办法）上的准确率。左半边是 GPT-3 到 GPT-4，右半边是 GPT-4 到 GPT-5。每条线旁边带加号的数是提高的幅度，单位是百分点。图片来源：Epoch AI，2025。}}

读这张表要注意两点。第一，两半用的是两套不同的基准测试。GPT-3 到 GPT-4 用的那几个，后来有的已经被做到很高的分数，不再能可靠地区分模型，所以右半边换成了更难的题。第二，右半边的起点是 GPT-4 较晚的版本（2023 年 6 月和 2024 年 4 月的版本），因为最初的 GPT-4 没有在这几个新的基准测试上测过。Epoch 的文章说明，这样算出来的提高幅度是真实幅度的一个偏低的估计。

总的意思是：每一代基础模型都比上一代有很大的进步。模型更强，agent 就能推理得更好，犯的错更少，编造的内容更少，能处理的任务也更长。

agent 的成绩

{{fig 27 | 左：各家模型在 SWE-bench Verified 上的准确率，横轴是模型的发布时间。右：两张花费和准确率的关系图，上面是 OSWorld 2.0，下面是 Terminal-Bench 4.0，横轴是 API 花费，纵轴是准确率，每条线是一个模型在不同设置下的几个点。}}

进步的不只是模型本身，agent 这一侧的成绩也在涨。左图的基准测试是 SWE-bench Verified：500 道经过人工核实的题，每道题来自 12 个开源 Python 仓库里一个真实的问题报告，要求 agent 改代码把它修好。

相隔不到一年半发布的两个模型，这个数从三成升到了八成以上。这个基准测试也因此越来越不好用：分数靠近上限之后，它越来越分不出模型的高下，Epoch 也提到题目可能已经进入了训练数据。第 13 讲专门讲基准测试的这种生命周期。

右边两张图换了更难的任务：OSWorld 是操作电脑桌面的任务，Terminal-Bench 是在命令行里完成的任务，图里用的是它们 2026 年的新版本。这两张图的样式显示它们出自某个模型的发布材料，具体是哪一份没有核对到，所以这里不引用上面的数。

右边的图有一个值得注意的地方：横轴是花费。现在报告 agent 的成绩，越来越多地把价格和准确率画在一起，因为大家开始在意过程的效率。

两个容易产生的疑问

  • 为什么准确率越高，花费越高？图里的 API 花费主要取决于过程中处理的 token（模型处理文字的最小单位）的数量。让模型想得更久，通常成绩更好，用掉的 token 也更多。
  • 新模型为什么比旧模型强？可能的原因很多：更好的数据，更好的蒸馏（用一个模型的输出去训练另一个模型），或者别的方面。实际情况是，这些闭源的模型是怎样训练出来的，外界知道得不多。
