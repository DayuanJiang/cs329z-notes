先看结论

一个 LLM agent，就是把一个大语言模型放进一个循环里：想一步，通过工具做一步，看环境返回的结果，再想下一步。循环里下一步做什么由模型自己决定，这是 agent；由事先写好的代码决定，叫 workflow。把这样的系统搭出来已经不难。搭出来之后还有五个难点没有解决：可靠性、训练、长任务、安全、评估。

这一页用到的几个词先说明一下。LLM 指大语言模型，prompt 指交给模型的输入文字，工具指模型可以调用的外部功能，环境指 agent 之外、它的动作作用在上面的那个世界。上下文指模型这一次调用能读到的全部文字，它的长度有上限。

一个 agent 可以拆成五个部件，下表每行说明一个。前四个组成 agent 本身。第五个是环境，它在 agent 之外，这一讲把它和前四个放在一起，合称五个部件。

表里第三列的例子出自 ReAct 论文里的一条运行轨迹（trajectory，一个 agent 每一步的动作和看到的结果的完整记录，也叫运行记录）：一个 agent 在用文字描述的厨房里找到胡椒瓶，把它放进抽屉。ReAct 是 2022 年提出的一种做法，让模型交替地推理和行动。这条轨迹里标着「想」的是模型写下的想法，标着「动作」的是它发出的动作，标着「观察」的是环境返回的结果。

表里前两行说的是同一个模型做的事。agent 的每一个决定，都是 LLM 核心在它生成的文字里做出的。规划和推理指这些文字里先于动作写出来的分析和打算，比如记录里「想」后面的内容。
