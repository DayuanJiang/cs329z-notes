先看结论

  • 对 agent 来说，推理是一种对内的动作：它更新的是 agent 自己的状态，也就是它接下来能看到的文字，环境不受影响。这里的 agent 指由 LLM 自己一步一步决定做什么、调用工具去完成任务的系统，环境指 agent 之外、它的动作作用在上面的那个世界。
  • 先推理再行动有两个好处：同样的推理思路可以用到相似的新情况里，人也能看出 agent 为什么做了这个动作。
  • ReAct 把推理和行动交替进行：想一步，做一步，看结果，再想。ReAct 论文在一个问答数据集上抽查了 ReAct 答错的 50 道题：没有一道是因为编造了推理过程或事实，47% 是推理本身出了错。各类错误的定义和完整的数在ReAct 的成绩一节。
  • 除了 ReAct，还有几种让推理更好的办法：多想几遍取多数（self-consistency），失败后写一段反思留给下一次（Reflexion），让几个 agent 就同一道题辩论，或者由一个 orchestrator 把任务分给几个 agent。orchestrator 指负责拆任务、派任务的 agent。
  • 这些办法改变的都是怎样组织对模型的调用，模型的权重保持不变。权重指模型内部由训练定下来的那些数值，也叫参数。

「推理」在三个场合指什么

第二部分有一条运行轨迹（trajectory，一个 agent 每一步的动作和看到的结果的完整记录）：一个 agent 在用文字描述的厨房里找到胡椒瓶，把它放进抽屉。这条轨迹里有一行「想：胡椒瓶找到了，接下来要把它放进 1 号抽屉」。这一行没有对环境做任何事，后面几步却是照着它走的。这一节说明这样的「想」在 agent 里算什么。

推理这个词用在人、LLM 和 agent 身上，意思不完全一样。下面的图和表把三种用法分开。

{{fig 33 | 上面是 agent 和环境之间的动作和观察，观察指环境在每个动作之后返回给 agent 的结果。下面两个例子是 LLM 的推理：模型在给出答案之前，先写出中间的步骤（橙色标出的部分）。一个是判断梨会不会沉到水里，一个是推算日期。}}

规划指把大任务拆成小步骤、决定下一步做什么。表里第一行把它列为推理的一种，所以这一页把两者放在一起讲。这一页标题里的「规划和推理」，就是第二部分五个部件里的那一个。

第三行的说法来自 CoALA 框架，它是 2023 年一篇论文提出的一套描述 LLM agent 的框架。它把动作分成对外的和对内的。对外的动作作用于环境，比如点击、执行命令。推理是对内的动作，它读取 agent 当前掌握的信息，生成新的信息，再写回去。写回去的内容会出现在后面每一步的上下文（模型那一步能读到的全部文字）里，影响后面的决定。

AI 的推理和人的推理是不是一回事，一直有争论，这里不展开。上面的对照只是为了说明这个词的用法。

i
模型写出来的推导过程，不一定是它实际得出答案的过程。把写出来的推导当作一份有用的记录来读，不要把它当成对模型内部的准确描述。后面说人能从推理里看出 agent 为什么这样做，指的是从这份记录里读到它写下的理由。写下的理由会留在上下文里，影响后面的步骤，所以值得检查。

为什么先推理再行动

只看 agent 的观察和动作，常常看不出它为什么做这个动作。

{{fig 34 | 一个做饭的 agent。橙色是它的观察，紫色是它的动作，绿色是加进去的推理。}}

图里的 agent 在某一步观察到的是「你正在做一道菜，发现盐用完了」，下一个动作是「向右转」。只看这两行，很难明白它为什么要向右转。

从观察直接对应到动作，有两个难处。对模型来说，可能遇到的观察和可以做的动作都非常多，要从观察直接选出该做的动作很难。对人来说，出了问题很难检查，也很难据此改进 agent。

在中间加一段推理就清楚了：「这道菜应该是咸的。盐用完了，可以用酱油代替。酱油在右手边的橱柜里。」接下来的「向右转」和再下一步的「打开橱柜」都有了来由。

这样做有两个好处，下表各用做饭的例子说明。

只推理不行动，和边推理边行动

ReAct 这个名字是 Reason 加 Act，意思是让模型交替地推理和行动。下面用 ReAct 论文里的一个例子，比较三种做法：直接回答，只推理不行动的 CoT，和 ReAct。问题来自 HotpotQA，一个要把几条资料连起来才能回答的问答数据集：

Apple Remote 最初是为了操作某个程序而设计的。除了 Apple Remote，还有什么设备可以控制这个程序？

{{figs 35 36 | 左：直接回答（Standard）和只推理不行动的 CoT（图上标 Reason Only）都答错了，红色标出的是模型编造的内容。右：ReAct 交替地推理（Thought）、行动（Act）、读观察结果（Obs），前三轮各搜索一次，第四轮给出了正确的答案，绿色标出的是它从搜索结果里读到的关键信息。图片来源：Yao 等，2022。}}

第二种做法比第一种更危险。它的推导读起来很有说服力，却是错的。模型没有任何办法核对「Apple Remote 是为 Apple TV 设计的」这句话，只能凭训练里留下的印象。

ReAct 的四轮是这样的。这个例子里它用到两种动作：在维基百科里搜索，和结束并给出答案。前三轮各搜索一次，第四轮给出答案。

这四轮里，推理决定了怎样行动，行动的结果又成为推理的材料，具体有四点：

  • 推理引出了行动。第 1 轮的想法决定了搜什么。
  • 行动给推理带来了新的事实。「Front Row」这个名字是从搜索结果里读到的，模型自己并不知道。
  • 推理从长文字里提取了要点。搜索返回的是一整段介绍，第 2 轮的想法把其中有用的一句挑了出来。
  • 推理处理了意外。第 2 轮搜索落空，第 3 轮根据返回的相近条目换了一个搜索词。

CoT 和 ReAct 的差别可以这样概括：CoT 是一个 prompt、一次生成，中途看不到任何新东西。ReAct 是一个循环，每一轮都能看到上一个动作的结果，所以能拿到新信息，也能改正自己的错误。

ReAct 的整条运行轨迹人也读得懂，每一步为什么这样做都写在里面。

ReAct 的成绩：哪里好，哪里不好

这一节看 ReAct 在实验里的成绩，结论按两类任务分开说。在问答任务上，单独的 ReAct 不一定比 CoT 强，几种 prompt 方法里，两个数据集上最好的成绩都来自把它和多做几遍取多数的 CoT 结合起来。在要动手的任务上，它明显好于只行动、不推理的做法。

ReAct 论文的主要实验用的是 PaLM-540B，这是 2022 年发表的一个大语言模型，参数量 5400 亿，也就是模型里有 5400 亿个权重。做法是在 prompt 里放几个写好的示范，模型的权重没有动。

问答实验用了两个数据集。一个是上一节见过的 HotpotQA，prompt 里放 6 个示范。另一个是 Fever，它要求判断一句话是否有资料支持，prompt 里放 3 个示范。

成功和失败各是什么类型

论文作者从 ReAct 和 CoT 在 HotpotQA 上各自答对的题里随机抽了 50 道，答错的题里也各抽了 50 道，一共 200 道，人工逐条归类。下表是归类的结果。

这张表说明了两种做法各自的弱点。

  • CoT 的主要问题是幻觉。它答错的题里 56% 属于编造了推理过程或事实，答对的题里也有 14% 是碰巧对的。ReAct 答错的题里没有一道归入这一类，很可能是因为它的事实来自搜索结果。
  • ReAct 的主要问题是推理错误。论文给的解释是：推理、行动、观察必须交替进行，这个固定的格式让模型组织推理步骤时不够灵活。推理错误里有一种是 ReAct 特有的：模型一直重复前面的想法和动作，没有再往下推进。
  • 推理错误和幻觉是两回事。按表里的定义，幻觉指推理过程或事实是编造的。推理错误指推理过程本身出了错，比如对已有信息的理解不对、下一步选得不对，或者陷在重复的步骤里。所以在抽查的错题里，ReAct 没有一道归入幻觉，推理错误却占 47%，两者并不矛盾。
  • ReAct 幻觉为 0% 这个数，只对抽查的 50 道错题成立。ReAct 答对的题里仍有 6% 属于碰巧对，也就是推理过程或事实是编造的。
  • 搜索落空会影响后面的整个过程。ReAct 答错的题里 23% 是搜索没有返回有用的信息，模型之后很难重新组织思路。

在要动手的任务上

问答之外，论文还在两个要动手的任务上比较了 ReAct 和只行动的 Act。

只行动、不推理的 agent 在 ALFWorld 里常见的失败，是反复做同一个没有效果的动作。找胡椒瓶那个任务里，它一遍遍地尝试从水槽里拿胡椒瓶，环境一遍遍地回答「什么也没发生」。

多想几遍取多数：self-consistency

CoT 只生成一次，这一次算错了，答案就错。下图上半部分就是这种情况：模型算错了，答成 14 美元。

self-consistency 是针对这一点的一个很直观的办法，可以译作自洽，简称 SC。上一节成绩表里的 CoT-SC 就是 CoT 配上它。做法分三步。

  1. 用 CoT 的 prompt 向模型提问。
  2. 让模型生成多条不同的推理路径。每次生成带一点随机性，得到的推导和答案就不完全一样。
  3. 看这些路径各自得出的最终答案，选出现次数最多的那个。
{{fig 38 | 上：普通的 CoT 只生成一次，这一次算错了，答案是 14 美元。下：self-consistency 生成三条推理路径，答案分别是 18、26、18 美元，取多数，得到 18 美元。图片来源：Wang 等，2023。}}

它的道理是：一道题的正确答案只有一个，不同的正确推导会得到同一个答案。出错的推导错法各不相同，答案也分散。所以出现最多的答案更可能是对的。这相当于一种多数投票。

它不需要额外的训练，也不需要别的模型，代价是要多调用很多次。

论文拿它和只生成一次的 CoT 比较。下表是用 GPT-3 的 code-davinci-002 这个模型、每道题生成 40 条推理路径时，四个数据集上的准确率。

失败后写一段反思：Reflexion

self-consistency 是把同一道题多做几遍，取出现最多的答案。Reflexion 是在多次尝试之间学习：这次失败了，写一段话总结为什么失败，下次尝试时带上这段话。

{{fig 39 | 左：Reflexion 的结构。右：两个例子，一个是家居任务，一个是写程序。每个例子从上到下是任务、这次的运行轨迹、评估结果、反思、下一次的运行轨迹。图片来源：Shinn 等，2023。}}

它由三个角色组成，下表每行一个。行动者和反思者是 LLM。评估者有三种做法，列在表里。表里的短期记忆指这一次尝试的运行轨迹，只在这一次尝试里用。长期记忆指跨多次尝试保留下来的内容，这里存的是每次失败后写下的反思。

评估者一行里的「幻觉」，和 ReAct 的成绩一节表里的意思不同。那里指编造推理过程或事实。这里它是一类失败的名字，按一条规则认定：同一个动作连续三轮以上得到同样的回应，就归为幻觉。图上的轨迹只留了两步，所以从表里看不出这条规则是怎样被触发的。

下一次尝试时，行动者的 prompt 里会带上之前的反思。例子里它这次改去 2 号灶台，拿到了锅。为了不让 prompt 太长，论文里保留的反思数量有上限，通常是最近的 1 到 3 条。

{{fig 40 | Reflexion 在 ALFWorld 的 134 个任务上的结果。左：横轴是第几次尝试，纵轴是累计解决的任务占的比例。右：没解决的任务按失败原因分成两类。图片来源：Shinn 等，2023。}}

左图比较两组，两组都把没做成的任务一次次重做。对照的一组只用 ReAct：一次尝试没做成，就跳过写反思这一步，把环境重置，重新开始一次尝试。这一组的线在第 6、7 次尝试之后就不再上升。从图上看，这一组累计解决的任务停在全部任务的 75% 左右。它在重做时为什么还能多做成一些任务，论文没有说明。

另一组加上 Reflexion，每次失败后写一段反思、带进下一次尝试，12 次尝试里解决了 134 个任务中的 130 个，约 97%。

右图把没解决的任务分成两类，按两条简单的规则区分。一类是上面说的幻觉：同一个动作连续三轮以上得到同样的回应。另一类是低效的规划：动作数超过 30 个。两条规则各对应哪一类失败，依据见资料说明。

只用 ReAct 时，归入幻觉这一类的任务停在全部 134 个任务的 22% 左右，不再下降。典型的情况是 agent 以为自己手里拿着某样东西，其实没有，然后在这个错误的认识上又做了很多步，没有办法退回去找到出错的地方。加上反思之后，这类情况几乎消失了。

Reflexion 也用在写程序上。写程序的数据集通常按一次提交的通过率算成绩。数据集给每道题配了一组评分用的测试。每道题只提交一个程序，这个程序通过了这组测试，这道题就算通过。通过的题占全部题目的比例，就是一次提交的通过率。

Reflexion 要反复尝试，每次都得有东西判断程序写得对不对。如果拿评分用的测试来判断，就等于提交了不止一次，成绩不能再算作一次提交的通过率。

论文的做法是让模型先自己写一组单元测试，也就是检查一段代码在给定输入下结果对不对的小程序，用它们充当评估者。提交之前的反复尝试只用这些自己写的测试，所以最后仍然只提交一次。按一次提交的通过率算，Reflexion 在写程序的 HumanEval 数据集上是 91%。按论文的说法，此前最好的成绩是 GPT-4 的 80%，这是 GPT-4 每道题只生成一次程序的成绩。91% 是在 GPT-4 上加了 Reflexion 之后的成绩，两个数用的是同一个模型。

这里 GPT-4 的 80%，和第一部分的表里 GPT-4 在 HumanEval 上的 67.0% 出处不同。67.0% 取自 Epoch AI 的数据表，和 OpenAI 发布 GPT-4 时的技术报告里的数相同。80% 是 Reflexion 论文的作者自己测的基线。两个数为什么不同，这几份材料都没有说明，核对的经过见资料说明。

!
Reflexion 论文的副标题里有「强化学习」，实际上没有训练。论文的副标题是 verbal reinforcement learning，正文里也用 reinforce 这个词，容易让人以为它用了强化学习，也就是让模型通过试错、按得到的奖励来学习的训练方法。它的做法是把反思写成文字放进 prompt，模型的权重完全没有更新。论文摘要自己写明了这一点：它让 agent 改进，靠的是语言反馈，不靠更新权重。

不止一个 agent：辩论和 orchestrator

前面几种办法里，做任务的都只有一个 agent。Reflexion 有三个角色，在环境里做任务的也只有行动者一个。这一节看两种用多个 agent 的组织方式：让几个 agent 就同一道题辩论，或者由一个 orchestrator 把任务分给几个各有专长的 agent。

这两种做法的论文用 agent 这个词，比本页开头的定义宽，下面讲到时各有说明。

让几个 agent 辩论

辩论的做法是让几个 agent 各自解同一道题，每一轮结束后互相读对方的推导，再各自更新答案。它的目的是提高推理的质量。论文说的 agent，是同一个语言模型的几份副本，每一份只负责回答这道题。

{{figs 41 42 | 论文里用来说明辩论过程的示例图：2 个 agent 在一道算术应用题上辩论，到第 3 轮都答对。题目：宝箱里有 175 颗钻石，红宝石比钻石少 35 颗，绿宝石的数量是红宝石的两倍，一共有多少颗宝石？左：第 1 轮，agent 1 算成 225（错），agent 2 算成 595（对）。右：第 2 轮 agent 1 读了对方的解法后改成 560（还是错），第 3 轮两个 agent 都得到 595。图片来源：Du 等，2023。}}

第 1 轮各个 agent 独立作答。从第 2 轮起，每一轮开始时每个 agent 收到的 prompt 是：「这是其他 agent 的解法，请把它们作为补充信息，给出你更新后的回答」，prompt 里附上别的 agent 上一轮的回答。

论文用的是 ChatGPT（gpt-3.5-turbo）。上图是说明辩论过程的示例，用了 2 个 agent、3 轮。论文的主要实验用的是另一种设置：3 个 agent 辩论 2 轮。下表是这种设置在其中两个任务上的结果。

如果目的只是提高成绩，多 agent 辩论在现在的模型上带来的帮助很可能已经不大。理由是，这个办法出现在单个模型还不够强的时候，那时它实际上是一种 prompt 技巧，用几份互相不同的回答来弥补单个回答的不可靠。现在的模型强了很多。这个推断没有新模型上的实测数据支持：上面的实验用的是 2023 年的模型，新模型上的效果要按具体的模型和任务去测。

用多个 agent 还有别的理由。几件事可以同时做，效率更高。也可以按数据的权限来划分，比如一个 agent 专门处理医疗信息，另一个专门处理别的敏感信息，各自只能看到自己该看的。

由一个 orchestrator 来分工

辩论是几个 agent 做同一件事。另一种组织方式是分工：设一个 orchestrator（负责拆任务、派任务、汇总结果的 agent），由它把一个大任务拆开，交给几个各有专长的 agent 去做。

orchestrator 自己维护两份记录：一份是整体的计划，一份是当前进度。每一步之后它检查进度，如果连续几步没有进展，就回头反思哪里出了问题，修改计划再来。

论文在三个基准测试（benchmark，一组题目加一个打分的办法）上报告了成绩，用了两种模型配置。默认的配置里，各个 agent 用的模型都是 GPT-4o。另一种配置把 orchestrator 里维护整体计划的那一部分和 Coder 换成 o1-preview。

o1-preview 是 OpenAI 的另一个模型。按论文的说法，它针对逻辑推理和解谜这类能力做了优化，但只能读文字。在换了模型的这种配置里，操作浏览器和读文件的两个 agent 仍然用 GPT-4o，它能读图片。

论文摘要的说法是，它在这三个基准测试上和当时最好的系统在统计上相当，也就是成绩的差别小到不能排除只是偶然出现的。

什么时候该用多个 agent、怎样设计它们之间的分工和通信、多 agent 系统为什么容易失败，是第 8 讲的内容。

资料说明

这一节记录核对资料时发现的出入和没有查到的地方。前面各节的结论已经按核对的结果来写。

  • ReAct 成功和失败类型表里的百分数。论文说每一组抽了 50 道，但表里有几个百分数（47%、23%、29%）换算不成 50 道里的整数道，ReAct 答错的四类加起来是 99%。具体是怎么算的，论文里没有找到说明。出处：Yao 等，2022 的表 2。
  • Reflexion 实验里对照组最后的比例。只用 ReAct 的一组最后停在多少，论文正文没有写出。75% 左右是从左图的曲线上读出来的。它和论文的另一句话对得上：论文说 Reflexion 在 ALFWorld 上比对照的做法高出 22 个百分点，而 134 个任务里解决 130 个约是 97%。出处：Shinn 等，2023。
  • GPT-4 在 HumanEval 上的两个数。第一部分的表里是 67.0%，这一页是 80%。67.0% 取自 Epoch AI 那篇文章的数据表，列在 2023 年 3 月发布的那一版 GPT-4 名下。OpenAI 在 2023 年 3 月发布 GPT-4 时的技术报告里也是 67.0%，报告注明测的时候没有在 prompt 里给例子，测的是 GPT-4 的基础模型（原文是 pre-trained base GPT-4 model）。80% 出自 Reflexion 论文：结果表把 GPT-4 列为 80.1%，表注说明每道题只生成一次程序，也没有在 prompt 里给例子，论文正文说这个基线是作者自己测的。论文没有写明用的是 GPT-4 的哪一版。两个数为什么不同，这几份材料里都没有找到说明。出处：Epoch AI，2025；OpenAI，2023；Shinn 等，2023。
  • Reflexion 的两类失败各对应哪条规则。论文的原句只给「动作数超过 30 个」注明了低效的规划，没有逐字写明「同一个动作连续三轮以上得到同样的回应」对应幻觉。正文按 Lilian Weng 的文章对这条规则的解读来写，她当时是 OpenAI 的研究员。出处：Shinn 等，2023；Weng，2023。
