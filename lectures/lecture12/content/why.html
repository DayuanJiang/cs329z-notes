先看结论

  • 训练 agent（能自己调用工具、分很多步去完成一个任务的语言模型系统）用的任务和运行轨迹，现在可以成批地自动生成，一个项目就能有几百万条。难的是决定留下哪些。
  • 从候选任务到最后用来训练的那批数据，中间有五步，其中四步在做挑选。后面五个部分讲这四步挑选。
  • 挑的是两样东西。运行轨迹用来做监督微调，让模型模仿。环境用来做强化学习，让模型自己练。
  • 训练数据出问题有三种方式：给的信号是错的，没有信号，信号是重复的。
  • 有一个问题还没有定论：数据是少而精更好，还是越多越好。两边都有实验支持，第六部分看它们各自在什么条件下成立。

造数据便宜了，难的是挑

第 11 讲讲的是 agent 的训练数据从哪里来：请人示范，从代码仓库、教程和视频里转换，用模型合成，在模拟环境里反复运行。这些办法里，后三种都可以自动化，所以现在造任务和造运行轨迹的成本很低。运行轨迹（trajectory，也叫 trace）指 agent 一次运行里每一步的动作和看到的结果的完整记录。

造出来的东西不能全部拿去训练。这一讲的问题是：造出来之后，留下哪些。

一个例子：CWM 留下了 300 万条轨迹

CWM（Code World Model）是 Meta 的 FAIR CodeGen 团队 2025 年发布的一个 320 亿参数的开源模型。它的训练数据里有一部分是 agent 的运行轨迹，收集的办法是：让一个语言模型在代码仓库的 Docker 镜像（一个打包好的、可以整个重建的运行环境）里做软件工程任务，把整个过程记下来。任务有两种，一种是往能通过测试的代码里故意放进一个 bug 再让 agent 修，一种是回到某次真实的 bug 修复之前，让 agent 把失败的测试改到通过。

这个例子里有两个决定，方向相反：重复的要丢，失败的要留。它说明挑数据没有一套通用的规则，留什么取决于拿这批数据去教模型什么。同一篇论文在后面的强化学习阶段就换了做法：模型几乎每次都能做对的任务（单次成功率高于 95%）被当作太容易而去掉，一次都做不对的任务放进另一个集合，开始时抽到的机会更少。这正是第三部分要讲的按难度筛选。

每一步都在丢数据

把造数据的整个流程画出来，形状像一个漏斗。五步里有四步是筛选，每筛一次，留下的都比筛之前少。中间从任务到运行的那一步是生成：一个任务可以运行很多遍，产生很多条轨迹，所以任务数和轨迹条数不能直接比大小。

真实的漏斗可以收得很窄。后面会讲到两个例子：CodeMidas 从 22,575 个候选任务里留下 5,545 个，约占四分之一；LEGO-RL 从 36,884 个候选任务里留下 2,699 个，约占 7%。

挑的是两样东西：轨迹和环境

训练 agent 主要有两种办法，它们用的数据不一样，所以要挑的东西也不一样。

{{fig 9 | 左：运行轨迹由一连串的「想、做、看结果」组成，最后是提交。右：环境由任务、沙盒（sandbox，一个隔离的、agent 可以在里面随便动手的运行环境）和验证器三样组成。图上的 Section 3 对应这里的第四和第五部分，Section 2 对应第二和第三部分。}}

两样东西是连着的。轨迹是模型在环境里运行出来的，所以环境有毛病，在它上面产生的轨迹也跟着有毛病。这就是漏斗里先挑任务、后挑轨迹的原因。

训练数据出问题的三种方式

把训练数据看成给模型的信号，它出问题的方式可以分成三种。

CWM 的去重处理的是第三种。它后面的强化学习阶段去掉太容易的任务，处理的是第二种。

同一个基础模型，数据不同，差别很大

挑数据值不值得花力气，要看数据的差别对结果有多大影响。OpenThoughts-Agent（Raoof 等，2026）这篇论文专门研究这个问题：基础模型固定为 Qwen3-8B 或 Qwen3-32B，只改训练数据，看微调之后的 agent 表现差多少。

{{fig 11 | 三张小图的横轴都是训练数据的条数，从 316 条到 10 万条。纵轴是准确率。左：SWE-Bench Verified 里抽出的 100 个任务。中：Terminal-Bench 2.0。右：七个基准测试的平均。红色和橙色是 OpenThoughts-Agent 自己的数据集，蓝色和青色是 Nemotron-Terminal-Corpus，紫色是 SERA。两条水平的虚线是没有微调的基础模型。图片来源：Raoof 等，2026。}}

这张图比的是什么。图里的每条线是一个完整的数据集，三个数据集出自三个不同的团队，各自截取到相同的条数，再用来微调同一个基础模型。所以这张图说的是：条数相同的时候，不同做法造出来的数据集，训练出的模型差别很大。它比的是整套造数据的做法。三条线来自三批各自独立的数据，彼此之间没有「从同一批数据里换一种挑法」的关系。另外，红线只在右边的平均图上基本领先：左图里紫色实线（SERA 用它自己的运行框架评测）在它有数据的范围内一直在红线上面。运行框架（harness）指包在模型外面、给它工具并管理多轮对话的程序。

「规模相同，挑得好的子集更好」这件事，论文里另有专门的实验。下面两组都用 Qwen3-8B。第一组两边的任务数相同，第二组两边的 token 总数相同，训练数据在约 1 万到 1.45 万条之间。分数是三个基准测试（SWE-Bench Verified 的 100 题、OpenThoughts-TBLite、Terminal-Bench 2.0）的平均准确率。

两组里，挑过的都比随机的高 3 个百分点以上。这篇论文里影响最大的一步是任务从哪里来：换一种任务来源，SWE-Bench Verified 那 100 题上的准确率最多能差 30 个百分点。

+
这篇论文里几个和直觉不一样的结果。用语言模型改写任务描述（加约束、加难度），没有一种做法比不改更好。最强的模型不一定是最好的示范者：用 GPT-5.3-Codex 生成的轨迹来训练，三个基准测试的平均准确率是 11.94%，用 GLM 4.7 的一个量化版本（把参数压缩成较低的精度、占用内存更少的版本）生成的是 18.16%。把数据从 3.16 万条加到 10 万条时，如果只是让同一批任务多跑几遍，成绩不再上升，要把任务描述改写出更多不同的写法才继续涨。最后一条和第六部分讲的多样性是同一件事。出处：Raoof 等，2026的第 3.3、3.5 节和第 4 节。

一个还没有定论的问题

既然挑数据有用，一个自然的推论是：只要挑得够好，少量数据就够了。有实验支持这个说法，也有实验支持相反的说法。

两个结论看上去矛盾。第六部分会逐个看它们的实验条件，然后说明两者是怎么对上的。
