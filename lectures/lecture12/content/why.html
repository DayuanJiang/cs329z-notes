先看结论

  • 训练 agent（能自己调用工具、分很多步去完成一个任务的语言模型系统）用的任务和运行轨迹，现在可以成批地自动生成，一个项目就能有几百万条。难的是决定留下哪些。
  • 从候选任务到最后用来训练的那批数据，中间有五步，其中四步在做挑选。后面五个部分讲这四步挑选。
  • 挑的是两样东西。运行轨迹用来做监督微调，让模型模仿。环境指一个任务连同运行它的地方和判断它做没做成的程序，用来做强化学习，让模型自己练。
  • 训练数据的作用是告诉模型哪种做法该多做、哪种该少做，这种信息下面叫信号。它出问题有三种方式：信号是错的，没有信号，信号是重复的。
  • 有一个问题还没有定论：数据是少而精更好，还是越多越好。两边都有实验支持，第六部分看它们各自在什么条件下成立。

造数据便宜了，难的是挑

第 11 讲讲的是 agent 的训练数据从哪里来，一共五种来源：请人演示，从代码仓库、教程和视频这些现成的材料里提取，让模型合成运行轨迹，让模型合成任务和环境，用模拟的用户和环境。除了请人演示，另外四种都可以自动化，所以现在造任务和造运行轨迹的成本很低。运行轨迹（trajectory，也叫 trace）指 agent 一次运行里每一步的动作和看到的结果的完整记录。

造出来的东西不能全部拿去训练。里面有三类用不上的东西：本身带毛病、做对了也会被判错的任务，模型每次都做对或每次都做错、学不到东西的任务，以及大量重复的内容。后面「训练数据出问题的三种方式」一节逐个讲。这一讲的问题是：造出来之后，留下哪些。

一个例子：CWM 留下了 300 万条轨迹

CWM（Code World Model）是 Meta 的 FAIR CodeGen 团队 2025 年发布的一个 320 亿参数的开源模型。它的训练数据里有一部分是 agent 的运行轨迹，收集的办法是：让一个语言模型在代码仓库的 Docker 镜像（一个打包好的、可以整个重建的运行环境）里做软件工程任务，把整个过程记下来。

任务有两种。一种是往能通过测试的代码里故意放进一个 bug，再让 agent 修。另一种是回到某次真实的 bug 修复之前，让 agent 修改代码，使原本失败的测试通过。

这个例子里，重复的要丢，失败的却要留。留下失败的轨迹，是因为这批数据要教模型的是「在代码环境里做一个动作会发生什么」，所以论文不按 bug 有没有修好来筛。

同一篇论文在后面的强化学习阶段就换了做法。强化学习是让模型自己反复去做任务，做成了得到奖励，再按奖励调整模型。在这个阶段，模型几乎每次都能做对的任务（单次成功率高于 95%）被当作太容易而去掉，一次都做不对的任务放进另一个集合，开始时抽到的机会更少。每次都做对或每次都做错的任务为什么要这样处理，后面讲「没有信号」时会说明。

这两种做法放在一起说明，挑数据没有一套通用的规则，留什么取决于拿这批数据去教模型什么。后一种做法就是第三部分要讲的按难度筛选。

训练数据出问题的三种方式

训练数据的作用是告诉模型哪些做法该多做、哪些该少做，下面把它传给模型的这种信息叫作信号。信号出问题的方式可以分成三种。

CWM 的去重处理的是第三种。它后面的强化学习阶段去掉太容易的任务，处理的是第二种。

同一个基础模型，数据不同，差别很大

挑数据值不值得花力气，要看数据的差别对结果有多大影响。OpenThoughts-Agent（Raoof 等，2026）这篇论文专门研究这个问题：基础模型固定为 Qwen3-8B 或 Qwen3-32B，只改训练数据，看微调之后的 agent 表现差多少。表现用基准测试（benchmark，一组题目加一个打分的办法）上的准确率来量。

下面的图里有两个基准测试的名字。SWE-bench Verified 考的是修复真实代码仓库里报告的问题，共 500 个经过人工检查的任务，第二部分会细讲，这张图用的是从中抽出的 100 个。Terminal-Bench 2.0 考的是在命令行终端里完成各种技术任务。

图里比较三个训练数据集。一个是 OpenThoughts-Agent 自己造的，另外两个叫 Nemotron-Terminal-Corpus 和 SERA，是另外两个团队公开的 agent 训练数据集。

从同一批数据里挑，规模相同时挑过的子集是不是比随机选的更好，论文里另有专门的实验。下面两组都用 Qwen3-8B，每组拿一种挑法和随机选做对比。第一组挑任务，两边的任务数相同，留下的是 GPT-5 作答时写得最长的任务。第二组挑轨迹，两边的 token 总数相同，留下的是至少有 5 轮的轨迹。训练数据在约 1 万到 1.45 万条之间。

两组里，挑过的都比随机的高 3 个百分点以上。论文把这类结果概括成一条：能得到更长轨迹的办法，训练效果更好。

挑选之外，这篇论文里影响最大的一步是任务从哪里来：换一种任务来源，SWE-bench Verified 那 100 题上的准确率最多能差 30 个百分点。

+
这篇论文里三个和直觉不一样的结果。
  • 给任务加约束、加难度没有用。用语言模型改写任务描述，给任务加上约束或提高难度，没有一种做法比不改更好。
  • 最强的模型不一定是最好的示范者。用 GPT-5.3-Codex 生成的轨迹来训练，三个基准测试的平均准确率是 11.94%。用 GLM 4.7 的一个量化版本生成的轨迹来训练，是 18.16%。量化版本指把参数压缩成较低的精度、占用内存更少的版本。
  • 加量要靠新的写法。把数据从 3.16 万条加到 10 万条时，如果只是让同一批任务多跑几遍，成绩不再上升。给同一批任务的描述改写出更多不同的写法，成绩才继续涨。这里的改写和第一条说的是两种：第一条是给任务加约束、加难度，这一条只增加写法的种类，任务本身不变。这一条和第六部分讲的多样性是同一件事。
