先看结论

  • 训练 agent（能自己调用工具、分很多步去完成一个任务的语言模型系统）用的任务和运行轨迹，现在可以成批地自动生成。运行轨迹（trajectory，也叫 trace）指 agent 一次运行里每一步的动作和看到的结果的完整记录。Meta 的 CWM 模型的训练数据里，留下的运行轨迹就有 300 万条。难的是决定留下哪些。
  • 从候选任务到最终的训练数据，中间有五步，其中四步在做挑选。后面五个部分讲这四步挑选。
  • 挑的是两样东西。运行轨迹用来做监督微调，让模型模仿。环境指三样东西合在一起：一段任务说明，一个沙盒（执行任务的隔离空间），一个验证器（判断任务做没做成的程序）。环境用来做强化学习，让模型自己练。
  • 训练数据的作用是告诉模型哪种做法该多做、哪种该少做，这种信息下面叫信号。它出问题有三种方式：信号是错的，没有信号，信号是重复的。
  • 有一个问题还没有定论：数据是少而精更好，还是越多越好。两边都有实验支持，第六部分看它们各自在什么条件下成立。

造数据便宜了，难的是挑

第 11 讲讲的是 agent 的训练数据从哪里来，一共五种来源：请人演示，从代码仓库、教程和视频这些现成的材料里提取，让模型合成运行轨迹，让模型成批地造出任务，让语言模型扮演用户或扮演 agent 要操作的系统。除了请人演示，另外四种都可以自动化，所以现在造任务和造运行轨迹的成本很低。

造出来的东西不能全部拿去训练。里面有三类用不上的东西：本身有缺陷、判出来的结果不可信的任务，模型每次都做对或每次都做错、学不到东西的任务，以及大量重复的内容。这三类大致对应后面「训练数据出问题的三种方式」一节的三种问题，那一节逐个讲。这一讲的问题是：造出来之后，留下哪些。

一个例子：CWM 留下了 300 万条轨迹

CWM（Code World Model）是 Meta 的 FAIR CodeGen 团队 2025 年发布的一个 320 亿参数的开源模型。它的训练数据里有一部分是 agent 的运行轨迹，收集的办法是：让一个语言模型在代码仓库的 Docker 镜像（一个打包好的、可以整个重建的运行环境）里做软件工程任务，把整个过程记下来。

任务有两种。一种是往能通过测试的代码里故意放进一个 bug，再让 agent 修。另一种是回到某次真实的 bug 修复之前，让 agent 修改代码，使原本失败的测试通过。

论文怎样处理这批轨迹，列在下表里。表里的 Jaccard 相似度量的是两个集合重合的程度，等于交集的大小除以并集的大小，1 表示完全相同。

CWM 的训练分前后四个阶段，这 300 万条轨迹用在第二个阶段，论文叫它 mid-training。在这个阶段，模型在这批轨迹上继续训练，既学着预测 agent 的下一个动作，也学着预测每个动作之后看到的结果。

这个例子里，重复的要丢，失败的却要留。留下失败的轨迹，是因为这批数据要教模型的是「在代码仓库的镜像里做一个动作会发生什么」，所以论文不按 bug 有没有修好来筛。

CWM 训练的最后一个阶段是强化学习，同一篇论文在这个阶段就换了做法。强化学习是让模型自己反复去做任务，做成了得到奖励，再按奖励调整模型。

进入这个阶段之前，论文先让上一个阶段训练完的模型把每个任务试做至少 32 遍，算出单次成功率。单次成功率高于 95% 的任务被当作太容易而去掉，一次都做不对的任务放进另一个集合，开始时抽到的机会更少。训练中途论文还按难度再筛一次，细节见第三部分的「几种难度筛选放在一起看」一节。每次都做对或每次都做错的任务为什么要这样处理，后面讲「没有信号」时会说明。

这两种做法放在一起说明，挑数据没有一套通用的规则，留什么取决于拿这批数据去教模型什么。后一种做法就是第三部分要讲的按难度筛选。

挑的是两样东西：轨迹和环境

训练 agent 主要有两种办法，它们用的数据不一样，所以要挑的东西也不一样：监督微调用运行轨迹，强化学习用环境。

{{fig 9 | 左：运行轨迹由一连串的「想、做、看结果」组成，最后是提交。右：环境由三样组成，图上标的是 Task、Sandbox、Verifier，也就是任务说明、沙盒（sandbox，一个隔离的运行环境，agent 在里面执行命令、改文件都不会影响到外面）和验证器（verifier，判断任务有没有做成的程序）。前面 CWM 用的 Docker 镜像，启动之后就是一个沙盒。图上的 Section 3 对应这里的第四和第五部分，Section 2 对应第二和第三部分。}}

下表把这两样东西并排比较。

表里写的是拿运行轨迹做监督微调的用法：挑出做得好的，让模型模仿。前面 CWM 的那 300 万条是另一种用法：模型除了学 agent 的动作，还要学每个动作之后会看到什么结果，所以没做成任务的轨迹也留着。

两样东西是连着的。轨迹是模型在环境里运行出来的，所以环境有缺陷，在它上面产生的轨迹也跟着有缺陷。这就是漏斗图里先挑任务、后挑轨迹的原因。

漏斗图把两种训练要挑的东西画在了同一张图里。强化学习直接在挑好的任务上训练，用的主要是图里的前两步筛选，按难度筛任务的理由也来自强化学习，后面讲「没有信号」时会说明。监督微调要用轨迹，所以还要让模型把任务做一遍、把轨迹记下来，再经过图里后面的两步筛选。

强化学习里也有轨迹：模型每做一遍任务，就产生一条。奖励由验证器按最后的结果来定，轨迹里的做法按这个奖励被加强或削弱。第四部分会讲到，这时还要检查整条轨迹里有没有走捷径，发现了就扣这次运行的奖励。

名字上有一点要说明。漏斗图和后面几页说的「任务」，指的就是这里的环境，也就是任务说明连同沙盒和验证器。这一页单说「环境」时都指这个整体，其中执行任务的那个地方叫沙盒。

要挑的东西有几样，有两种数法。这一页数成两样，就是环境和轨迹。这一讲的总览页数成三样，多出来的第三样是最后用多少条数据、各种来源怎么搭配，第六部分讲。

训练数据出问题的三种方式

训练数据的作用是告诉模型哪些做法该多做、哪些该少做，下面把它传给模型的这种信息叫作信号。信号出问题的方式可以分成三种。

CWM 的去重处理的是第三种。它后面的强化学习阶段去掉太容易的任务，处理的是第二种。

同一个基础模型，数据不同，差别很大

挑数据值不值得花力气，要看数据的差别对结果有多大影响。OpenThoughts-Agent（Raoof 等，2026）这篇论文专门研究这个问题：基础模型（拿来继续训练的那个现成的模型）固定为 Qwen3-8B 或 Qwen3-32B，只改训练数据，看微调之后的 agent 表现差多少。表现用基准测试（benchmark，一组题目加一个打分的办法）上的准确率来量。

下面的图分成左、中、右三张小图，左边和中间两张各用一个基准测试。左边是 SWE-bench Verified，它考的是修复真实代码仓库里报告的问题，共 500 个经过人工检查的任务，第二部分会细讲，这张图用的是从中抽出的 100 个。中间是 Terminal-Bench 2.0，它考的是在命令行终端里完成各种技术任务。

从同一批数据里挑，规模相同时挑过的子集是不是比随机选的更好，论文里另有专门的实验。下面两组都用 Qwen3-8B，每组拿一种挑法和随机选做对比。

第一组挑任务，两边各选 1 万个任务。论文的这类实验里一个任务配一条轨迹，所以两边的训练数据都是 1 万条。挑法是让 GPT-5 解答每个候选任务，按它的回答用了多少 token 来排，留下回答最长的那些任务。token 是模型处理文字的最小单位，大致是一个词或半个词。论文把回答的长度当作任务难度的一种估计：回答越长，说明 GPT-5 要用越多的 token 才能解决这个任务。

这种挑法沿用自 OpenThoughts。OpenThoughts 是这个项目之前的一篇论文，题目是「Data Recipes for Reasoning Models」，研究的是怎样准备训练数据来提高模型的推理能力，OpenThoughts-Agent 在它的基础上把对象换成了 agent。为什么这样挑出的任务训练效果更好，这篇论文没有另外说明。

第二组挑轨迹，留下的是至少有 5 轮的轨迹。按通常的用法，一轮（turn）指 agent 做一个动作、看到一次结果，轮数多的轨迹也就更长。两边的 token 总数相同，所以条数不一样多：随机选的一边是 14,470 条，挑过的一边是 9,859 条。

两组的结果列在下面的表里。表里的分数是三个基准测试的平均准确率，这三个是 SWE-bench Verified 的 100 题、OpenThoughts-TBLite 和 Terminal-Bench 2.0。论文比较各种挑法时只用这三个来评测，没有用前面图里右边那张小图的七个。OpenThoughts-TBLite 是这篇论文的作者新做的基准测试，有 100 个和 Terminal-Bench 同一类的任务，用来更快地估计模型在 Terminal-Bench 2.0 上的成绩。

两组里，挑过的都比随机的高 3 个百分点以上。论文把这类结果概括成一条：能得到更长轨迹的办法，训练效果更好。

上面两组实验各属于论文流程里的一个环节。论文把造训练数据的流程分成六个环节：任务从哪里来，几种来源怎么混合，要不要改写任务描述，怎么挑任务，用哪个模型来生成轨迹，怎么挑轨迹。每个环节单独做对比实验，默认的做法是用 1 万条轨迹微调 Qwen3-8B。

六个环节里影响最大的是任务从哪里来。论文比较了 95 种任务来源，例如用 SWE-smith 这种方法合成的修复代码问题的任务，和问答网站 StackExchange 上由人写的电脑使用问题。换一种任务来源，训练出的模型在 SWE-bench Verified 那 100 题上的准确率可以差 30 个百分点。这是综合排名第一和排名最后的两种来源之间的差距，综合排名是把前面说的三个基准测试上的成绩合起来排的。

+
这篇论文里三个和直觉不一样的结果。
  • 给任务加约束、加难度没有用。用语言模型改写任务描述，给任务加上约束或提高难度，没有一种做法比不改更好。
  • 最强的模型不一定是最好的示范者。这个实验同样用 1 万条轨迹微调 Qwen3-8B，只换生成轨迹的模型。用 GPT-5.3-Codex 生成的轨迹来训练，三个基准测试的平均准确率是 11.94%。用 GLM 4.7 的一个量化版本生成的轨迹来训练，是 18.16%。量化版本指把参数压缩成较低的精度、占用内存更少的版本。
  • 加量要靠新的写法。把数据从 3.16 万条加到 10 万条时，如果只是让同一批任务多运行几遍，SWE-bench Verified 那 100 题和 Terminal-Bench 2.0 上的准确率都不再明显变化，论文说变化在误差范围以内。给同一批任务的描述改写出更多不同的写法，三个基准测试上的准确率才继续涨。这里的改写和第一条说的是两种：第一条是给任务加约束、加难度，这一条只增加写法的种类，任务本身不变。这一条和第六部分讲的多样性是同一件事。
