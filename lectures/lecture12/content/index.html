先看结论

训练 agent 用的任务和运行轨迹，现在造起来很便宜。要花力气的是决定留下哪些。

任务要先确认本身是对的，再留下对模型不太容易也不太难的。轨迹要看它是怎么通过测试的，没通过的也有办法用。这里的测试，指编程任务里用来判定任务有没有做成的一组测试。

从这一讲的几个实验可以归纳出：候选数据有限、质量参差时，挑选最有价值。数据本来就都合格、还能再加时，加量更划算。多样性在两个实验里有帮助，数据很少时有反例。

第 11 讲讲的是这些数据从哪里来，这一讲讲造出来之后怎么挑。

要挑的东西有三样，下表每样占一列。表里的 LEGO-RL 和 Orchard 各是一个训练框架，表里引的是介绍它们的论文里的实验，各自在「在哪一页」那一行指向的页面里介绍。基准测试（benchmark）指一组题目加一个打分的办法，用来比较不同的模型。

表里还有四个词要先说明。前两个是奖励和验证器。奖励是模型做成任务后得到的分数，训练按它来调整模型。验证器是判断任务有没有做成的程序，在编程任务里通常就是上面说的那组测试。

后两个是走捷径和监控。走捷径指 agent 没有真正完成任务，却让测试判了通过。举一个例子：编程任务常常是根据代码仓库里一次真实的修改造出来的，交给 agent 的是这次修改之前的代码，要它自己把问题修好。仓库的历史记录里如果还留着这次修改，agent 把它找出来照着改，测试就会通过。监控指训练时检查整条运行轨迹里有没有这类行为，发现了就扣这次运行的奖励。
