先看结论

  • 「少而精」有实验支持：LIMI 用 78 条人工精选的轨迹微调（用这些数据继续训练一个现成的模型），在 AgencyBench 上得 73.5%，高于用 10,000 条数据微调的同一个模型的 47.8%。AgencyBench 是 LIMI 的作者自己做的一个 agent 基准测试，基准测试（benchmark）指一组题目加一个打分的办法。这个结果有几处限定条件，读的时候要一起看。
  • 「越多越好」也有实验支持：Orchard 固定模型和训练方法，只改数据的条数和挑选策略。把条数从 512 加到 2,048 带来的提高，比六种挑选策略之间的差距更大。
  • 两者可以这样对上：候选的数据有限、质量参差的时候，挑选最有价值。候选的数据本来就都合格、而且还能再加的时候，加量更划算。
  • 多样性在几个实验里都有帮助：训练的环境种类更多、代码仓库更多，模型在没见过的任务上表现更好。也有反例，数据很少时集中在少数几个仓库反而更好。
  • 整讲可以归纳成五步：验证任务，筛难度，审查成功的轨迹，留下带标记的失败轨迹，扩大来源的多样性。

问题：少而精，还是越多越好

先说明三个词。agent 指能自己调用工具、分很多步去完成一个任务的语言模型系统。运行轨迹（trajectory）是 agent 一次运行里每一步的动作和看到的结果的完整记录。监督微调（supervised fine-tuning，简称 SFT）是用现成的示范继续训练模型，让它照着做。这一部分讲的训练方式主要是监督微调，示范就是运行轨迹。

前面几部分讲的都是怎么筛。筛得越严，留下的越少。于是有一个必须回答的问题：同样的力气，是花在把一小批数据做精上，还是花在把数据量做大上。

{{fig 52 | 横轴是训练数据的量，纵轴是效果。红线是少量精选的数据，起点高，很快变平。灰线是大量没筛过的数据，起点低，一直上升，最后超过红线。这张图是示意，上面没有实测的数据。}}

这张示意图表达的是一种可能的关系：数据少的时候，精选的占优，数据多到一定程度，量占优。下面先分别看支持两种说法的实验，再看两条线是不是真的像图里这样相交。

少量精选数据的先例

「少即是多」这个说法在 agent 之前就有了。三篇名字相近的论文，各自在一个方向上用很少的精选数据做微调。

{{fig 53 | 一条对数刻度的横轴，表示训练样本的条数。从左到右标出了 LIMI 的 78 条、LIMO 的 817 条、LIMA 的 1,000 条，以及 LIMI 用来对比的 10,000 条。}}

LIMA 和 LIMO 的解释是一致的：知识和能力主要是模型在预训练时学到的，微调只是教它用哪种方式把这些能力用出来，所以不需要很多数据。LIMO 给了一个旁证：同样的 800 道题，拿去微调上一代的 Qwen1.5-32B，AIME 2024 上只有 9.2%。

LIMO 挑题的办法和第三部分的难度筛选是同一个思路：先去掉一个小模型 4 次以内能做对的题，再让一个较强的模型每题做 32 遍，只留下做对 1 到 3 遍的。

LIMI：78 条轨迹

LIMI（Less Is More for Agency）是三篇里唯一讲 agent 的。

78 条是怎么来的

先定 78 个任务。其中 60 个来自开发者和研究者实际遇到的场景，18 个是从 GitHub 的代码合并请求（pull request，简称 PR，指请求把一组代码改动并入仓库的申请）合成出来的任务里挑的。任务分两类：一类是用自然语言指挥模型写软件，一类是研究工作流，比如查论文、跑实验、分析数据。

然后由 4 个博士生和 GPT-5 合作，在一个命令行的 agent 工具（SII CLI，作者所在实验室自己的工具）里把每个任务做完，一直做到成功为止，整个过程记下来就是一条轨迹。

{{fig 56 | 左：78 条轨迹的长度分布，横轴是 token 数（token 是模型处理文字的最小单位），纵轴是占比。最短 1.3 万，最长 15.2 万，平均 4.24 万。右：任务的领域。内圈是两大类，外圈是细分的方向。图片来源：Xiao 等，2025的图 4。}}

所以这 78 条有三个特点：任务大多来自实际的场景，轨迹很长，每一条都有人全程参与并且最后做成了。

「78 条胜过 10,000 条，提高 53.7%」里的 53.7% 是相对的比例。这句话流传很广，出自论文的摘要。73.5 除以 47.8 约等于 1.537，所以说提高 53.7%。两个分数的差是 25.7 个百分点。

这个对比的四个限定条件

对照论文的正文和表，「78 条胜过 10,000 条」还要加四个限定条件。

  • 用来对比的三份数据，有两份让模型变差了。GLM-4.5 不微调是 45.1%。用另外三份数据微调之后，两份低于 45.1%，10,000 条的那份只高 2.7 个百分点。所以这个对比同时也在说：那三份数据对这个基准测试帮助很小，甚至有害。
  • 基准测试很小，而且出自同一批作者。LIMI 用的 AgencyBench 是 2025 年 9 月放在 GitHub 上的第 1 版，只有 10 个任务。它的 15 个作者全部是 LIMI 的作者。训练的 78 个任务和这 10 个测试任务属于同样的两类，用的也是同一个命令行工具。
  • 离开那个命令行工具，提高很小。不用命令行工具时，论文在七项其他的评测上比较了 LIMI 和没微调的 GLM-4.5，论文给的平均分是 50.0% 和 48.7%。七项里有一项，LIMI 还低于 GLM-4.5。
  • 没有报告波动。论文没有说每个分数评测了几次，也没有给误差范围。

这四点出自Xiao 等，2025的摘要、第 4.3 和 4.5 节、表 2 和表 4，以及AgencyBench 的代码仓库。

考虑了这些限定之后仍然成立的结论是：在和训练任务同类的任务上，78 条有人全程参与的长轨迹，效果好过几百到一万条现成的通用 agent 数据。

Orchard：只改条数和挑法，其他都不动

Orchard（Peng 等，2026，微软研究院等）是一个训练 agent 的开源框架，其中编程 agent 的那部分有一个专门的实验，把「数据量」和「怎么挑」这两个因素分开来测。

实验固定了三样东西：基础模型 Qwen3-30B-A3B-Thinking，微调的各项参数，以及评测用的运行框架 mini-swe-agent。运行框架指包在模型外面、给它工具并管理多轮对话的程序。

实验只做监督微调，不做强化学习。强化学习是另一种训练方式：让模型自己反复去做任务，做成了得到奖励，再按奖励调整模型。

实验只改两样。一样是训练轨迹的条数，取 512、1,024、2,048 三档。另一样是挑法：候选是一批已经成功解决了问题的轨迹，用六种策略从里面挑出这么多条。

论文从这张表得出两条结论。

  • 数据量的影响大于挑选策略。表里最差的策略是仓库分散。它从 512 条加到 2,048 条，解决率从 44.0 升到 52.2，高了 8.2 个百分点。这比 512 条时六种策略之间最大的差距（5.5 个百分点）还大。
  • 数据越多，怎么挑越不重要。六种策略之间的差距，随着条数增加从 5.5 降到 3.2，再降到 2.0 个百分点。用到参考补丁信息的三种策略在 512 条时大体领先，到 2,048 条时已经和随机差不多。

另外，表里最差的一格是 44.0，也比没有微调的基础模型的 22.0% 高出 22 个百分点。论文据此说，少量高质量的轨迹就能带来大部分的提高。这里有一个细节：22.0% 这个数在论文里是在另一个运行框架 OpenHands 下测的，和表里用的 mini-swe-agent 不同，所以这 22 个百分点里混进了换运行框架的影响。

i
这个结论的适用范围。
  • 候选的数据本来就都是好的。六种策略都是从同一批成功的轨迹里挑，这些轨迹由很强的模型生成，已经过滤掉了太长的和格式有错的。实验比较的是「好数据里怎么挑」，没有测「好数据和没筛过的数据」。
  • 挑选在条数相同时仍然有用。512 条时最好的策略是 49.5，最差的策略用两倍的数据是 49.0，两者大致相等。也就是在数据少的时候，一个好的挑法的作用大约相当于把数据量翻一倍。
  • 没有误差范围。论文没有说明每一格训练了几次。SWE-bench Verified 有 500 个任务，粗略估算，解决率在 50% 附近时，单次评测的标准误差大约是 2.2 个百分点。标准误差指同一个模型换一批同样多的题来测，成绩上下波动的典型幅度。2,048 条那一行六个数之间的差距都在这个范围以内，512 到 2,048 条的提高（每列 3.4 到 8.2 个百分点）则超过了它。
  • 条数最多只到 2,048。这张表里最高是 54.2%。用全部 10.7 万条轨迹做监督微调是 64.3%，再加强化学习是 67.5%。

两个结论怎么对上

LIMI 说少而精更好，Orchard 说量更重要。有一个实验把两种情况放在了同一张表里，它出自第四部分的那篇 The Verification Horizon。

实验的任务是按一份自然语言的说明生成整个代码仓库。训练方式是拒绝采样微调（rejection sampling fine-tuning，简称 RFT）：先让一个强模型生成轨迹，把不合格的筛掉，用留下的来微调 Qwen 3.6 Turbo。Qwen 3.6 Turbo 是论文在这个实验里写的模型名。第四部分讲的那个强化学习实验里，论文写的是 Qwen-Turbo，两处是不是同一个模型，论文没有说明。

第五部分讲的 RFT 在这三步之后还有几轮：被训练的模型自己去做任务，把做成的轨迹加进训练数据再训练。这个实验的论文只写了生成、筛选和微调这三步。

筛选分两层。第一层用规则去掉空的、超时的和格式有错的，剩下 19,050 条。第二层让一个评审 agent 给每条打分，8 分以上（满分 10 分）的留下。这个评审 agent 会把说明拆成检查清单，自己写测试去跑生成的仓库。

{{fig 68 | 三根柱子是三种训练数据微调之后的得分，下面标着各自的条数。图上的三个数取自下面表里每一行最后的那个检查点（checkpoint，训练过程中按固定步数保存下来的模型）。}}

下表是三种训练数据在各个检查点上的得分。

这张表可以读出三件事。

  • 条数相同，筛过的更好。同样是 9,139 条，评审筛过的最后是 23.52，随机取的是 21.61，高 1.91 分。
  • 条数翻倍，不筛也能追上。19,050 条没经过评审筛选的数据，训练到第 600 步是 24.75，超过了筛过的 9,139 条。
  • 追上要花更多的训练。同样训练到 450 步左右时，全部数据是 21.15，低于筛过的 23.52。全部数据那一行的得分先升、再降、再升，并不平稳。

论文作者的说法是：数据量翻倍可以弥补没有评审筛选的不足，代价是更多的算力。评审最有价值的时候，是候选的数据有限、需要仔细挑的时候。

把这句话和前面两节放在一起，可以这样归纳：挑选在候选数据有限、质量参差时最有价值。候选数据本来就都合格、还能继续加的时候，加量更划算。

SWE-Prime 和 Orchard 两行的结论是一致的。两者的候选都是强模型生成的成功轨迹。只挑整条轨迹时，SWE-Prime 在多数组合上也比不过用全部，这和 Orchard 的结论相同。SWE-Prime 的提高来自在留下的轨迹里再屏蔽低分的片段。

多数实验里都有帮助的：多样性

不管是精选还是加量，有一个因素在几个实验里都有帮助：训练数据覆盖的环境和任务要多样。

第一部分讲过的 OpenThoughts-Agent（Raoof 等，2026）里就有一个这样的结果。把数据从 3.16 万条加到 10 万条时，只是让同一批任务多跑几遍，成绩不再上升，把任务描述改写出更多不同的写法才继续涨。

下面再看两篇论文。AgentRefine 认为多样性是它效果好的原因，但没有做只改多样性的对照实验。SWE-smith 做了轨迹条数相同、只改仓库个数的实验。

AgentRefine：在很多种环境里学会改正错误

AgentRefine（Fu 等，ICLR 2025，北京邮电大学和美团）从一个观察开始：现有的 agent 微调数据，在训练时见过的环境里效果很好，换到没见过的环境，效果就明显变差。

下图左边比的指标叫任务进度（progress rate）：把每个任务拆成几个小目标，量的是完成了其中多大的比例。

{{fig 61 | 左：五种环境上的任务进度（progress rate），蓝色是 Agent-FLAN（Chen 等 2024 年提出的一种 agent 微调方法，论文拿它当对照），橙色是 AgentRefine。虚线左边的 Alfworld（一个用文字操作的模拟环境，任务是「把洗过的苹果放进厨房的冰箱」这一类家务）是 Agent-FLAN 训练时见过的环境，右边四种都没见过。右：AgentRefine 的流程图。图片来源：Fu 等，2025的图 1 和图 4。}}

作者检查了这些模型在新环境里的错误，大多数属于三类：输出的格式不对，推理不合逻辑，反复生成同样的内容。论文没有给出三类各占多少。他们的判断是，模型记住了训练环境里「看到什么就做什么」的对应关系，没有学会根据环境的反馈调整自己。

AgentRefine 的数据是这样造的。

  • 环境是合成的，而且各不相同。从一个人物设定库里取一个人物，让 GPT-4o 按桌面角色扮演游戏的方式写一份剧本：环境是什么，目标是什么，有哪些可用的动作。每条数据的环境都不一样。
  • 轨迹里必须有错误和改正。GPT-4o 同时扮演主持人和玩家，生成多轮的轨迹。主持人负责指出玩家的动作哪里错了。一条轨迹里至少要有两处「出错然后改正」，不够就重新生成。
  • 错的那一步不学。训练时，出错的那几轮留在上下文里，但不计算损失。损失是训练时衡量模型的输出和示范相差多少的数，不计算损失就是不让模型学这几轮。模型学的是出错之后怎么改。

评测用的五种环境来自 AgentBoard 这套基准测试，都用文字和 agent 交互。

  • Alfworld 是家务任务。
  • BabyAI 是一个方格世界，agent 要在里面走动、拿放物品。
  • SciWorld 的全名是 ScienceWorld，考科学常识，例如测出橙汁的熔点。
  • PDDL 是几个要先规划好步骤的小游戏。
  • Jericho 是一组文字冒险游戏。

AgentBoard 给每种环境算两个指标。成功率是完整做成的任务占的比例。任务进度就是图前说的那个指标，按完成的小目标的比例来算，所以没做成的任务也能得到一部分分数。上面的图画的是任务进度，下面的表列的是成功率。按论文的表 1，两个指标下 Agent-FLAN 和 AgentRefine 在五种环境上谁高谁低是一样的。

读这个结果时要注意的三点。
  • 在 Agent-FLAN 见过的环境上，AgentRefine 更差。Alfworld 是 Agent-FLAN 训练时见过的环境，AgentRefine 在这里的成功率低于 Agent-FLAN，论文自己也这样写。

SWE-smith：轨迹条数相同，来自更多的仓库

SWE-smith（Yang 等，NeurIPS 2025）在第 11 讲里出现过：它先为每个代码仓库建一个可以执行的环境，再往里面合成 bug，从 128 个 Python 仓库造出了约 5 万个任务。

论文里有一个专门测多样性的实验。四组训练数据的轨迹都是 700 条，都由 Claude 3.7 Sonnet 生成，区别只在这 700 条取自多少个仓库。微调的是一个 70 亿参数（7B）的模型，在 SWE-bench Verified 上评测。

条数不变，仓库从最少加到 100 个，解决率高了 4.8 个百分点。论文说解决率和仓库个数大致是对数关系，也就是每多一倍仓库，提高的幅度差不多。只有四个点，这个形状只能算一个粗略的描述。

+
多样性也有不管用的时候。有三个结果提醒不要把「越分散越好」当成定律。
  • 数据很少时，集中更好。上面 Orchard 的表里，512 条时仓库集中的解决率是 47.9，比仓库分散的 44.0 高 3.9 个百分点，到 2,048 条时差距缩到 1.2 个百分点。论文的解释是，数据很少时，在少数几个仓库上各有较多的轨迹，比在很多仓库上各只有几条轨迹，学到的做法更能用到别的仓库上。
  • 来源多到一定程度，再加不一定有帮助。OpenThoughts-Agent 发现，混合 4 个最好的任务来源比只用 1 个好，但到 10 万条时，混 8 个或 16 个并没有稳定地比混 4 个更好。
  • 目标是某一个仓库时，集中是合理的。SWE-smith 自己的另一个实验显示，只用 SymPy 一个仓库的 700 条轨迹来微调，在 SymPy 的任务上明显更好，7B 的模型从 13.6% 升到 21.2%。在其他任务上只略有下降，从 15.3% 降到 14.0%。
出处：Peng 等，2026，Raoof 等，2026，Yang 等，2025。

整讲的小结

第一部分说过，任务和运行轨迹现在可以成批地自动生成，成本很低。整讲的结论是下面这一句话，分到任务、轨迹和训练用的那批数据上是三条。

{{fig 70 | 左边是第一部分的漏斗图，右边是三句话的小结，分别对应任务、轨迹和训练用的那批数据。}}

造 agent 的数据已经便宜，要花力气的是决定留下哪些。

  • 任务。把每个任务实际运行几遍来检查它，留下模型有时能做对的，模型进步之后更新任务池。
  • 轨迹。测试通过可能是靠捷径，所以要检查它是怎么通过的。失败的轨迹里也有可学的东西。
  • 训练用的那批数据。数据少的时候精心挑选。数据多了之后，起作用的是数据量和多样性。

这一讲和第 11 讲讲的都是怎样用数据让 agent 变强。接下来的问题是：怎么知道 agent 真的变强了。这是第 13 讲的内容。这一讲里其实已经遇到了这个问题：好几个实验的结论，都依赖 SWE-bench Verified、SWE-bench Pro 和 AgencyBench 这些基准测试本身靠不靠得住。

资料说明

这一节记录核对资料时发现的出入和没有查到的地方。前面各节的结论已经按核对的结果来写。

  • LIMI 论文里的「53.7 个百分点」。摘要写的是提高 53.7%，这是相对的比例。论文正文有一处把它写成了「53.7 个百分点」，和摘要不一致。两个分数的差是 25.7 个百分点。
