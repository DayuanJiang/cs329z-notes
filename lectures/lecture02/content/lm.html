先看结论

  • 语言模型是一个给一串 token 算概率的模型。token 是模型处理文字的最小单位，大致是一个词或半个词。算法是：依次算出「前面这些 token 之后，下一个是某个 token」的概率，再把这些概率连乘。
  • 每一步，模型都给词表里的每一个 token 一个概率，词表是所有可能的 token 组成的固定集合。从里面挑一个接到后面，再算下一步，就是生成文字。挑的办法叫解码策略，常用的有四种：greedy 每一步都选概率最高的 token，top-k 和 top-p 只在概率最高的一部分 token 里随机抽，束搜索（beam search）同时保留几条候选的序列。
  • temperature 是挑之前对概率分布做的一次调整。它越低，结果越接近「每次都选最可能的那个」。它越高，结果越多样。
  • 解码策略和 temperature 怎么定，看三件事：要不要多样性，任务是什么，预算有多少。temperature、top-p、top-k 都能调多样性。数学和代码用低的 temperature，创意写作的输出多样一些可能更好，temperature 可以高一些。束搜索更花时间和内存。

语言模型就是一个算概率的公式

语言模型的定义是一个公式：一串 token 的概率，等于每个 token 在它前面所有 token 之后出现的概率的乘积。

先用句子「The class was about agents.」走一遍。从第一个 token 开始，依次算出每个 token 在它前面那些 token 之后出现的概率，再把这些概率乘起来。下面图表里的概率只用来演示算法，图上没有标出它们是哪个模型算的，见资料说明。

{{fig 8 | 句子「The class was about agents.」的概率是怎么算出来的。每一行是一个条件概率，最右边一列把它们列出来连乘，结果是 1.2e-17。}}

把这个算法写成公式，是 P(x1, …, xT) = P(x1) × P(x2 | x1) × … × P(xT | x1, …, xT-1)。各个符号的意思如下。

  • x1 到 xT 是这串文字里的第 1 个到第 T 个 token。
  • P(xt | x1, …, xt-1) 读作：已经有了前 t-1 个 token，第 t 个 token 是 xt 的概率。竖线后面是条件。上表里的每一行就是这样一个条件概率。
  • 等号左边是整串文字的概率，右边是 T 个条件概率连乘。

句子越长，乘出来的数越小。这么小的数连乘下去，计算机的浮点数很快就表示不了。所以实际计算时取每个概率的对数再相加。对数之和等于连乘结果的对数。比较两句话时，谁的概率大，谁的对数之和也大，所以用对数之和来比较效果相同，数值上稳定得多。

token 和词表

上面把 token 当成了词。实际上，文字先被切成小块，每一小块是一个 token，可以是一个词、半个词或一个标点。所有可能的 token 组成一个固定的集合，叫词表（vocabulary）。词表有多大是模型设计时定下的。例如 OpenAI 的模型 GPT-2 的词表有 50,257 个 token，Meta 的模型 Llama 3 的词表约有 12.8 万个 token。任何文字都能用词表里的 token 拼出来，模型的概率就是在这个固定的集合上算的。

生成式模型和判别式模型

机器学习模型常被分成两类。语言模型属于生成式的那一类。这一节先说两类的区别，再说为什么可以从生成式的模型里抽样，也就是按模型给出的概率随机抽出一段文字。

{{fig 11 | 左：判别式模型学的是一条把两类数据分开的线。右：生成式模型学的是数据本身的分布，图里的数据分成两类，所以画成每一类各占一片区域。图片来源：Akanksha Malhotra，medium.com。}}

按上一节的公式算概率的语言模型属于生成式。它的数据是一串串 token，不分类别。把它归为生成式的理由是：给它任意一串 token，它都能算出这串 token 的概率，也就是说它学的是 token 序列本身的分布。

i
这两类的界线有些模糊。公式右边的每一项，是在整个词表里决定下一个 token 是哪一个，单看这一项很像一个分类问题。下一节会看到，「The class was about」之后概率最高的两个 token 是 to 和 as。如果专门训练一个模型，只判断这里该接 to 还是 as，那它更像判别式模型。语言模型给词表里的每一个 token 都算出概率，把每一项连乘起来，就能得到任意一串 token 的概率。它被归为生成式，理由就是上一段说的这一点。

生成式的模型可以从里面抽样，原因在公式右边的每一项：模型每一步给出的是整个词表上的概率，所以可以按这个概率随机抽一个 token 接到后面，再算下一步，一步一步生成文字。下一节用一个例子走一遍。

生成式模型更系统的介绍，可以读斯坦福深度生成模型课程的导论笔记。

怎样挑出下一个 token

已经有了「The class was about」这四个 token。模型给词表里的每个 token 算出它接在后面的概率，然后从里面挑一个。下面两张图里的概率也只用来演示算法，图上没有标出是哪个模型算的。

还有一种挑法是按概率随机抽一个，概率越高的 token 越容易被抽中，这就是上一节说的抽样。第二步演示的就是这种挑法：选中的是排第二的 begin，概率最高的 be 没有被选中。再往下走一步选中句号，最后得到「The class was about to begin.」。

这说明：每一步拿到的是一个概率分布，从里面怎么挑是可以选择的。

从概率分布里挑 token 的办法叫解码策略（decoding strategy）。下面的表用上一节两张图里的数字来演示。

英文资料里也把这四种统称 sampling strategies（抽样策略），其中 greedy 和束搜索其实并不随机抽。

top-k 和 top-p 的差别在候选的个数。top-k 的候选永远是 k 个。top-p 的候选个数跟着分布变：概率集中在少数几个 token 上的时候候选很少，概率分散在很多 token 上的时候候选很多。上表里同一个 p 在两步里分别选出了 1 个和 4 个候选，就是这个意思。

temperature：让概率更集中或更分散

temperature 是一个可以调的数，记作 T。它在抽样之前改变概率分布的形状。T 低时，概率集中到最可能的几个 token 上。T 高时，概率在各个 token 之间分得更平均。

{{fig 20 | 同一个 prompt（交给模型的那段输入文字）「I am tired, I will take a ___」在四个 temperature 下的下一个 token 的分布。T 等于 0.1 时 nap 几乎占了全部的概率，T 等于 2.0 时五个候选词的概率已经比较接近。右边红字写的算法照字面去做没有效果，实际的算法见下面的正文。图片来源：Towards Data Science。}}

具体的算法要从 logits 说起。模型最后一层输出的是一组没有归一化的分数，词表里每个 token 一个，叫 logits。把 logits 送进 softmax 函数（把一组分数变成加起来等于 1 的概率），才得到概率。temperature 作用在 logits 上：先把每个 logit 除以 T，再做 softmax。

i
除的是 logits，除概率没有用。上图右边的红字写的是「把所有概率除以 T，再重新归一化到加起来等于 1」。照这句话的字面去做，分布不会有任何变化：所有概率同除以一个数，归一化之后又回到原样。实际的做法是在 softmax 之前把 logits 除以 T。出处：Hinton 等，2015 里带 temperature 的 softmax；Hugging Face 上讲解码策略的文章。

关于 temperature 的四个问题

  • 它有固定的取值范围吗？没有。它只是一个缩放的系数，「temperature 等于 5 意味着什么」没有直观的解释。T 等于 1 保持原样，T 越接近 0 越接近 greedy。
  • 它是训练出来的吗？通常不是，它是人设定的值，因为它主要在推理时用，训练里没有哪个信号能告诉模型它该取多少。具体分两种情况。强化学习以外的训练用不到它，训练之后在推理时才设定。用强化学习训练模型时会用到它，因为训练中要让模型自己去做任务、生成输出，要给抽样设一个 temperature，这时它仍然是人设定的。
  • 生成到一半可以换一个值吗？可以这样理解：temperature 只作用在模型最后一层输出的 logits 上，前面各层已经算好并保存下来的中间结果不受影响，所以中途换值在技术上没有障碍。实际这样做的不多。
  • 它对先写出思考过程再回答的模型有影响吗？有。思考过程也是按同样的办法一个 token 一个 token 生成的。给这类模型定 temperature，同样是一个设计决定。这类模型叫推理模型（reasoning model，先写出思考过程再回答的模型），见第六部分。这个名字里的「推理」指思考，和前面「推理时」里的推理是两回事。

束搜索：往后多看几步再决定

前面三种策略每一步只决定一个 token，定了就不再改。这样可能错过更好的整句话：某一步概率稍低的 token，接下去几步的概率也许都很高，整条序列的概率反而更大。束搜索为此同时保留几条候选的序列，往后多走几步，再决定留下哪一条。

{{fig 21 | 一棵束搜索的树。从 start 出发，绿色的节点是被保留下来、继续往后延伸的候选，灰色的节点是被放弃的。例如第一步保留了 arrived 和 the，之后在这两条线上分别往后延伸。图片来源：Chaw Thiri San，medium.com。}}

保留的候选条数叫束宽（beam width）。每一步，每条候选都往后延伸出若干个新的 token，然后从所有延伸出来的序列里，再挑出得分最高的那几条留下。

几条候选之间怎么比

最常用的得分是模型自己给的：把这条序列上每个 token 的对数概率加起来。概率都小于 1，它的对数是负数，所以序列越长，加起来的数越小。为了让长的序列不因为长而得分偏低，通常再把总和除以序列的长度。

也可以用模型之外的东西来打分。例如在解数学题时，用一个外部的验证程序来判断哪一条更有希望，或者用一个估值函数，它给一条还没写完的解答估一个分，表示沿着它做下去有多大希望做对。

代价

束搜索要同时保存多条序列各自的中间结果，每一步要算的东西也成倍增加，所以时间和内存的开销都比前三种大。

+
延伸阅读。Hugging Face 上的文章 Decoding Strategies in Large Language Models 用 GPT-2 把 greedy、束搜索、top-k、top-p 各实现了一遍，并画出了每一步的树。

怎么选

解码策略和 temperature 怎么定，要看三件事：要不要多样性，任务是什么，预算有多少。

搭 agent 的时候一直在用这些设置：agent 每调用一次模型，模型都要按定好的解码策略和 temperature 生成一段文字。用强化学习训练模型时也一样，训练中模型要自己把任务从头到尾做很多遍，每一遍的文字都是这样生成的。

这一部分的小结

  • 语言模型给一串 token 算概率，算法是把每个 token 的条件概率连乘。
  • 它是生成式的模型，所以可以从它抽样，一个 token 一个 token 地生成文字。
  • 解码策略决定每一步怎么挑。temperature 通过缩放 logits 来调多样性。

到这里，模型内部怎样算出下一个 token 的概率还没有讲。下一部分讲 Transformer 是怎么算出这个概率的。Transformer 是 2017 年提出的一种模型结构，现在的大语言模型大多用它。
