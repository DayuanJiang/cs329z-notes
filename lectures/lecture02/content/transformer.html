先看结论

  • 现在的大语言模型大多是只有解码器的 Transformer。它的流程是：每个 token 变成一个向量，加上表示位置的向量，经过很多层「注意力加前馈网络」，最后变成词表上的一组概率。token 是模型处理文字的最小单位，大致是一个词或半个词。
  • 注意力（attention）这一层做的事是：每个 token 去看它前面的所有 token，按相关程度把它们的信息加权汇总到自己身上。计算时每个 token 会产生三个向量，分别叫 query、key、value。
  • 这个结构有一个大优点：一段文字里所有位置可以同时算，适合在 GPU 上并行训练。也有一个大代价：计算量随文字长度的平方增长，上下文一长就很贵。
  • 后面几部分反复用到这里的三样东西：每个 token 的 key 和 value、位置向量、平方级的计算量。

Transformer 之前的语言模型

给下一个 token 算概率的办法，在 Transformer 出现之前换过几代。

循环神经网络有一个特点要记住：它必须按顺序一个词一个词地算，后一步要等前一步的状态。下面会看到，Transformer 正是在这一点上和它不同。

2017 年的 Transformer 和只有解码器的版本

Transformer 出自 Google 的研究者 2017 年的论文《Attention Is All You Need》，作者是 Vaswani、Shazeer、Parmar、Uszkoreit、Jones、Gomez、Kaiser 和 Polosukhin。论文里的模型是为机器翻译设计的，由编码器和解码器两半组成。

{{fig 27 | 论文里的结构图。左边被红色盖住的是编码器，右边红框里的是解码器。解码器从下往上依次是：输入的向量加位置编码、带掩码的多头注意力、多头注意力、前馈网络，重复 N 次，最后经过线性层和 softmax（把一组分数变成加起来等于 1 的概率的函数）得到输出的概率。图片来源：Vaswani 等，2017。}}

编码器把输入的文字变成一组向量，解码器读着这组向量，一个 token 一个 token 地写出译文。现在的大语言模型大多只保留解码器这一半，叫 decoder-only。两半用的是同一套零件，所以下面只讲解码器是怎么工作的。

第一步：把 token 变成带位置的向量

还是用「The class was about」这四个 token，目标是算出下一个 token 的概率。

{{fig 31 | 最下面是四个 token。每个 token 上面有两条向量：彩色的一条是它的词向量，黑色的一条是它所在位置的位置向量，两条相加。四个相加后的结果叠成右上方的一个矩阵，每个 token 占一行。}}
  • 词向量（embedding）。模型里有一张表，词表里每个 token 对应表里的一行，这一行就是它的向量。这张表是训练出来的。
  • 位置向量（positional embedding）。再给每个位置一个向量，第 1 个位置一个、第 2 个位置一个，依此类推，和词向量相加。这些向量可以是一张训练出来的表，也可以用固定的公式算出来，2017 年的论文用的是公式。
  • 叠成矩阵。四个 token 的向量叠起来，是一个 4 行的矩阵。后面的计算都是对这个矩阵整体做的。

为什么需要位置向量

后面的注意力计算，只看两个 token 的内容有多相关，结构本身不知道哪个 token 在前、哪个在后。去掉位置向量，模型就分不清「was 在 class 之后」还是「class 在 was 之后」。所以要把位置直接告诉它。

i
掩码里其实带着一点顺序的信息，但太少。下一节的因果掩码规定每个 token 只能看它前面的 token。原则上，模型可以靠这一点自己数出位置：第一个 token 只能看到自己，第二个 token 能看到两个，依此类推。但这等于让模型在内部学会数数，很难学出来。直接给一个位置向量要容易得多。

第二步：注意力层，一步一步算

注意力层是整个结构的核心。它让每个 token 按相关程度，把前面各个 token 的信息加权汇总到自己身上。下面分成八步。

先算出 query、key、value

{{fig 35 | 输入矩阵先做一次 Layer Norm，再分别乘上三个权重矩阵 WQ、WK、WV，得到 Q、K、V 三个矩阵。图里的方块是权重，圆点是计算出来的中间结果。K 的右上角有一个 T，表示它被转置了。旁边三个点的小向量是偏置。}}

图里有两种东西要分清。彩色的方块是权重，也就是模型的参数，训练好之后固定不变，对任何输入都一样。圆点是中间结果，是输入和权重算出来的，每段输入都不同。权重在训练开始时是随机数，所以没训练的模型第一次算出来的全是没有意义的结果。

Q、K、V 各有 4 行，每个 token 一行。图里每行画了 3 个数，表示 query、key、value 的维度是 3。2017 年论文的基础模型里，这个维度是 64。

再算出每个 token 该看谁

{{fig 40 | 完整的计算。Q 乘以转置后的 K，得到左上的 4 乘 4 的方阵；方阵右上角的黑色部分是因果掩码；除以 dk 的平方根，做 softmax，得到中间那个只有左下半边有数的方阵；它再乘以 V，得到最右边的矩阵。左侧是这一串计算写成的公式。}}

第 3 到第 7 步写成一个公式，是 Attention(Q, K, V) = softmax(Q × K转置 ÷ √dk) × V。

{{fig 42 | 最后两步。粉色的 WO 把结果变回模型的维度，左边那条带加号的弧线是残差连接：把这一层的输入直接加到这一层的输出上。}}

三个常被问到的细节

  • 为什么要因果掩码。训练的时候，整句话「The class was about」都在手里。但生成的时候，后面的 token 还不存在。如果训练时允许 The 看到 class，那么「The 后面是什么」这个预测就已经看过答案了。掩码保证训练时和生成时的条件是一样的。也有不加掩码、前后都能看的注意力，用在不需要逐个生成的模型里。
  • 为什么要除以 dk 的平方根。论文的解释是：维度大的时候点积的数值会很大，softmax 会落到梯度极小的区域，训练不动。除以这个数能把数值拉回合适的范围。
  • 残差连接有什么用。它让梯度（训练时用来更新权重的信号）可以沿着这条直通的路一路传回前面的层，训练很深的网络时更稳定。

多头注意力：同一件事并排做好几遍

上一节讲的是只有一组 WQ、WK、WV 的注意力。实际的模型用的是多头注意力（multi-head attention），改动有三处。

{{fig 48 | 多头注意力。WQ、WK、WV 各有好几个，叠在一起画；每一组各自算出一个结果，几个结果左右拼在一起，成为右上方那个更宽的矩阵；再用一个更大的 WO 投影回模型的维度。}}
  1. 多组权重。准备好几组 WQ、WK、WV，每一组叫一个头，各自独立地算一遍注意力。
  2. 拼接。把各个头的输出左右拼成一个更宽的矩阵。
  3. 更大的投影矩阵。WO 也相应变大，把拼起来的结果投影回模型的维度。最后输出的形状和单头时一样。

这样做的好处是，同一段文字可以同时有好几种表示。不同的头可以各看各的关系。2017 年论文里的基础模型用了 8 个头，模型的维度是 512，每个头里 key 和 value 的维度是 64。

第三步：叠成一个完整的模型

把多头、带因果掩码的自注意力层当成一个零件，再配上一个前馈网络，就是一个 Transformer block。

{{fig 54 | 一个 Transformer block。从下往上：Layer Norm，多头因果自注意力层，左边的弧线是第一条残差连接；再做一次 Layer Norm，经过前馈网络，右边的弧线是第二条残差连接。}}

前馈网络（feed forward）对每个 token 的向量单独做一次变换，token 之间不交换信息。2017 年的论文里，它是两次线性变换，中间夹一个 ReLU 激活函数：先把 512 维放大到 2048 维，再变回 512 维。token 之间的信息交换全部发生在注意力层。

{{fig 60 | 完整的模型。四个 token 的向量经过 N 个 Transformer block，做一次 Layer Norm，再经过 LM Head 和 softmax。最上面一排是四组概率，每个位置各一组。}}

输出有四组概率。第 1 组是「The 之后是什么」，第 2 组是「The class 之后是什么」，最后一组是「The class was about 之后是什么」。生成文字时用的是最后一组，它就是第一部分里那张下一个 token 的概率表。前面三组在训练时有用：一段文字过一遍模型，每个位置都能和真实的下一个 token 比一次，见第四部分。

i
Layer Norm 放在哪里，新旧模型不一样。上面几张图里，Layer Norm 放在注意力层和前馈网络的前面，最后还有一个。这是 GPT-2 开始的做法。2017 年的原始论文是放在后面的，写作 LayerNorm(x + Sublayer(x))。出处：Radford 等，2019。

和循环神经网络比：能并行，但长了就贵

论文里有一张表，比较了几种层的计算量。这张表说明了 Transformer 为什么能取代循环神经网络，也说明了它的代价在哪里。

{{fig 61 | 论文的表 1。红框里是要看的两列和两行：自注意力每层的计算量是 n 的平方乘以 d，顺序操作数是常数；循环层每层的计算量是 n 乘以 d 的平方，顺序操作数是 n。n 是序列长度，d 是向量的维度。图片来源：Vaswani 等，2017。}}
  • 顺序操作数是常数，对在 GPU 上并行训练非常重要。上面算四个 token 时，四个位置是在同一次矩阵运算里一起算完的。训练时把很长的文字送进去，过一遍模型，所有位置的预测就都有了。循环神经网络做不到这一点。
  • n 的平方，意味着长上下文很贵。注意力那个方阵的边长就是 token 的个数。第三部分讲的线性注意力，要解决的就是这一点。

2017 年的结果：效果更好，训练更省

在当时的机器翻译任务上，Transformer 的翻译质量超过了以前的模型，训练花的计算量还更少。

{{fig 62 | 论文的表 2。BLEU 是衡量翻译质量的分数，越高越好。Training Cost 是训练用掉的浮点运算次数，越少越省。红框里是 Transformer 的两个版本。图片来源：Vaswani 等，2017。}}

基础版在 8 块 NVIDIA P100 GPU 上训练了 12 小时，大号版训练了 3.5 天。大号版用的计算量不到 ConvS2S 集成英译德那一项的三分之一，英译德的 BLEU 高了大约 2 分。

+
当年的「大号」放到今天有多小。论文里叫 big 的那个模型有 2.13 亿个参数。2026 年公开权重的 Kimi K3，技术报告写的是 2.8 万亿个参数，每个 token 实际用到其中的 1040 亿个。按总参数算，相差大约 1.3 万倍。出处：Kimi K3 的技术报告。

这一部分的小结

  • decoder-only Transformer 的流程是：词向量加位置向量，经过 N 个 block，再经过 LM Head 和 softmax，得到每个位置上下一个 token 的概率。
  • 注意力层里，每个 token 产生 query、key、value。query 和前面各个 token 的 key 算出权重，再用权重把 value 加权汇总。
  • 所有位置可以并行算，这让大规模训练成为可能。计算量随长度的平方增长，这让长上下文变贵。
