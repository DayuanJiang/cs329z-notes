先看结论

  • 注意力（attention）是模型里让每个 token 用到前面各个 token 的信息的那一层计算。注意力层为每个 token 算出 query、key、value 三个向量：query 表示它在找什么，key 表示它有什么，value 是别的 token 看它时它交出去的内容。token 是模型处理文字的最小单位，大致是一个词或半个词。
  • 标准的注意力先拿每个 token 的 query 去乘各个 token 的 key，得到一个边长等于 token 个数的方阵，再用这个方阵去乘 value。因为要算这个方阵，计算量随长度的平方增长。标准注意力也叫全局注意力或 softmax 注意力，这一页统一叫标准注意力。
  • 线性注意力换一个相乘的顺序：先把 key 和 value 乘起来，累加成一个固定大小的状态。每来一个 token，只更新这个状态。一次处理一整段文字时，计算量随长度线性增长。逐个生成时，要保存的状态不随长度变大。
  • 代价是整段历史都要存进这个固定大小的状态里。需要从上下文里准确找回某一条信息的任务，它做得比标准注意力差。
  • 注意力的计算本身没有规定上下文最长是多少。实际能用的长度主要受训练限制：超出训练时见过的长度，模型的表现通常明显变差。
  • 两种注意力可以放在同一个模型里混着用：一部分层用线性注意力，另一部分层用标准注意力。已经有大模型这样做，例子是月之暗面的模型 Kimi K3。混用之后，用标准注意力的那些层计算量仍然随长度的平方增长，省下的是其余各层的计算和内存。
  • 选模型时，值得先弄清它用的是哪一种注意力。

换一个相乘的顺序

Transformer 是 2017 年提出的一种模型结构，现在的大语言模型大多用它。第二部分讲了它的注意力公式：softmax(Q × K转置 ÷ √dk) × V。先回顾公式里的几样东西。注意力层为每个 token 算出三个向量：query 表示它在找什么，key 表示它有什么，value 是别的 token 看它时它交出去的内容。Q、K、V 分别是所有 token 的 query、key、value 叠成的矩阵，每个 token 占一行。dk 是 key 的维度，也就是 key 这个向量里有几个数。公式里的「K转置」是把 K 的行和列对调之后的矩阵。

照这个公式，第一步是算 Q 乘 K 的转置，得到一个 n 乘 n 的方阵，n 是 token 的个数。方阵第 i 行第 j 列的数，是第 i 个 token 的 query 和第 j 个 token 的 key 的点积。点积是把两个向量对应位置的数相乘再加起来，得到一个数。这个数叫分数：分数越高，第 i 个 token 从第 j 个 token 那里取的信息越多。平方级的计算量就出在这个方阵上。

第二步是 softmax。softmax 是把一组分数变成加起来等于 1 的一组数的函数，它对方阵的每一行分别做。做完之后，每一行表示一个 token 从它自己和前面各个 token 那里各取多少信息，这组数下面叫注意力比例。第三步是用注意力比例去乘 V。

softmax 夹在中间，这三步只能按这个顺序算：必须先把整个 n 乘 n 的方阵算出来，才能对它的每一行做 softmax，然后才能乘 V。

为了看清线性注意力的思路，下面先假设把 softmax 直接去掉。这是简化的写法：去掉之后，分数不再被变成加起来等于 1 的注意力比例。提出线性注意力的论文实际上是用另一种变换代替 softmax，并且保留了归一化。归一化指把一组数按比例调整，让它们加起来等于 1。具体做法见本节末尾的说明框。

{{fig 67 | 把 softmax 去掉之后，红框里只剩下矩阵相乘。左边三句话的意思依次是：现在这里全是线性的运算，可以改变相乘的结合顺序，改成先乘 K 和 V。「线性的运算」在这里指的就是矩阵相乘。图里只画了一个 token，所以 Q、K、V 各只有一行。}}

去掉 softmax 之后，剩下的是三个矩阵连乘。公式里的「÷ √dk」只是把方阵里的每个数都除以同一个数，不影响相乘的顺序，下面的式子里省略不写。矩阵连乘可以改变结合的顺序，结果不变：

(Q × K转置) × V = Q × (K转置 × V)

在去掉 softmax 的前提下，两种顺序算出的结果一样，差别在中间结果的大小。

第二部分的图里，四个 token 算出来的是 4 乘 4 的方阵。换成线性注意力，中间结果是 3 乘 3，因为图里 key 和 value 的维度画的是 3。再来一千个 token，它还是 3 乘 3。

「结果一样」只在去掉 softmax 之后成立。标准注意力带着 softmax，所以线性注意力算出的结果和标准注意力的结果不同。这个差别带来的代价见后面的「代价」一节。

i
论文里的做法和「直接去掉 softmax」有两处不同。提出线性注意力的论文是 Katharopoulos 等人 2020 年的《Transformers are RNNs》。
  • 用一个变换代替 softmax 里的指数运算。softmax 分两步做：先对每个分数做指数运算，把它变成一个正数，再把每个正数除以这一行的总和。论文换掉的是第一步。它先用一个函数 φ 把 query 和 key 各自变换一下，再用变换后的两个向量的点积当分数。论文用的是 φ(x) = elu(x) + 1。elu 是一个函数：输入是正数时原样输出，是负数时输出一个大于负 1 的负数。所以加 1 之后，结果保证是正数，这样算出的分数也是正数。论文对分数只有一条要求：不能是负数。分数都不是负数，除以总和之后才是一组加起来等于 1 的比例。
  • 保留归一化。按上一条的做法，分数是变换后的 query 和变换后的 key 的点积。一个 token 给它能看到的每个 token 的注意力比例，等于它对这个 token 的分数除以它对各个 token 的分数的总和。线性注意力的输出要除以一个分母，这个分母就是这个总和。除过之后，输出相当于各个 value 按一组加起来等于 1 的比例汇总的结果，这组比例本身用不着单独算出来。这个总和算起来用不到那个 n 乘 n 的方阵：一个 query 和每个 key 的点积加在一起，等于这个 query 和这些 key 的和的点积。所以论文先把这个 token 自己和前面各个 token 变换后的 key 加在一起，记作 Z，分母就是变换后的 query 和 Z 的点积。下一节逐个生成时，Z 要作为第二个状态保存下来。
交换相乘顺序这个核心想法，和上面讲的一样。出处：Katharopoulos 等，2020。

一个不断更新的状态

线性注意力在生成文字时，只需要保存一个固定大小的状态。下面沿用上一节「直接去掉 softmax」的简化写法，状态是一个矩阵，记作 S。

S 就是上一节的 K转置 × V，它可以拆开来算。K 和 V 里每个 token 各占一行，所以 K转置 × V 等于每个 token 各自的 key 和 value 相乘，再把各个 token 的结果加在一起。这样 S 就可以一个 token 一个 token 地累加：每来一个 token，把这个 token 的 key 和 value 相乘的结果加进 S。

一个 token 的 key 和 value 的这种相乘和点积不同：它拿 key 里的每个数分别去乘 value 里的每个数。下面的图里 key 和 value 各有 3 个数，乘出来是 9 个数，排成一个 3 乘 3 的矩阵。

{{fig 72 | 处理第一个 token「The」。它的 key 和 value 按上面的办法相乘，得到 3 乘 3 的状态 S1。它的 query 乘以 S1，得到这一层的输出，再经过 WO 投影和残差连接。WO 是一个权重矩阵，权重是模型里训练出来的那些数，也叫参数。投影指乘上 WO，把结果变回模型的维度，也就是每个 token 的向量里有几个数。残差连接是把这一层的输入直接加到这一层的输出上。}}

处理完第一个 token，Q、K、V 这些中间结果都可以清掉，只留下 S1。下一个 token 来的时候，重复同样的事，只多一步相加。

{{fig 82 | 处理到第四个 token「about」。about 的 key 和 value 相乘，得到一个新的 3 乘 3 矩阵，加到上一步保存的 S3 上，成为 S4。about 的 query 乘以 S4，得到输出。}}

论文的写法还要多保存一个状态 Z，用来算归一化的分母，见上一节末尾的说明框。两个状态的大小都是固定的，所以下面的结论不变。

有三点值得注意。

  • 不需要因果掩码。因果掩码是标准注意力里的一条规定：每个 token 只能看它自己和它前面的 token。这里算第 t 个 token 的时候，状态里只有前 t 个 token 的信息，后面的 token 还没有加进来，效果和加了因果掩码一样。
  • 这就是一个循环神经网络。读一个 token，更新一次状态，再用状态算输出，和第二部分说的循环神经网络是同一种形式。论文标题《Transformers are RNNs》说的就是这件事，RNN 是循环神经网络的英文缩写：带因果掩码的 Transformer 层，可以写成一个「给一个输入，修改内部状态，再给出输出」的模型。用线性注意力时，这个内部状态就是上面大小固定的 S 和 Z。
  • 逐个更新状态是生成时的算法，训练时仍然可以并行。第二部分说循环神经网络必须一个 token 一个 token 地算，后一步要等前一步的状态，不能并行。线性注意力能写成循环神经网络的形式，训练时却没有这个限制。原因在上面的公式里：每个 token 加进状态的那一块，只由它自己的 key 和 value 算出，用不到前面的状态。训练时整段文字都已经给到模型，各个 token 的这一块可以同时算出来。剩下的只是把这些算好的块按顺序加起来，得到每个位置的状态，这一步只有加法。循环神经网络的每一步，要拿上一步的状态和新的 token 一起算，才能得到新的状态，所以各步要算的东西没法提前同时算好。论文的说法是：训练时计算可以并行，能充分利用 GPU。生成时每预测一个 token 花的时间和内存是固定的。

好处：快，占的内存少

因为不用再算那个 n 乘 n 的方阵，一次处理一整段文字时，线性注意力的时间和内存都随长度线性增长。训练时就是这样一次处理一整段，下图量的也是这种情况。逐个生成时的花费在图后面讲。

{{fig 83 | 两张图的横轴都是序列长度，从 2 的 9 次方到 2 的 16 次方。左图的纵轴是一次前向加反向计算的时间（毫秒）。前向计算是从输入算出输出，反向计算是接着算出梯度，也就是训练时用来更新权重的信号，训练的每一步都要各做一次。右图的纵轴是占用的 GPU 内存（MB）。两个纵轴都是对数刻度，也就是每往上一格，数值乘以同一个倍数。黑线是线性注意力，红色虚线是标准的 softmax 注意力，蓝色的三条是另一种省计算的方法 Reformer。图片来源：Katharopoulos 等，2020。}}

图里的红线只画到 2 的 12 次方，也就是长度 4,096。原因写在论文里：实验用的是一块有 11 GB 内存的 GPU（GTX 1080 Ti），每种方法都测到 GPU 内存放不下为止。标准注意力放得下的最长长度是 4,096，再长就放不下了。从图上看，线性注意力一直画到了 65,536。

生成的时候好处更大。标准注意力每生成一个 token，都要拿这个 token 的 query 和前面所有 token 的 key、value 算一次注意力，所以这些 key 和 value 得一直存着（见第五部分的 KV cache）。线性注意力只需要保存固定大小的状态，论文的写法里是 S 和 Z 两个。

论文摘要里说，在很长的序列上做逐个生成时，线性注意力的速度最多是标准注意力的 4000 倍。这个数来自逐个像素生成图片的实验，比的是每秒能生成多少张图片：线性注意力每秒生成 17.85 张，标准注意力每秒生成 0.004 张，论文的表里写的倍数是 4,462。

代价：从长上下文里找回信息更难

把整段历史存进一个固定大小的状态，一定会丢信息。受影响最明显的，是需要从上下文里原样找回某条信息的任务。

{{fig 84 | 左边的表是 RULER 基准测试里三种「找数字」的任务。右边的图比较了三个模型在不同长度下的准确率：Llama2-7B（标准注意力的 Transformer，图例里写作 Llama2-7b）、RWKV-v5-7b 和 Mamba-2.8b-slimpj。虚线表示这个长度超出了模型训练时的长度。图片来源：Hsieh 等，2024。}}

左边表里的三种任务都叫 needle in a haystack，字面意思是在草堆里找一根针。最基本的一种是：在一篇很长的文章中间插一句「和 long-context 这个词对应的数字是 12345」，后面接着是更多的文章，最后问「前面提到的和 long-context 对应的数字是多少」。题目的英文原文把这个数叫作 special magic number，意思是「特别的神奇数字」。

另外两种在这个基础上加难度。一种多插几句对应别的词的数字当干扰，只问其中一个词对应的数字。另一种给同一个词插入好几个数字，要求全部找出来。

可以这样理解两种结构的差别。标准注意力的模型在被问到的时候，前面每个 token 的 key 和 value 都还留着，可以重新去读整段上下文，找到那句话。线性注意力的模型能读的只有状态，前面各个 token 的 key 和 value 都已经清掉，没法重新去读。它必须在读到那句话的时候就把数字记进状态里，并且在后面读几千个无关的 token 的过程中一直把它保留在状态里。

右边的图里，RWKV 和 Mamba 都用固定大小的状态记住读过的内容。RULER 论文对这张图的结论有两句，说的都是 RWKV 和 Mamba 这两个非 Transformer 的模型：在 4K 以内，它们都明显落后于 Llama2-7B；上下文扩展到 8K 时，它们自己的成绩也大幅下降。4K 和 8K 是上下文的长度，单位是 token，K 表示一千。

论文没有列出这两个模型的具体数字，下面 RWKV 和 Mamba 的数是从图上读出来的近似值，见资料说明。4K 时，Llama2-7B 是 85.6%，RWKV 大约是 50%，Mamba 不到 20%。到 8K 时，RWKV 降到 10% 出头，Mamba 接近 0。

上下文长度的上限是从哪里来的

不管是标准注意力还是线性注意力，注意力的计算本身都没有哪一处规定「最多只能处理多少个 token」。注意力的方阵可以任意大，线性注意力的状态可以一直更新下去。一次能放进模型的 token 数的上限叫上下文窗口，这一节讲这个上限是从哪里来的。

限制来自两处。第一处是位置信息的给法。第二部分讲过，注意力的计算只看两个 token 的内容有多相关，结构本身不知道哪个 token 在前、哪个在后。所以模型要给每个 token 的向量加上一个位置向量，也就是表示它排在第几个的一组数。

位置向量有两种给法。一种是一张按位置查的表，表有多少行，模型最多就能处理多少个位置。OpenAI 的模型 GPT-2 沿用上一代 GPT 的做法，用的就是这样一张训练出来的表，上下文窗口是 1,024 个 token。另一种是用公式算出来，这样的模型没有这个硬上限。提出 Transformer 的那篇 2017 年的论文《Attention Is All You Need》用的是公式，它选公式的一个理由，就是公式也许能让模型处理比训练时更长的序列。

第二处是训练时见过的长度，不管位置向量是哪种给法，它都起作用。怎样使用位置的信息是训练出来的，训练时最长只见过 4,096 个 token 的模型，没有学过第 5,000 个位置该怎么处理。所以实际能用的上下文长度，主要受训练时用过的长度限制。不用位置向量的模型也受这个限制，原因见本节末尾的说明框。

上一节图里 Llama2-7B 在 8K 处的那段虚线是一个例子。RULER 论文的表里写着 Llama2-7B 的上下文窗口是 4K，8K 超出了它训练时的长度，从图上看准确率掉到接近 0。RULER 的论文对此的说法是，Llama2 用在比训练时更长的序列上时表现很差。

实际的做法：两种混着用

线性注意力省计算，标准注意力更能从长上下文里找回信息。自然的做法是把两种混在一个模型里：一部分层用线性注意力，另一部分层用标准注意力或它的省计算的变体。下图是两种混合的办法。

{{fig 88 | 两种混合的办法，例子里的线性注意力层是 DeltaNet。左：DeltaNet 层和滑动窗口注意力层（SWA）一层隔一层地放，旁边的小方格图表示每个 token 只看它自己和它前面相邻的几个 token。右：大部分是 DeltaNet 层，中间插两层标准注意力，图里写作 Global Attention，旁边的小方格图表示每个 token 能看它自己和前面所有的 token。图片来源：Songlin Yang 的文章。}}

DeltaNet 是线性注意力的一个改进版，改的是状态的更新规则。前面讲的线性注意力只往状态里加新内容，旧的内容去不掉。DeltaNet 每来一个 token，分三步更新状态。第一步，拿这个 token 的 key 去乘状态，得到状态里原来和这个 key 存在一起的 value。这一步的算法和前面拿 query 去乘状态得到输出相同，只是把 query 换成了 key。第二步，把这份旧的 value 按一个比例从状态里去掉。第三步，按同样的比例把这个 token 的 value 写进状态。这个比例在 0 和 1 之间，由模型根据当前这个 token 算出来：比例是 1 时，旧的 value 被完全换成新的。比例是 0 时，状态不变。出处：Yang 等，2024。

滑动窗口注意力是标准注意力的一种省计算的变体：每个 token 只看它自己和紧挨在它前面的固定个数的 token。

下面的图是三个模型的成绩：全部用线性注意力的 DeltaNet，和上面两种混合模型。图后面的表多列了一行全部用标准注意力的 Transformer++，作为参照。

{{fig 89 | 三个模型的成绩，从上到下是 DeltaNet、DeltaNet 加滑动窗口注意力、DeltaNet 加两层标准注意力。Wiki. ppl 是在维基百科文字上的困惑度（衡量模型预测下一个 token 时有多拿不准的指标），越低越好。Avg. Common-sense 是几个常识类任务的平均准确率，Avg. Retrieval 是几个从上下文里抽取信息的任务的平均准确率，都是越高越好。图片来源：同上。}}

这张表分两类任务来读。

  • 常识类任务不受影响。三种 DeltaNet 的模型在这类任务上的平均准确率都是 42.1%。这类题问的是很简单的问题，不需要到上下文里去找回信息。
  • 抽取信息类任务差别很大。纯线性注意力的 DeltaNet 的平均准确率是 22.7%，比全用标准注意力的 Transformer++ 低 5.9 个百分点。加上滑动窗口注意力到 30.2%，加上两层标准注意力到 32.7%，都超过了 Transformer++ 的 28.6%。混合模型为什么会超过全用标准注意力的模型，这篇文章没有解释。

文章对两种混合办法各有一句评价。滑动窗口那一种的计算量仍然低于平方级，但窗口以外的信息还是只能靠状态。插两层标准注意力那一种，计算量严格说回到了平方级，但因为只有两层要保存 key 和 value，占的内存比全用标准注意力的模型少得多。

也就是说，混进标准注意力层之后，这几层的计算量仍然随长度的平方增长。省下来的是其余各层的计算，其余各层也不用保存 key 和 value。

一个大模型的例子：Kimi K3

Kimi K3 是月之暗面（Moonshot AI）的 Kimi 团队在 2026 年公开权重的模型，公开权重指训练好的模型参数公开发布、可以下载。它的结构图里有三种部件：线性注意力层、标准注意力层和前馈网络。前两种前面几节讲过。前馈网络是对每个 token 的向量单独做一次变换的那一层，每个注意力层后面跟一个，见第二部分。各部件在图里的名字和细节见图后面的表。

{{fig 90 | Kimi K3 的结构图，右边彩色的框和文字是后加的标注。一个大的模块里从下往上画了两对层：下面一对是「线性注意力（图里叫 KDA）加前馈网络」，旁边标着 3×，表示重复三次。上面一对是「标准注意力（图里叫 Gated MLA）加前馈网络」，标着 1×，右边的标注把这一层写作 Multi-Head (Latent) Attention。左边两个虚线框分别是前馈网络和 KDA 的内部结构。图片来源：Kimi K3 的技术报告。}}

整个模型里，每个模块是 3 层 KDA 之后跟 1 层 Gated MLA，线性注意力层和标准注意力层的比例是 3 比 1。一共有 69 层 KDA 和 24 层 Gated MLA。69 层 KDA 对应 23 个模块，每个模块带 1 层 Gated MLA，是 23 层。技术报告说，在叠起来的这 23 个模块之后又额外加了 1 层 Gated MLA，保证最后一层是标准注意力，所以一共是 24 层。

按标准注意力的计算量随长度的平方增长来推，这 24 层 Gated MLA 的计算量仍然随长度的平方增长，随长度线性增长的是那 69 层 KDA。这是一句推论，技术报告没有直接讲，见资料说明。

它的上一代 Kimi K2 用的是 61 层 MLA，也就是上表里 Gated MLA 没有加门的版本。这 61 层全部是标准注意力，没有线性注意力。

Kimi K3 一共有 2.8 万亿个参数。因为上表里的 Stable LatentMoE 让每个 token 只用到一小部分专家，每个 token 实际用到的参数是 1040 亿个。它的上下文窗口是 100 万个 token，上下文窗口就是前面说的一次能放进模型的 token 数的上限。

这些和搭 agent 有什么关系

agent 指能自己调用工具、分很多步去完成一个任务的语言模型系统。它和模型结构的关系有四条。

  • agent 的上下文可以非常长。对话历史、工具的返回结果、读进来的文件，全都在上下文里。
  • 推理的效率是设计 agent 系统时要考虑的一项。推理指使用训练好的模型生成输出。agent 每一步都要调用模型，上下文越长，每一步越贵、越慢。
  • 了解模型的结构，有助于给应用选对模型。要处理很长的上下文、又要从里面准确找回信息的任务，值得先查一下：这个模型用的是线性注意力，还是标准注意力，还是混合的。查的地方是模型的技术报告或模型说明，上一节 Kimi K3 的 3 比 1 就写在它的技术报告里。按前面小模型的成绩，抽取信息类任务上成绩最低的是全部用线性注意力的模型，两种混合模型的成绩都不低于全部用标准注意力的模型。
  • 围绕具体模型的长处和短处来设计运行框架。运行框架（harness，也叫 scaffold）是包在模型外面、给它工具并管理多轮对话的程序。知道模型在哪里弱，就知道运行框架要在哪些地方替模型多做一些事。例如模型不擅长从很长的上下文里找回信息，运行框架就少往上下文里放东西，用检索只挑最相关的内容放进去。这样做有没有效果，要用实验来验证。这几条做法见第八部分。

这一部分的小结

  • 线性注意力维护一个固定大小、不断更新的状态，标准注意力里那个随长度变大的方阵就用不着计算了。生成时，这个状态代替了标准注意力要保存的 KV cache，也就是前面所有 token 的 key 和 value。
  • 它快而且省内存，但从长上下文里找回信息的能力弱一些。
  • 上下文长度的上限也叫上下文窗口，它主要由训练时见过的长度决定，所以训练时要专门安排一段，用长文档把序列加长。位置向量是一张按位置查的表时，表的行数是另一个上限。
  • 两种注意力可以混在一个模型里用，已经有大模型这样做。例子是 Kimi K3，它的线性注意力层和标准注意力层的比例是 3 比 1。
