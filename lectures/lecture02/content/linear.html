先看结论

  • 标准的注意力（attention）要算一个边长等于 token 个数的方阵，计算量随长度的平方增长。标准注意力也叫全局注意力或 softmax 注意力，这一页统一叫标准注意力。token 是模型处理文字的最小单位，大致是一个词或半个词。
  • 线性注意力换一个相乘的顺序：先把 key 和 value 乘起来，累加成一个固定大小的状态。每来一个 token，只更新这个状态。计算量随长度线性增长，生成时占的内存不随长度增长。
  • 代价是整段历史都要存进这个固定大小的状态里。需要从很长的上下文里准确找回某一条信息的任务，它做得比标准注意力差。
  • 注意力的计算本身没有规定上下文最长是多少。实际能用的长度主要受训练限制：超出训练时见过的长度，模型的表现通常明显变差。
  • 现在的做法是混着用：大部分层用线性注意力，隔几层放一层标准注意力。选模型时，值得先弄清它用的是哪一种。

换一个相乘的顺序

第二部分的注意力公式是 softmax(Q × K转置 ÷ √dk) × V。先回顾公式里的几样东西。注意力层为每个 token 算出三个向量：query 表示它在找什么，key 表示它有什么，value 表示它能提供什么。Q、K、V 分别是所有 token 的 query、key、value 叠成的矩阵，dk 是 key 的维度。公式里的「K转置」是把 K 的行和列对调之后的矩阵。softmax 是把一组分数变成加起来等于 1 的权重的函数。

照这个公式，要先算 Q 乘 K 的转置，得到一个 n 乘 n 的方阵，n 是 token 的个数。平方级的计算量就出在这个方阵上。softmax 夹在中间，三个矩阵只能按这个顺序算。

为了看清线性注意力的思路，下面先假设把 softmax 直接去掉。这是简化的写法：去掉之后，分数不再被变成加起来等于 1 的权重。提出线性注意力的论文实际上是用另一种变换代替 softmax，并且保留了归一化，具体做法见本节末尾的说明框。

{{fig 67 | 把 softmax 去掉之后，红框里只剩下矩阵相乘。左边三句话的意思依次是：现在这里全是线性的运算，可以改变相乘的结合顺序，改成先乘 K 和 V。图里只画了一个 token，所以 Q、K、V 各只有一行。}}

去掉 softmax 之后，剩下的是三个矩阵连乘。矩阵连乘可以改变结合的顺序，结果不变：

(Q × K转置) × V = Q × (K转置 × V)

两种顺序算出的结果一样，差别在中间结果的大小。

第二部分的图里，四个 token 算出来的是 4 乘 4 的方阵。换成线性注意力，中间结果是 3 乘 3，因为图里 key 和 value 的维度画的是 3。再来一千个 token，它还是 3 乘 3。

i
论文里的做法和「直接去掉 softmax」有两处不同。提出线性注意力的论文是 Katharopoulos 等人 2020 年的《Transformers are RNNs》。
  • 用一个变换代替 softmax 里的指数运算。它先用一个函数 φ 把 query 和 key 各自变换一下，再用变换后的两个向量的点积当分数。点积是把两个向量对应位置的数相乘再加起来，得到一个数。论文用的是 φ(x) = elu(x) + 1。elu 是一个函数：输入是正数时原样输出，是负数时输出一个大于负 1 的负数。所以加 1 之后，结果保证是正数。
  • 保留归一化。输出要除以一个分母，让每个 token 分出去的权重加起来仍然等于 1。这个分母是 query 和 Z 的点积，Z 是前面各个 token 变换后的 key 加在一起的结果。下一节逐个生成时，Z 要作为第二个状态保存下来。
交换相乘顺序这个核心想法，和上面讲的一样。出处：Katharopoulos 等，2020。

一个不断更新的状态

线性注意力在生成文字时，只需要保存一个固定大小的状态。下面沿用上一节「直接去掉 softmax」的简化写法，状态是一个矩阵，记作 S。每来一个 token，就把这个 token 的信息加进 S。

{{fig 72 | 处理第一个 token「The」。它的 key 和 value 相乘，得到 3 乘 3 的状态 S1。它的 query 乘以 S1，得到这一层的输出，再经过 WO 投影和残差连接。}}

处理完第一个 token，Q、K、V 这些中间结果都可以清掉，只留下 S1。下一个 token 来的时候，重复同样的事，只多一步相加。

{{fig 82 | 处理到第四个 token「about」。about 的 key 和 value 相乘，得到一个新的 3 乘 3 矩阵，加到上一步保存的 S3 上，成为 S4。about 的 query 乘以 S4，得到输出。}}

论文的写法还要多保存一个状态 Z，用来算归一化的分母，见上一节末尾的说明框。两个状态的大小都是固定的，所以下面的结论不变。

有三点值得注意。

  • 不需要因果掩码。因果掩码是标准注意力里的一条规定：每个 token 只能看它前面的 token。这里算第 t 个 token 的时候，状态里只有前 t 个 token 的信息，后面的 token 还没有加进来，效果和加了因果掩码一样。
  • 这就是一个循环神经网络。读一个 token，更新一次状态，再用状态算输出，和第二部分说的循环神经网络是同一种形式。论文标题《Transformers are RNNs》说的就是这件事：带因果掩码的 Transformer 层，可以写成一个「给一个输入，修改内部状态，再给出输出」的模型。用线性注意力时，这个内部状态就是上面大小固定的 S 和 Z。
  • 逐个更新状态是生成时的算法，训练时仍然可以并行。第二部分说循环神经网络必须一个 token 一个 token 地算，不能并行。线性注意力没有这个限制。论文的说法是：训练时整段文字都在手里，计算可以并行，能充分利用 GPU。生成时每预测一个 token 花的时间和内存是固定的。

好处：快，占的内存少

因为不用再算那个 n 乘 n 的方阵，线性注意力的时间和内存都随长度线性增长。

{{fig 83 | 两张图的横轴都是序列长度，从 2 的 9 次方到 2 的 16 次方。左图的纵轴是一次前向加反向计算的时间（毫秒）。前向计算是从输入算出输出，反向计算是接着算出梯度，也就是训练时用来更新权重的信号，训练的每一步都要各做一次。右图的纵轴是占用的 GPU 内存（MB）。两个纵轴都是对数刻度。黑线是线性注意力，红色虚线是标准的 softmax 注意力，蓝色的三条是另一种省计算的方法 Reformer。图片来源：Katharopoulos 等，2020。}}

图里的红线只画到 2 的 12 次方，也就是长度 4,096。原因写在论文里：实验用的是一块 11 GB 显存的 GTX 1080 Ti，每种方法都测到显存放不下为止，标准注意力到 4,096 就放不下了。从图上看，线性注意力一直画到了 65,536。

生成的时候好处更大。标准注意力每生成一个 token，都要回头和前面所有 token 的 key、value 算一遍，这些 key 和 value 还得一直存着（见第五部分的 KV cache）。线性注意力只存一个 S。论文摘要里说，在很长的序列上做逐个生成时，线性注意力的速度最多是标准注意力的 4000 倍。这个数来自逐个像素生成图片的实验。

代价：长上下文里找东西更难

把整段历史存进一个固定大小的矩阵，一定会丢信息。丢得最明显的，是需要从上下文里原样找回某条信息的任务。

{{fig 84 | 左边的表是 RULER 基准测试里三种「找数字」的任务。右边的图比较了三个模型在不同长度下的准确率：Llama2-7b（标准注意力的 Transformer）、RWKV-v5-7b 和 Mamba-2.8b-slimpj。虚线表示这个长度超出了模型训练时的长度。图片来源：Hsieh 等，2024。}}

左边表里的任务叫 needle in a haystack：在一篇很长的文章中间插一句「长上下文的特殊魔法数字是 12345」，后面接着是更多的文章，最后问「刚才提到的特殊魔法数字是多少」。

可以这样理解两种结构的差别。标准注意力的模型在被问到的时候，可以回头去看整段上下文，找到那句话。线性注意力的模型没有回头看的机会。它必须在读到那句话的时候就把数字记进状态里，并且在后面读几千个无关的 token 的过程中一直把它保留在状态里。

右边的图里，RWKV 和 Mamba 都用固定大小的状态记住读过的内容。RULER 论文对这张图的结论是：这两个非 Transformer 的模型在 4K 以内都明显落后于 Llama2-7B，扩展到 8K 时成绩大幅下降。

这张图能说明的只到这一步：这两个模型在这个基准测试上落后。三个模型之间除了注意力的种类还有别的差别，纵轴也不只是找数字的任务，见下面的说明框。更直接的对照在后面「实际的做法：两种混着用」一节的表里。那张表里的几个模型大小相同，训练用的 token 数也相同。在抽取信息类任务上，全部用线性注意力的 DeltaNet 的平均准确率是 22.7%，全部用标准注意力的 Transformer++ 是 28.6%。

i
读这张图有三点要注意。
  • Mamba 用的是另一种结构。RWKV 的论文说自己用了一种线性注意力。Mamba 是状态空间模型，它的论文明确说结构里没有注意力。两者和线性注意力的共同点是：都用一个固定大小的状态来记住读过的内容。RULER 的论文把它们统称为「非 Transformer 结构」。
  • 纵轴是 RULER 全部 13 个任务的平均准确率。找数字只是其中一类，另外还有多步追踪、汇总和问答。
  • 三个模型的大小和训练数据都不同。Mamba 只有 28 亿个参数，另外两个是 70 亿。
出处：RULER；RWKV；Mamba。

图里还有一个细节：Llama2-7b 那条线在 4K 时是 85.6%，到 8K 时从图上看掉到了接近 0。这和注意力的种类无关，下一节讲原因。

上下文长度的上限是从哪里来的

不管是标准注意力还是线性注意力，注意力的计算本身都没有哪一处规定「最多只能处理多少个 token」。注意力的方阵可以任意大，线性注意力的状态可以一直更新下去。

限制来自两处。第一处是位置信息的给法（见第二部分）。如果位置向量是一张按位置查的表，表有多少行，模型最多就能处理多少个位置。GPT-2 沿用上一代 GPT 的做法，用的就是这样一张训练出来的表，上下文是 1,024 个 token。用公式算位置向量的模型没有这个硬上限，2017 年的论文选公式的一个理由，就是它也许能让模型处理比训练时更长的序列。

第二处是训练时见过的长度，不管位置向量是哪种给法，它都起作用。怎样使用位置的信息是训练出来的，训练时最长只见过 4,096 个 token 的模型，没有学过第 5,000 个位置该怎么处理。所以实际能用的上下文长度，主要受训练时用过的长度限制。

上一节图里 Llama2-7b 在 8K 处的那段虚线是一个例子：它超出了训练时的长度，从图上看准确率掉到接近 0。RULER 的论文对此的说法是，Llama2 外推到更长序列时表现很差。

+
出处。GPT 和 GPT-2 的位置表和上下文长度见 Radford 等，2018 和 Radford 等，2019。选公式的理由见 Vaswani 等，2017。Llama2 外推的表现见 RULER。

训练时怎样把长度加上去

长的序列训练起来很贵，所以通常先用短的序列训练大部分时间，再专门用长文档把长度加上去。这一步叫长上下文扩展。

+
不用位置向量的模型也要做这一步。Kimi K3 的技术报告说，它没有显式的位置向量，位置的信息由线性注意力层里的门控和衰减机制隐含地带出来，所以不需要为了更长的上下文去改位置向量。门控和衰减机制指的是：每读一个 token，状态里旧的内容只保留一部分，保留多少由一个算出来的「门」决定。但它仍然分阶段把训练的长度加到 100 万，并且专门准备了长文档的数据。可以这样理解：训练时见过多长的序列，本身就是一个独立的限制。出处：Kimi K3 的技术报告。

两种注意力放在一起比

前面几节的结论放在一张表里，是下面这样。

实际的做法：两种混着用

线性注意力省计算，标准注意力更能从长上下文里找回信息。自然的做法是把两种混在一个模型里：大部分层用线性注意力，少数几层用标准注意力。

{{fig 88 | 两种混合的办法，例子里的线性注意力层是 DeltaNet。左：DeltaNet 层和滑动窗口注意力层（SWA）一层隔一层地放，旁边的小方格图表示每个 token 只看它前面相邻的几个 token。右：大部分是 DeltaNet 层，中间插两层标准注意力，图里写作 Global Attention，旁边的小方格图表示每个 token 能看前面所有的 token。图片来源：Songlin Yang 的文章。}}

DeltaNet 是线性注意力的一个改进版，改的是状态的更新规则。滑动窗口注意力是标准注意力的一种省计算的变体：每个 token 只看前面固定个数的 token。下面是这两种混合模型的成绩。

{{fig 89 | 三个模型的成绩。Wiki. ppl 是在维基百科文字上的困惑度（衡量模型预测下一个 token 时有多拿不准的指标），越低越好。Avg. Common-sense 是几个常识类任务的平均准确率，Avg. Retrieval 是几个从上下文里抽取信息的任务的平均准确率，都是越高越好。图片来源：同上。}}

怎么读这张表：

  • 常识类任务不受影响。三种 DeltaNet 的模型都是 42.1。这类题问的是很简单的问题，不需要回头去上下文里找东西。
  • 抽取信息类任务差别很大。纯线性注意力的 DeltaNet 是 22.7，比全用标准注意力的 Transformer++ 低 5.9 个百分点。加上滑动窗口注意力到 30.2，加上两层标准注意力到 32.7，都超过了 Transformer++ 的 28.6。混合模型为什么会超过全用标准注意力的模型，这篇文章没有解释。

文章对两种混合办法各有一句评价。滑动窗口那一种的计算量仍然低于平方级，但窗口以外的信息还是只能靠状态。插两层标准注意力那一种，计算量严格说回到了平方级，但因为只有两层要保存 key 和 value，占的内存比全用标准注意力的模型少得多。

一个大模型的例子：Kimi K3

Kimi K3 是月之暗面（Moonshot AI）的 Kimi 团队在 2026 年公开权重的模型。看过前面的内容，它的结构图里的线性注意力层、标准注意力层和前馈网络都能认出来。各部件在图里的名字和细节见图后面的表。

{{fig 90 | Kimi K3 的结构图，右边彩色的框和文字是后加的标注。一个大的模块里从下往上画了两对层：下面一对是「线性注意力（图里叫 KDA）加前馈网络」，旁边标着 3×，表示重复三次。上面一对是「多头注意力（图里叫 Gated MLA）加前馈网络」，标着 1×。左边两个虚线框分别是前馈网络和 KDA 的内部结构。图片来源：Kimi K3 的技术报告。}}

整个模型里，每个模块是 3 层 KDA 之后跟 1 层 Gated MLA，线性注意力层和标准注意力层的比例是 3 比 1。一共有 69 层 KDA 和 24 层 Gated MLA。69 层 KDA 对应 23 个模块，每个模块带 1 层 Gated MLA，是 23 层。技术报告说在主干的末尾又额外加了 1 层，保证最后一层是标准注意力，所以一共是 24 层。

它的上一代 Kimi K2 用的是 61 层 MLA，全部是标准注意力，没有线性注意力。

Kimi K3 一共有 2.8 万亿个参数。因为上表里的 Stable LatentMoE 让每个 token 只走一小部分专家，每个 token 实际用到的参数是 1040 亿个。它的上下文窗口（一次能放进模型的 token 数的上限）是 100 万个 token。

这些和搭 agent 有什么关系

agent 指能自己调用工具、分很多步去完成一个任务的语言模型系统。它和模型结构的关系有四条。

  • agent 的上下文可以非常长。对话历史、工具的返回结果、读进来的文件，全都在上下文里。
  • 推理的效率是设计 agent 系统时要考虑的一项。每一步都要调用模型，上下文越长，每一步越贵、越慢。
  • 了解模型的结构，有助于给应用选对模型。要处理很长的上下文、又要从里面准确找回信息的任务，值得先查一下：这个模型用的是线性注意力，还是标准注意力，还是混合的。查的地方是模型的技术报告或模型说明，上一节 Kimi K3 的 3 比 1 就写在它的技术报告里。按前面小模型的成绩，在抽取信息上吃亏的是全部用线性注意力的模型，两种混合模型的成绩都不低于全部用标准注意力的模型。
  • 围绕具体模型的长处和短处来设计运行框架。运行框架（harness，也叫 scaffold）是包在模型外面、给它工具并管理多轮对话的程序。知道模型在哪里弱，就知道运行框架该在哪里补。例如模型不擅长从很长的上下文里找回信息，运行框架就少往上下文里放东西，用检索只挑最相关的内容放进去。补得有没有效果，要用实验来验证。这几条做法见第八部分。

这一部分的小结

  • 线性注意力用一个固定大小、不断更新的状态，代替标准注意力里那个随长度变大的方阵。
  • 它快而且省内存，但从长上下文里找回信息的能力弱一些。
  • 上下文长度的上限来自训练时见过的长度，训练时要专门把它加上去。
  • 大模型已经在混用两种注意力，Kimi K3 的比例是 3 比 1。
