先看结论

  • 训练语言模型的损失函数是交叉熵：模型给真实的下一个 token 的概率越高，损失越低。token 是模型处理文字的最小单位，大致是一个词或半个词。
  • 预训练（pretraining）的数据主要来自网页。原始网页要经过抽取文字、识别语言、规则过滤、质量过滤和去重，留下来的只是很小的一部分。DCLM 的流程最后只留下了 1.4% 的文档。
  • 各种来源的数据按什么比例混在一起，是可以学出来的。预训练之后、后训练之前，把配比调向目标领域再训练一段，叫中期训练（midtraining）。
  • 后训练（post-training）用的是精心挑选的数据：示范怎样按指令回答，让模型学人的偏好，或者让模型去做能自动判对错的任务。
  • 要让模型会做 agent 的工作，还要专门造出大量带运行环境的任务让它练。

损失函数：给真实的下一个 token 多高的概率

训练任何神经网络都要先定一个损失函数。它衡量模型离目标有多远，训练就是不断调整权重，让损失变小。语言模型的训练数据就是一段段文字，例如：

「The class was about how agents work, and how to build AI systems that use tools, retrieve information, and carry out tasks across multiple steps…」

把前四个 token「The class was about」送进模型，模型给出下一个 token 的概率分布（就是第一部分里那张表）。训练数据里真实的下一个 token 是 how，模型给它的概率是 0.0124。损失就是这个概率的对数取负号。

{{fig 100 | 交叉熵损失的公式。红框：对词表里的每个 token 求和，V 是词表的大小。蓝框 y：这个 token 是训练数据里真实的下一个 token 时取 1，其余取 0。绿框：模型给这个 token 的概率取对数。}}

公式写出来是 L = −（y1 × log p1 + y2 × log p2 + … + yV × log pV）。因为 y 只在真实的那个 token 上是 1，其余全是 0，整个求和只剩下一项：损失等于负的「log（模型给真实 token 的概率）」。下表用几个概率算出对应的损失。

一段文字里每个位置都能这样算一次损失。第二部分讲过，模型过一遍就同时给出所有位置的预测，所以一段几千个 token 的文字，一次就提供几千个训练信号。

i
同一个概率，对数的底不同，损失的数值不同。0.0124 这个概率，用以 10 为底的对数算，损失是 1.907，用自然对数算是 4.39。训练程序里通常用自然对数。两种算法只差一个固定的倍数（约 2.3 倍），所以哪一组权重让损失最低，两种算法的答案相同。梯度是训练时用来更新权重的信号，它的大小也跟着差这个倍数。比较不同来源的损失数值时，要先确认用的是哪一种。出处：PyTorch 的 log 函数说明。

预训练的数据：从网页到训练集

预训练是训练的第一个、也是最大的阶段：让模型在海量的文字上学会预测下一个 token。这些文字大部分来自对互联网的抓取，原始的形式是 HTML 文件。

一个公开的例子：DCLM

DCLM（DataComp-LM）是一个公开的数据集和基准测试。它提供了从 Common Crawl（一个公开的网页抓取库）里抽出来的 240 万亿个 token 的原始文字，让参加的人比谁能从里面挑出最好的训练集。它自己给出的基线训练集，是按下图的流程筛出来的。

{{fig 103 | DCLM 基线训练集的筛选流程。从左到右，色带越来越窄，表示留下的文档越来越少。灰色的块是每一步去掉的部分，上面的百分比是它占原始文档总数的比例。图片来源：Li 等，2024。}}

最后留下的只有 1.4% 的文档，大约 3.8 万亿个 token。

最后一步的 fastText 是一个很轻的文本分类器。论文试了很多种质量过滤的办法，效果最好的是训练它去区分两类文字：一类是指令格式的优质数据和 Reddit 上 ExplainLikeImFive 版块的高分帖子，另一类是随机抽的普通网页。

这个训练集的效果，论文用一个从头训练的模型来检验。模型有 70 亿个参数，用了 2.6 万亿个训练 token，在 MMLU（一个覆盖 57 个学科的选择题基准测试）上给 5 个例子时的准确率是 64%。论文拿两个大小相近的模型作对照：同一个测试上，Mistral-7B-v0.3 是 63%，Llama 3 8B 是 66%。

+
偏数学的数据集，流程差不多，工具要换。NVIDIA 的 Nemotron-CC-Math 是一个偏数学的数据集。它总的顺序和上面一样：拿到原始数据、过滤、变成文字、去重。换掉的是抽取文字的工具：它没有用 Resiliparse 或 Trafilatura，改用文本浏览器 Lynx 来渲染网页，因为这样能更好地保留公式，之后再用一个语言模型做清理。规模上，它从 98 份 Common Crawl 的快照里找出 2.2954 亿个数学网页，最后得到 1.0115 亿篇文档、1332.6 亿个 token。这些网页是按网址挑出来的，内容并不都以数学为主题：论文随机抽了 15 万篇文档按主题分类，主题是数学的占 60.28%，其余的大多归在计算机科学、物理、统计等学科下。出处：Nemotron-CC-Math 的论文。

配比是可以学出来的

有了很多种来源，下一个问题是各取多少。比如 30% 来自网页、20% 来自 GitHub。一种一种去试的成本太高，因为每试一种配比就要完整训练一个模型。下图的办法分三步。

{{fig 107 | 学配比的三步。1：准备很多种配比，每种配比训练一个小的代理模型，记下它的成绩。2：拟合一个回归模型，输入是配比，输出是预测的成绩。3：在允许的配比范围里，找出预测成绩最好的那一种。图片来源：Olmix 的论文。}}

这张图来自 Allen Institute for AI 等机构 2026 年的 Olmix，它是为预训练 Olmo 3 模型开发的。论文里和实际操作有关的发现有三条。

  • 代理模型要有 1500 万个以上的参数，排出的名次才可靠。
  • 需要训练的代理模型个数，和数据来源的个数成正比。
  • 数据来源在开发过程中会不断增减，这时可以沿用旧的配比，只重算受影响的那几项。在连续五次调整数据来源的实验里，这样做比每次全部重算少用 74% 的计算量。

中期训练：把配比调向目标领域

中期训练是夹在预训练和后训练之间的一段：继续用大量数据做同样的下一个 token 预测，但把配比调向数学、代码这类目标领域，同时仍然混着一般的数据。

它也常被叫作冷却阶段（cooldown），下面 Marin 的例子用的就是这个名字。

预训练、中期训练、后训练三个阶段之间没有严格的界线。从一个阶段到下一个阶段，改动的主要是数据的分布，有时也会调学习率，也就是每一步把权重改动多大的系数。一种通俗的区分是看对数据有多了解。

一个正在公开训练的例子：Marin

Marin 是一个把训练全过程公开出来的语言模型项目。它最近一次大规模训练用的原始数据是 187.1 亿篇文档、25.25 万亿个 token（按 Llama 3 的分词器计）。去重和清理之后，每篇文档按 40 个主题和 5 个质量档分进 200 个桶。

每个桶在训练数据里占的比例，下面叫这个桶的占比，用上一节学配比的办法来定：做了 1000 多次小规模的代理训练，拟合一个从各个桶的占比预测成绩的回归。这些实验把预训练阶段和冷却阶段分开来看。下面这张图出自这批实验。

{{fig 109 | Marin 的一张热力图。每一行是一个主题，每一列是一个质量档（Q0 到 Q4），左半是预训练阶段，右半是冷却阶段。格子的颜色表示这个桶的占比和模型成绩之间的相关系数。图片来源：Open Athena 的文章。}}

这张图画的是相关系数。按原文对这张图的说明，它用的是 872 次代理训练的结果，这个次数和前面「1000 多次」的关系见资料说明。对每个桶，算它的占比和模型成绩之间的 Spearman 相关系数（按排名算的相关系数），预训练和冷却分开算。蓝色表示这个桶的占比越高，成绩越好。红色表示占比越高，成绩越差。灰色表示这个桶的占比在这批实验里没有变过。

成绩用的是 UncheatableEval 这个评测的一个子集上的 BPB（bits per byte）。它是把模型在评测文字上的交叉熵损失换算成比特、再按这些文字的字节数取平均得到的数。模型给评测文字里真实的下一个 token 的概率越高，损失越低，BPB 也越低，所以 BPB 越低越好。

读这张图要看颜色的方向。例如冷却阶段 Business Software and Strategy（商业软件和战略）这一行最右边 Q4 的格子是深蓝色，意思是在这批实验里，这个桶的占比越高，成绩越好。同一个桶在左右两半的颜色可以不同，也就是它和成绩的关系在两个阶段不一样。

i
这张图容易被读成两个阶段各自的配比。单看图，很容易以为格子颜色越深，这个桶在这个阶段的占比越高，比如读成「冷却阶段把商业软件这一行的占比调高了」。图里的颜色只表示占比和成绩一起变化的方向，从图上看不出每个桶实际的占比是多少。原文还提醒：所有桶的占比加起来等于 1，一个桶多了别的桶就少，所以这些相关性不能当作每个桶单独的效果。出处：Open Athena，2026 年 9 月。

把目标领域的数据提前混进去有用吗

中期训练是在预训练之后才把配比调向目标领域。DatologyAI 团队 2026 年的论文《The Finetuner's Fallacy》研究的是更早的做法：把一小份本来留着做微调（fine-tuning，用自己的数据接着训练模型）的领域数据，从预训练开始就混进去，反复出现。

{{fig 110 | 左：做法的示意，大块是一般的数据，下面一排蓝色小块是同一份领域数据重复出现 10 到 50 遍。右：之后做微调时两种损失的变化，横轴是微调的步数。蓝线是领域测试集上的损失（左轴），橙线是一般数据上的损失（右轴），都是越低越好。实线是提前混入了领域数据的模型，虚线是只用一般数据预训练的模型。图片来源：DatologyAI，2026。}}

实验里，每个领域的数据大约是 3 亿个 token，预训练一共 2000 亿个 token。领域数据占 5% 时，相当于把它重复了大约 33 遍。结果有两条。第一，之后做微调时，领域测试集上的损失更低。第二，一般数据上的损失涨得更慢，也就是忘掉的一般知识更少。

这种做法的效果可以超过把模型做大。在离网页文字很远的领域上，10 亿参数的模型用这种做法，微调之后领域测试集上的损失，比 30 亿参数、按常规方式预训练的模型还低。

论文标题里的 finetuner's fallacy 指的是一种容易有的错觉：微调看上去是让模型适应一个领域最省的办法。论文的结论是，把领域数据尽早放进训练，同一份数据能起更大的作用。

{{fig 111 | 一张示意图。平面上的每个点代表模型的一组权重，图上标出了三组：预训练结束时的权重、中期训练之后的权重、后训练要达到的目标权重。训练会一步步改动权重，所以一次训练在图上是一条从一个点走到另一个点的线。底色表示权重在这一处时，预训练目标和后训练目标的梯度方向（训练时更新权重的方向）有多一致：蓝色表示一致，红色表示冲突大。红色虚线是从预训练的权重直接做微调到目标，中途要穿过红色的区域。白色实线是先训练到中期训练的权重、再到目标，一路都在蓝色的区域里。图片来源：Liu 等，2025。}}

这张示意图来自卡内基梅隆大学的一篇论文，它把中期训练的作用解释为在预训练和后训练两种数据分布之间加一段过渡。

论文在 7000 万到 10 亿参数的模型上做了对照实验，结论有两条。第一，目标领域离一般的预训练数据越远（比如代码和数学），中期训练的好处越大。第二，领域数据引入得早，可以用高的配比，引入得晚就只能用低的配比。引入得晚造成的差距，不能靠后面加大配比补回来。

后训练：教模型按我们想要的方式回答

预训练出来的模型只会接着往下写。要让它成为能听指令、会对话的助手，还要经过后训练。常用的做法有三类。

指令微调

指令微调（instruction fine-tuning）也叫有监督微调（SFT）。准备很多条「指令加上理想的回答」，让模型在这些例子上继续做下一个 token 的预测。预训练用的是题材各异的大量文字，这里的数据是按我们希望模型怎样说话专门写的。

{{fig 113 | 左边是三种指令的例子：直接回答问题、先一步步推理再回答、在大量任务上一起微调（1800 个任务）。右边是模型应该给出的回答。虚线下面是微调时没见过的新任务，模型同样能按指令完成。图片来源：Chung 等，2022。}}

这张图出自 Google 的 Flan 论文。它在 1800 个写成指令形式的任务上微调模型，再在没见过的任务上测试。测试用的是 MMLU、BBH、TyDiQA 和 MGSM 四个基准测试，它们都没有出现在微调的数据里。

结果是：5400 亿参数的 Flan-PaLM 在这四个测试上的平均分，比没有微调的 PaLM 高 9.4 个百分点。平均分取自四个测试的六项成绩。算平均之前，各项成绩先做了换算：随机猜的水平记作 0 分，满分记作 100 分。核对的经过见资料说明。

学人的偏好

有些事很难写出标准答案，但人能说出两个回答哪个更好。让模型从这种比较里学习，就是 RLHF（基于人类反馈的强化学习）。到这里训练的目标换了：前面各个阶段都是让交叉熵损失变小，强化学习是让模型生成的回答拿到的奖励变高。下图里的 prompt 是交给模型的那段输入文字。

{{fig 114 | 三个步骤。第一步：标注员为 prompt 写出示范回答，用来做有监督微调。第二步：同一个 prompt 让模型生成几个回答，标注员从好到差排序，用这些排序训练一个打分模型。第三步：用强化学习更新模型，让它生成打分模型给分更高的回答。图片来源：Ouyang 等，2022。}}

这张图出自 OpenAI 的 InstructGPT 论文，ChatGPT 这类助手的训练方法就是从这里发展来的。论文雇了 40 名标注员。结果是：在论文用的那批 prompt 上，13 亿参数的 InstructGPT 的回答，比 1750 亿参数的 GPT-3 的回答更受人喜欢，尽管前者的参数还不到后者的百分之一。

能自动判对错的奖励

另一条路是让奖励可以自动验证，叫 RLVR（reinforcement learning with verifiable rewards）。前面「学人的偏好」那一小节里，打分的是一个猜测人喜欢什么的模型。这里打分的是一个能客观判对错的检查：答案对了给分，错了不给。

{{fig 116 | 右上的方框列出了四种可以自动验证的奖励：单元测试、Lean 证明、精确匹配、系统状态。下面的流程图是一种常用的强化学习算法 GRPO：对同一个问题 q，模型生成一组回答，每个回答得到一个奖励，在组内比较之后算出每个回答比平均水平好多少，再据此更新模型。图片来源：Shao 等，2024。}}

图下半部分的 GRPO 出自 DeepSeekMath 的论文，它是在早先的 PPO 算法上改出来的。InstructGPT 的第三步用的就是 PPO。PPO 要另外训练一个估值模型，用来估计一个回答大概能得多少分，作为比较的基准。GRPO 省掉了这个单独的估值模型，改用同一组回答的平均得分作为比较的基准。

为 agent 专门准备的训练

agent 指能自己调用工具、分很多步去完成一个任务的语言模型系统。要训练模型做这样的工作，需要大量「带运行环境、能自动判对错」的任务。真实的任务很少，于是有了自动造任务的办法。SWE-smith 是其中一个例子。

{{fig 117 | SWE-smith 的流程，从左到右四栏。第一栏是真实的代码仓库和它自带的单元测试。第二栏是让一个 agent 试着安装仓库并运行测试，再做成环境。第三栏是四种往代码里放 bug 的办法。第四栏是最后得到的任务，每个任务包含环境、一段说明问题的文字、放进去的 bug 和用来验证的测试。图片来源：Yang 等，2025。}}
  1. 建环境。拿一个真实的 Python 代码仓库，让 SWE-agent（一个写代码的 agent）试着把它装好并运行测试。人工核对安装步骤，确认 80% 以上的测试能通过，再把它做成一个 Docker 镜像。
  2. 放 bug。有四种办法。
    • 让语言模型改坏一个函数，或者只看函数的签名和说明重写它。
    • 用程序按规则改代码，比如删掉一个判断、换掉一个运算符。
    • 把几个小 bug 合成一个大的。
    • 找出仓库历史上的代码合并请求，让语言模型把其中的改动反过来撤销。
  3. 筛选和配说明。只留下确实让已有测试失败的那些改动，再让语言模型为每个 bug 写一段像真实问题报告那样的文字。

这样从 128 个仓库里造出了 5 万个任务。任务的解法是否正确，用仓库自带的测试来验证，和上一节说的可以自动验证的奖励是同一种检查。在这篇论文里，测试的用途是挑出做成功的运行轨迹（trajectory，agent 完成一个任务的全过程记录），模型再在这些轨迹上微调。结果见下表。

SWE-agent-LM-32B 是在 Qwen 2.5 Coder Instruct 32B 上微调出来的。它在 SWE-bench Verified 上的成功率是 40.2%，论文写明比微调前高 33.4 个百分点，由此推算微调前大约是 6.8%。

用来微调的 5,016 条运行轨迹，是让 Claude 3.7 Sonnet 去做这些造出来的任务、并且做成功了的记录。

更长的任务用什么数据训练

要让模型能连续工作几小时甚至更久，用的也是这类环境。现在有不少公司专门制作强化学习用的环境：雇人或者用高质量的合成办法，在真实的代码仓库上造出又长又难的任务。同一个环境既可以用来评估模型，也可以用来训练。代码是其中最容易做、也最常见的一类，办公类的工作任务也有人在做。

i
预训练的数据能不能全由模型来造。从生成能力上说可以，但一般不建议这样做。预训练一个开放权重的模型要用多少 token，一个例子是 Qwen3：技术报告写的是大约 36 万亿个。现在模型每天生成的文字量已经非常大，这么多预训练数据可以全部由模型来造。不建议的原因是，互联网数据的优势正在于它的多样。可以这样理解今后的方向：从互联网里能学到的东西接近饱和之后，进一步的提升要更多地依靠强化学习这类办法。出处：Qwen3 的技术报告。
