先看结论

  • 让模型在回答之前多生成一些 token，等于在推理时多花算力，成绩通常会更好。这叫推理时扩展（inference-time scaling，也叫 test-time scaling）。token 是模型处理文字的最小单位。
  • 第一种做法是让模型先写推理过程，靠 prompt（交给模型的那段输入文字）来引导。
  • 第二种做法是用推理模型。这种模型是专门训练成先推理再回答的，并且推理强度可以分档调。
  • 第三种做法是同一道题做很多遍，再挑一个答案。做的遍数越多，至少做对一遍的机会越大。有办法自动验证答案时，就能把做对的那一遍挑出来。
  • 没有验证办法时，第三种做法可以改成让多次的答案投票。这种挑法到一定遍数之后就不再有提升。
  • 这些办法的共同点：花多少由使用者决定。觉得一个任务难，就多花一些。

除了把模型做大，还有一个方向

提高模型的能力，过去主要靠在训练上加大投入：更多的参数、更多的数据、更多的训练计算量。推理时扩展是另一个方向：模型不变，在使用它的时候让它为一个任务多算一些。

它和把模型做大有一个很大的不同：多花多少算力，由使用者决定。你知道某个任务很难，愿意为它多花钱，就可以让模型多用一些 token。任务简单，就少用。

先写推理过程：chain of thought

最早被广泛使用的办法是 chain of thought（思维链）：让模型在给出答案之前，先把中间的推理步骤写出来。

{{fig 139 | 左：普通的 prompt，例子里的回答只有答案，模型照着直接给出答案 27，错了。右：chain of thought 的 prompt，例子里的回答先写了推理过程（蓝色高亮），模型也照着先推理（绿色高亮），得到正确答案 9。图片来源：Wei 等，2022。}}

具体有两种写法。

  • 给例子。在 prompt 里放几个「问题、推理过程、答案」的例子，模型会照这个样子回答新的问题。图里就是这种。论文里，5400 亿参数的 PaLM 只用了 8 个这样的例子，就在数学应用题基准测试 GSM8K 上达到了当时最好的准确率。
  • 加一句话。不给例子，只在回答的开头加上「Let's think step by step」（一步一步地想）。这个办法出自 Kojima 等，2022。

它算是推理时扩展，是因为推理过程也是模型一个 token 一个 token 生成的。写得越多，为这道题花的计算越多。

推理模型：把「先想再答」训练进模型

现在的推理模型（reasoning model）是专门训练成先长篇推理、再给答案的，用的时候 prompt 里不用再加引导的话。

{{fig 140 | 同一道题的两种回答。题目：一件夹克 80 美元，先涨价 25%，再在新价格上打七五折，最后多少钱。左下是传统模型的回答，直接列式算出 75 美元。右边是推理模型的输出：它先冒出一个错误的想法（涨 25% 再降 25% 等于没变，还是 80 美元），接着发现不对，重新算，再验算一遍，最后给出 75 美元。}}

右边那段文字里有一句「等等……」。模型先走了一条错的路，自己发现了，退回来改正。这样做让模型有机会在给出答案之前发现并纠正自己，中途的错误就不容易一路带进最后的答案。代价也很明显：输出的 token 比传统模型多得多。

{{fig 141 | 一个推理模型的原始输出。题目：一张电影票和一份爆米花一共 18 美元，电影票比爆米花贵 6 美元，电影票多少钱。think 标签里是推理过程。红框标出的那句是「等等，这不对」，模型发现自己前面列错了式子，随后改正，最后在 answer 标签里给出 12。图片来源：Sebastian Raschka 的文章。}}

这种模型发现并纠正自己错误的时刻，被叫作「Aha」时刻。它是怎么训练出来的，和第四部分讲的 RLVR 直接有关。RLVR 是用能自动判对错的任务做强化学习。强化学习是让模型反复做题、按每次的得分来调整模型的训练办法，这个得分叫奖励。

DeepSeek-R1 是一个例子。Raschka 的文章这样概括它的做法：让模型去做数学、代码这类能自动判对错的题，奖励由最后的答案对不对和输出格式是否合乎要求两项组成，中间的推理过程不参与打分。按这篇文章的说法，仅靠这样的奖励，模型就学会了写中间步骤、回退和自我纠正。出处：Raschka 的文章；DeepSeek-R1 的论文。

推理强度是一个可以调的档位

推理模型通常提供几个推理强度的档位。档位越高，模型想得越久，用的 token 越多，花费越高，成绩通常也更好。发布新模型时常见下面这种图。

下面这张图出自 OpenAI 发布 GPT-6 Sol 和 Luna 的页面。图里也画了同一个月稍早发布的 GPT-6 Astra，下面读的就是它的那条线。图里的基准测试叫 Agents' Last Exam。原页面对它的介绍是，它评估 agent 完成复杂的专业工作流程的能力。agent 指能自己调用工具、分很多步去完成一个任务的语言模型系统。

{{fig 142 | 左：一个叫 Agents' Last Exam 的基准测试上的成绩。横轴是每个任务的花费，是对数刻度，从 0.02 美元到 20 美元；纵轴是得分。每条折线是一个模型，线上的每个点是这个模型的一个推理强度档位。右上是蓝色那条线（GPT-6 Astra）的放大，上面用红字标出了 Low、Medium、Max 三个点。右下是产品界面里选择推理强度的滑块。图片来源：OpenAI 的 GPT-6 Sol 和 Luna 发布页，2026 年 9 月。}}

读这张图的办法是沿着一条线看：同一个模型，从左下的低档到右上的高档，花费增加，得分大体上升。从图上读，GPT-6 Astra 的五个点从大约 53% 升到大约 59%，每个任务的花费从 3 美元左右升到 6 美元左右。这里的花费基本上就是 token 数：档位越高，生成的 token 越多。

调高档位不保证得分更高。从图上读，有几条线在中间或最后出现了回落。

使用时怎么设

对使用者来说，档位通常就是 system prompt 里的一行字。system prompt 是放在对话最前面、用来设定模型行为的那段文字。

{{fig 143 | 开放权重模型 gpt-oss 设置推理强度的办法：在 system prompt 里写一行 Reasoning: low、medium 或 high，后面的用户 prompt 不变。}}

OpenAI 的 gpt-oss 模型说明里写的是：推理强度有低、中、高三档，在 system prompt 里设置，例如写上 Reasoning: high。产品界面里的滑块和菜单，很可能只是把用户的选择换成了这样一行文字。

档位是怎么训练出来的

在 system prompt 里写一行字就能让模型多想或少想，是因为模型在后训练（预训练之后、让模型学会按人希望的方式回答的训练阶段）里专门学过这件事。公开的做法大致有两种，可以单用也可以合用。下表里的有监督微调，指拿一批写好了示范回答的例子让模型照着学。

Inkling：公开的是两点，公式是推测

按 Raschka 文章的转述，Inkling 的技术报告说到的是两点：强化学习时在 system prompt 里写明想要的强度，并调整每个生成的 token 的代价。图上的公式 R(e) = R_task − λ(e) × N_tokens 出自 Raschka 的文章，是他根据这两点作出的推测。

Inkling 的强度是 0 到 1 之间的一个连续的数，写法类似 Thinking effort level: 0.8，这一点也来自 Raschka 的文章。Inkling 的发布文章里，成绩曲线是把强度从 0.2 调到 0.99 画出来的。

Kimi K3：技术报告里写明的做法

下面五步按 Kimi K3 的技术报告第 4.1 节整理。

  1. 给每道题定一个 token 预算。先用还没做强化学习的模型估出每道题大致要用多少 token，作为这道题的初始预算。
  2. 超预算就把奖励改成负 1。一次尝试用掉的 token 数如果超过「预算乘以一个倍数」，不管任务本身得了多少奖励，都改成负 1。对一般的任务，计入的是思考用的 token。对 agent 类任务，计入的是全部输出的 token，包括推理过程和调用工具时写的参数。
  3. 靠调倍数得到不同的档位。先用一个比较大的倍数训练出最高档的模型，再把倍数逐步调小，得到高档和低档的模型。
  4. 三个领域各做一遍。一般任务、一般的 agent 任务、写代码的 agent 任务，各自训练出低、高、最高三个档位的专家模型，一共九个。
  5. 合成一个模型。用多老师蒸馏，把九个专家的能力合进一个学生模型，也就是最后发布的 Kimi K3。训练时每条样本抽一个领域和一个档位，由对应的那个老师来指导。

同一道题做很多遍，再挑

另一类办法是让模型把同一道题独立地做很多遍，每一遍想多久都照旧。模型的输出有随机性，每一遍的结果都可能不同。

{{fig 145 | 两步。第一步：语言模型为同一个问题生成很多个候选解答。第二步：用一个验证器（比如单元测试、证明检查器、多数投票）从里面挑出最终答案。图下方是两个要解决的问题。图片来源：Brown 等，2024。}}

如果有一个可靠的自动验证器，比如代码有单元测试、数学证明有检查器，第二个问题就解决了，只剩下第一个：多抽几遍，覆盖率能涨多少。

{{fig 146 | 四个基准测试上，覆盖率随抽样次数的变化。横轴是每道题抽的次数，对数刻度，从 1 到 1 万。蓝线是 Llama-3-8B-Instruct，绿线是 Llama-3-70B-Instruct。红色虚线是 GPT-4o 只做一遍的成绩，作为参照。下面两张图标着 Oracle Verifier，意思是假定有一个能完美认出正确答案的验证器。图片来源：同上。}}

四张图里的曲线都随抽样次数上升，并且在对数刻度的横轴上接近直线。论文的说法是：覆盖率和抽样次数的对数之间，常常近似是线性关系。

小模型抽很多遍，覆盖率可以赶上甚至超过更强的模型只做一遍的成绩。从图上看，80 亿参数的 Llama 3 在抽了足够多遍之后，四个测试上都到达或超过了红色虚线。

读这个比较时要分清两个数。红色虚线是只做一遍的成绩，曲线是「做很多遍、有一遍对就算对」的比例，这是两个不同的数，一般不能放在一起比。只有在有可靠的验证器、能把做对的那一遍挑出来的任务上，覆盖率才是实际能拿到的成绩。第 13 讲会讲到这一点。

没有验证器时：让答案投票

没有验证器，也有一个简单的办法：把同一道题做很多遍，哪个答案出现的次数最多，就选哪个。这叫自洽性（self-consistency）。

{{fig 147 | 上半部分：普通的 chain of thought 加 greedy 解码（每一步都选概率最高的 token），只走一条推理路径，得到 14 美元。下半部分：同一个 prompt 抽样出三条不同的推理路径，答案分别是 18 美元、26 美元、18 美元，汇总后选出现最多的 18 美元。题目是：Janet 的鸭子每天下 16 个蛋，她早餐吃 3 个，烤松饼用 4 个，剩下的每个卖 2 美元，一天能卖多少钱。图片来源：Wang 等，2022。}}

道理是：一道题的正确答案只有一个，错法却有很多种。不同的推理路径如果都对，会汇合到同一个答案上；如果错了，往往各错各的。所以出现次数最多的答案更可能是对的。这道题正确答案是 18 美元：16 减 3 减 4 等于 9 个蛋，每个 2 美元。

{{fig 148 | ARC 挑战集（一个科学常识选择题的基准测试）上的准确率。横轴是抽样的推理路径条数。蓝线是自洽性，绿线是另一种办法 Sample & Rank，橙线是只走一条路径的 greedy 解码。图片来源：同上。}}

论文摘要报告了五个基准测试上的提升。比较的两边用的是同样的 chain of thought prompt：一边用自洽性，另一边只用 greedy 解码走一条路径。下表的数是自洽性的准确率比另一边高出多少个百分点，对应的是另一个模型 code-davinci-002 的结果。

上图用的 code-davinci-001 在 ARC 挑战集上起点低，提升更大：按论文的表 3，从 43.1% 升到 53.7%，高 10.6 个百分点，和从图上读到的数一致。

图里蓝线后半段变平：靠投票来挑答案，遍数多到一定程度就不再有提升。上一节那篇重复抽样的论文有同样的发现：在没有自动验证器的任务上，用多数投票或者打分模型来挑答案，到几百遍之后成绩就不再上升，跟不上覆盖率。
