一句话的结论

agent 的记忆要回答的是同一个问题：此刻，哪些信息应该出现在模型的上下文窗口里。设计一个记忆系统，就是回答三个小问题：存什么，什么时候存取，怎么存取。常见的四种架构是四种回答，每一种都有代价。

这里的 agent，指能自己调用工具、分很多步去完成一个任务的语言模型系统。上下文窗口（context window）是模型一次能读进去的全部文字。语言模型本身不保留状态：两次调用之间，上一次交互里出现过的内容它不会记得，要用就得重新放进窗口。预训练时学到的知识存在模型的权重里，不受这一点影响。记忆是把窗口放不下、或者会话结束后会丢掉的信息存到外面，需要时再取回来的一套机制。

还有一个贯穿后半讲的提醒：专门的记忆系统不一定让 agent 更准。在好几项评测里，把全部历史放进上下文窗口，或者用最普通的检索，成绩并不比它们差。它们在速度和花费上的好处是有条件的。Mem0 和 Zep 各自的论文里，和把全部历史放进上下文窗口相比，回答时的耗时和放进 prompt（给模型的输入文字）的 token（模型处理文字的最小单位，大致是一个词或半个词）都少得多，写入记忆的开销没有算在里面。第六部分的两项独立评测里情况相反：PersonaMem 里把写入记忆的时间算进去，Mem0 平均每个问题要 150 秒，简单的检索是 0.61 秒；MemoryArena 里专门的记忆系统完成子任务的耗时是三类做法里最长的。
