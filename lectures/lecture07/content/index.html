一句话的结论

agent 的记忆要回答的是一个问题：此刻，哪些信息应该出现在模型的上下文窗口里。设计一个记忆系统，就是回答三个小问题：存什么，什么时候存取，怎么存取。常见的四种架构是四种回答，每一种都有代价。

为什么需要记忆，三个小问题各有哪些答案

这里的 agent，指能自己调用工具、分很多步去完成一个任务的语言模型系统。上下文窗口（context window）是模型一次能读进去的全部文字。

语言模型本身不保留状态：两次调用之间，上一次交互里出现过的内容它不会记得，要用就得重新放进上下文窗口。预训练时学到的知识存在模型的权重里，不受这一点影响。

记忆是把上下文窗口放不下、或者会话结束后会丢掉的信息存到外面，需要时再取回来的一套机制。下表是这一讲对三个小问题和四种架构的回答。

专门的记忆系统不一定更准

后面几部分会反复遇到一个结论：专门的记忆系统不一定让 agent 更准。在好几项评测里，把全部历史放进上下文窗口，或者用最普通的检索，成绩并不比专门的记忆系统差。

专门的记忆系统在速度和花费上的好处是有条件的。Mem0 和 Zep 是两个专门的记忆系统，它们各自的论文都拿「把全部历史放进上下文窗口」来对比，结果是自己回答时的耗时少得多，放进 prompt 的 token 也少得多。prompt 是给模型的输入文字。token 是模型处理文字的最小单位，大致是一个词或半个词。这两篇论文的比较都没有把写入记忆的开销算进去。

第六部分的两项独立评测里情况相反。PersonaMem 把写入记忆的时间算了进去，结果 Mem0 平均每个问题要 150 秒，简单的检索是 0.61 秒。MemoryArena 比较三类做法：直接用长上下文，检索，专门的记忆系统。它量的是完成一个子任务的耗时，专门的记忆系统最长。
