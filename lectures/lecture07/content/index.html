先看结论

agent 的记忆要回答的是一个问题：此刻，哪些信息应该出现在模型的上下文窗口里。设计一个记忆系统，就是回答三个小问题：存什么，什么时候存取，怎么存取。已有的系统回答这三个问题时，常见的组合有四种，叫作四种架构模式，每一种都有代价。

为什么需要记忆，三个小问题各有哪些答案

这里的 agent，指能自己调用工具、分很多步去完成一个任务的语言模型系统。上下文窗口（context window）是模型一次能读进去的全部文字。

语言模型本身不保留状态：两次调用之间，上一次交互里出现过的内容它不会记得，要用就得重新放进上下文窗口。预训练时学到的知识存在模型的权重里，不受这一点影响。预训练是模型最初在海量文字上做的训练，权重是模型训练出来的参数。

记忆是把上下文窗口放不下、或者会话结束后会丢掉的信息存到外面，需要时再取回来的一套机制。会话（session）指从开始到结束的一次连续的对话或运行。下表列出三个小问题各自常见的答案，和这一讲里的例子。

已有的系统回答这三个问题时，常见的组合有四种，这一讲把它们叫作四种架构模式。

专门的记忆系统不一定更准

后面几部分会反复遇到一个结论：专门的记忆系统不一定让 agent 更准。专门的记忆系统指 Mem0 这一类系统：先让语言模型把历史加工成一条条记忆存起来，回答时再取出相关的几条。

拿来和它比的简单做法有两种。一种是把全部历史放进上下文窗口。另一种是简单的检索：直接从历史的原文里取出最相关的几条，中间没有加工这一步。第五部分和第六部分里，有三项实验的结果同时列出了专门的记忆系统和这两种简单做法的成绩。每一项里，都至少有一种简单做法的成绩不比专门的记忆系统差。专门的记忆系统胜过其中一种简单做法的情况也有，见第六部分。

专门的记忆系统在速度和花费上的好处是有条件的：支持这个好处的数字，只算了回答时的耗时和 token。Mem0 和 Zep 是两个专门的记忆系统，它们各自的论文都拿「把全部历史放进上下文窗口」来对比，结果是自己回答时的耗时少得多，放进 prompt 的 token 也少得多。prompt 是给模型的输入文字。token 是模型处理文字的最小单位，大致是一个词或半个词。这两篇论文比的都是回答时的耗时和 token，把内容写进记忆的开销没有算进去。

第六部分有两项独立评测量了耗时，两项里专门的记忆系统大体上都比拿来比较的简单做法慢。第一项是 PersonaMem，它用选择题考聊天助手能不能按用户的偏好作答。它拿 Mem0 和简单的检索比，并把 Mem0 写入记忆的时间算了进去，结果 Mem0 平均每个问题要 150 秒。简单的检索是 0.61 秒，这个数不含事先计算向量的时间。这里的检索按向量找内容，向量是把一段文字转成的一串数字，意思相近的文字，转出来的数字也相近。

第二项是 MemoryArena，它让 agent 跨多个会话完成任务。它比较三类做法：把全部历史放进上下文窗口，检索，专门的记忆系统。它量的是完成一个子任务的耗时，专门的记忆系统最长，把全部历史放进上下文窗口最短。这是三类做法大致的排序，按单个系统看有例外：最快的记忆系统比最慢的检索快。
