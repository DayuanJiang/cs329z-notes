先看结论

  • 模式三是反思式整理：先让模型从 agent（能自己调用工具、分很多步去完成任务的语言模型系统）原始的经历里总结出结论，再把结论存进记忆。存下来的东西更短、更容易再用，代价是结论可能没有依据。
  • 两个例子都说明反思这一步有用。Reflexion 是一个让 agent 在任务失败后写一段反思、重试时带上这段反思的方法。它在 HotPotQA 问答数据集的 100 道题上做的实验里，重试时在上次的运行轨迹（trajectory，每一步的动作和看到的结果的完整记录）之外再带上反思，答对的题占的比例比只带轨迹高 8 个百分点。Generative Agents 用语言模型模拟一个小镇上的居民，每个居民都有自己的记忆。它的实验里，评估者比较 agent 的回答有多可信，也就是像不像一个真实的人说的话。去掉反思之后，由此算出的评分明显下降。
  • 模式四是记忆维护：记忆存进去之后还要继续整理。Sleep-time compute 利用空闲时间提前推理、重写记忆。A-Mem 每存一条新记忆，就把它和相近的旧记忆连起来，再检查这些旧记忆上的标注要不要改写。标注指每条记忆带的关键词、标签和一句话的背景说明。Mem0 对每条新事实决定添加、更新、删除还是不动。
  • 读这些系统的成绩要留意对比的对象。Mem0 论文自己的表里，把整段对话放进上下文窗口（context window，模型一次能读进去的全部文字）的做法准确率最高，Mem0 换来的是回答更快、用的 token（模型处理文字的最小单位，大致是一个词或半个词）更少。

模式三：反思式整理

原始的记录有两个缺点：太长，而且太细。比如 agent 记下一条「书桌空着」，这一条记录本身没什么用，很多条这样的记录合起来才能看出一个人的习惯。反思式整理的做法是，让语言模型读一批原始记录，写出更概括的结论，把结论也当作记忆存起来。

这件事可以用 CoALA 的两个词来描述。CoALA 是第一部分介绍的那篇把 agent 的记忆分成四种的论文，它把 agent 内部的动作也分了类。其中「推理」指用语言模型从工作记忆（working memory，大致就是上下文窗口里的内容）得出新的信息，「学习」指把信息写进长期记忆。CoALA 把工作记忆以外的三种记忆都叫长期记忆，它们分别存经历、知识和做法。反思式整理就是一次推理加一次学习。

后面两节各讲一个例子：Reflexion 和 Generative Agents。再后面一节比较这两个例子。

Reflexion：在上一次的轨迹之外再加上反思

Reflexion（Shinn 等，2023）在第 6 讲讲过，这里只回顾和记忆有关的部分。agent 做一个任务失败之后，系统让模型用文字写下这次为什么失败、下次该怎么改，这段反思存进记忆，下一次尝试时放进 prompt（给模型的输入文字）。

它的记忆分两种，名字是 Reflexion 的论文自己起的：当前这次尝试的轨迹叫短期记忆，历次的反思叫长期记忆。这里的长期记忆只指存下来的反思，通常只保留最近的 1 到 3 条，免得占满上下文窗口。论文的摘要把存放这些反思的地方又叫作情景记忆缓冲区，第一部分的表里用的是这个叫法，两个名字指的是同一样东西。情景记忆是第一部分讲的四种记忆里存经历的那一种。

论文做过一组对比，看反思这一步本身有没有用。

{{fig 52 | 在 HotPotQA 问答数据集的 100 道题上的对比。横轴是第几次重试，纵轴是答对的题占的比例。灰线：每次重试都不带任何记忆。浅紫色的线：重试时带上最近一次尝试的轨迹。深紫色的线：再加上对那次尝试的反思。图片来源：Shinn 等，2023。}}

灰线是平的，说明不带记忆地重试没有用。论文的说法是：在重试时带上上一次轨迹的基础上，反思又带来 8 个百分点的提升，也就是表里后两行 0.66 和 0.74 的差距。

这个结果说明，在把旧的轨迹放回上下文窗口的基础上，再加一段「为什么这条轨迹没成」的反思，比只放旧轨迹有用。实验里带反思的一组仍然带着上一次的轨迹，没有测只留反思、去掉轨迹的情况。

还有两点限制了这个结果能说明的范围。第一，这组实验把题目需要的参考资料直接给了模型，所以它测的主要是推理，不包括 agent 自己去找资料的那部分。第二，每次重试之前，系统会告诉 agent 上一次的答案对不对。这个信号来自和标准答案的比对，没有标准答案的任务拿不到它。

Generative Agents：把反思也存进记忆流

Generative Agents（Park 等，2023，发表于人机交互领域的会议 UIST）用语言模型模拟一个小镇上 25 个居民的生活。每个居民是一个 agent，有自己的身份、目标和记忆，会计划一天的安排，和别的居民聊天。每个 agent 的记忆是一张按时间排的列表，论文叫它记忆流（memory stream）。

论文里的主线故事是：研究者只给其中一个 agent Isabella 设定了「想在情人节办一场派对」的意图，然后看这件事怎样在小镇里自己发展。

{{fig 54 | Generative Agents 的记忆结构。agent 感知到的一切都存进记忆流。需要行动时，从记忆流里检索出相关的记忆，据此决定动作。检索出来的记忆还用来生成计划和反思，这两样也存回记忆流。图片来源：Park 等，2023。}}

下面三小节依次讲记忆流和检索时的打分、反思是怎么生成的、反思起了多大作用。

记忆流和三项打分

记忆流里的每条记忆有一句自然语言的描述、创建的时间和最近一次被取用的时间。里面有三种记录：观察（agent 看到的和自己做的事）、反思、计划，三种混在一起，检索时一视同仁。

第一部分拿记忆流当过情景记忆（episodic memory，对经历的记录）的例子，说的是其中的观察。CoALA 论文把从观察里得出的反思算作语义记忆（semantic memory，存知识的那一种记忆）。

记忆流很长，不可能全部放进上下文窗口，所以每次要检索。检索时给每条记忆打三项分，相加之后取最高的几条。

{{fig 55 | 一次检索的例子。左边是 Isabella 的记忆流。右上是问题：你现在最期待什么？中间是得分最高的三条记忆和各自的三项分数。右下是 Isabella 的回答：最期待正在筹备的情人节派对。图片来源：Park 等，2023。}}

图里排第一的记忆是「Isabella 正兴奋地筹备 2 月 14 日在咖啡馆举办的情人节派对」，总分 2.34，由新近 0.91、重要 0.63、相关 0.80 相加得到。另外两条是「为派对订购装饰」和「为派对找点子」。这三条被放进 prompt，模型据此写出了回答。

反思是怎么生成的

记忆里只有观察记录、没有反思的 agent 不会归纳。论文举的例子里，Klaus 和 Maria 都是小镇的居民。问 Klaus「如果只能选一个你认识的人共度一小时，你选谁」，只靠观察记录的 agent 选了和他碰面次数最多的宿舍邻居，其实两人只是擦肩而过。加上反思之后，agent 从很多条「Klaus 花好几个小时做研究」的观察里得出「Klaus 对研究很投入」，又从关于 Maria 的观察里得出她同样在用心做研究，于是选了 Maria。

反思的生成分三步。

  1. 触发。最近感知到的事件的重要程度分数加起来超过 150，就做一次反思。实际运行中，每个 agent 在模拟里的一天大约反思两三次。
  2. 提问。把记忆流里最近的 100 条记录交给语言模型，让它提出 3 个最值得回答的概括性问题。
  3. 作答。用这些问题去检索记忆，再让模型从检索到的记录里得出 5 条结论，并注明每条结论依据的是哪几条记录。结论作为反思存回记忆流。

反思本身也是记忆，以后生成反思时可以拿已有的反思当依据，于是形成一棵树：叶子是最原始的观察，越往上越概括。结论带着依据的编号，这一点很要紧：它让人能回头检查一条反思是从哪些事实得出来的。

反思起了多大作用

论文用消融实验（ablation）来量反思的作用。消融实验的做法是把系统的某个部件去掉，再和完整的系统比较，看成绩下降多少。

{{fig 56 | 左边是消融实验的结果。每个条件一根横条，横轴是评分，横条越长评分越高。从上到下：完整的架构；去掉反思；去掉反思和计划；反思、计划、观察都去掉；真人扮演 agent 写的回答。右边是小镇里派对场景的截图。图片来源：Park 等，2023。}}

这个评分量的是 agent 的回答有多可信。可信（believable）在这篇论文里指 agent 的言行让人觉得像一个真实的人。

评分是这样得到的。研究者像面试一样向 agent 提问，问题分五类：对自己的了解、回忆、计划、应变、反思。100 名评估者先看一个 agent 在小镇里的生活回放，再看这个 agent 在五种条件下的回答，按可信的程度从高到低排序，再由排序算出评分。它评的是单个 agent 的回答。整个小镇模拟得怎么样，是下面另外统计的。

去掉反思，评分从 29.89 降到 26.88，差 3 分左右。这个差距是明显的：论文给每个条件的评分都附了一个标准差（衡量一组数彼此相差多少的量），五个条件都在 0.7 左右，3 分是它的四倍多。论文的统计检验也确认，去掉反思前后的差别是显著的，也就是不大可能是偶然造成的。

读这张表还要知道两点。第一，去掉一个部件的做法是在回答面试问题时不让 agent 看这一类记忆，小镇本身没有重新模拟，各个条件用的都是完整的架构在模拟里积累下来的记忆。如果从头就用去掉部件的架构来模拟，agent 的经历本来就会不一样，所以论文说这样估出的差距偏保守，也就是很可能比真实的差距小。第二，「真人扮演 agent 写的回答」那一行是请众包工作者（在网上平台接零散任务的人）看了 agent 的生活回放之后代它作答，论文说明这一行只用来确认架构达到了基本的水平，不代表人的最好表现。

整个小镇层面的结果是另外统计的，看的是完整的架构，没有单独量反思的作用。两天的模拟结束时，知道派对的 agent 从 1 个增加到 13 个，占 25 个 agent 的 52%。被邀请的 12 个 agent 里，有 5 个在情人节当天到了场。

论文自己写到的三个问题。Generative Agents 的论文也写了这套系统的三个问题。第一，agent 回答时有时会给自己知道的事添上原本没有的细节。小镇里除了派对还有一件事在居民之间传开：一个叫 Sam 的居民要竞选镇长。Isabella 知道 Sam 要竞选，却又补了一句「他明天要发表声明」，而两人从没谈过这件事。反思也是模型的推断，这类没有依据的内容如果进了反思、被当成记忆存下来，就可能留在记忆里被反复引用。第二，检索会漏。有的 agent 明明听说过竞选的事，被问到时却说自己没怎么关注。第三，这套系统很贵。论文说模拟 25 个 agent 两天花了几千美元的 token 费用。

模式三的两个例子差在哪里

Reflexion 和 Generative Agents 这两个例子的差别在于什么时候生成反思、依据什么来生成。Reflexion 在每次尝试失败之后马上写一段反思，依据是刚结束的那一次尝试。Generative Agents 先把观察原样存进记忆流，等最近事件的重要程度分数加起来超过 150，再从已经存下的记录里生成反思。

两个例子也有相同的地方：反思生成之后都存进记忆，以后再用。

模式四：记忆维护

前面几种模式主要讲怎样往记忆里加东西。只加不管，记忆会出三种问题。

  • 过时。用户的情况变了，旧的事实还留着。第四部分里「男朋友叫 James」要改成「前男友叫 James」就是一例。
  • 零散。相关的几条记忆各存各的，每次使用都要全部取出来，让模型重新综合一遍。
  • 越积越多。检索、上下文、维护的开销都跟着涨。

记忆维护指记忆存进去之后继续整理：合并、更新、删除已有的记忆，或者利用空闲时间提前推理、把记忆重写一遍。它和模式三的分界可以这样理解：模式三往记忆里新增概括性的结论，原始记录不动。模式四会改动已有的记忆。

CoALA 论文在 2023 年就指出，修改和删除记忆在当时的 agent 研究里很少有人做。下面讲三项工作：Sleep-time compute 做的是提前推理和合并，A-Mem 做的是更新，Mem0 做的是更新和删除。它们都是 2025 年的工作，这是一个很活跃的方向。

Sleep-time compute：趁空闲提前把记忆整理好

Sleep-time compute 由 Letta 公司和加州大学伯克利分校的研究者在 2025 年 4 月提出，作者里有好几位也是 MemGPT 的作者。MemGPT 是第四部分讲的一个让模型自己用函数读写记忆的系统。Sleep-time compute 的出发点是：agent 在两次交互之间有大量空闲时间，这段时间可以用来提前推理。

{{fig 58 | 上半部分是通常的做法：用户每问一个问题，模型都从原始的上下文开始推理。下半部分是 sleep-time compute：空闲时，模型先对原始的上下文做推理，写出一份整理过的上下文；用户提问时，模型看的是这份整理过的版本，很快就能回答。图片来源：Lin 等，2025。}}

图里的例子是一道应用题。原始的上下文说：一个杂耍演员能同时抛 800 个球，其中四分之一是网球，网球里一半是靛蓝色的，靛蓝色的网球里十分之一有标记。空闲时，模型把能算的先算出来：网球 200 个，靛蓝色的网球 100 个，有标记的 10 个。之后用户问「有标记的靛蓝色网球有几个」，模型不用再推一遍，直接回答 10。

难处在于空闲时并不知道用户会问什么，只能猜哪些推理以后可能有用。猜错了，这部分计算就没有用处。

用在记忆上

同样的办法可以用来整理记忆。下图是 Letta 的博客里的例子。

{{fig 59 | 左边是原始的记忆：用户叫 Chad；Chad 喜欢蓝色；Chad 喜欢红色胜过蓝色；Chad 最喜欢灰色；Chad 讨厌绿色。右边是空闲时整理之后的记忆：用户叫 Chad；颜色偏好依次是灰、红、蓝、绿（讨厌）。图片来源：Letta 的博客。}}

左边五条记忆里，有四条讲的都是颜色偏好。每次要用 Chad 的颜色偏好，都得把这四条全取出来，再由模型推出四种颜色的先后顺序。右边把这一步推理提前做完了，四条合成了一条排好顺序的偏好。这是一个特意简化的例子，说明的是记忆维护里「合并」这件事。

Letta 的产品沿用了 MemGPT 的分层的记忆。在这个产品里，对话和整理记忆分给两个 agent 来做。主 agent 负责和用户对话，它没有修改自己常驻记忆的工具，常驻记忆指一直放在上下文窗口里的那部分记忆。另有一个 sleep-time agent 在后台运行，负责改写主 agent 的记忆。

Letta 的博客说，这样分开是因为 MemGPT 原来的设计有两个问题。在 MemGPT 里，对话和管理记忆都由同一个 agent 负责，它会变慢，也更容易出错。记忆又是一点点追加的，时间长了会变乱。分开之后，两个 agent 还可以用不同的模型，对话用快的，整理记忆用强的。

效果和适用的范围

论文用数学题来量效果，拿 sleep-time compute 和两种对照比。一种对照是回答时并行生成多个答案，只要其中有一个对就算对。另一种对照是通常的做法，也就是同一个模型不用 sleep-time compute，用户提问时才从原始的上下文开始推理。下图是其中一组数学竞赛题上和前一种对照比的结果。

{{fig 60 | 四个模型在一组数学竞赛题上的结果。横轴是回答每个问题时平均用的 token 数，纵轴是准确率。蓝线是用了 sleep-time compute，灰线是对照的做法：回答时并行生成多个答案，只要其中有一个对就算对。图片来源：Lin 等，2025。}}

论文对这张图的概括是，sleep-time compute 总体上胜过并行生成多个答案这种对照。从图上看，在蓝线有数据的范围里，回答时用同样多的 token，蓝线的准确率高于灰线。

所以这个方法主要的好处是回答时用的 token 变少。总的花费省不省要看条件：按表里的第二条，要看回答时的 token 比空闲时的贵多少、同一份上下文对应多少个问题。在回答时只允许用很少 token 的条件下，它也让回答更准。

回答时允许用的 token 很多时情况不同：论文的结果里，通常的做法略好一些。可以这样理解：知道了问题再去推理更直接，所以回答时的 token 不受限制时，提前推理很可能不会更准。这一点论文没有专门验证。

空闲时运行的模型能用哪些工具

让 agent 在后台使用的工具越多，就越要考虑一个安全方面的问题：没有人看着的时候，它在做什么。论文的数学题实验和软件工程案例里，空闲时运行的模型能用的工具不一样多。

数学题的实验里，空闲时运行的模型只能用两个工具：一个用新的文字替换掉当前的上下文，一个表示整理结束，前一个最多调用 10 次。论文没有提到它在这些实验里可以搜索或运行代码。

论文另有一个软件工程的案例，那里空闲时运行的 agent 可以先在代码仓库里查看一遍，再写出整理过的上下文。

A-Mem：每存一条新记忆，就检查旧记忆要不要更新

A-Mem（Xu 等，2025，论文页面注明被学术会议 NeurIPS 2025 接收）每存一条新记忆，都回头检查相关的旧记忆要不要更新。它给每条记忆配上关键词、标签和一句话的背景说明，这一页把这三样合称标注。新的信息会改变对旧信息的理解，所以旧记忆上的标注也要跟着变。

它借鉴的是一种做笔记的方法，叫 Zettelkasten，意思是卡片盒：每张卡片只记一件事，卡片之间用链接连起来。A-Mem 把每条记忆做成一张带标注的笔记。

{{fig 62 | A-Mem 的流程，从左到右四步：生成笔记，建立链接，更新旧记忆，检索。图片来源：Xu 等，2025。}}

i
A-Mem 名字里的「agentic」指什么。A-Mem 是 Agentic Memory 的缩写。agentic 的意思是像 agent 那样，由模型自己做决定。在 A-Mem 里它指的是：链接连到哪里、标注改成什么，都由语言模型决定，系统里没有为这两件事事先写好的固定规则。这个词容易让人以为有一个专门的 agent 在管理记忆。按论文的描述，A-Mem 是每次写入时固定执行的一串语言模型调用：一次生成笔记，一次判断链接，对每条相近的旧笔记各一次判断要不要更新。里面没有自己选工具、自己决定步骤的循环。这样做的代价是每存一条记忆要调用好几次模型。

论文在 LoCoMo 等对话基准测试（benchmark，一组题目加一个打分的办法）上做了实验。LoCoMo 是一组很长的模拟对话加上问答题，第六部分细讲。

这里只引用一个数：回答问题时放进 prompt 的长度。A-Mem 是 1,200 到 2,500 个 token，换一个模型来回答，这个数就不同：论文的成绩表里，用 GPT-4o 这个模型时是 1,216 个，用 GPT-4o-mini 时是 2,520 个。拿来对比的参照做法（基线，baseline）是把整段对话放进去，约 16,900 个。约 16,900 是 A-Mem 的论文自己统计的数，和 LoCoMo 公开的数据集里每组对话平均 16,618 个 token 接近。A-Mem 的 1,200 到 2,500 个只算了回答时取出的内容，写入时那几次模型调用用的 token 不在里面。

分问题类型的成绩这里不引用。这篇论文的几个版本以及引用它的论文里，类别的标法不一致。

Mem0：对每条新事实做四选一

Mem0（Chhikara 等，2025，被学术会议 ECAI 2025 接收）是一家同名公司的产品，读作 mem-zero。它用一套独立于回答模型的流程来管理记忆，每来一轮新的对话就处理一次，分提取和更新两个阶段。提取阶段从最新的一轮对话里提取出值得记的事实，这一页叫它们新事实。更新阶段决定每条新事实怎样写进已有的记忆。

{{fig 63 | Mem0 的基本流程。左边的提取阶段：语言模型读对话的摘要、最近的若干条消息和最新的一轮对话，提取出新事实。右边的更新阶段：为每条新事实找出最相似的旧记忆，再由语言模型通过一次工具调用，在 ADD、UPDATE、DELETE、NOOP 四个操作里选一个。图片来源：Chhikara 等，2025。}}

带图谱的版本

Mem0 还有一个把记忆存成知识图谱的版本。知识图谱（knowledge graph）把信息存成一张图：节点是实体，比如人和地点，边是实体之间的关系。图里的一条记录叫三元组，写成「实体、关系、实体」，比如「Alice，住在，旧金山」。

{{fig 64 | Mem0 的图谱版本。提取阶段从消息里提取实体，再生成实体之间的关系，得到一组三元组。更新阶段先在已有的图里找相关的节点，检测有没有冲突，再由语言模型决定怎样更新图。图片下方有两行字，写的是「一个后台的记忆流程检测冲突并自动更新记忆」和「用四个记忆操作来处理：ADD、UPDATE、DELETE、NOOP」。图片来源：Chhikara 等，2025。}}

这个图谱是 Mem0 自己建的，存在 Neo4j 图数据库里。它处理冲突的办法和基本版本不同：发现新的关系和旧的矛盾时，旧的关系被标记为失效，不会被删掉，这样以后还能回答和时间有关的问题。

标记失效和第二部分里 Zep 的做法是同一个思路。Zep 是另一个把记忆存成知识图谱的商业记忆服务，和 Mem0 是互相竞争的产品，Mem0 的论文把 Zep 当作对比的基线之一。

怎么读它的成绩

Mem0 的论文在 LoCoMo 上和几种做法比了三样：回答的准确率，回答时放进 prompt 的记忆有多少 token，回答要花多长时间。

论文摘要里有三个数：比 ChatGPT 的记忆功能高 26%，延迟低 91%，token 省 90% 以上。对着上面的表看，它们各自的含义是这样的。

  • 26% 量的是准确率，是相对比例：Mem0 基本版本的准确率是 66.88%，ChatGPT 的记忆功能是 52.90%，相差 14 个百分点。
  • 91% 量的是回答总耗时的 95 分位，是和「把整段对话放进上下文窗口」比的。Mem0 基本版本 95% 的回答在 1.440 秒以内，把整段对话放进去是 17.117 秒。
  • 90% 以上量的是回答时放进 prompt 的 token 数，也是和「把整段对话放进上下文窗口」比的。Mem0 基本版本放进 prompt 的记忆是 1,764 个 token，整段对话是 26,031 个。token 数只算回答时取出的记忆，提取和更新记忆时调用模型用的 token 不在里面。

这三个数都没有提到表里的另一件事：准确率最高的是把整段对话放进上下文窗口。它比 Mem0 的两个版本高 4 到 6 个百分点。论文自己也写明了这一点，并说这种做法延迟太高，不实用。

所以按这篇论文自己的数据，在一段 2.6 万 token 的对话上，表里的记忆系统准确率都比把整段对话放进去低，好处在回答更快、用的 token 更少。把整段对话放进去时，回答总耗时的 95 分位是 Mem0 两个版本的 7 到 12 倍左右，放进 prompt 的 token 是 Mem0 两个版本的 7 到 15 倍左右。

表里整段对话的长度和 LoCoMo 论文给的数对不上：这张表里是 26,031 个 token，LoCoMo 论文给的平均值是 16,618 个。两篇论文都没有说明差别来自哪里，核对的经过见资料说明。

四种模式放在一起

第二部分说设计记忆系统要回答三个问题，前两个是存什么、什么时候存取。下表按这两个问题把四种模式排在一起，最后一列是每种模式主要的取舍。

四种模式的取舍有一个共同点：每多做一步加工，记忆就更好用一些，加工后的内容也更可能和原始的记录不一致。做法是从轨迹里归纳的，分层的记忆会把移出上下文窗口的消息写成摘要，反思是从观察里推出来的，维护会改写甚至删掉旧的内容。加工错了的时候，如果原始记录还在，就有办法回头查。这也是第一部分说要留着情景记忆的原因。

这些系统到底好不好用，要靠评测来回答。下一部分讲怎么评测记忆。

资料说明

这一节记录核对资料时发现的出入和没有查到的地方。前面各节的结论已经按核对的结果来写。

  • Mem0 图谱版本配图下方的「后台」一词。图片下方有一行字说，一个后台的记忆流程检测冲突并自动更新记忆。论文只写了每收到一轮新消息就处理一次，没有写明提取和更新是在后台运行的。第二部分把 Mem0 归在后台的流程，指的是提取和更新记忆由一套独立于回答模型的流程来做。出处：Chhikara 等，2025。
  • Mem0 成绩表里检索一行的 token 数。论文试了 14 种检索配置，表里是成绩最好的一种：取 2 个片段，每个 256 个 token。这一行的 token 数论文的表没有另给，512 是按 2 个片段的长度粗略估算的上限。出处：Chhikara 等，2025，表 2。
  • LoCoMo 每组对话有多长。Mem0 成绩表里整段对话是 26,031 个 token，Mem0 的论文正文说平均约 2.6 万。LoCoMo 论文给的平均值是 16,618。Mem0 的论文写明自己用 tiktoken 的 cl100k_base 编码来数 token。tiktoken 是 OpenAI 公开的数 token 的工具，cl100k_base 是其中一套切分文字的规则。差别来自哪里，两篇论文都没有说明。出处：Chhikara 等，2025，表 2；Maharana 等，2024。
  • A-Mem 论文里 LoCoMo 的两种长度。A-Mem 的成绩表里，把整段对话放进去的做法回答一个问题平均用 16,910 个 token，正文写作 16,900，和 LoCoMo 公开的数据集的 16,618 接近。同一篇论文介绍 LoCoMo 时写的是对话平均 9 千 token、共 7,512 个问题，这是 LoCoMo 最早上传到 arXiv（研究者公开上传论文的网站）的版本的数字，两个版本的差别见第六部分。出处：Xu 等，2025，第 4.1 节和表 1。
