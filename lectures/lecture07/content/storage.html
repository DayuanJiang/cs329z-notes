先看结论

  • 设计一个记忆系统，要回答三个问题：存什么，什么时候存取，怎么存取。每一个记忆系统都要回答它们，读一个系统时可以拿这三个问题去问它。
  • 什么时候存取，常见的答案是三种触发方式：agent（能自己调用工具、分很多步去完成任务的语言模型系统）按需调用工具，后台的流程自动处理，由某个事件触发。
  • 怎么存取，常见的答案是三种存放的办法：文件系统、数据库、知识图谱。文件系统最简单，查找时靠模型自己一步步去搜索和打开文件，所以慢。数据库查得快。知识图谱把信息存成实体和实体之间的关系，能表达事物之间的关系和随时间的变化，建起来最费事。
  • 一个实用的建议是：能用文件系统就先用文件系统。文件系统满足不了要求时，比如对查找速度有要求，再考虑另外两种。
  • 后面三部分讲四种架构模式，也就是已有的系统回答这三个问题时常见的四种组合：从经验里学做法，分层的记忆，反思式整理，记忆维护。从经验里学做法指 agent 把做成的任务整理成可以再用的做法存起来。分层的记忆指上下文窗口（context window，模型一次能读进去的全部文字）里只留一部分随时要用的信息，其余的存在外面，需要时再取进来。反思式整理指让模型从经历里总结出结论，把结论也存进记忆。记忆维护指记忆存进去之后继续整理。

什么时候存取：三种触发方式

「什么时候存取」的常见答案有三种，区别在于一次存或取是怎样启动的，所以叫作三种触发方式。第一种由做任务的 agent 自己决定。第二种由做任务的 agent 之外的另一套流程决定。第三种在系统里事先定好的某件事发生时自动启动。下表列出这三种方式和各自的例子。

前两种方式之间有一个取舍。让 agent 自己决定最灵活，但它可能忘了去存，也可能忘了去查，第一部分开头那个经营小店的 agent Luna 就是存了却没有去查的例子。交给后台的流程更可靠，代价是多一套要设计和运行的东西。

表里的例子提到 MemGPT、Mem0 和 Letta 三个名字。MemGPT 是一个让模型自己用函数读写记忆的系统。Mem0 是一个每轮对话之后自动提取和更新事实的记忆系统。Letta 是一家做 agent 产品的公司，它的研究者里有好几位是 MemGPT 的作者。它的产品里有两个 agent：主 agent 负责和用户对话，sleep-time agent 专门在后台整理记忆。表里的技能文件是写着某一类任务该怎么做的文件，agent 需要时自己去读。

三种方式可以同时用。MemGPT 就是表里第一种和第三种的结合：平时由模型自己决定存什么、查什么，上下文窗口快满时由事件提醒它。

怎么存取：三种存放的办法

不管记忆是哪一种，都需要一个办法把信息存下来，以后再读出来。最常见的三种办法是文件系统、数据库和知识图谱。下面三节各讲一种，之后一节放在一起比较。

这一页按 agent 存取记忆时面对的是什么来分这三种办法：一个个文件，一条条可以检索的记录，或者由实体和关系组成的知识图谱。信息实际写在哪一种存储里是另一回事。下一节的产品例子里，agent 面对的是文件，这些文件实际存在数据库里，这一页仍把它算作文件系统的办法。

文件系统：把记忆存成文件

最直接的办法是把记忆存成文件，让 agent 自己管理这些文件。一个文件里可以只有一条记忆，也可以有很多条。这样做有三个特点。

  • 天然有层级。文件放在文件夹里，文件夹可以再套文件夹。agent 可以先看一个文件夹里有什么，再进到子文件夹里看。
  • 不需要专门的记忆工具。列目录的 ls、搜索文字的 grep 这些命令行工具，就是读记忆的工具。写记忆就是写文件。
  • 模型本来就会用。现在的模型很擅长操作文件系统，读写文件的命令不用额外教。什么时候该记、记到哪个文件里，仍然要在 prompt（给模型的输入文字）里向它说清楚，下面的产品例子会讲到。

数据库：把记忆存成可以检索的记录

第二种办法是把记忆存进数据库，用检索的办法取。第 3 讲讲过检索增强生成（RAG，先检索相关的资料，再让模型根据资料作答），那里介绍的技术在这里都用得上。按怎么查，可以分成三种。

三种查法经常混着用，也可以对不同的内容用不同的查法。第四部分的 MemGPT 就是这样：上传的文档转成向量来搜，对话的原文则保留全文，按字符串和日期来查。哪些内容该转成向量、哪些该保留全文做精确查找，没有统一的答案，要看具体的应用。

知识图谱：把记忆存成实体和关系

第三种办法是知识图谱，它最不直观。前两种办法把记忆存成一个个文件或一条条记录。知识图谱还能表达事物之间的关系，以及这些关系随时间的变化。后一点针对的是第一部分里饮食偏好那个例子暴露的问题：用户的情况变了，记忆得知道哪一条是现在的、哪一条是过去的。

知识图谱（knowledge graph）把信息存成一张由节点和边组成的图，下面简称图谱。节点是实体，比如人、公司、产品。边是实体之间的关系，比如「任职于」「喜欢」。

这里用 Zep 来说明。Zep 是一个面向 agent 的商业记忆服务，它的论文在 2025 年 1 月上传，核心是一个叫 Graphiti 的知识图谱引擎。

{{fig 28 | 左：Zep 官网上的示意图。节点是人、公司、话题、产品，边上写着关系，其中一条是「任职于，到 2026 年 3 月为止」。右：一篇教程里画的 Zep 的三层结构，从上到下是原始片段、实体和关系、社区。教程的图上把第一层标为原始数据，把第三层标为聚类和它们的摘要。图片来源：getzep.com 和 Daily Dose of Data Science。}}

配图右边的三层结构和左边那条带时间的边，下面分两小节讲。

三层结构

Zep 的图谱分三层，下表从最原始的一层列到概括程度最高的一层。

举一个例子。用户在一次对话里聊到自己的狗，还提到表弟很喜欢这条狗。系统读了这段对话，会建两个实体，「表弟」和「狗」，再在两者之间连一条边「喜欢」。对话越积越多，这张图谱会变得很大。这时第三层就有用了：查找时可以先从社区这一层找出相关的是哪一群实体。怎样找，下面讲查找的小节会说。

按 Zep 论文自己的说法，原始片段这一层对应情景记忆，实体和关系这一层对应语义记忆。知识图谱主要用来存语义记忆。做法这类程序性记忆也可以写成「先做这一步、再做那一步」的图谱，但很少有人这样做。

事实会过期

Zep 的一个特点是每条事实都带时间。一条边上记着这件事从什么时候开始成立、到什么时候不再成立。新的信息进来时，语言模型把它和图谱里相关的旧事实对比，如果发现矛盾，旧的那条边会被标上失效的时间，但不会被删掉。配图里那条「任职于，到 2026 年 3 月为止」的边就是这个意思：这个人曾经在这家公司工作，现在不在了，两件事图谱里都记着。

这样，用户的情况变了之后怎样分清哪一条是现在的，就有了答案：现在成立的事实和过去成立的事实都留在图谱里，靠边上的时间分开。

查的时候有什么不同

图谱比前两种办法多出来的，是可以沿着关系查。Zep 提供三种搜索：向量相似度，BM25 关键词匹配，以及从某个节点出发、沿着边向外一层层找的广度优先搜索。前两种找的是文字上或意思上相近的内容，第三种找的是在图谱上离得近的内容。

搜索的对象有三类：事实，实体，社区。搜社区时比对的是社区的名字，这个名字由社区摘要里的关键词组成。搜到的结果再经过一次重新排序（rerank，用另一套打分办法把初步搜到的结果按相关程度重新排一遍），最后交给 agent。事实会连同它成立的时间段一起给出，社区给出的是它的摘要。

换一个角度看，三种办法的差别在于查找时的判断由谁来做。文件系统的办法让模型自己一步步去搜索和打开文件。数据库的办法由检索程序来查，一次查询就返回结果。图谱的办法在存入时先把关系整理好，查找时由检索程序沿着这些关系去找。和数据库的办法比，查找的过程多做了一件事：顺着关系把有关的信息一起找出来，这件事不用再靠模型。

Zep 论文里的两组成绩

Zep 的论文在两个测试上报告了成绩，下表把它和「把全部对话直接放进上下文窗口」的做法放在一起。深度记忆检索（DMR）是 MemGPT 论文提出的测试，考 agent 能不能回答关于以前对话的问题。

LongMemEval 是另一个考长期对话记忆的基准测试（benchmark，一组题目加一个打分的办法），每个问题要读的对话历史平均约 11.5 万 token。token 是模型处理文字的最小单位，大致是一个词或半个词。LongMemEval 和下一节的 LongMemEval-V2 是两个测试，后者考的是 agent 的运行轨迹（trajectory，每一步的动作和看到的结果的完整记录）。

深度记忆检索上，同样用 GPT-4 Turbo 时几种做法的成绩很接近。Zep 是 94.8%，把全部对话放进上下文窗口是 94.4%，MemGPT 论文报告的带 MemGPT 的成绩是 93.4%。第四部分引用的 92.5% 是 MemGPT 配 GPT-4 时的成绩。Zep 的作者自己说，这个测试里每组对话只有 60 条消息，放得进现在模型的上下文窗口，不足以用来评价记忆系统。

LongMemEval 上 Zep 领先得多。它只取大约 1,600 个 token 的内容交给模型，准确率比把全部对话放进上下文窗口高 11 个百分点，回答也快得多。论文摘要里说的「准确率最多提高 18.5%」是相对比例，指的就是这 11 个百分点。

分问题的类型看，有一类是例外。LongMemEval 的问题分六类，其中一类考模型记不记得聊天助手在某一次对话里说过的内容。在这一类上，用 GPT-4o 时把全部对话放进上下文窗口的准确率是 94.6%，Zep 是 80.4%，低 14.2 个百分点。Zep 的论文自己把这一类称为值得注意的例外。

读 LongMemEval 这组成绩时要留意对比的对象。这是产品方自己写的论文，拿来对比的参照做法（基线，baseline）只有把全部对话放进上下文窗口这一种，没有和别的记忆系统在这个测试上比。

三种办法怎么选

下表把三种办法放在一起比较。

介绍一个系统的论文通常都论证自己的系统最好，所以很难从论文里得出一个通用的排名。这一讲的建议是：能用文件系统的地方，就先用文件系统。理由是它的结构最简单，查什么、怎么查都让模型自己决定，现在的模型做得了这件事。告诉模型「这是你的文件系统，把它当记忆来用」，很多时候就行得通。

模型会操作文件，和它知道什么时候该记、该记到哪个文件里是两回事。前面 LangChain 的产品里，后一件事要靠反复改 prompt 来解决。

文件系统满足不了要求时，比如对查找速度有要求，再考虑另外两种办法。按上表列的好处和代价，如果只要求查得快，可以用数据库。如果要表达事物之间的关系和随时间的变化，可以用知识图谱，代价是建图谱要调用很多次语言模型。

文件系统的代价是延迟。agent 每查一次记忆，都要运行命令、读结果、推理、再决定下一步，来回好几轮。

第六部分的 LongMemEval-V2 基准测试给出了一组具体的数字。它考的是记忆系统能不能从 agent 过去的大量运行轨迹里找到答案，这些轨迹是操作网页的 agent 在几个网站上做任务留下的。

这个测试把查找和作答分成两步。被测的做法负责查找，也就是针对一个问题找出有关的内容。找出的内容再交给一个固定的小模型，由它写出答案。

这个测试一共比较了四种被测的做法。下表列出其中三种的准确率和查询耗时，第四种在表后的段落里讲。表里的前两种靠检索来查，属于数据库的办法。表里的第三种把轨迹存成文件，属于文件系统的办法。这个测试没有测知识图谱的办法。

表里第一行取出的有两样东西。片段是轨迹里相邻几步的记录。笔记是存入每条轨迹时由语言模型写的两条概括，一条总结可以再用的任务步骤，一条记下这条轨迹所在的网站特有的情况和容易出错的地方。

准确率最高的是文件加写代码的 agent，它的查询耗时是最基本的检索的几百倍。

准确率的差距有一部分来自查找用的模型不同。前两行检索用的向量模型是 Qwen3-Embedding-8B，第二行写检索词的小模型是 Qwen3.5-9B，第三行负责查找的是 GPT-5.4-mini。

所以这组实验能说明的是：把轨迹存成文件、让 agent 自己去查的做法更准，靠检索的做法更快，其中准确率的差距不能全算在存放的办法上。选存放的办法时要做的取舍，就在准确率和查找速度之间。

四种架构模式一览

前面几节讲的是三个问题各自常见的答案。已有的系统回答这三个问题时，常见的组合有四种，这一讲把它们叫作四种架构模式。

这四种模式是对已有论文的一种归纳。记忆系统怎样分类，目前没有公认的标准。一个系统也可以同时用到几种模式。比如 Letta 的产品沿用 MemGPT 的分层的记忆，又加了一个在后台整理记忆的 sleep-time agent，表里第二种和第四种模式都用上了。把它们分开讲，是为了看清每一种做法各自解决什么问题、带来什么代价。

下一部分从第一种模式讲起：从经验里学做法。
