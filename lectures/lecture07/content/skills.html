先看结论

  • 已有的记忆系统可以归纳成四种架构模式：从经验里学做法、分层的记忆、反思式整理、记忆维护。这一部分讲模式一。
  • 模式一是从经验里学做法。它存的是程序性记忆（procedural memory），也就是「怎样把一件事做成」的知识。agent（能自己调用工具、分很多步去完成任务的语言模型系统）做成一件事之后，把做法整理成可以再用的形式存起来，以后遇到相关的任务时取出来用。
  • 三个例子存的形式不同。Voyager 是一个在游戏 Minecraft 里自己探索的 agent，它靠写程序来操作游戏，存的就是做成了任务的程序，按描述的相似程度检索。Agent Workflow Memory 面向操作网页的 agent，存的是带变量的文字步骤，论文把它叫作工作流（workflow），整批放进 prompt（给模型的输入文字）。技能文件是一个个 Markdown 文件，每个文件写着一类任务该怎么做，agent 先看到每个文件的名字和描述，需要时再去读全文。
  • 技能库是 Voyager 存放这些程序的地方。它起了多大作用，要分两个实验看。在自由探索的实验里，带技能库的版本是唯一做出钻石工具的方法，三次运行里成功了一次。钻石工具是游戏里四级工具中最难做的一级。在另一个给定目标的实验里，去掉技能库的版本也做出过钻石镐，钻石镐是钻石工具的一种。
  • Agent Workflow Memory 的论文报告任务成功率有提高，提高多少要看和哪一个参照做法比。参照做法（基线，baseline）是论文拿来和自己的方法比成绩的别的做法。WebArena 是一个考 agent 操作网页的基准测试（benchmark，一组题目加一个打分的办法），有 812 个任务。Agent Workflow Memory 在 WebArena 上的任务成功率是 35.5%，论文拿来对比的参照做法是 23.5%。
  • 这两个成绩的输入不一样，输入指每一步给模型看的网页内容。23.5% 的那个参照做法输入里比 Agent Workflow Memory 多一份网页的 HTML。另一个参照做法输入和 Agent Workflow Memory 相同，任务成功率是 15.0%，Agent Workflow Memory 比它高 20.5 个百分点。
  • 共同的局限是存下来的做法不会自己更新。环境变了，旧做法就过时了，而 Voyager 和 Agent Workflow Memory 的论文都没有讲怎样修改或删除旧的做法。

这种模式在做什么

没有记忆的 agent，每次都要重新摸索同一件事怎么做。这种模式让 agent 把摸索出来的做法留下来。它的流程可以分成四步。

  1. 做任务。agent 照常完成一个任务，留下一条运行轨迹（trajectory，每一步的动作和看到的结果的完整记录）。
  2. 判断做成了没有。只有成功的轨迹才值得学。判断的办法可以是环境给出的结果，也可以是让另一个模型来判断。
  3. 把做法整理出来，存进记忆。整理的结果可以是一段代码、一份分步骤的文字说明，或者一个文件。
  4. 以后取出来用。遇到相关的新任务时，把存下的做法放回上下文窗口（context window，模型一次能读进去的全部文字）。

下面三个例子里，Voyager 四步都有。Agent Workflow Memory 从 agent 自己做任务留下的轨迹里学的时候，也是四步都有。它还可以从事先准备好的示范里学，这种情况下没有前两步。技能文件可以由人直接写好放进去，这种情况下也没有前两步。

Voyager：把做法存成代码

Voyager 是一个在 Minecraft 里自己探索的 agent，由 NVIDIA、加州理工等机构的研究者在 2023 年 5 月提出。整个过程不改模型的权重（模型训练出来的参数），学到的东西都存在技能库里。

它用代码来操作游戏：GPT-4 写一段 JavaScript 程序，程序通过 Mineflayer 这个库提供的接口控制游戏里的角色。它不看游戏画面，游戏的状态以文字的形式给它，比如背包里有什么、附近有什么生物。

{{fig 31 | Voyager 的三个部分。左边是自动课程（Automatic Curriculum，系统里负责出题的部分）提出的一串任务，比如做工作台、打僵尸、挖钻石。中间是迭代提示机制（Iterative Prompting Mechanism，系统里负责把程序改到能用的部分），图里画的是 GPT-4 为「打僵尸」写的程序。右边是技能库，存进去的每一段程序叫作一个技能。下方是 Minecraft 环境和自我验证，迭代提示机制按它们给出的结果来改程序：验证通过，新技能加进技能库。没有通过，就带着环境的反馈和报错信息去改程序。图片来源：Wang 等，2023。}}

图里的三个部分各管一件事。

技能怎么存，怎么取

技能库是这个系统里的记忆，存进去的每一段程序叫作一个技能。它是一个向量数据库，每个技能存两样东西：程序本身，和由程序的描述转成的向量。下图的上半部分是存技能的过程，下半部分是取技能的过程。

{{fig 32 | 上半部分是存技能，下半部分是取技能。图片来源：Wang 等，2023。}}

存和取各是这样做的。

  • 存。GPT-4 写出的程序先交给 GPT-3.5 写一段描述。图里「打僵尸」的描述是：这个函数先装备一把石剑，没有就做一把，再做一面盾牌，恢复饥饿值，然后去找僵尸战斗。描述转成向量之后作为键，程序本身作为值。
  • 取。遇到新任务，比如「做一把铁镐」，GPT-3.5 先写一段大致怎么做的建议。这段建议加上环境的反馈，转成向量去技能库里查，取出最相近的 5 个技能。这 5 个技能的代码会放进 GPT-4 写新程序时的 prompt，新程序可以直接调用它们。

取技能时用到的环境的反馈，是程序运行时游戏里返回的文字。从 Voyager 公开的源代码看，一个任务刚开始、GPT-4 写的程序还没有运行过时，Voyager 只用那段建议去查。程序每运行一轮，Voyager 就从这一轮游戏返回的文字里找出还缺哪些东西，写成一句话加到建议后面，重新查一次。出处：Voyager 代码仓库的 voyager.py。

新技能可以调用旧技能，所以复杂的技能是由简单的技能一层层搭起来的。图里「打僵尸」的程序就调用了「做石剑」和「做盾牌」这两个更早存下的技能。

查询和键只要意思相近就能匹配上，不要求文字完全一样。论文在附录里检查了检索的准确度，只说一共评了 309 个样本，没有写明一个样本是什么、怎么选出来的。需要的技能出现在前 5 个结果里的比例是 96.5%，排在第 1 个的比例是 80.2%。

i
技能库里会不会有重复的技能。论文正文没有讲怎样处理重复或相近的技能。从 Voyager 公开的源代码看，新技能和已有的技能函数名完全相同时，技能库里的条目会被新程序替换，旧的程序文件留在磁盘上，新文件的名字后面加上 V2、V3。源代码里没有检查两个技能做的事是否相近，所以名字不同、功能差不多的技能可以同时存在。出处：Voyager 代码仓库的 skill.py。

Voyager 的结果：技能库起了多大作用

论文用两个实验来看技能库的作用。第一个实验让各个方法自由探索，看多少轮之内能做出某一级的工具。这里的一轮，指让模型生成或修改一次代码。Minecraft 里的工具从木质、石质、铁质到钻石，一级比一级难做。

表里拿来对照的有两类。一类是 ReAct、Reflexion、AutoGPT 这三种已有的 agent 做法，论文作者按原来的思路在 Minecraft 里各写了一个版本。另一类是去掉技能库的 Voyager。

三种已有的做法各是这样的。ReAct 让模型每一步先写出推理，再给出动作。Reflexion 在 ReAct 的基础上加了一步，让模型反思之前的尝试。AutoGPT 把一个大目标拆成一串子目标，再一个个去执行。论文说明，和 Voyager 相比，AutoGPT 没有技能库，没有检查任务做成与否的自我验证，也没有自动课程。

  • 带技能库的 Voyager 是唯一做出钻石工具的方法。
  • 去掉技能库之后，前三级工具仍然做得出来。铁质工具慢了一些，去掉技能库的版本用了 29 轮，带技能库的版本是 21 轮。石质工具反而略快，去掉技能库的版本用了 9 轮，带技能库的版本是 11 轮。
  • Voyager 的两个版本都比 AutoGPT 快很多。连去掉技能库的版本也比 AutoGPT 快很多，所以这个差距来自技能库以外的部分，论文把它归功于自动课程。

换到没见过的任务上

第二个实验更能说明技能库的用处。agent 被放进一个新的世界，背包清空，目标是四样东西：钻石镐、金剑、岩浆桶、指南针。论文把它们称为没见过的任务（unseen tasks）。

两个版本的差别在写程序时能不能取到技能。带技能库的 Voyager 用的是它在之前的探索中积累下来的技能库。去掉技能库的 Voyager 写程序时取不到任何技能。

{{fig 34 | 图的上半是第一个实验的表，内容和前面第一张表相同。图的下半有两张小图，是第二个实验里的两个任务：左边是做金剑，右边是收集岩浆桶。横轴是轮数，纵轴是从砍木头到最终目标要依次做出的东西，线越早升到顶越好。橙色是 Voyager，黄色是去掉技能库的 Voyager，浅紫色是 AutoGPT，深紫色是加上 Voyager 技能库的 AutoGPT。图片来源：Wang 等，2023。}}

四个任务上，带技能库的 Voyager 都是三次全部成功，用的轮数也都比去掉技能库的版本少。差得最多的是钻石镐，带技能库的版本平均用 19 轮，去掉技能库的版本用 36 轮。差得最少的是岩浆桶，两个版本分别用 21 轮和 27 轮。图里橙色的线比黄色的线更早升到顶，说的就是这件事：很多中间步骤可以直接取用存好的技能，不用重新写。

另一个值得注意的结果是 AutoGPT。它自己一个任务都做不成，加上 Voyager 积累的技能库之后，有三个任务至少成功了一次。论文据此说，技能库可以直接给别的方法用。右边收集岩浆桶的那张图里，深紫色的线停在「岩浆源」这一步，没有到顶，和表里岩浆桶那一格的「没做到」是一致的。

论文的消融实验（每次去掉系统的一个部分，看成绩下降多少）还有一个观察：去掉技能库的版本，在探索的后期会停滞不前。作者的解释是，技能库让新技能可以调用旧技能，agent 才能不断做出更复杂的动作。

Agent Workflow Memory：把做法存成带变量的步骤

Agent Workflow Memory（下面简称 AWM）是卡内基梅隆大学和麻省理工学院的研究者在 2024 年 9 月提出的方法。它和 Voyager 的思路相近，面向的是更一般的场景：操作网页的 agent。这类 agent 通过点击、填写、滚动这些动作在网站上完成任务，比如查出某个订单是谁下的。

{{fig 35 | AWM 的论文把整个过程画成三步。左下是第一步，得到一串动作：点「订单」链接，滚动找到 0130 号订单，把下单人的名字发给用户。中下是第二步，判断这条轨迹有没有把问题答对。右边是第三步，从做对的轨迹里归纳出工作流，再放回 agent 的记忆。「这种模式在做什么」一节说的四步里，第三步「把做法整理出来，存进记忆」对应图里的第三步，第四步「以后取出来用」在图里没有单独画成一步。图片来源：Wang 等，2024。}}

下面四小节依次讲工作流是什么、怎么归纳出来、放在哪里，以及后学到的工作流怎样沿用先学到的。

工作流是什么

AWM 把存下来的做法叫作工作流（workflow）。一个工作流有两部分：一句话描述它是做什么的，加上一串步骤。每一步又有三样：对当前页面状态的描述，agent 为什么要这样做的推理，以及一个可以执行的动作。

{{fig 37 | 两个工作流的例子。上面一个是购物网站上「浏览某个类别的商品」，下面一个是购物网站的管理后台上「修改并保存」。图片来源：Wang 等，2024。}}

拿上面一个来看。它说的是：要浏览某个类别的商品，先把鼠标悬停在主类别的菜单项上，让子类别显示出来，再点击子类别的链接。这是 agent 从经验里学到的一条关于这个网站的知识：子类别藏在一个悬停才出现的下拉菜单里。

工作流有两个特点，都是在归纳时特意要求的。

  • 粒度小。工作流对应的是会在很多任务里反复出现的子任务，比如「在网站上搜索一件商品」，不对应某一个完整的任务。
  • 具体的值换成了变量。图里的 main_category_id、field_id 都是变量。原来轨迹里的「干猫粮」这类具体的词，会换成 {product-name} 这样的名字，工作流才能用到别的商品上。

工作流怎么归纳出来

归纳这一步是让语言模型做的。给它的指令很短，先交代任务：给定一组网页操作任务，每个任务有一条指令和完成它的一串动作，请找出在多个任务里重复出现的那部分动作，把每一段提取成一个工作流。指令里另有四条要求。

  • 每个工作流应该是经常被重复使用的子流程。
  • 不要生成相似或重叠的工作流。
  • 每个工作流至少有两步。
  • 会变的内容用有含义的变量名表示。

归纳可以在两种情况下进行。

在线的情况有一个明显的风险：评判的模型会判错。论文自己也指出，agent 自己做任务留下的轨迹不一定是对的，从这样的轨迹里归纳，可能归纳出错误的工作流，反过来拉低成绩。

工作流放在哪里

AWM 把归纳出来的工作流直接加进 agent 的 prompt，作为解决任务时的参考，中间没有检索这一步。为了让放进去的工作流和任务相关，论文按网站分组：每个网站单独归纳一套工作流，做这个网站的任务时，只放这个网站的那一套。

这样做在几百个任务的实验里没有问题。agent 如果要长期运行，工作流会越积越多，全部放进 prompt 就行不通了，需要像 Voyager 那样加一个检索的步骤。

工作流会越学越复杂

下图是两个工作流，后学到的一个沿用了先学到的一个。

{{fig 12 | 左边是先学到的工作流「按名字找一个地点」：在地图网站上搜索地点的名字。右边是后学到的工作流「查一个地点的邮政编码」：前几步直接沿用左边的做法，后面加上从搜索结果里读出邮政编码并告诉用户。图片来源：Wang 等，2024。}}

在线的情况下，前面学到的工作流会成为后面工作流的一部分。图里的 agent 先学会了怎样在地图上找到一个地点。之后遇到要查邮政编码的任务，它先照已有的工作流找到地点，再往下多做几步，这个更长的做法又被存成一个新的工作流。这和 Voyager 里新技能调用旧技能是同一个道理。

AWM 的结果

论文在两个网页操作的基准测试上做了实验。WebArena 有 812 个任务，分布在五个网站上，按任务最后有没有做成来算成功率。Mind2Web 主要看每一步做得对不对：选中的页面元素和对它做的动作都对，这一步才算成功。

下表是 WebArena 上的结果。表里的 BrowserGym 和 SteP 是论文拿来对照的两种已有做法。BrowserGym 不用人写的网站知识，AWM 就是在它的框架上搭的。SteP 给 agent 配上了专家手写的工作流。

论文摘要里有两个相对提高的数，量的是两种指标。「在 WebArena 上相对提高 51.1%」指的是任务成功率，是 35.5% 相对 23.5% 的提高幅度，两者相差 12.0 个百分点。「在 Mind2Web 上相对提高 24.6%」指的是每一步的成功率，量的是单步对不对：论文拿来对照的已有做法 MindAct 是 36.2%，AWM 是 45.1%。两者用的模型都是 GPT-4，AWM 用的是离线的版本。

WebArena 上的 12.0 个百分点是和输入更多的做法比出来的。23.5% 那一行的输入比 AWM 多一份 HTML。和输入相同、成功率是 15.0% 的那一行比，AWM 高 20.5 个百分点。

步数也少了。AWM 平均每个任务用 5.9 步，输入相同的那个参照做法是 7.9 步。

AWM 比用了人写工作流的 SteP 高 2.5 个百分点。分网站看，两者互有高低：SteP 在购物、Reddit、GitLab 三个网站上更高，AWM 在购物网站的管理后台和地图上更高。可以说自动归纳的工作流大体上达到了专家手写的水平，在一部分网站上更好。

{{fig 38 | 左边的表是 WebArena 里题目模板互不相同的那部分任务上的成功率，后面一小节有说明。右边的曲线是 AWM 在地图网站的任务上的累计成功率：横轴是已经做完的任务数，纵轴是到这时为止的平均成功率。虚线左边标的是快速学习阶段，右边是稳定阶段。图片来源：Wang 等，2024。}}

右边的曲线说明 AWM 需要的例子不多。论文的说法是，agent 在最初的 0 到 40 个任务里学到了最要紧的工作流，成功率快速上升，之后趋于稳定。曲线在最初十几个任务时就有一段很陡的上升，但那时参与平均的任务太少，数值波动很大，这一段不能当作已经学会的依据。论文把学习阶段的终点放在 40 个任务左右。这条曲线只是地图这一个网站的结果。

AWM 不改模型的权重，学到的东西全部以文字的形式放在 prompt 里，几十个任务就能看到效果。和强化学习比，它需要的例子很可能少得多。强化学习让模型在环境里反复尝试，按得到的奖励更新权重，通常要靠大量的尝试才能把权重改好。这是按两种做法各自的特点作的判断，AWM 的论文没有和强化学习做对比实验。优化 prompt 和优化权重这两条路线的比较，第 9 讲会讲到。

成绩是不是靠同模板的任务互相照搬

前面那张图左边的表检查的就是这件事。WebArena 的很多任务是从同一个模板生成的，只换了里面的具体内容，做法几乎一样。在线的 AWM 做完其中一个，学到的工作流正好能用在同模板的下一个任务上。为了排除这种情况，论文从每个模板里只随机留一个任务，得到一个 197 个任务的子集，再测一遍。

排除了同模板的任务之间互相照搬之后，AWM 仍然领先。分网站看，购物网站上 SteP 是 26.5%，高于 AWM 的 24.5%。

技能文件：把做法写成 agent 自己会去读的文件

技能文件是通用的 agent 存做法的一种办法，属于程序性记忆。它比前两种简单得多：做法就写在一个 Markdown 文件里，agent 需要的时候自己去读。

这里用 Anthropic 的 Agent Skills 来说明。它的文档把技能定义为一个个模块，每个模块打包了指令、元数据（描述这个模块的简短信息）和可选的资源（脚本、模板），模型在相关的时候会自动使用。

从文件上看，一个技能是一个文件夹。里面的 SKILL.md 就是技能文件，文件夹里别的说明文件和脚本是它附带的资源。这里说的技能和 Voyager 的技能是两样东西：Voyager 的一个技能是存进技能库的一段程序。

{{fig 39 | 一个技能的样子。左边是技能的文件夹，里面有 SKILL.md、两份说明文档和一个 Python 脚本。右边是 SKILL.md 的内容：开头蓝色的一块是元数据，写着名字和描述。下面是正文，写着品牌用的颜色和字体。图片来源：Anthropic 的技能入门教程。}}

图里的技能教 agent 怎样把 Anthropic 的品牌颜色和字体用到 PowerPoint 演示文稿上。它的 SKILL.md 由两部分组成。

  • 元数据。文件开头用 YAML 格式写的两项：名字（name）和描述（description）。文档把这两项合称元数据。描述要同时说清这个技能做什么、什么时候该用它。
  • 正文。自由格式的 Markdown，写具体怎么做。这里写的是品牌的主色有哪几种、各用在什么地方，标题和正文各用什么字体。

分三层加载

一个 agent 可以装很多技能。如果把所有技能的全文都放进上下文窗口，窗口很快就满了。技能文件的办法是分层加载，文档里叫 progressive disclosure，意思是需要多少才加载多少。

{{fig 40 | 上下文窗口里的情况。最上面是 agent 的系统 prompt，后面跟着每个技能的名字和描述，一个技能一小段，图里有 bigquery、docx、pdf、pptx、xlsx 等。右上角放大了 xlsx 这一段，里面只有名字和描述。往下是用户的请求：填一份 PDF 表格。模型于是用 bash 命令读出 PDF 技能的 SKILL.md，又根据其中的指引读了 forms.md。图片来源：Anthropic 的 Agent Skills 文档。}}

Voyager 用向量数据库检索技能库里的程序，AWM 把一个网站的全部工作流都放进 prompt。技能文件要做的只有两件事：把文件放好，并且让模型知道有这些文件。读哪个、什么时候读，由模型自己判断，向量数据库和专门的检索程序都用不上。

可以这样理解这种做法为什么行得通：模型足够强之后，给它一个文件系统和读写文件的工具，一部分原来要专门搭建的东西就可以省掉。

技能文件可以由人写好放进去，也可以由 agent 自己写。后一种情况下，它就成了 agent 给自己记下的做法。第二部分里 LangChain 公司的产品经验说明了让 agent 自己写这些文件时会遇到的问题，比如该记的时候不记、把内容写错了文件。

i
照着图里的名字写会通不过检查。这一节第一张图里技能的名字写的是「Anthropic Brand Style Guidelines」。按现在的文档，名字只能用小写字母、数字和连字符，最长 64 个字符，而且不能含有 anthropic 和 claude 这两个保留词。合规的写法类似 brand-style-guidelines。描述最长 1,024 个字符。

局限：环境变了，存下的做法会过时

这种模式的三个例子有一个共同的局限：存下来的做法不会随着环境的变化自己更新。环境变了，旧做法就可能不再管用，甚至会误导 agent。

{{fig 41 | 右边是两张 Minecraft 的截图。上面是原版的游戏。下面是装了模组（玩家自制的扩展）之后的同一个游戏，多了原版没有的机器和工具。在上面的世界里学到的技能，到了下面的世界里不一定还管用。}}

网页 agent 也一样。网站改版之后，「先把鼠标悬停在主类别上」这样的工作流就可能对不上新的页面。Voyager 和 AWM 的论文都只讲了怎样往记忆里加东西，没有讲怎样修改或者删除已经存下的做法。

+
一篇专门讨论这个问题的论文。Cao 等人的论文提出了 ReMe，一个把 agent 的经验存成记忆的系统。这篇论文 2025 年 12 月上传，后来收录在学术会议 ACL 2026 的 Findings 论文集里。它把已有的做法概括为「被动积累」（passive accumulation），意思是记忆被当成一个只往里加、从不整理的档案。论文列了三个具体的问题。
  • 整条轨迹一起存，里面混着无关的内容。
  • 取出来的经验不加调整就用，场景稍有不同就会失败。
  • 没有及时的更新，经验库里有用的经验和有害的内容会混在一起。
出处：Cao 等，2025。
+
ReMe 怎样删掉没用的经验。它的办法里和这里最相关的一条是按效用删除。效用是这样算的：一条经验每被取用一次，如果那一次的任务做成了，就给它记一分。一条经验被取用至少 5 次之后，如果平均每次取用得到的分数低于阈值，就删掉。论文的实验是在两个工具调用的基准测试上做的，没有测试环境本身发生变化的情况，也没有拿 Voyager 或 AWM 做对比。出处：Cao 等，2025。

技能文件在这一点上好一些，因为文件可以改：人可以改，agent 自己也可以改。难处在于判断什么时候该改、改成什么。怎样让记忆保持最新，是第五部分的记忆维护要讲的事。

这一部分的小结

  • 从经验里学做法，是把成功的运行轨迹整理成可以再用的程序性记忆。存的形式可以是代码、带变量的步骤，或者文件。
  • 存之前要有一步判断：这次到底做成了没有。Voyager 和在线的 AWM 都让语言模型来判断，判错了就会存下错的做法。
  • 取的办法有三种：Voyager 用向量检索，AWM 把一个网站的全部工作流放进 prompt，技能文件只把名字和描述放进上下文窗口、让模型自己去读文件。
  • 存下来的做法会过时。光往里加是不够的，还要能改、能删。
