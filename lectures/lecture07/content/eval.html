先看结论

  • 好的记忆评测有四条要求：真实，上下文够长，有挑战，可验证。
  • 四个基准测试（benchmark，一组题目加一个打分的办法）一个比一个接近 agent（能自己调用工具、分很多步去完成任务的语言模型系统）的实际工作。LoCoMo 用的是两个人之间的模拟对话。PersonaMem 换成用户和聊天助手的对话。LongMemEval-V2 换成 agent 的运行轨迹（trajectory，每一步的动作和看到的结果的完整记录）。MemoryArena 让 agent 在多个会话里真的去完成任务。
  • 四个基准测试各有一个不太符合直觉的发现。取到了正确的记忆，回答仍然可能是错的。简单的检索比专门的记忆系统成绩更好，也快得多。最准的做法，查询耗时是最基本的检索的几百倍。在真实的多步任务上，专门的记忆系统平均成绩最低。
  • 前三个基准测试各有一两条只做到一部分。只有 MemoryArena 四条都算做到，代价是分数里混着记忆以外的因素。读记忆系统的成绩时，要看它是在哪一种评测上得到的。

四条要求

被检索的那一大堆历史记录，论文里常叫 haystack，其中只有很少几条包含问题的答案。好的基准测试应该有哪些性质，第 13 讲会讲到，和这四条是相通的。这里多出来的是「上下文够长」这一条，它是记忆评测特有的。

四个基准测试一览

LoCoMo：很长的模拟对话

LoCoMo（Maharana 等，ACL 2024）是用得最多的记忆基准测试之一。它的对话是这样造出来的：两个由语言模型扮演的虚拟人物，各有一份人物设定和一条时间线，时间线上有最多 25 件互相有因果联系的事，跨度 6 到 12 个月。两个人物隔一段时间聊一次，聊的内容受这段时间里发生的事影响，还会互相发图片。生成对话的 agent 用的正是 Generative Agents 的记忆和反思结构。生成之后由人来检查和修改，论文说标注者改了将近 15% 的对话轮次，删掉或换掉了约 19% 的图片。

{{figs 71 72 | 左：LoCoMo 的一段对话和三种任务的例子。右：对话的生成流程，每个 agent 有人物设定、事件时间线、记忆和反思模块，生成的对话最后由人修改。图片来源：Maharana 等，2024。}}

问答任务有五类问题：只看一次会话就能答的，要综合几次会话的，要推算时间的，要结合常识的，以及故意问一件对话里没有的事、正确做法是指出无法回答的。最后一类叫对抗性问题。评分用 F1，衡量回答和标准答案用词重合的程度，满分 100。

!
LoCoMo 的规模有两套数字，经常被混着引用。
  • 最早上传到 arXiv 的版本：50 组对话，平均 305 轮、9,209 个 token、19.3 次会话，共 7,512 个问题。摘要里写的是「平均 300 轮、9 千 token，最多 35 次会话」。很多后来的论文沿用这一套数字。
  • ACL 2024 正式发表的版本和公开的数据集：10 组对话，平均 588 轮、16,618 个 token、27.2 次会话，共 1,986 个问题。数据集的说明写明，这是从最初的 50 组里挑出的最长、标注质量高的一部分。
现在的论文做实验时实际用的是后一个版本。常见的一种写法「约 1.6 万 token、7,512 个问题」，是把两个版本的数字拼在了一起。出处：arXiv 版；ACL 版；数据集的说明。

两个结果

第一个结果是模型离人还很远。把整段对话放进上下文窗口，成绩最好的是 GPT-4 Turbo，F1 是 51.6，人是 87.9。对抗性问题上尤其差：GPT-4 Turbo 只有 15.7，论文的解释是上下文一长，模型更容易被带着编出一个答案。

第二个结果来自检索的实验，也是这篇论文最值得记住的地方。

{{fig 73 | 用检索增强生成（先检索，再让模型根据检索到的内容作答）回答问题的成绩，模型是 GPT-3.5 Turbo。每一行是一种检索的单位和取回的条数。左半边是回答的 F1，右半边是检索的召回率，也就是包含答案的那段内容有没有被取回来。图片来源：Maharana 等，2024。}}

从表里可以读出三点。

  • 取回得更多，回答没有跟着变好。取回 50 条时召回率明显高于取回 5 条时，总 F1 却几乎没涨（对话原文，38.8 到 40.5），甚至下降（陈述，43.3 到 40.6）。下降主要出在对抗性问题上：取回的内容越多，模型越容易从里面找一段内容编出一个答案。论文的结论是，要让模型用好取回的内容，就得减少其中的噪声。
  • 存什么形式有讲究。把对话先整理成一条条陈述再检索，取 5 条时比检索原文高 4.5 分。但做成摘要就不行了：召回率高达 84.7，F1 只有 32.0，论文认为是对话变成摘要时丢了信息。
  • 包含答案的内容取回来了，回答仍然常常是错的。召回率 82.7 的那一行，F1 是 40.5，离人的 87.9 很远。F1 这个指标本身比较严，这个差距不能全算作「不会用记忆」，但方向是清楚的。

按四条要求看 LoCoMo：有挑战、可验证这两条做到了。真实这一条只做到一部分，因为两个人之间的聊天不是 agent 通常要记的东西。上下文也不算长，1.66 万 token 放得进现在大多数模型的上下文窗口。

PersonaMem：偏好会变的用户

PersonaMem（Jiang 等，COLM 2025）针对 LoCoMo 的两个不足做了改动：对话的一方换成聊天助手，历史大大加长。它关心的是个性化：助手能不能根据用户说过的话，给出适合这个用户现在情况的回答。

{{fig 76 | 左边是一个用户的设定和她与聊天助手的多次会话，话题有美食推荐、旅行计划、心理咨询等。右边是偏好变化的例子：用户先说喜欢意大利菜，后来说对麸质过敏、改吃地中海菜，再后来请助手推荐菜谱，助手的回答应该按最新的情况来。图片来源：Jiang 等，2025。}}

数据全部由 GPT-4o 生成：先造人物，再给人物排一条时间线，上面有事件、偏好和偏好的变化以及变化的原因，然后把这些展开成一次次会话，最后按时间顺序拼成很长的历史。会话涉及 15 个话题。

题目是四选一。给模型一段历史和用户新说的一句话，让它在四个回答里选最合适的一个。举一个数据集里的例子：用户以前聊过自己喜欢用软件做音乐，现在说最近参加了一个活动，现场把现代节拍和太平洋岛屿的声音融合在一起。正确的回答提到了用户做音乐这件事。三个干扰项分别是：说用户不喜欢音乐制作（和历史矛盾），泛泛地回应（没有用到历史），把话题说成了艺术展（用对了人，说错了事）。评分是算选对的比例，随机猜是 25%。

七类问题里，有的考能不能想起用户说过的事实，有的考能不能认出最新的偏好，有的考能不能说出偏好为什么变了，有的考能不能据此推荐新的东西。

结果

  • 最好的模型也只有一半左右。把整段历史放进上下文窗口，GPT-4.5、GPT-4.1、Gemini 等模型的总准确率在 50% 上下。回忆事实和追踪偏好变化这类问题能到 60% 到 70%，要把用户最新的情况用到回答里的问题只有 30% 到 50%。
  • 相关的信息在历史中间时最容易被忽略。信息出现在很早或很近的会话里时，模型答得更好。
  • 没有人的成绩可比。论文说历史太长，没法请人读完再答题。
{{fig 79 | GPT-4o 和 GPT-4o-mini 在七类问题上的准确率，历史是 3.2 万 token 的那一档。每类问题有六根柱子：两个模型各自不加记忆、加 Mem0、加检索。柱子上的数是相对于同一个模型不加记忆时的变化。最右边一组是平均。图片下方的红字写的是：记忆和检索必不可少，Mem0 对偏好的演变和最新的偏好有帮助。和论文对照，后半句只在一部分情况下成立：追踪偏好演变这一类，Mem0 让 GPT-4o-mini 提高 17.0 个百分点，却让 GPT-4o 下降 7.0 个百分点；认出最新偏好这一类，Mem0 提高 24.0 和 25.0 个百分点，简单的检索也提高 24.0 和 22.0 个百分点。论文自己的结论是简单的检索在多数问题类型上好于 Mem0。图片来源：Jiang 等，2025。}}

这张图比较了两种外加的记忆：Mem0，和一个很简单的检索办法，每个问题按向量相似度取最相关的 5 条消息。向量（embedding）是把文字转成的一串数字，意思相近的文字数字也相近。两种都明显好于不加。按图上标的平均值，GPT-4o 加检索提高 25.9 个百分点，加 Mem0 提高 19.1 个百分点；GPT-4o-mini 分别是 17.4 和 7.7 个百分点。图上的标签写的是百分数，论文没有写明是相对比例还是百分点。对照柱子的高度看，指的是百分点：比如回忆事实这一类，GPT-4o 不加记忆时的柱子大约在 0.18，加检索之后大约在 0.76，标签是「+58.0%」。

论文的结论是：在多数问题类型上，简单的检索比 Mem0 成绩更好。Mem0 只在少数几格里领先，还有三格比不加记忆更差。速度的差别更大：在 589 个问题上，检索平均每个问题 0.61 秒（不含事先计算向量的时间），Mem0 平均每个问题 150 秒，因为它要让语言模型把长长的历史一轮一轮地处理成记忆。作者说明这部分实验只是初步的验证。

按四条要求看 PersonaMem：上下文够长、可验证做到了。真实这一条比 LoCoMo 好，但选择题不是 agent 实际使用记忆的方式，所以只做到一部分。有挑战这一条也因为是选择题，只做到一部分。

LongMemEval-V2：从 agent 的运行轨迹里学会一个环境

前两个基准测试记的都是对话。LongMemEval-V2（Wu 等，2026 年 5 月上传）记的是 agent 的运行轨迹。它的设想是：一个好的记忆系统，应该能让 agent 像一个在这里干了很久的同事那样熟悉一个特定的环境。

轨迹来自网页 agent 在四个定制过的网站上做任务的记录：三个来自 WebArena（购物网站、购物网站的管理后台、论坛），一个是 WorkArena 里的企业服务管理系统 ServiceNow。一共 1,540 条轨迹，成功和失败的各占一半左右，每一步都有截图和页面结构。451 个问题全部由人对着轨迹写出来，考五种能力。

{{fig 82 | 上面是四条历史轨迹的缩略图，每条有任务、动作序列和结果。下面是问题的例子，分左右两栏：左栏是新来的同事会问的问题，右栏是从别的环境来的有经验的同事会问的问题，后者的前提在这个环境里是错的。图片来源：Wu 等，2026。}}

这个基准测试有时被说成是选择题，其实选择题只占 15.3%。简答题占 50.1%，自由作答占 34.6%。有固定答案的题用规范化之后的字符串匹配来判，自由作答的题由一个语言模型当评判，后者大约占三分之一。

它的难处在于答案很稀疏。每个问题平均只有 1.4 条轨迹里有答案，而这些轨迹混在 100 条或大约 500 条轨迹里，后一档合起来超过 1 亿 token。很多问题只能从失败的轨迹里找到答案。论文在正式评测之前做过一个预实验：不给任何历史，让几个模型直接作答，其中最好的一个也只答对 14.1%，说明这些题靠模型本来的知识答不出来。

怎么考，结果怎样

被测的是记忆模块。它要实现两个接口：存入一条轨迹，以及针对一个问题返回一段内容。评测时先把轨迹一条条存进去，再拿问题去查，返回的内容截到 20 万 token 以内，交给一个固定的小模型（Qwen3.5-9B）作答。所以它测的是记忆模块能不能把有用的证据找出来。

{{fig 85 | 各种记忆做法的准确率和查询耗时，左图是 100 条轨迹的一档，右图是约 500 条轨迹的一档。越靠左上越好。蓝点是最基本的检索。粉色是加强的检索，负责查找的模型是 Qwen3.5-9B。绿色是直接用写代码的 agent。橙色是把轨迹存成文件、再配上一些辅助材料的写代码的 agent，负责查找的模型是 GPT-5.4-mini。同一种颜色的几个点是模型的不同推理强度。图片来源：Wu 等，2026。}}

把轨迹存成文件、配上辅助材料、再让一个写代码的 agent 去搜和看（表里最后一行），准确率最高，比加强的检索高 13 到 16 个百分点，查询耗时是它的 4 到 5 倍多。不配辅助材料、让写代码的 agent 直接翻文件的那一行，准确率低一些，查询也更慢，是表里最慢的做法。这和第二部分说的文件系统的特点一致。要留意检索和写代码的 agent 这两组做法负责查找的模型不同，差距里有一部分来自模型。最高的 74.9% 也说明这个基准测试离满分还很远。论文没有报告人的成绩。

按四条要求看 LongMemEval-V2：上下文够长、有挑战、可验证都做到了。真实这一条比前两个更进一步，因为记的是 agent 的轨迹。它仍然是在问关于旧记录的问题，没有直接测 agent 能不能因此把任务做得更好，论文自己也把这一点列为局限。

MemoryArena：让 agent 带着记忆去完成任务

MemoryArena（He 等，ICML 2026）的出发点是：已有的评测把「记住」和「行动」分开考，而实际工作里两者是一个循环。agent 做动作，环境给反馈，反馈更新记忆，记忆又影响后面的动作。它把这个循环放在多个会话里来测。

{{fig 88 | 上面是记忆、agent、环境之间的循环。下面是多会话的工作流程：每个会话对应一个子任务，agent 先从记忆里取出相关的内容，再在环境里行动，子任务结束后记忆被更新。图片来源：He 等，2026。}}

每个任务由一串互相依赖的子任务组成，每个子任务在一个单独的会话里做。前一个会话的交互记录在会话结束后就看不到了，后面的子任务又必须用到前面的结果，所以 agent 只能靠记忆。

{{fig 90 | 团体旅行计划的例子。第一个子任务：Tracy 一个人的 5 天行程，给了出发地、目的地、日期和预算。第二个子任务：Chelsea 加入，她的要求是参照 Tracy 的安排提出来的，比如住宿可以比 Tracy 第一天的贵 150 美元。第三个子任务：Emily 加入。图片来源：He 等，2026。}}

图里的例子说明了依赖关系是怎么来的。Chelsea 的要求是相对于 Tracy 的行程说的，agent 必须记得上一个会话里给 Tracy 订了什么，才能排出 Chelsea 的行程。旅行的人一个个加进来，每人都带着新的约束，最后检查整份计划是否满足所有人。

结果：专门的记忆系统平均成绩最低

论文比较了三类做法。第一类是长上下文：把之前会话的记录原样接在 prompt（给模型的输入文字）前面。第二类是专门的记忆系统：Letta（也就是 MemGPT）、Mem0 和它的图谱版本、Mirix、ReasoningBank。第三类是检索：BM25 关键词检索、向量检索，以及两种带结构的检索。

{{fig 91 | 三类做法在各个环境里的成绩。每个环境有任务成功率（SR）和进度分（PS）两列，团体旅行多一列按约束算的进度分（sPS）。任务成功率是整个任务完全做成的比例。进度分是一个任务里做对的子任务占的比例。按约束算的进度分是每个子任务里满足的约束占的比例，再取平均。每一类最后一行是这一类的平均。图片来源：He 等，2026。}}
  • 所有做法的成功率都很低。团体旅行这一项，13 种做法的成功率全是 0。购物这一项，只有长上下文的几行不是 0。进度分比成功率高不少，说明 agent 能做对一部分子任务，但没法把它们合成一个整体上正确的结果。
  • 专门的记忆系统这一类平均最低。记忆系统和检索都是接在同一个做任务的模型上测的，论文的表里把这个模型写作 GPT-5.1-mini。每一个记忆系统的总平均成功率（12% 到 14%）都低于这个模型不接任何记忆、直接用长上下文时的 16%，也低于每一种检索（17% 到 20%）。上面表里长上下文一行的 15% 是 4 个不同模型的平均，所以和这里的 16% 不是同一个数。
  • 专门的记忆系统也是最慢的一类。论文另有一张表给出完成一个子任务平均用的时间：专门的记忆系统是 99 到 133 秒，检索是 90 到 107 秒，同一个模型直接用长上下文是 74 秒。论文的原话是，带外部记忆的 agent 耗时总是最长，检索居中，长上下文最短。
  • 成绩最低这个结论在有的环境里不成立。在网上搜索这一项，记忆系统和检索都比长上下文好得多。这个环境里单个子任务的记录就可能超过 12 万 token，全部堆在上下文窗口里，模型反而用不好。

论文对「外加记忆为什么不一定有帮助」给了两个解释。一是表示上不匹配：长上下文的 agent 看到的是前后一致的原始记录，记忆系统返回的是压缩过、切碎了或者重新排过的信息。二是训练上不匹配：记忆系统和做任务的模型不是一起优化的，模型不擅长向记忆提出好的查询，也不擅长把查到的东西用进推理。论文还观察到，需要原样复用前面结果的任务（比如某一天具体订了哪家餐厅）上，检索比做了很多概括的记忆系统更稳。

i
失败不能全算在记忆头上。这些任务本身就难，行程要排满 30 个时间段，证明题是研究水平的。长上下文的 agent 看得到全部历史，照样做得很差。论文做过一个补充实验：直接把近似正确的记忆内容给 agent，成功率有所提高，但仍然很低。所以这张表反映的是记忆和 agent 本身的推理能力两方面的问题。另外，多数成功率在 25% 以下，表里没有给误差范围，数学和物理分别只有 40 个和 20 个任务，小的差别不宜多读。

四个基准测试放在一起

四个基准测试合起来，有三点对动手做记忆系统的人有用。

  • 先和简单的做法比。把全部历史放进上下文窗口，或者最普通的检索，在好几个评测里都不输给专门的记忆系统。第五部分里 Mem0 论文自己的表也是这样。
  • 准确率要和耗时一起看。成绩最好的做法往往慢得多。能不能接受，取决于应用。
  • 对话问答上的好成绩，不能直接推到真实任务上。MemoryArena 的论文专门指出，在 LoCoMo 这类评测上成绩已经接近满分的记忆系统，在它的任务里表现很差。
