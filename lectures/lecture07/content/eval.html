先看结论

  • 好的记忆评测有四条要求：真实，上下文够长，有挑战，可验证。
  • 四个基准测试（benchmark，一组题目加一个打分的办法）一个比一个接近 agent（能自己调用工具、分很多步去完成任务的语言模型系统）的实际工作。LoCoMo 用的是两个人之间的模拟对话。PersonaMem 换成用户和聊天助手的对话。LongMemEval-V2 换成 agent 的运行轨迹（trajectory，每一步的动作和看到的结果的完整记录）。MemoryArena 让 agent 在多个会话（session，从开始到结束的一次连续的对话或运行）里真的去完成任务。
  • 四个基准测试各有一个不太符合直觉的发现。LoCoMo 里，取到了正确的记忆，回答仍然可能是错的。PersonaMem 里，直接从历史里取出最相关的几条消息的简单检索，在多数问题类型上比专门的记忆系统 Mem0 成绩更好，也快得多。专门的记忆系统指 Mem0 这一类系统：先让语言模型把历史加工成一条条记忆存起来，回答时再取出相关的几条。LongMemEval-V2 里，最准的做法是把轨迹存成文件、配上辅助材料、让一个写代码的 agent 去查，它的查询耗时是最基本的检索的几百倍，它和检索在查找时用的模型也不同。MemoryArena 的多步任务上，专门的记忆系统这一类平均成绩最低，它和另外两类做法只差几个百分点。
  • 前三个基准测试各有一两条要求只做到一部分。只有 MemoryArena 四条都算做到，它也最接近 agent 的实际工作，但分数里混着记忆以外的因素。这些判定取自「四条要求」一节的配图，其中 MemoryArena 的「上下文够长」一条在 token 数上有出入，见那一节的说明。读记忆系统的成绩时，要看它是在哪一种评测上得到的。

四条要求

一个评测记忆的基准测试好不好，可以用下面四条要求来衡量。

好的基准测试应该有哪些性质，第 13 讲会讲到，和这四条是相通的。这里多出来的是「上下文够长」这一条，它是记忆评测特有的。

「上下文够长」在 LoCoMo 和 MemoryArena 上的两处判定

「上下文够长」这条要求只说不必在很短的对话上测记忆，没有给出多少 token 才算够长。token 是模型处理文字的最小单位，大致是一个词或半个词。配图上，这一条在 LoCoMo 上判为部分做到，在 MemoryArena 上判为做到。下表把两处各自的 token 数并排列出来。

四个基准测试一览

下表先把四个基准测试并排列出来，后面各节逐个细讲。

LoCoMo：很长的模拟对话

LoCoMo（Maharana 等，发表于学术会议 ACL 2024）是用得最多的记忆基准测试之一。它的对话是这样造出来的：两个由语言模型扮演的虚拟人物，各有一份人物设定和一条时间线，时间线上有最多 25 件互相有因果联系的事，跨度 6 到 12 个月。两个人物隔一段时间聊一次，聊的内容受这段时间里发生的事影响，还会互相发图片。每个虚拟人物是一个 agent，它的记忆和反思结构沿用 Generative Agents。Generative Agents 是第五部分讲的一个用语言模型模拟小镇居民的系统，每个居民把经历存进记忆，再让语言模型读这些记录、写出更概括的结论。这种结论叫反思，也存进记忆。

对话生成之后由人来检查和修改。论文说标注者改了将近 15% 的对话轮次，删掉或换掉了约 19% 的图片。

{{figs 71 72 | 左：LoCoMo 的一段对话和三种任务的例子。右：对话的生成流程，每个 agent 有人物设定、事件时间线、记忆和反思模块，生成的对话最后由人修改。图片来源：Maharana 等，2024。}}

问答任务有五类问题：只看一次会话就能答的，要综合几次会话的，要推算时间的，要结合常识的，以及故意问一件对话里没有的事、正确做法是指出无法回答的。最后一类叫对抗性问题。评分用 F1，衡量回答和标准答案用词重合的程度，满分 100。

!
LoCoMo 的规模有两套数字，经常被混着引用。
  • 最早上传到 arXiv（研究者公开上传论文的网站）的版本：50 组对话，平均 305 轮、9,209 个 token、19.3 次会话，共 7,512 个问题。摘要里写的是「平均 300 轮、9 千 token，最多 35 次会话」。后来有论文沿用这一套数字，例如 A-Mem 和 MemoryOS 这两个记忆系统的论文。
  • ACL 2024 正式发表的版本和公开的数据集：10 组对话，平均 588 轮、16,618 个 token、27.2 次会话，共 1,986 个问题。数据集的说明写明，这是从最初的 50 组里挑出的最长、标注质量高的一部分。
现在的论文做实验时实际用的是后一个版本。把「约 1.6 万 token」和「7,512 个问题」写在一起，是把两个版本的数字拼在了一起，LongMemEval-V2 论文的对比表里 LoCoMo 那一行就是这样写的。出处：arXiv 版；ACL 版；数据集的说明。

两个结果

第一个结果是模型的成绩比人低很多。把整段对话放进上下文窗口，成绩最好的是 GPT-4 Turbo，F1 是 51.6，人是 87.9。对抗性问题上尤其差：GPT-4 Turbo 只有 15.7，论文的解释是上下文一长，模型更容易受其中内容的误导，编出一个答案。

第二个结果来自检索的实验，也是这篇论文最值得记住的地方。

{{fig 73 | 用检索增强生成（先检索，再让模型根据检索到的内容作答）回答问题的成绩，模型是 GPT-3.5 Turbo。每一行是一种检索的单位和取回的条数。左半边是回答的 F1，右半边是检索的召回率，也就是包含答案的那段内容有没有被取回来。图片来源：Maharana 等，2024。}}

从表里可以读出三点。

  • 取回得更多，回答几乎没有变好。取回 50 条时召回率明显高于取回 5 条时，总 F1 却只涨了一点，或者反而下降。以对话原文为检索单位时，召回率从 56.7 升到 82.7，总 F1 只从 38.8 升到 40.5。以陈述为检索单位时，召回率从 56.2 升到 71.2，总 F1 反而从 43.3 降到 40.6。对抗性问题的 F1 在两种检索单位下都明显下降：取回的内容越多，模型越容易从里面找一段内容编出一个答案。论文的结论是，要让模型用好取回的内容，就得减少其中的噪声。
  • 存什么形式有讲究。把对话先整理成一条条陈述再检索，取 5 条时总 F1 比检索原文高 4.5 分。但做成摘要就不行了：召回率高达 84.7，总 F1 只有 32.0。按摘要检索时，召回率算的是包含答案的那次会话的摘要有没有被取回来。摘要取回来了，里面不一定还留着答案。论文认为总 F1 低是因为对话变成摘要时丢了信息。
  • 包含答案的内容取回来了，回答仍然常常是错的。召回率 82.7 的那一行，总 F1 是 40.5，比人的 87.9 低得多。这个差距不能全算作模型不会用取回的内容，因为总 F1 里算进了对抗性问题。这类问题在对话里本来就没有答案，这一行在这类问题上只有 9.9 分。但差距这样大，说明取回了包含答案的内容之后，模型仍然常常答错。

按四条要求看 LoCoMo：有挑战、可验证这两条做到了。真实这一条只做到一部分，因为两个人之间的聊天不是 agent 通常要记的东西。上下文够长这一条也只做到一部分，1.66 万 token 放得进现在大多数模型的上下文窗口。这一条在 MemoryArena 上判为做到，两处判定在 token 数上的出入见「四条要求」一节。

PersonaMem：偏好会变的用户

PersonaMem（Jiang 等，发表于学术会议 COLM 2025）针对 LoCoMo 的两个不足做了改动：对话的一方换成聊天助手，历史大大加长。它关心的是个性化：助手能不能根据用户说过的话，给出适合这个用户现在情况的回答。

{{fig 76 | 左边是一个用户的设定和她与聊天助手的多次会话，话题有美食推荐、旅行计划、心理咨询等。右边是偏好变化的例子：用户先说喜欢意大利菜，后来说对麸质过敏、改吃地中海菜，再后来请助手推荐菜谱，助手的回答应该按最新的情况来。图片来源：Jiang 等，2025。}}

数据全部由 GPT-4o 生成：先造人物，再给人物排一条时间线，上面有事件、偏好和偏好的变化以及变化的原因，然后把这些展开成一次次会话，最后按时间顺序拼成很长的历史。会话涉及 15 个话题。

题目是四选一。给模型一段历史和用户新说的一句话，让它在四个回答里选最合适的一个。评分是算选对的比例，随机猜是 25%。

举一个数据集里的例子。用户以前聊过自己喜欢用软件做音乐，现在说最近参加了一个活动，现场把现代节拍和太平洋岛屿的声音融合在一起。正确的回答提到了用户做音乐这件事。另外三个回答是干扰项：第一个说用户不喜欢音乐制作，和历史矛盾；第二个泛泛地回应，没有用到历史；第三个用对了关于这个用户的信息，却把话题说成了艺术展。

七类问题里，有的考能不能想起用户说过的事实，有的考能不能认出最新的偏好。有的考能不能追踪偏好的演变，也就是说清偏好前后是怎样变的。有的考能不能说出偏好为什么变了，有的考能不能据此推荐新的东西。

结果

  • 最好的模型也只答对一半左右的题。主实验把整段历史放进上下文窗口，历史用的是 12.8 万和 100 万 token 两档。GPT-4.5、GPT-4.1、Gemini 等模型的总准确率在 50% 上下。回忆事实和追踪偏好的演变这两类问题能到 60% 到 70%，要把用户最新的情况用到回答里的问题只有 30% 到 50%。
  • 相关的信息在历史中间时最容易被忽略。信息出现在很早或很近的会话里时，模型答得更好。
  • 没有人的成绩可比。论文说历史太长，没法请人读完再答题。

外加记忆有没有帮助

上面的成绩都是把整段历史放进上下文窗口得到的。论文还测了给模型外加记忆有没有帮助，比较了两种做法。一种是 Mem0，它是一个专门的记忆系统：让语言模型从每一轮对话里提取事实存起来，回答时取出最相关的 5 条事实。另一种是很简单的检索：每个问题按向量相似度取最相关的 5 条消息。向量（embedding）是把文字转成的一串数字，意思相近的文字数字也相近。

{{fig 79 | GPT-4o 和 GPT-4o-mini 在七类问题上的准确率，历史是 3.2 万 token 的那一档。每类问题有六根柱子：两个模型各自不加记忆、加 Mem0、加检索。柱子上的数是相对于同一个模型不加记忆时的变化，单位是百分点。最右边一组是平均。图片下方的红字写的是：记忆和检索必不可少，Mem0 对偏好的演变和最新的偏好有帮助。图片来源：Jiang 等，2025。}}

按七类问题的平均准确率看，两种外加的记忆都明显好于不加。分开看每一类问题时有例外，下面的表后会讲。按论文的图注，不加记忆的模型看到的是 3.2 万 token 这一档的整段历史。所以这个实验比的是「外加记忆」和「把整段历史放进上下文窗口」。

论文的结论是：在多数问题类型上，简单的检索比 Mem0 成绩更好。把七类问题和两个模型分开来看，一类问题配一个模型算一种情况。Mem0 只在少数几种情况里比简单的检索提高得多，还有三种情况比不加记忆更差。图片下方的红字说 Mem0 对偏好的演变和最新的偏好有帮助，这句话只在一部分情况下成立，具体的数见资料说明。

读这组结果还要留意，这里不加记忆时的成绩比上一小节主实验的成绩低得多。以回忆事实这一类为例，主实验里 GPT-4.5、GPT-4.1、Gemini 等模型能到 60% 到 70%，用的历史是 12.8 万和 100 万 token 两档。这里的历史是更短的 3.2 万 token 一档，GPT-4o 不加记忆时的准确率从图上读大约是 0.18。两处差这么多，论文没有给出原因，见资料说明。

速度的差别更大。速度是在历史为 3.2 万 token 的那一档上比的，这一档有 589 个问题。检索平均每个问题 0.61 秒，这个时间不含事先计算向量的时间。Mem0 平均每个问题 150 秒，因为它要让语言模型把长长的历史一轮一轮地处理成记忆。作者说明这部分实验只是初步的验证。

按四条要求看 PersonaMem：上下文够长、可验证做到了。真实这一条比 LoCoMo 好，但选择题和 agent 实际使用记忆的方式不一样，所以只做到一部分。有挑战这一条也只做到一部分。按成绩看题目够难，最好的模型只答对一半左右。但四选一的考法让题目比实际使用时容易：随机猜也能对 25%，模型只要在给好的回答里挑一个，不用自己写出回答。

LongMemEval-V2：从 agent 的运行轨迹里学会一个环境

前两个基准测试记的都是对话。LongMemEval-V2（Wu 等，2026 年 5 月上传）记的是 agent 的运行轨迹。论文的说法是，好的记忆应该让 agent 在一个特定的环境里成为有经验的同事。意思是 agent 要熟悉这个环境：页面长什么样，做了某个操作之后会怎样，常见的任务分哪几步，哪些地方容易出错。

轨迹来自网页 agent 在四个定制过的网站上做任务的记录。其中三个网站来自 WebArena，这是一个考 agent 操作网页的基准测试，用到的是它的购物网站、购物网站的管理后台和论坛。第四个是企业服务管理系统 ServiceNow，来自另一个考网页 agent 的基准测试 WorkArena。

研究者一共收集了 1,540 条轨迹，成功和失败的各占一半左右，每一步都有截图和页面结构。评测用的两档历史都是从这些轨迹里选出来的。较小的一档是 100 条轨迹一组，由许多问题共用。较大的一档给每个问题单独配一组，每组大约 500 条。451 个问题全部由人对着轨迹写出来，考五种能力。

{{fig 82 | 上面是四条历史轨迹的缩略图，每条有任务、动作序列和结果。下面是问题的例子，分左右两栏：左栏是新来的同事会问的问题，右栏是从别的环境来的有经验的同事会问的问题，后者的前提在这个环境里是错的。图片来源：Wu 等，2026。}}

五种能力各考什么，见下表。

这个基准测试里，选择题占 15.3%，简答题占 50.1%，自由作答占 34.6%。有固定答案的题，先把答案的写法统一，再用字符串匹配来判。自由作答的题由一个语言模型当评判，这类题大约占三分之一。

它的难处在于答案很稀疏。每个问题平均只有 1.4 条轨迹里有答案，而这些轨迹混在 100 条或大约 500 条轨迹里，后一档合起来超过 1 亿 token。很多问题只能从失败的轨迹里找到答案。

这些题靠模型本来的知识也答不出来。论文在正式评测之前做过一个预实验：不给任何历史，让几个模型直接作答，其中最好的一个也只答对 14.1%。

怎么考，结果怎样

被测的是记忆模块。它要实现两个接口：存入一条轨迹，以及针对一个问题返回一段内容。评测时先把轨迹一条条存进去，再拿问题去查，返回的内容截到 20 万 token 以内，交给一个固定的小模型（Qwen3.5-9B）作答。所以它测的是记忆模块能不能把有用的证据找出来。

论文比较了四种记忆模块的做法，下面叫它们被测的做法。

  • 最基本的检索。按问题取出相关的轨迹片段和笔记。笔记是存入每条轨迹时由语言模型写的两条概括，一条总结可以再用的任务步骤，一条记下这个环境特有的情况和容易出错的地方。
  • 加强的检索（AgentRunbook-R）。存入轨迹时先提取出几类整理过的记录，查询时由一个模型写出检索词去取。
  • 写代码的 agent 直接搜索和查看文件（Codex）。轨迹原样存成文件，查询时让一个会写代码、会运行命令的 agent 自己去搜索和查看。
  • 文件加辅助材料，再用写代码的 agent（AgentRunbook-C）。在上一种做法上多给 agent 三样辅助材料：一份说明按哪些步骤找证据的文档，一份概括当前存了哪些轨迹的清单，一个把常用的查看操作包装好的脚本。

括号里是论文里的名字。AgentRunbook 是这篇论文自己提出的做法，有两个版本，名字里的 R 代表检索，C 代表写代码的 agent。Codex 是 OpenAI 现成的写代码的 agent，论文直接拿来用。

按四条要求看 LongMemEval-V2：上下文够长、有挑战、可验证都做到了。真实这一条比前两个更进一步，因为记的是 agent 的轨迹。它仍然是在问关于旧记录的问题，没有直接测 agent 能不能因此把任务做得更好，论文自己也把这一点列为局限。

MemoryArena：让 agent 带着记忆去完成任务

MemoryArena（He 等，发表于学术会议 ICML 2026）的出发点是：已有的评测把「记住」和「行动」分开考，而实际工作里两者是一个循环。agent 做动作，环境给反馈，反馈更新记忆，记忆又影响后面的动作。它把这个循环放在多个会话里来测。

{{fig 88 | 上面是记忆、agent、环境之间的循环。下面是多会话的工作流程：每个会话对应一个子任务，agent 先从记忆里取出相关的内容，再在环境里行动，子任务结束后记忆被更新。图片来源：He 等，2026。}}

每个任务由一串互相依赖的子任务组成，每个子任务在一个单独的会话里做。一个会话结束之后，agent 不能再直接看到这个会话的交互记录，后面的子任务又必须用到前面的结果，所以只能靠记忆把前面的信息带过来。论文说的记忆有三种：把之前会话的记录原样接在 prompt（给模型的输入文字）前面，检索，以及专门的记忆系统。后面的结果比的就是这三类做法。

{{fig 90 | 团体旅行计划的例子。第一个子任务：Tracy 一个人的 5 天行程，给了出发地、目的地、日期和预算。第二个子任务：Chelsea 加入，她的要求是参照 Tracy 的安排提出来的，比如住宿可以比 Tracy 第一天的贵 150 美元。第三个子任务：Emily 加入。图片来源：He 等，2026。}}

图里的例子说明了依赖关系是怎么来的。Chelsea 的要求是相对于 Tracy 的行程说的，agent 必须记得上一个会话里给 Tracy 订了什么，才能排出 Chelsea 的行程。旅行的人一个个加进来，每人都带着新的约束，最后检查整份计划是否满足所有人。

结果：专门的记忆系统平均成绩最低

论文比较了三类做法。

  • 长上下文。把之前会话的记录原样接在 prompt 前面，试了 4 个模型。
  • 专门的记忆系统。一共 5 个：Letta、Mem0 和它的图谱版本、Mirix、ReasoningBank。Mem0 的图谱版本把记忆存成实体和实体之间的关系。Letta 是一家做 agent 产品的公司，研究者里有好几位是 MemGPT 的作者，这里的 Letta 指它的产品。这个产品沿用 MemGPT 的分层的记忆，也就是上下文窗口里只留一部分随时要用的信息，其余的存在外面，需要时再取进来。论文的正文里把这一个写作 MemGPT。MemGPT 是第四部分讲的一个让模型自己用函数读写记忆的系统。Mirix 和 ReasoningBank 是这一讲没有讲到的两个记忆系统。按各自的论文，Mirix 把记忆分成六种，由一组 agent 配合着更新和检索。ReasoningBank 从 agent 做成和没做成的经历里提炼出可以再用的推理策略，存起来供以后的任务取用。出处：Wang 和 Chen，2025；Ouyang 等，2025。MemoryArena 的论文把它们的记忆各归在哪一档，见列表后面讲分档的一段。
  • 检索。一共 4 种：BM25 关键词检索、向量检索，以及 MemoRAG 和 GraphRAG。前两种直接在原始记录里查。后两种在查之前先把内容加工一遍，做法见列表后面的两段。

按 MemoRAG 自己的论文，它先用一个模型读完全部内容，形成一份整体的记忆。收到问题之后，这个模型先写出答案的草稿，检索工具拿草稿当线索去原文里找相关的内容，再由另一个模型根据找到的内容写出最后的答案。出处：Qian 等，2025。

按 GraphRAG 自己的论文，它先让语言模型从文本里提取实体（人、地点、物品这类对象）和它们之间的关系，建成一张图。然后 GraphRAG 给图上联系紧密的每一群实体写好摘要，回答问题时用的是这些摘要。出处：Edge 等，2024。

MemoryArena 的论文按记忆怎样组织，把这 13 种做法分成三档。第一档原样保存历史，不做归纳，长上下文、BM25 和向量检索属于这一档。第二档对信息做了归纳和提炼，得到的内容一条条并列存放，条目之间没有连接，Letta、Mem0 的基本版本、ReasoningBank 和 MemoRAG 属于这一档。第三档把记忆组织成树或图，Mirix、Mem0 的图谱版本和 GraphRAG 属于这一档。

{{fig 91 | 三类做法在各个环境里的成绩。每个环境有任务成功率（SR）和进度分（PS）两列，团体旅行多一列按约束算的进度分（sPS）。任务成功率是整个任务完全做成的比例。进度分是一个任务里做对的子任务占的比例。按约束算的进度分是每个子任务里满足的约束占的比例，再取平均。每一类最后一行是这一类的平均。图片来源：He 等，2026。}}

从论文的结果里可以读出四点。

  • 所有做法的成功率都很低。团体旅行这一项，13 种做法的成功率全是 0。购物这一项，只有长上下文的几行不是 0。进度分比成功率高不少，说明 agent 能做对一部分子任务，但没法把它们合成一个整体上正确的结果。
  • 专门的记忆系统这一类平均最低。记忆系统和检索都是接在同一个做任务的模型上测的，论文的表里把这个模型写作 GPT-5.1-mini。5 个记忆系统的总平均成功率在 12% 到 14% 之间。这个模型不接任何记忆、直接用长上下文时是 16%，4 种检索在 17% 到 20% 之间，都高于每一个记忆系统。这几类之间只差几个百分点，这样的差距能说明多少，见列表后面讲样本量的一段。
  • 专门的记忆系统也是最慢的一类。论文另有一张表给出完成一个子任务平均用的时间：专门的记忆系统是 99 到 133 秒，检索是 90 到 107 秒，同一个模型直接用长上下文是 74 秒。论文把这概括成：专门的记忆系统耗时最长，检索居中，长上下文最短。这句概括说的是三类做法大致的排序。按单个系统看有例外：最快的记忆系统是 99 秒，比最慢的检索的 107 秒短。
  • 成绩最低这个结论在有的环境里不成立。在网上搜索这一项，记忆系统和检索都比长上下文好得多。论文说，这个环境里单个子任务的记录就可能超过 12 万 token。这样长的记录全部放在上下文窗口里，模型反而用不好。

论文的结论是，给做任务的模型接上专门的记忆系统或检索，成绩不一定比直接用长上下文好。它给了两个解释。第一个解释是两边给模型的信息形式不同：长上下文的 agent 看到的是前后一致的原始记录，专门的记忆系统返回的是压缩过、切成片段或者重新排过顺序的信息。第二个解释是专门的记忆系统和做任务的模型是分开优化的：模型不擅长向记忆提出好的查询，也不擅长把查到的东西用进推理。

论文还观察到，有的任务需要原样复用前面的结果，比如某一天具体订了哪家餐厅。在这类任务上，检索比做了很多概括的记忆系统更稳。

失败不能全归到记忆上。这些任务本身就难。团体旅行里，行程由每天的三餐、住宿、游览这样一项项安排组成，论文说每个子任务要排一份有 30 项安排的行程。形式推理里的证明题是研究水平的。长上下文的 agent 看得到全部历史，照样做得很差。论文做过一个补充实验：直接把近似正确的记忆内容给 agent，成功率有所提高，但仍然很低。所以这张表反映的是记忆和 agent 本身的推理能力两方面的问题。

读这张表还要留意样本量。多数成功率在 25% 以下，表里没有给误差范围，数学和物理分别只有 40 个和 20 个任务，小的差别不能说明问题。

按四条要求看 MemoryArena：四条都算做到了。任务是要实际完成的，约束可以逐条检查，各种做法的成功率都很低。

上下文够长这一条，是按「四条要求」一节配图上的判定算做到的，那张图上写的是任务的轨迹有几十万 token。论文的统计表给出了每个环境里一个任务的记录平均有多长。购物、团体旅行和网上搜索这三个环境，平均都在 4 万 token 以上。这三个环境合起来有 641 个任务，全部任务是 701 个。最短的是形式推理这个环境，数学部分平均约 1.8 万 token，物理部分约 1.4 万 token，一共 60 个任务。LoCoMo 每组对话平均约 1.66 万 token，和形式推理这个环境差不多长，这一条在 LoCoMo 上却判为部分做到。两处判定在 token 数上的出入，见「四条要求」一节。

还要记住上面说的另一点：MemoryArena 的分数里混着记忆以外的因素。

四个基准测试放在一起

下表把四个基准测试并排放在一起，前四行是四条要求各做到了多少，最后一行是各自最主要的发现。

四个基准测试合起来，有三点对动手做记忆系统的人有用。

  • 先和简单的做法比。简单的做法有两种：把全部历史放进上下文窗口，和最普通的检索。PersonaMem 里，简单的检索在多数问题类型上比 Mem0 成绩更好。MemoryArena 里，同一个模型直接用长上下文，或者接上 4 种检索里的任何一种，总平均成功率都高于接上任何一个记忆系统。第五部分里 Mem0 论文自己的表，也是把整段对话放进上下文窗口时准确率最高。也有反过来的结果：PersonaMem 里，Mem0 的平均准确率高于把整段历史放进上下文窗口。
  • 准确率要和耗时一起看。LongMemEval-V2 里最准的做法，查询耗时是最基本的检索的几百倍。PersonaMem 和 MemoryArena 里，最慢的都是专门的记忆系统，它们的成绩却不是最好的。一种做法的耗时能不能接受，取决于应用。
  • 对话问答上的好成绩，不能直接推到真实任务上。MemoryArena 的论文在摘要里说，在 LoCoMo 这类已有的记忆评测上成绩接近上限的 agent，在它的任务里表现很差。论文没有写明这指的是哪些系统、哪一种分数，所以这句话和 LoCoMo 一节里 51.6 的 F1 没法直接对照。
