先看结论

  • 基准测试（benchmark）是一组题目，加一个报告成绩的办法。用它来回答一个问题：对模型或系统做的改动，到底有没有让它变好。
  • 早期的题目是语言学里的小任务。模型变强之后，新的基准测试换更难的问题来问，按问的问题分成四类：考试类、聊天类、安全类和 agent 类。agent 类问的是模型能不能在一个环境里做很多步，把一件事做成。这一讲关心的是 agent 类。
  • 基准测试有三个用处：让开发时有实验结果可以对照，让一个领域的人集中做同一批问题，让不同论文的结果可以比较。
  • 它也有代价。一个分数一旦成了大家追的目标，就会有办法把分数做高而能力没有跟上。古德哈特定律（Goodhart's Law）说的就是这件事。

这一讲要回答的问题

这门课前面的各讲讲了两件事。一件是怎样搭一个基于语言模型的 agent 系统，另一件是怎样让它的能力更强。

搭系统这件事的内容有四样：框架、设计模式、记忆和多 agent 系统。框架（framework）指写 agent 程序时调用的现成的库。设计模式是对常见解法的总结。记忆指把信息存下来、需要时再取回来的机制。多 agent 系统是一组 agent 朝着同一个任务一起工作。

让能力更强这件事的内容有两样：优化 prompt 和模型权重（模型内部的参数）的方法，以及 agent 系统需要的数据。

做完这两件事之后，要回答一个问题：怎么知道这些改进真的起作用了？

回答这个问题的工具就是基准测试。这一讲和第 15 讲都在讲评估，第 15 讲的题目是用语言模型当评审，以及评估的基础设施。评估的基础设施，指把任务交给 agent 去跑、给结果评分并汇总成绩的那套程序。

从训练损失到一道一道的题

评估语言模型最基础的办法是看训练损失（training loss）。语言模型的训练目标是预测下一个 token（模型处理文字的最小单位，大致是一个词或半个词）。训练损失是一个数，衡量的是模型在训练数据上预测得有多不准：预测得越准，损失越低。

可以一直训练到损失降不下去为止。但损失反映的是下一个 token 预测得准不准，模型能不能把真实的事情做好，从损失里看不出来。所以要拿具体的任务来考它。

这样的任务有很多，下面是四个例子。

  • 词性标注：判断一句话里的每个词是名词、动词还是别的词类。
  • 情感分类：判断一段话的态度是正面的还是负面的。
  • 指代消解：判断「他」「它」这类词指的是前文里的哪个人或哪样东西。
  • 阅读理解：读一段文字，再回答关于它的问题。

这些任务语言学家研究了很多年，早期的语言模型出现之后，其中一些被改造成了基准测试。

{{figs 7 8 | 两个早期基准测试的例子。左：SQuAD，给一段维基百科的文字和一个问题，答案是原文里的一小段，按和标准答案是否完全一致以及重合多少来评分。右：MultiNLI，给一句前提和一句假设，判断假设是被前提支持、与前提矛盾，还是无关，按准确率评分，准确率是答对的题占全部题的比例。}}

这类任务的评估可以写成一行：response = LM(prompt)。给模型一段输入，模型回答一次，再拿回答和标准答案比。T5 是 Raffel 等人 2019 年提出的一个语言模型，它把这个形式用到了所有任务上：翻译、分类、摘要全部写成「输入一段文字，输出一段文字」。

之后出现了把很多任务打包在一起的合集，用来全面地评一个模型。从单个任务到合集的这段时间里，有代表性的基准测试有六个：SQuAD、GLUE、SuperGLUE、MMLU、BIG-bench 和 HELM。其中 SQuAD 就是上面图里那个单一的阅读理解任务，其余五个是合集。

五个合集里装的东西各不相同。GLUE 把一批已有的语言理解任务合在一起，报一个总分。SuperGLUE 照 GLUE 的做法换了一批更难的任务。MMLU 是 57 个学科的选择题，下面还会讲到。BIG-bench 收了 204 个任务，题材从语言学、数学到软件开发都有。HELM 在很多种使用场景上评模型，一共看 7 个指标，除了准确率，还有稳健性、毒性等。稳健性指输入里有错别字这类小改动时，模型的回答稳不稳。毒性指模型生成的内容里有没有攻击人、侮辱人的话。

换更难的问题来问：四类基准测试

模型变强之后，旧的题目分不出高下，新的基准测试就换更难的问题来问。这些新的基准测试按问的问题可以分成并列的四类。

表里考试类的第一个例子 MMLU，上一节把它列在合集里。两处说的是同一个基准测试：它是 57 个学科的合集，题目是考试式的选择题。它出现的原因，也是更早的 SuperGLUE 这类题目已经分不出模型的高下，下一节有一张图讲这件事。

表里 agent 类那一行先说明一下。环境指 agent 执行任务的地方。按字面理解，数字环境是电脑里的环境，例如代码仓库和网站，现实环境是电脑之外的现实世界。表里的两个例子用的都是数字环境：SWE-bench 的题是修真实代码仓库里的问题，WebArena 让 agent 在作者自己搭的一组网站上办事。数字环境有模拟出来的，也有真实的，例如模拟的网店和装了完整操作系统的电脑，第二部分会讲。

前三类在下一节简要介绍，这一讲关心的是第四类。

前三类的八个例子

这一节用八个例子说明前三类基准测试各考什么、分数怎么算：考试类四个，聊天类两个，安全类两个。先看考试类。这四个基准测试一个比一个难。其中三个出现的原因，是旧的题目已经分不出模型的高下。下面这张图是其中第一个 MMLU 出现时的情况。

{{fig 14 | 右边的图说明了当时为什么需要 MMLU。图的纵轴是成绩，用百分数表示。红色和紫色是两个旧的基准测试（HellaSwag 考常识，SuperGLUE 考语言理解），GPT-3 最小的版本在这两个基准测试上的成绩就在 60% 以上。蓝色是 MMLU，成绩是准确率。GPT-3 较小的三个版本的准确率都在 25% 左右，和四个选项里随机猜一个的准确率一样，只有最大的版本到了 43.9%。图片来源：Hendrycks 等，2020。}}

MMLU-Pro 和 Humanity's Last Exam 出现的原因也一样。MMLU-Pro 的论文说，模型在 MMLU 这类基准测试上的成绩已经开始停滞，所以把它加难。Humanity's Last Exam 的论文摘要开头就说，模型在 MMLU 这类基准测试上已经超过 90%，没法再用它们衡量最强的模型。

GPQA 是例外的那一个。它的论文摘要说，这批题是为一项研究准备的：AI 的能力超过人之后，人怎样监督它给出的回答。做这项研究，需要其他领域的专家和当时最强的模型都很难答对的题，所以 GPQA 出的是研究生水平的难题。

这四个是按难度排的，和发布的先后并不完全一致：GPQA 在 2023 年发布，比 2024 年的 MMLU-Pro 早。第四部分把旧的基准测试被新的接替这个现象，叫作基准测试的生命周期。

考试类的两处细节

MMLU-Pro。MMLU-Pro 把 MMLU 的 57 个学科合并成了 14 个大类。83% 的题有 10 个选项，其余的少一些。

MMLU-Pro 去掉的题有两种。一种是有问题的题：有的题目本身没法作答，例如缺少作答需要的信息，有的标准答案标错了。另一种是太容易的题：8 个小模型里超过 4 个能答对的题都删了，一共删了 5,886 道。另外还从别的来源加了新的难题。

GPQA。GPQA 的作者通过外包平台雇了 61 个人来出题和验证，要求有博士学位或正在读博士。每道题由其中一个人出，出好之后由另外五个人各答一遍，这就是验证。先是两位和这道题同领域的专家先后作答，作答时看不到答案，目的是检查这道题的答案有没有争议。第一位答完后，出题人按他的意见改题，再交给第二位。然后是三位其他领域的专家作答，他们作答时可以上网查资料，目的是检查这道题够不够难。

论文公开的全部 546 道题叫扩展集。表里的主数据集是从扩展集里去掉两种题之后留下的 448 道。一种是两位同领域的专家都不认可答案的题，这样的题答案很可能有争议。另一种是三位其他领域的专家全都答对的题，这样的题很可能不够难。认可指专家自己答对了，或者答错之后看了出题人的解释，能说清自己错在哪里，或者表明自己看懂了这个解释。

GPQA 的论文报了三个成绩，都是答对的题的比例，都是在扩展集上测的。前两个就是验证时测到的：同领域的专家答对 65%，其他领域的专家只答对 34%。其他领域的专家作答时可以上网查资料，平均每道题花了 30 多分钟。第三个是当时最强的、用来作比较参照的基线模型（基于 GPT-4）的成绩，它答对 39%。

两个聊天类的基准测试有什么不同

Chatbot Arena 可以看作把 AlpacaEval 的做法扩展到了真实用户在实际使用时提出的 prompt 上。两者相同的地方是都做两两比较：拿两个模型对同一个问题的回答，判哪一个更好。

两者不同的地方有四处。题目从固定的一套换成用户在实际使用时提出的，是其中一处。另外三处是谁来评、和谁比、报什么分数。四处都列在下面的表里。

表的最后一行里，Chatbot Arena 的强度分是把所有投票汇总之后算出来的。Chatbot Arena 的论文把 Bradley-Terry 系数当作强度分。Bradley-Terry 系数是从两两胜负的记录里给每个选手估出来的一个强度值。Chatbot Arena 在这篇论文之前用的是 Elo 分，也就是按对战胜负算出的等级分，国际象棋排名用的就是它。

模型当评审和真人投票，排出的名次有多接近。评审模型偏爱长回答，所以 AlpacaEval 后来加了一个按长度校正过的胜率。校正之后，AlpacaEval 给模型排的名次和 Chatbot Arena 排的名次之间的相关系数，从 0.94 升到了 0.98。相关系数衡量两份名次有多一致，完全一致时是 1。0.98 说明这两个基准测试当时把共同的那批模型排得几乎一样。

为什么离不开基准测试

别的领域也早就有基准测试，下面是四个例子。

  • 计算机视觉：ImageNet 图像识别比赛。
  • 推荐系统：Netflix Prize。它是视频网站 Netflix 办的比赛，比的是谁能更准地预测用户会给电影打几分。
  • 机器人：DARPA 的挑战赛。DARPA 是美国国防部下属的研究机构，这个比赛让无人驾驶的车辆在限定的时间内自己跑完一段野外路线。
  • 科学计算：蛋白质结构预测的比赛。

基准测试有三个用处，列在下面的表里。

第三条有一个前提：两边跑分的方式得一样，分数才可比。第五部分讲的就是这个前提。

代价：分数成了目标之后

基准测试也有代价：一个分数成了大家追的目标之后，就会有办法把分数做高，而它本来要代表的能力没有跟上。在基准测试上，想把分数做高的是整个领域：大家都在同一个基准测试上比，题目会进入训练数据，系统会针对这个基准测试调整，评分办法里的漏洞也会被用上。

这个现象有一个名字，叫古德哈特定律（Goodhart's Law）。它流传最广的说法是：当一个度量变成了目标，它就不再是一个好的度量。

{{fig 28 | 上面是定律的两种说法，下面左边是一个赛艇游戏的画面，中间是一组曲线，右边是一句举例的话。}}

图里的赛艇游戏和曲线是两个实际的例子，这两个例子里把分数做高的都是单个系统。下面分别看。

例一：赛艇游戏

这个例子出自 OpenAI 2016 年的文章《Faulty reward functions in the wild》。游戏叫 CoastRunners，人玩的时候目标是尽快跑完比赛，但游戏给分是按撞到沿途的目标物算的。

OpenAI 用强化学习训练了一个玩这个游戏的程序。强化学习（reinforcement learning）是让程序反复尝试、按得分的高低调整做法的训练方法。文章把这个程序叫作 agent，它是一个玩游戏的程序，和这一讲说的语言模型系统是两种东西。

这个程序找到一个小水湾，在里面不停转圈，反复撞同样的三个目标物。它着火、撞船、逆行，从来不跑完比赛，可是它的游戏得分平均下来比人类玩家的得分高 20%。

例二：优化一个打分模型给的分

这个例子来自 Gao、Schulman 和 Hilton 2022 年的论文《Scaling Laws for Reward Model Overoptimization》。它的背景是：训练聊天模型时，常常先训练一个打分模型（reward model）来模仿人的偏好，再去优化聊天模型，让这个打分模型给它的回答打的分尽量高。

这篇论文做的是一个模拟实验，里面有两种打分模型。一种是一个固定的大的打分模型，实验里用它代替人：它给的分被当作人的真实偏好。论文把它叫作金标准（gold）打分模型。另一种是小一些的打分模型，论文训练了好几个，大小各不相同。它们都被训练来模仿金标准打分模型。每次实验用其中一个，被优化的是它给的分。

图里优化分数的做法，是让聊天模型一次生成很多个回答，用这个小的打分模型挑出分数最高的一个。

横轴表示优化的程度：越往右，每次生成的回答越多，也就是从越多的回答里挑。

横轴上的数在图上标的名字是 KL distance。KL distance 衡量两样东西整体上相差多少。这里的两样东西，一样是经过挑选之后给出的回答，另一样是聊天模型不经挑选时给出的回答。

这里说的相差，指的是各种回答出现的概率相差多少。聊天模型对同一个 prompt 可以给出很多种回答，每种回答各有一个出现的概率。经过挑选之后，小的打分模型打分高的那些回答出现的概率变大了。KL distance 量的是：每种回答出现的概率，在挑选之后和挑选之前整体上相差多少。

这个数是用每次生成的回答个数按一个公式直接算出来的。公式是 log n - (n - 1) / n，其中 n 是每次生成的回答个数，log 是自然对数。公式里只有回答个数这一个量，回答的内容和用的是哪个打分模型都不在公式里。论文只给出了这个公式，没有写推导。只生成一个回答时没有挑选，按公式算出来是 0。每次生成的回答越多，挑选之后的概率和挑选之前的概率相差越远，它就越大。所以横轴越往右，每次生成的回答越多，这个数越大，优化的程度也越高。

论文除了这种挑选的做法，还用强化学习做了同样的实验。强化学习的做法是直接训练聊天模型，让小的打分模型给它的回答打的分变高。这时 KL distance 比的两样东西，是训练之后的聊天模型给出的回答和训练之前的聊天模型给出的回答。论文说，这个数在训练的过程中一直变大。所以两种做法都能用 KL distance 来表示优化的程度。

纵轴是得分。虚线是小的打分模型给的分，一直在涨。实线是金标准打分模型给的分，先涨，到了一个顶点之后往下掉。图里有好几种颜色，每种颜色是一个小的打分模型，它们的大小各不相同，各有一条虚线和一条实线。这个模型越大，实线的顶点越高，来得也越晚。最大的几个，实线在图上画出的范围里还没有往下掉。

两个例子说明了什么

两个例子说的是同一件事：被优化的那个分数做高了，它本来要代表的东西却没有跟上。例一里，程序的游戏得分比人类玩家高，比赛却从来没有跑完。例二里，小的打分模型给的分一直在涨，金标准打分模型给的分先涨，到了顶点之后多数往下掉。

图右边的那句话举的是同一类例子：按长度给作文打分，你会得到很长的作文，不一定是好作文。

后面有两处是应对这件事的。第四部分的「耐用」这条性质从出题的人这边应对：基准测试要能抵抗两件事，一是题目和答案进了模型的训练数据，二是不完成任务、靠评分办法的漏洞拿到分数。第五部分的「诚实」这条要求从跑分的人这边应对：测试集只用来测量。

定律的两种说法出自两个人

图上方印着这条定律的两种说法。它们出自两个人，两人讲的场合不同：一个讲货币政策，一个讲大学的考核。后一种说法是对前一种的概括。

这一部分的小结

  • 改了一个语言模型系统之后，它的行为或能力有没有变好，要用基准测试来衡量。
  • 一个基准测试一般是一组题目，加一个报告成绩的办法。考试、聊天、安全这三类的一道题是一段 prompt，可以是一个问题、一条指令或一个请求。agent 类的一道题是一个任务加一个环境。
  • 除此之外，基准测试的样子千差万别：任务的类型不同，期望模型给出的回答不同，评分的办法也不同。
  • 基准测试有三个用处：度量、方向、交流。
  • 它的代价是古德哈特定律说的那件事：一个分数成了大家追的目标之后，就会有办法把分数做高，而能力没有跟上。
  • 这一讲剩下的部分讲的是 agent 的基准测试。第四部分讲好的基准测试有哪些性质时，也会拿 agent 类以外的基准测试举例，例如 MMLU 和 GPQA。第 15 讲接着讲用语言模型当评审，以及评估的基础设施。

  • AIR-Bench 2024 的评分办法是从哪里核对的。论文摘要给出了 prompt 的条数和风险类别的个数。回答分成照做、含糊带过、拒绝三档，以及由 GPT-4o 来判，是在官方代码仓库的说明里核对到的。拒绝率的定义出自论文正文，论文的网页版没能直接打开，读到的是缓存副本里的摘录。出处：AIR-Bench 2024 的论文，官方代码仓库。
  • Chatbot Arena 和 AlpacaEval 的关系。把 Chatbot Arena 看作 AlpacaEval 的做法的扩展，是配图上的说法。Chatbot Arena 的论文没有这样说自己，两者相同的只是都做两两比较。出处：Chatbot Arena 的论文。
  • 「数字环境」和「现实环境」是怎么解释的。配图上 agent 类这一问的原话是：模型能不能在 a digital/real environment 里做很多步，把一件事做成。配图没有解释 digital 和 real 各指什么。这一页把它们译成「数字环境」和「现实环境」，解释成电脑里的环境和电脑之外的现实世界，是按字面作的理解。
  • MMLU-Pro 的 16% 到 33% 为什么按百分点读。论文摘要没有写明这是百分点还是相对的比例，按论文里的数来算是百分点。相对的比例指两个百分数的差除以原来的成绩。论文的表里，GPT-4o 在 MMLU 上的准确率是 88.7%，在 MMLU-Pro 上是 72.6%，相差 16.1 个百分点，和这个范围的下限 16% 对得上。论文有一张图列了十个模型在两个基准测试上的准确率，其中下降最多的是 Yi-34B，从 76.3% 降到 43.0%，相差 33.3 个百分点，和这个范围的上限 33% 对得上。出处：MMLU-Pro 的论文。
  • 相关系数在校正之前是多少。按长度校正的那篇论文在图注里写的是从 0.94 升到 0.98，AlpacaEval 代码仓库的说明里有一处写的是从 0.93 升到 0.98。正文用的是论文的数。出处：Dubois 等，2024。
  • 赛艇游戏那张图的出处。配图上没有标出处。画面和 OpenAI 2016 年那篇文章里的游戏视频对得上，所以按这篇文章来讲。出处：OpenAI，2016。
