先看结论

一个基准测试的分数，是两样东西合起来的结果：题目本身，和这个分数是怎么跑出来的。前一样叫任务定义，后一样叫评估协议。题目出得不好，分数说明不了能力。题目出得好，跑分的方式不一致，分数之间也没法比。

这一讲分五部分，每部分一页。前三部分讲基准测试是什么，并教你把一个 agent 基准测试拆开来看。后两部分分别说这两样要满足什么：第四部分讲好的基准测试的七条性质，第五部分讲可信的分数的四条要求。

下面的表把这两样并排列出来。表里任务定义的三样是这样分的：问题描述说清要 agent 做什么、交什么，环境是 agent 执行任务的地方和开始时可用的东西，验证是给 agent 交出来的东西评分的办法。

表里的七条性质各问一件事。有挑战问的是题目够不够难，自然问的是任务像不像真实的工作，有区分度问的是能不能看出不同系统之间的差别。容易运行问的是别人好不好把基准测试跑起来，容易验证问的是判分对不对。可解释问的是失败了看不看得出原因，耐用问的是基准测试会不会很快失效。

这一讲最后的结论是：没有哪一个基准测试能说明一切。理由有两条。第三部分的十二个案例各考一类任务，比如编程、操作网页或者客服。七条性质又很难同时做到，实际的基准测试通常各有侧重。所以要判断一个模型或 agent 的能力，得同时看很多个基准测试。
