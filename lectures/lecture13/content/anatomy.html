先看结论

  • agent 的基准测试给的是一个任务和一个环境，agent 可以在这个环境里执行操作。agent 在里面做很多步，最后按它做成了什么来评分。
  • 一个 agent 基准测试可以拆成两块：任务定义（要解决什么任务）和评估协议（怎样把一个 agent 系统放到这个任务上去跑）。
  • 任务定义里有三样：问题描述、环境、验证。问题描述有一条轴，从把要求全部写明到只给一个开放的目标。环境也有一条轴，从模拟到真实。验证按两个问题分成四格。不同的基准测试落在不同的位置。
  • 评估协议是五个问题：每题跑几次、什么时候停、模型怎么设置、用谁的运行框架和工具、结果怎么汇总。运行框架指包在模型外面、给它工具并管理多轮对话的程序。同一个模型，这五个问题的答案不同，分数就不同。

它和考试、聊天、安全三类基准测试差在哪

agent 基准测试的定义是：让一个系统在环境里做很多步动作来完成一个任务，然后给它完成的结果评分。

上一部分讲了另外三类基准测试。考试类问的是人参加的考试模型能不能考好，聊天类问的是开放的问题模型答得好不好，安全类问的是模型会不会拒绝恶意的请求。和这三类相比，agent 基准测试给系统的东西、过程、交出来的东西和评分办法都变了。

两大块：任务定义和评估协议

一个 agent 基准测试可以拆成两大块。任务定义说的是题目，评估协议说的是怎样让一个 agent 系统去做这些题。

评估协议由两边一起定，原因是这样的。协议里那几个问题的答案，是在每次跑分时才填的，所以不属于题目本身。但排行榜上的数要能互相比较，就得按同一套值来跑，所以基准测试通常会给出规定或默认值。

这四个基准测试各是做什么的，先说明一下。WebShop 让 agent 在一个模拟的网店里按要求买东西，SWE-bench 的题是修真实代码仓库里的问题，τ-bench 让 agent 当客服。最后一行的 CodeClash 让模型写程序去参加游戏比赛：在游戏里和对手的代码对战的，是模型写的那份代码。表里的「竞技场」指比赛用的一种游戏。

SWE-bench 那一行的例子是一条真实的 bug 报告的标题。这种写在 GitHub 代码仓库里的问题报告叫 GitHub issue。这一条报告的是 astropy 这个库里的问题，astropy 是一个天文学用的 Python 库。标题里的 separability_matrix 是库里的一个函数。CompoundModels 指由几个模型组合成的模型，这里的模型是库里用来做计算的数学模型，和语言模型无关。这个函数算的是模型的每个输出依赖哪些输入，报告把这叫可分离性。这条报告说的是：把一个组合成的模型再放进另一个组合里时，这个函数算出的结果不对。

这个例子要说明的是：这条报告是写给熟悉这个库的人看的，bug 在哪个文件、应该怎么改，要 agent 自己去找。

验证：agent 交出来的东西怎么评分

验证指给 agent 交出来的东西评分的办法，下面叫评分办法。评分办法不同，分数的读法就不同。评分办法可以用两个问题来分，每个问题有两种答案，合起来是四格。

第一个问题：分数是「通过或不通过」，还是一个连续的数。通过或不通过的分数好懂，但做对九成和完全没做是同一个零分。连续的分数能看出差距，但要先回答「多少分算好」。

第二个问题：和谁比，是和一个固定的参照比，还是和别的 agent 或人比。和固定的参照比，指分数只看 agent 自己交出的结果，按题目定好的标准来算：答案对上了没有，测试过了没有，环境的状态对不对，或者按定好的规则算出一个得分或经营结果。和别的 agent 或人比，指分数是按别人的成绩算出来的：赢了对手没有，或者达到了人的成绩的多少。这两句解释是按下面表里各个基准测试的归类整理出来的。

和对手比输赢得出的分数没有固定的满分，换一批对手，同一个系统的分数就变了。Elo 分是这类分数的例子，它是按对战胜负算出的等级分。

按人的成绩折算的分数，参照是人已经做出的成绩。例子有两个。AIRS-Bench 在下面的表里，它让 agent 从零写代码训练模型，完成机器学习的研究任务，分数是和人类发表过的最好成绩比出来的。SWE-fficiency 在表后的蓝色框里，它让 agent 把跑得慢的代码改快，分数是和人类专家把同一段代码改快的程度比出来的。

表里的归类是简化过的。下面五个基准测试的评分办法，表里的一格写不全，细节见第三部分。

  • τ-bench 的环境里有一个数据库，存着订单、航班预订这类记录，agent 当客服办理业务时改动的就是它。评分时除了检查这个数据库的最终状态，还检查 agent 回复用户的话里有没有必须告知的信息。
  • WebArena 只有一部分任务检查网站的状态。查信息的那部分任务，评的是 agent 的文字答案对不对。
  • OSWorld 每个任务的满分是 1，只完成一部分时可以得到一个小于 1 的分数。
  • Terminal-Bench 归在「单元测试过了没有」一格，它的测试检查的是容器的最终状态，不看 agent 执行过什么命令。
  • TextWorld 的游戏有两种：一种是人写的老游戏，一种是程序自动生成的游戏。只有人写的老游戏按游戏得分算，自动生成的游戏默认只在通关时给奖励，也就是只有通关才得分。

评估协议：五个问题

任务定义说的是题目。评估协议说的是怎么让一个 agent 系统去做这些题。它包括五个问题。

同一个模型，这五个问题的答案不同，分数就不同。第五部分有一张图把这件事说得很具体：同一个基准测试上，同一个模型按三种跑法得到三个分数。

另一种拆法：四元组

这一讲把基准测试拆成两块。第三部分先用十二个案例演示这个拆法，再往后的两部分各讲一块。第四部分的七条性质说的是出题的人怎样把任务定义做好，其中两条还要求随题目提供配套的脚本和工具。第五部分的四条要求说的是跑分时怎样对待评估协议。

同样的内容还有另一种拆法，出自 SWE-bench 的作者之一 Ofir Press 的一篇文章。他把基准测试拆成四样，叫四元组。两种拆法的差别在于，「什么时候停」和「能用什么工具」各算在哪一块。
