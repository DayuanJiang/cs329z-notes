先看结论

  • agent 的基准测试给的是一个任务和一个可以动手的环境。agent 在里面做很多步，最后按它做成了什么来评分。
  • 它可以拆成两块：任务定义（要解决什么任务）和评估协议（怎样把一个 agent 系统放到这个任务上去跑）。
  • 任务定义里有三样：问题描述、环境、验证。问题描述有一条轴，从把要求全部写明到只给一个开放的目标。环境也有一条轴，从模拟到真实。验证按两个问题分成四格。不同的基准测试落在不同的位置。
  • 评估协议是五个问题：每题跑几次、什么时候停、模型怎么设置、用谁的运行框架和工具、结果怎么汇总。运行框架指包在模型外面、给它工具并管理多轮对话的程序。同一个模型，这五个问题的答案不同，分数就不同。

它和考试类的基准测试差在哪

agent 基准测试的定义是：让一个系统在环境里做很多步动作来完成一个任务，然后给它完成的结果评分。和上一部分的考试、聊天、安全三类相比，输入、过程、输出都变了。

{{fig 31 | 左边是考试类基准测试的流程，可以写成一行 response = LM(prompt)。右边是 agent 基准测试：agent 是模型加上包在它外面的程序（工具、prompt、记忆），这层程序叫运行框架。agent 和环境来回很多轮。评分看的是环境的最终状态，运行轨迹可以作为参考。}}

两大块：任务定义和评估协议

一个 agent 基准测试可以拆成两大块。任务定义说的是题目，评估协议说的是怎样让一个 agent 系统去做这些题。

评估协议由两边一起定，原因是这样的。协议里那几个问题的答案，是在每次跑分时才填的，所以不属于题目本身。但排行榜上的数要能互相比较，就得按同一套值来跑，所以基准测试通常会给出规定或默认值。

验证：agent 交出来的东西怎么评分

评分方式有几种，选哪一种，分数的读法就不同。下面是三种。第一种是通过或不通过的分数，它好懂，但做对九成和完全没做是同一个零分。第二种是连续的分数，它能看出差距，但要先回答「多少分算好」。第三种是和别人比出来的分数，例如 Elo 分，它是按对战胜负算出的等级分。这类分数没有固定的满分，换一批对手，同一个系统的分数就变了。

用两个问题可以把评分方式分成四格。第一个问题：分数是「通过或不通过」，还是一个连续的数。第二个问题：和谁比，是和一个固定的参照比，还是和别的 agent 或人比。

第二个问题的两头，按下面表里各个基准测试的归类，可以这样理解。和固定的参照比，指拿 agent 交出的结果去对题目自带的标准答案、测试或目标状态。和别的 agent 或人比，指分数是按别人的成绩算出来的：赢了对手没有，或者达到了人的成绩的多少。

任务定义说的是题目。评估协议说的是怎么让一个 agent 系统去做这些题。它包括五个问题。

另一种拆法：四元组

这一讲把基准测试拆成两块。第三部分先用十二个案例演示这个拆法，再往后的两部分各讲一块：第四部分的七条性质说的是任务定义要满足什么，第五部分的四条要求说的是跑分时怎样对待评估协议。

同样的东西还有另一种数法，出自 Ofir Press 的文章，数成四样，叫四元组。两种拆法的差别在于，「什么时候停」和「能用什么工具」算在题目里，还是算在跑分的规定里。
