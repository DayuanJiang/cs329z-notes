先看结论

  • 题目好不好，看的是任务定义，也就是问题描述、环境和验证这三样。分数可不可信，看的是跑分的人有没有照评估协议来跑。
  • 评估协议是在基准测试上运行 agent 时的各种规定：每题跑几次、什么时候停、模型怎么设置、用什么运行框架和工具、结果怎么汇总。运行框架是包在模型外面、给它工具并管理多轮对话的程序。
  • 有四条要求。公平：照基准测试的规定跑，改了要说明。可复现：把模型、运行框架、数据集的版本都固定并记下来。透明：除了分数，还要报跑了几次、误差范围、花费、设置和被排除的任务。诚实：测试集只用来测量，报的系统就是发布的系统。
  • 读别人的分数时，可以把这四条倒过来当作四个问题去问。

题目好，分数也可能不可比

题目出得好，跑出来的分数也可能没法和别人的分数比。同一个模型，换一个运行框架、每个任务多跑几次再挑最好的一次，分数可以从 48% 变成 72%。这两个数是示意用的，下一节有完整的表。题目和模型都没有变，变的只是跑法。

这里的角色变了。第四部分是站在出题的人这边说话，讲任务定义要做成什么样。这一部分是站在拿别人的基准测试来跑分的人这边，讲跑分时怎样照评估协议来做。同一个人常常两边都要做。

公平：照同一套规定跑

照着协议跑，排行榜上的数才可以互相比较。要和基准测试保持一致的有五样：运行框架和工具，轮数、时间和花费的预算，模型的设置，每个任务尝试的次数，能不能上网和能用哪些资源。如果有不一致的地方，要说清楚改了什么、为什么改。

这五样可以和评估协议的五个问题对照着看。运行框架和工具、预算、模型的设置、尝试的次数，对应协议的前四个问题，顺序不同。能不能上网和能用哪些资源，在协议里和工具归在同一个问题下，这里单独列出。协议的第五个问题是结果怎么汇总、报哪些数，这五样里没有单列，报哪些数在后面透明一节讲。

公平和可复现容易混。公平问的是你的跑法和别人的是不是同一套。可复现问的是别人拿着你写下来的信息，能不能把你的跑法重做一遍。跑法和别人不同但写得清清楚楚，是可复现但不可比。跑法和别人相同但没记版本，是当时可比、事后没法核对。

透明：除了分数，还要报什么

报的东西要比一个数多：跑了几次、误差范围、花费、设置，以及有没有把某些任务排除在外。只报一个分数，读的人没法判断它有多可靠、花了多少钱。下面用一张真实的排行榜表来说明。

  • pass@1 是每个任务只尝试一次时的成功率。这张榜上每个任务跑大约 4 次，先取这几次的平均通过率，再对所有任务等权平均。
  • 误差范围是重复测量时分数可能波动的幅度。表里的正负 4% 指的是上下各 4 个百分点。
  • mini-SWE-agent 是一个简单的运行框架，它只让模型执行 bash 命令。这张榜上所有模型都用它。

怎么读这张表

只看表面，70% 高于 67%。把误差范围和花费也看进去，结论就不同：3 个百分点的差距落在误差范围以内，而分数高的那个系统，每个任务的花费大约是另一个的 3 倍。

  • 误差范围。第一行的范围是 66% 到 74%，第二行是 61% 到 73%，两个范围大部分是重叠的。
  • 花费。70% 的那个系统每个任务花 21.63 美元，67% 的那个花 7.23 美元，21.63 除以 7.23 约等于 3。

两个范围重叠，说明只凭这张表，不能确认 3 个百分点的领先是可靠的。它也不能反过来证明两个系统一样强。

要判断谁更强，得拿到两个系统在每一道题上的结果，按题成对地比。两个系统做的是同一批题，往往在同样的题上做对、在同样的题上做错。表里的两个误差范围是各算各的，量不出两个分数之差有多不确定。把每一道题上两个系统的结果配成一对来比，题目难易带来的波动就抵消了，这样才能算出分数差值本身的误差范围。这张表里没有逐题的数据。这种比法的依据见 Anthropic 讲评估统计的文章。

i
表里的误差范围是怎么算的。DeepSWE 一共 113 个任务，每个任务跑大约 4 次，相当于把整个基准测试重跑了大约 4 遍，得到大约 4 个总分。表里的正负 4% 和正负 6% 是按这几个总分之间的波动算出来的 95% 置信区间。置信区间是误差范围的一种算法。95% 的意思是：按同样的办法重复做很多次实验，算出来的范围大约有 95% 会包含真实的平均值。它说的是平均成功率这个估计值有多不确定。出处：DeepSWE 的论文；DeepSWE 排行榜。
i
这个误差范围只算了一种误差。它只算了同一批题重跑时分数的波动。题目只有 113 道，换一批同样难度的题，分数也会变，这一种没有算进去。假设 113 道题互相独立、成功率是 70%，粗略估算，这部分误差大约是正负 8 个百分点，比表里的数还大。这是按假设估算的数，论文没有给，算法见资料说明。它的意思是：把某一个系统的分数推广到同类的其他任务时，不确定的程度比表里看到的大。正负 8 个百分点也不能直接拿来比较两个系统，比较两个系统要像上面说的那样按题成对地比。
+
出题的人该报什么。Zhu 等人 2025 年的论文给出题的人列了一份报告清单，其中三条和这一节直接有关。
  • 报告统计显著性方面的指标，比如置信区间。
  • 报告人类专家这类非 AI 基线的成绩。
  • 报告最简单的 agent 的成绩，比如一个什么都不做的 agent。
出处：Zhu 等，2025。
+
什么都不做的 agent 能拿多少分。上面清单的最后一条做起来很省事，却很管用。τ-bench 让 agent 按规定和一个模拟的用户对话，用工具办理业务。Zhu 等人发现，在 τ-bench 的航空任务里，一个只返回空回答的 agent 能拿到 38% 的成功率，比一个基于 GPT-4o 的 agent 还高。原因是有 38% 的任务本来就设计成无法完成，这些任务的正确结果是数据库不被改动。评分只检查数据库有没有被改动，所以什么都不做的 agent 在这些任务上都算通过。出处：Zhu 等，2025。

有一个看上去相反的建议。Ofir Press 是 SWE-bench 这个编程类基准测试的作者之一，他有一篇讲怎样做基准测试的文章。文章建议基准测试只设一个大家去追的主指标，原话举的例子是不要同时设准确率、精确率、召回率这三个分类任务常用的指标，只留一个。可以这样理解：两处说的是不同的时刻。Press 说的是出题的人怎样设计榜单，一个数容易被大家记住和追赶。这一节说的是跑分的人怎样汇报结果，读的人要靠分数以外的信息来判断这个分数。Press 自己也说，其他指标和分类别的成绩可以放在论文的分析部分。出处：Press 的文章。

整讲的小结

这一讲可以归纳成四条。

  • 要改进基于语言模型的 agent 系统，就得知道怎样衡量它的行为和表现。基准测试是做这件事的主要工具。
  • 一个基准测试可以拆成两块：任务定义（问题描述、环境、验证）和评估协议。
  • 评估协议规定了在基准测试上运行 agent 时的各种参数。所有系统照同一套参数跑，分数才能互相比较。
  • 没有哪一个评测能说明一切。要对一个模型的能力下一个大致的判断，得同时看很多个基准测试。

最后一条是这一讲的结论，可以从两方面理解它。第三部分的十二个案例各考一类任务，比如编程、操作网页或者客服。第四部分还说过，七条性质很难同时做到，实际的基准测试通常各有侧重。所以看一个模型或 agent 强不强，要看它在一组各有侧重的基准测试上的成绩，并且每个成绩都按这一部分的四个问题问过一遍。
