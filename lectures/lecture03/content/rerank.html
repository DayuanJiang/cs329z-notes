先看结论

  • 双编码器（bi-encoder）把查询和段落分开编码，各得到一个向量（表示一段文字的一串固定个数的数字，意思相近的文字向量也相近）再比较。它快，因为段落的向量可以提前算好。它的短处是整段文字只用一个向量表示，细节丢了。
  • 交叉编码器（cross-encoder）把查询和段落拼在一起送进同一个模型，模型处理一边的每个词时都会参考另一边的每个词。它通常判断得更准，但每一对都要完整跑一遍模型，什么都没法提前算。
  • 所以交叉编码器只用在重排（reranking）上：先用快的检索器从整个文档库里取出一批候选，再用它给这批候选重新排序。
  • ColBERT 的做法介于双编码器和交叉编码器之间：查询和段落仍然分开编码，但每个 token（模型处理文字的最小单位，大致是一个词或半个词）保留一个向量，打分的时候才逐个 token 比较。MS MARCO 是一个段落排序的评测数据集，查询来自必应搜索的真实提问。在这个数据集上，ColBERT 重排 1,000 个段落用 61 毫秒，用 BERT-base 做的交叉编码器用 10,700 毫秒，两者排序的质量接近。BERT 是 2018 年的一个预训练语言模型，BERT-base 是它较小的版本。预训练指在用目标任务的数据训练之前，先让模型在大量文字上训练一轮。
  • 在 BM25、DPR、ColBERT 和交叉编码器这四种方法之间选的时候，看四件事：哪些东西能离线算好，查询要多久，擅长什么，会在什么地方出问题。BM25 是按词匹配的传统检索算法，DPR 是把查询和段落各变成一个向量再比较的检索器。

双编码器和交叉编码器

上一部分的 DPR 是双编码器的代表：它用两个编码器把查询和段落各变成一个向量，再算两个向量的内积。内积是把两个向量对应位置上的数字相乘、再加起来得到的一个数，越大表示查询和段落越相关。和它相对的是交叉编码器。两者的差别在于查询和段落在什么时候放到一起比较。

先说明这一页的几个叫法。「查询」指用户交给检索系统的那句话。DPR 是为问答任务做的，它的论文按问题来计数，所以后面引用它的吞吐量时写的「每秒处理多少个问题」，问题就是查询。

「段落」指文档库里被检索的一小段文字。引用的论文有的把它叫文档，所以图上的文档（Document）指的也是段落。「候选」指第一步检索找出来、等着重新排序的那一批段落。

{{fig 50 | 左：双编码器。两个编码器分别处理两段输入，各自汇总成一个向量，最后算一次内积得到分数。右：交叉编码器。两段输入拼成一串，送进同一个编码器，输出一个分数。图里的 Context 和 Candidate 在检索里对应查询和段落。图片来源：Humeau 等，2020。}}

对比这两种结构的一篇论文（Humeau 等，2020）在摘要里把取舍说得很清楚。摘要说，交叉编码器通常效果更好，但慢到没法实际用来检索。双编码器因为两边的向量是分开算的，可以把段落的向量提前算好存起来，反复使用。

交叉编码器太慢，没法给整个文档库的每个段落都打一遍分，只能处理别的检索器筛过的一小批。可以粗略估算一下。下面会看到，BERT-base 交叉编码器给 1,000 个段落打分要 10.7 秒，平均每个段落约 10.7 毫秒。BERT 是 2018 年的一个预训练语言模型，BERT-base 是它较小的版本。MS MARCO 数据集有 880 万个段落，如果对每个查询都把全部段落打一遍分，要 880 万乘以 10.7 毫秒，约 26 个小时。

查询和段落在哪一步比较：四种结构

双编码器和交叉编码器之外还有别的结构。神经网络的排序模型按「查询和段落在哪一步放到一起比较」可以分成四种。

{{fig 51 | 上面是 (d) 这种结构的定义和打分公式，它叫后期交互（late interaction）。下面四张小图是四种结构，绿色是查询这一侧，蓝色是段落这一侧。红框里的 (d) 是 ColBERT 的做法。图片来源：Khattab 和 Zaharia，2020。}}

比较这四种结构，最要紧的是看段落这一侧能不能提前算好。段落的数量非常大，这一侧的计算能离线做完就尽量离线做完。(b) 和 (c) 做不到：(b) 的矩阵每一格都要用到查询里的词，(c) 必须把查询和段落放进同一次计算里。(a) 和 (d) 可以把图上蓝色的那一部分提前算好，查询来了只算绿色的部分，再做最后那一步比较。

ColBERT：每个 token 一个向量，最后才比较

ColBERT 是 Khattab 和 Zaharia 2020 年在学术会议 SIGIR 上发表的模型。它的做法叫后期交互（late interaction），意思是查询和段落之间的比较放到最后才做：查询和段落各自独立地编码，每个 token 保留一个向量，两边到打分的那一步才放到一起比较。

{{fig 52 | ColBERT 的结构。左下是查询编码器，右下是段落的编码器，图上叫文档编码器（Document Encoder），灰色的底表示段落这一侧可以离线做完。中间每个 MaxSim 方框对应查询的一个 token。最上面把所有方框的结果加起来，得到分数。图片来源：Khattab 和 Zaharia，2020。}}

打分的办法叫 MaxSim，分两步。

  1. 对查询里的每一个 token，在段落的所有 token 里找出和它最相近的那一个，记下这个最大的相似度。
  2. 把查询里所有 token 的最大相似度加起来，就是这个段落的分数。

图上的每个 MaxSim 方框做的是第 1 步，最上面的求和是第 2 步。

S(q, d) = 对查询的每个 token i 求和： max over 段落的 token j ( qi · dj )

可以这样理解这个分数：查询里的每个词都去段落里找一个最能对应它的词，把每个词和它找到的那个词有多相近加起来，就是整体的匹配程度。段落里只要有一处和查询里的某个词很相近，这个词的得分就高，不会因为段落里其他不相干的内容被拉低。

MaxSim 打分这一步先算查询的每个 token 向量和段落的每个 token 向量之间的相似度，再取最大值、求和，里面没有要训练的参数。论文说这是一种特别省计算的比较办法。计算量大的部分是用 BERT 算出每个 token 的向量，而段落这一侧的这部分计算可以离线做完。

+
几个实现上的细节。
  • 每个 token 的向量是 128 维，比 BERT 原本的 768 维小，为的是省空间。向量都归一化到长度为 1，所以内积就是余弦相似度，也就是只看两个向量的方向是否一致。
  • 每个查询固定用 32 个向量。查询不够长时，用 [MASK] 补到 32 个。[MASK] 是 BERT 词表里的一个特殊符号，本身不代表任何词，这里拿它来占位置。BERT 算每个位置的向量时会参考整条查询，所以这些补出来的位置也各得到一个由查询内容决定的向量，和其他 token 的向量一样参加打分。论文认为，模型可以借这些位置学着给查询补充新的词，或者调整已有的词的权重。
  • 段落这一侧会去掉标点符号对应的向量，以减少每个段落的向量个数。
出处：Khattab 和 Zaharia，2020，第 3 节。

ColBERT 可以给别的检索器找出的候选重排，也可以自己直接从整个文档库里检索。直接检索分两步。第一步，把所有段落的所有 token 向量放进一个近似搜索的索引里，查询的 32 个向量各自去搜一批最相近的 token 向量，找出它们属于哪些段落，得到候选。第二步，对这些候选用完整的 MaxSim 打分排序。近似搜索的索引能很快找出最相近的一批向量，但不保证一个不漏，见第三部分。下一节的两张表分别给出重排和直接检索这两种用法的成绩。

ColBERT 的成绩

评测用的是 MS MARCO 段落排序数据集，880 万个段落，查询来自必应搜索的真实提问。指标是 MRR@10：第一个相关段落排在第几位，取名次的倒数，前 10 个里没有就记 0，再对所有查询取平均。数值越高，说明第一个有用的结果排得越靠前。

直接从全部段落里检索

这张表显示了重排做不到的一件事：它只能调整候选的先后，候选里没有的段落，它补不回来。第七部分把这叫作召回的上限，召回指相关的段落里有多少进入了候选。上一张重排表里的 BM25 一行和各个模型重排的候选，用的都是官方那一份 BM25 结果。ColBERT 只做重排时，Recall@1000 是 81.4%，和这份候选名单（表里第一行）完全一样。ColBERT 自己直接检索时，Recall@1000 升到 96.8%，MRR@10 也从 34.8 升到 36.0。

ColBERT 的代价是索引的体积：DPR 每个段落存一个向量，ColBERT 每个 token 存一个向量。论文里直接检索用的那份 MS MARCO 索引占 154 GiB，里面每个向量是 128 维、每维用 2 个字节存。论文列出索引体积的那张表一共有五份索引，向量的维数和每维用几个字节存各不相同，体积从 27 GiB 到 286 GiB。

只用于重排的索引可以做得更小：论文那张表里最小的一份把向量从 128 维降到 24 维、每维用 2 个字节存，是 27 GiB，MRR@10 比 128 维时低 1 分。

建索引的时间是另一项代价。论文按每分钟能处理的段落数推算，给 MS MARCO 的全部段落建一次索引，用一台装了 4 块 GPU 的服务器约 3 小时。论文没有按前面说的五份索引分别给出这个时间。

四种方法放在一起比

这一节把前面讲过的四种方法放在一起比：BM25、DPR、ColBERT 和交叉编码器。前三种能从整个文档库里检索，交叉编码器只用来重排。对应到上一部分的三类检索器，BM25 属于按词的一类，DPR 属于按向量的一类，ColBERT 属于第三类，也就是让查询和段落的每个 token 都参与比较的那一类。交叉编码器是这三类之外的重排模型。

实际要检索的文档差别很大，适合的方法也不一样。选的时候可以看四件事：哪些东西能离线算好，查询要多久，它擅长什么，它会在什么地方出问题。下表的四列各对应一件。

这张表的后三行可以连起来读。从 DPR 到 ColBERT 再到交叉编码器，查询和段落之间的比较越来越细：DPR 整段只比一个向量，ColBERT 逐个 token 比，交叉编码器在模型的每一层里处理一边的 token 时，都参考另一边的 token。查询到来之后才能做的计算也越来越多，速度越来越慢。

没有哪一种在所有方面都最好。BM25、DPR 和 ColBERT 都能把段落这一侧提前算好，其中 ColBERT 要存的东西最多。交叉编码器什么都不能提前算。

实际的做法：先检索，再重排

既然快的不够准、准的不够快，实际的系统把它们串成几步来用，每一步处理的数量都比上一步少。

  1. 检索。用 BM25、向量检索或两者的混合，从整个文档库里取出一批候选，通常是几十到上千个。这一步要的是不漏掉。
  2. 重排。用交叉编码器这类更准的模型给候选逐个打分，重新排序。这一步要的是把最相关的排到最前面。
  3. 截取。只把排在最前面的一部分交给语言模型，下面的例子里是前 20 个。

第二部分里 Anthropic（一家开发语言模型的公司）的测试给了这种做法的一组数字。他们先检索出前 150 个块，用一个重排模型打分，再取前 20 个交给语言模型。块是从文档里切出来的一小段文字，相当于这一页前面说的段落。

读下面的表要先知道两个说法。检索失败率指全部相关内容里没有出现在前 20 个结果中的比例。「补上背景」指建索引时，先让语言模型给每一块写一小段背景文字，交代这一块在整篇文档里讲的是什么，再把这段文字加在块的前面。

两行里重排都把失败率降低了三成左右。

同一篇文章也提醒了代价：重排是查询时多出来的一步，会增加延迟和费用，候选取得越多，增加得越多。取多少个候选来重排，要在效果和速度之间试出来。

重排有一件事做不到，「ColBERT 的成绩」一节里直接检索的那张表已经显示过：它只能改变候选的顺序。相关的内容如果没有进入候选，重排帮不上忙。所以第一步检索的召回，也就是相关的内容有多少进入了候选，决定了整条流水线的上限。

这一部分的小结

  • 从 DPR 到 ColBERT 再到交叉编码器，查询和段落之间的比较越来越细，查询到来之后才能做的计算也越来越多，速度越来越慢。
  • 交叉编码器通常比双编码器准，但只能用来重排。ColBERT 用后期交互保留了 token 一级的比较，又让段落这一侧可以离线算好，在重排表里和 BERT-base 交叉编码器的成绩接近，代价是索引更大。
  • 实际的系统分成几步：快的方法负责不漏，准的方法负责排好。

到这里为止，流水线对每个查询都是固定地走一遍：检索，重排，生成。下一部分讲把检索交给模型自己来决定之后会发生什么。
