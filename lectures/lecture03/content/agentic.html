先看结论

  • RAG（Retrieval-Augmented Generation，检索增强生成）指先检索出相关的内容，再交给语言模型写回答。负责检索的部件叫检索器，写回答的语言模型叫生成器，下面也叫生成模型。前面几部分的流水线，对每个问题都按固定的步骤检索一次。它能把一个问题答好，但它自己不决定要不要查、查什么、什么时候停。
  • agentic RAG 把检索变成 agent 可以采取的一个动作。agent 指能自己调用工具、分很多步完成任务的语言模型系统。这样一来有三个决定要做：查还是直接答，发出什么查询，查到的结果够不够好。结果不够好就再查一次，够好了就停下来回答，所以第三个决定也决定了什么时候停。
  • 三个有代表性的系统做这些决定的办法不同。Self-RAG 把「查不查」和「够不够好」训练进生成模型本身。CRAG 在检索器和生成器之间加一个很小的评估器，也就是给检索结果打分的模型，生成器不用重新训练。Search-R1 用强化学习训练模型，让模型自己学会整个搜索过程，训练时只告诉模型最后的答案对不对。强化学习指让模型反复去做题，按结果的好坏给奖励，再据此调整模型。
  • 把检索交给模型之后，一个问题可以检索不止一次，这叫多轮检索。多轮检索让系统能回答更难的问题，也让出错的方式变多了，这些问题放在第七部分讲。什么时候该停是其中的一个。第七部分为此举了三个系统的做法：这一页的 Search-R1，和另外两个系统 IRCoT、ReAct。这三个系统里，什么时候停都靠一个硬性的次数上限，再加一个表示结束的信号。

三个决定

到这里为止讲了三样东西：提问之前为文档建好的索引，从索引里找出相关内容的检索器，和给找出的内容重新排序的重排。它们合起来能把一个问题答好。但整个过程里系统没有任何主动性：不管问的是什么，它都检索一次，把结果交给模型，然后结束。

RAG 和 agent 结合之后，检索成了 agent 的一个动作，和调用别的工具一样，由模型决定用不用、怎么用。这带来三个决定。

下面三个系统，可以按「这三个决定各由谁来做」去读。

Self-RAG：让生成模型自己输出判断

Self-RAG（Asai 等，发表在学术会议 ICLR 2024）的办法是训练一个模型，让它在写回答的同时输出一些特殊的 token，用来表示它对检索和对自己输出的判断。token 是模型处理文字的最小单位。这些特殊的 token 叫反思 token（reflection token）。

{{fig 57 | Self-RAG 回答「美国各州的名字是怎么来的」的过程，分三步。绿色、红色、橙色的小标签是模型自己输出的反思 token。图片来源：Asai 等，2024。}}

按图里的三步看。

  1. 需要时才检索。模型先写出回答的第一句「美国各州的名字有各种来源」，然后输出一个表示「需要检索」的 token。这时检索器才去找段落，图里找回了三段。
  2. 对每个段落各写一个候选。模型把三个段落分别和问题放在一起，各自写出回答的下一句话，这三句话是三个候选。模型同时给每个候选打上标签。标签有两种：一种说这个段落和问题相不相关，一种说这句话是不是得到段落的支持。第一个候选是「50 个州里有 11 个以人名命名」，标签是「相关」和「完全支持」，图上印的是 Relevant 和 Supported。第二个候选是「得克萨斯以一个美洲原住民部落命名」，标签是「不相关」。第三个候选讲加利福尼亚的名字出自一本 16 世纪的小说，标签是「相关」和「部分支持」，图上的 Partially 就是部分支持。
  3. 评判，留下最好的。按这些标签给三个候选排序，第一个候选排在最前，被接到回答里。然后回到第一步，继续写下一句，直到回答写完。

四种反思 token

反思 token 一共四种，上面例子里的两种标签是其中的 ISREL 和 ISSUP。下表列出每一种判断的是什么、可以取哪些值。

后三种 token 都归在决定三上，它们判断的对象不同。ISREL 判断的是检索回来的段落。ISSUP 和 ISUSE 判断的是模型按这个段落写出的那个候选。留下哪个候选，也就定下了采用哪个段落的结果，所以这里把三种都算作决定三。

排序时三种 token 一起用。按论文的算法，模型给每个候选都输出 ISREL、ISSUP 和 ISUSE，再按这三种 token 给候选排序。上面图里的例子只画出了 ISREL 和 ISSUP 两种。

怎么训练

要让模型学会输出这些 token，训练数据里就得有它们。论文的做法分两步。先让 GPT-4 给一批样本标上反思 token，用这些标注训练出一个评判模型。再用评判模型给 15 万条「指令，回答」样本离线插入反思 token，然后在这份数据上按普通的「预测下一个 token」的方式训练生成模型。训练完之后，生成模型自己就能输出反思 token，使用时不再需要评判模型。

这个办法的代价就在这条训练流程上：需要一份带评判标签的数据，生成模型也必须重新训练。论文用的生成模型是 Llama 2 的 7B 和 13B 两个版本。Llama 2 是 Meta 公开发布的语言模型。名字里的 B 表示十亿，7B 是有 70 亿个参数的版本，13B 是有 130 亿个参数的版本。

效果

论文一共评测了六项任务。下表摘出其中两项的成绩，把 Self-RAG 13B 和同样大小的 Llama2-chat 放在一起比。Llama2-chat 是 Llama 2 的对话版本，这里有两种用法：检索后直接把段落拼进输入，和不检索。

论文对六项任务的总结是：Self-RAG 在所有任务上超过了 Llama2-chat 和 Alpaca，在其中四项任务上超过了带检索的 ChatGPT。Alpaca 是用指令数据微调出来的一种模型，论文里用的是作者在 Llama 2 的基础上重做的版本。微调（fine-tuning）指在已经训练好的模型上，用新的数据接着训练。

也有没超过的任务。在科学选择题 ARC-Challenge 上，ChatGPT 的准确率带检索和不带检索时都是 75.3%，Self-RAG 13B 的准确率是 73.1%。

CRAG：在检索器和生成器之间加一个评估器

CRAG（Corrective RAG，Yan 等，2024）用的是另一种办法：生成模型不做任何改动，在检索器和生成器之间插入一个评估器。CRAG 的论文把检索回来的每一条内容叫文档（document），这一节照它的叫法。它和上一节的段落一样，是检索器找回来的一条文字。评估器给检索回来的每篇文档打一个分数，系统设了一高一低两个阈值，分数和阈值比较的结果决定接下来做什么。

{{fig 58 | CRAG 的流程，从上到下三层：检索，知识修正，生成。例子里的问题是「《Death of a Batman》的编剧是谁」。中间一层左边是检索评估器，它的判断有三种：Correct、Ambiguous、Incorrect，各自通向右边不同的处理。图片来源：Yan 等，2024。}}

下表列出评估器的三种判断各在什么情况下得出、接下来做什么。三种判断各接一种处理办法，下面把它们叫三条分支。

图里的例子走的是「错误」这条分支：问题被改写成「Death of a Batman; screenwriter; Wikipedia」这样一串关键词，拿去做网页搜索。

这个设计有三个特点。

  • 评估器很小。它是一个微调过的 T5-large，有 7.7 亿参数。T5 是 Google 的一个预训练语言模型（先在大量文字上训练过一轮、可以拿来接着训练的模型），有大小不同的几个版本，T5-large 是其中之一。作为对照，Self-RAG 用来给训练数据打标签的评判模型是 70 亿参数的 Llama 2。
  • 可以直接接到已有的系统上。它不要求改动生成器，所以可以接在任何一套 RAG 流水线的检索之后。论文把它分别接到了普通的 RAG 和 Self-RAG 上。
  • 它负责的是决定三。决定一没有变，每个问题仍然先检索。决定二只在检索被判为错误或不确定时出现一次，由另一个语言模型把问题改写成搜索用的关键词。

四种做法的差别在检索回来的文档怎么用。普通 RAG 把检索到的文档直接拼在问题前面，交给这个模型。Self-RAG 按上一节的三步来做，用模型输出的反思 token 挑选候选。另外两种是在这两种做法上各接上 CRAG，检索回来的文档先经过评估器的判断和处理。

Search-R1：用强化学习学会怎么搜

Self-RAG 和 CRAG 的流程都是人设计好的：一共有哪几步、每次判断之后接着做什么，都写在系统里，模型只在指定的位置做判断。Search-R1（Jin 等，2025）把整个流程交给模型：查不查、查什么、查到的结果够不够好，都由模型在训练里自己学会。下面先看它的一条运行记录，再看它怎么训练、效果如何。

{{fig 59 | Search-R1 的一条真实的运行记录。问题是「Jed Hoyer 和 John William Henry II 谁的年纪大」。红色的标签把记录里的文字分成四种：think 是模型的推理，search 是模型发出的查询，information 是搜索引擎返回的内容，answer 是模型最后的回答。图片来源：Jin 等，2025。}}

图里说的搜索引擎是论文的叫法。它由一个文档库和一个检索器组成，文档库是 2018 年的维基百科，搜索引擎只在这份文档库里找段落。具体的配置见后面的「怎么训练」。

这条记录里模型搜了三次。

  1. 第一次的查询把两个名字放在一起，返回的是 Jed Hoyer 的词条，里面没有出生日期。模型读完之后的推理是：知道了他是谁，还要找他的年龄，再和另一个人比。
  2. 第二次只搜 John William Henry II，返回的段落里有他的出生日期：1949 年 9 月 13 日。
  3. 第三次把查询改成「Jed Hoyer birth year」，返回的仍然是第一次那一段。模型随后的推理说他生于 1973 年 12 月 7 日，于是回答 John William Henry II 年纪大。

第三步有一处要留意：图上显示的检索结果里找不到 1973 年 12 月 7 日这个日期，它很可能来自模型自己记住的知识。最后的答案是对的，但这一步的依据不在检索回来的文字里。第七部分会讲到，证据没有找回来时，模型只能用自己记住的知识回答。

先把两个名字放在一起查、再单独查 John William Henry II、最后回头查 Jed Hoyer 的出生年份，这个顺序是模型自己定的。每一步查什么，它读了上一步的结果之后才决定。论文对这个例子的评语是：模型写的第一个查询意义不大，但它在这之后开始一步一步地写查询、解决问题。

怎么训练

训练分两部分看：给模型的指令，和强化学习的流程。下图把两者画在一起。

{{fig 60 | 上半部分是两种强化学习算法（PPO 和 GRPO）的训练流程，两者都在生成过程里接入了搜索引擎。黄色是被训练的模型，绿色是训练中参数固定的部分，蓝色是搜索引擎。下半部分是给模型的指令。图片来源：Jin 等，2025。}}

图下半部分的指令规定了输出的格式，一共四条。

  • 每次得到新信息，都要先在 think 标签里推理。
  • 觉得缺知识时，在 search 标签里写查询，系统会把搜到的结果放在 information 标签里返回。
  • 可以搜任意多次。
  • 不需要更多外部知识时，在 answer 标签里直接给出答案。

指令里说可以搜任意多次，系统另外设了一个上限：一道题最多做 4 次动作。一次动作指模型连续输出的一段文字，这段文字写到它发出一个查询或给出答案为止。

训练用的是强化学习：模型按这套格式去做题，做完得到一个奖励，再根据奖励调整模型。和通常的强化学习训练相比，主要的改动是：在模型生成的过程中，每当它输出一个查询，就真的去调用搜索引擎，把结果插回到它的上下文（模型此刻能读到的全部文字）里，再让它接着写。

别的部分和标准的做法一样。论文用了 PPO（Proximal Policy Optimization）和 GRPO（Group Relative Policy Optimization）两种常用的强化学习算法，两者都按上面说的过程训练：做题，得到奖励，再调整模型。论文的主要结果用的是 PPO。

两种算法的差别在调整模型这一步。调整时要拿一次输出得到的奖励和一个参照值比较：奖励高出参照值，就让模型以后更倾向于这样输出，低于参照值就让它更少这样输出。PPO 另外训练一个模型来估计这个参照值，这个模型就是配图里的 Value LLM。GRPO 让模型对同一道题写出一组输出，拿这一组的平均奖励作参照值。

配图里绿色的框有两种，训练中它们的参数都固定。Reward Model 负责给出奖励，这篇论文里它是一条固定的规则，也就是下面第一个要点说的看答案对不对，论文没有为此另外训练模型。

Reference LLM 是另一个语言模型。训练要让模型拿到的奖励尽量高，同时带一项限制：被训练的模型的输出和 Reference LLM 的输出差得越远，从奖励里扣掉的就越多。论文说这项限制是为了让训练保持稳定。Reference LLM 具体是哪一个模型，论文没有写明。

训练有三个要点。

  • 奖励只看结果。最后的答案和标准答案完全一致，奖励是 1，否则是 0。中间搜了几次、查询写得好不好，都不单独给奖励。
  • 搜回来的文字不参与训练。上下文里 information 标签中的内容是搜索引擎给的，模型没有写它们。计算训练的损失（衡量模型的输出离目标差多远的数）时把这部分遮掉，只在模型自己生成的 token 上算。论文的对比实验里，遮掉时七个数据集的平均完全匹配率是 0.431，不遮是 0.343。完全匹配率指答案和标准答案一字不差的题所占的比例。
  • 搜索引擎是现成的。前面说的搜索引擎，文档库和检索器都是现成的。文档库是 2018 年的维基百科。检索器是 E5 向量模型，它把查询和段落各变成一个向量，也就是一串固定个数的数字，再按向量相近的程度来找。每次搜索返回 3 个段落。

+
不训练模型也可以做多轮检索。上面三个系统都要训练一个模型。还有一类做法只靠 prompt（给模型的输入文字），下面是两个例子。
  • IRCoT（Trivedi 等，2022）让模型一句一句地写推理，每写一句就用这一句去检索一次，再根据检索结果写下一句。论文报告在 HotpotQA 等四个数据集上，和只用问题检索一次的做法相比，检索的召回率最多提高 21 个百分点，最后问答的 F1 分数最多提高 15 分。召回率指应该找到的段落里实际找到的比例。F1 分数衡量回答和标准答案在用词上的重合程度，满分 100。
  • FLARE（Jiang 等，2023）让模型先试写下一句。模型生成每个 token 时都带有一个概率，概率低表示模型对这个 token 没有把握。试写的这一句里只要有 token 的概率低于设定的值，就去检索并重写这一句。
IRCoT 也出现在 Search-R1 论文的结果表里，是用来对照的做法之一。它在七个数据集上的平均完全匹配率是 0.239，低于同一张表里只检索一次的 RAG 的 0.304，和 IRCoT 论文自己的结果方向相反。两处的实验条件不同。IRCoT 论文里提高 21 个百分点和 15 分的结果是用 GPT-3 这个模型测的，比的是召回率和 F1 分数。Search-R1 的表用的模型是 Qwen2.5-7B，比的是完全匹配率。所以这两个结果不能直接放在一起比。出处：IRCoT；FLARE。

这一部分的小结

  • 把检索变成 agent 的一个动作之后，要做三个决定：查不查，查什么，够不够好。
  • Self-RAG 把判断训练进生成模型，CRAG 把判断交给一个外加的小模型，Search-R1 让模型用强化学习自己学出整个过程。
  • RAG 是一种设计上的原则，在 agent 系统里同样用得上：模型需要它没有的信息时，去外面取回来再接着写。三个系统用的都是这个原则，各自不同的地方是查不查、查什么、够不够好由谁来决定。

多轮检索让系统能回答更难的问题，也让出错的方式变多了。下一部分集中讲 RAG 会在哪里出问题。

资料说明

这一节记录核对资料时发现的出入和没有查到的地方。前面各节的结论已经按核对的结果来写。

  • Search-R1 摘要里的提高幅度。arXiv 是研究者公开发布论文的网站，同一篇论文可以先后更新出几个版本，Search-R1 的论文在上面有五个版本。摘要里以 Qwen2.5-7B 为基础模型的提高幅度，第一版写的是 26%，第三版是 41%，第四版和第五版的 PDF 里是 24%。每篇论文在 arXiv 上另有一个摘要页，直接显示摘要的文字，这篇论文的摘要页和 PDF 不一致，显示的仍是 41%。三个数都是七个数据集平均完全匹配率的相对提高。按各版本表里的数推算，变化有两个原因。第三版更新了 Search-R1 自己的结果。第四版加进了 Rejection Sampling 这个更强的基线，比较的对象从 RAG（0.304）换成了它（0.348）。第三版的 41% 比的是 Search-R1 的 0.431 和 RAG 的 0.304，按这两个数算是 41.8%，摘要写成 41%，论文没有给出算式。出处：Jin 等，2025。
  • Search-R1 名字里的 R1。Search-R1 论文第一版的摘要把 Search-R1 称为 DeepSeek-R1 的扩展，后来的版本在正文里说它可以看作 DeepSeek-R1-Zero 的扩展。DeepSeek-R1-Zero 是 DeepSeek-R1 那篇论文里介绍的另一个模型，只用强化学习训练，前面没有监督微调这一步。监督微调指用带标准答案的样本把已有的模型接着训练一轮。按那篇论文的摘要，DeepSeek-R1 的训练分成多个阶段，强化学习之前还用了一批预先准备的数据。两个模型的差别在这里。出处：两种说法见 Jin 等，2025的各个版本，DeepSeek-R1-Zero 的介绍见 DeepSeek-R1 论文第一版的摘要。
  • 训练曲线图上的 Valid Search。Search-R1 的论文正文把它称为有效的搜索引擎调用次数，没有写明什么样的调用算有效。出处：Jin 等，2025，第 5.3 节。
  • CRAG 的数字取自哪一版。CRAG 一节的两张表用的是论文 2024 年 10 月的第三版，和第一版里的数字不同。出处：Yan 等，2024。
