先看结论

模型和 agent 实际会做什么，人读不出来，最后要以评估的结果为准。评估指拿一批任务去测、给结果打分。越来越多的软件由 agent 生成，这些软件也越来越靠运行和测试来判断。这一讲说评估是软件，指的是评估用的那批任务：任务是软件，要像软件一样写、测试、发版本、持续修。

这一讲用的例子是 Terminal-Bench 和 Harbor。Terminal-Bench 这个基准测试里的一道题，这一讲叫一个任务，拿这些任务去测 agent、给结果打分就是评估。Harbor 是 Terminal-Bench 的团队把做基准测试的经验整理成的一套工具。

下表把一个评估任务从写到修的四个环节，和软件工程里对应的做法放在一起。第一行里的任务说明是交给 agent 的那段文字，写明要做成什么。环境是 agent 动手的地方，里面放着它要用的文件和软件。表里说的一次运行，指 agent 对一个任务的一次尝试，同一个任务通常要跑很多次。

这一讲按四个问题展开，每个问题对应一个部分，下表是每个问题的答案和一个依据或例子。第一行里的规格说明（specification），指用文字或文档写明软件应该做什么。第四行里的系统，指一个模型配一个运行框架，运行框架是包在模型外面、给它工具并管理多轮对话的程序。排行榜上的每一行是一个系统。
