先看结论

  • 做软件有两种办法。演绎式：人写规则，程序把规则用到新的输入上。归纳式：人给出例子，也就是输入和期望的输出，规则照着例子找出来，没有人逐条去写。传统软件工程是前一种。机器学习是后一种，它找规则的办法是训练。
  • 演绎式的软件，原则上可以靠读代码推出它会做什么。用归纳式做出来的东西，对不对只能靠在例子上测量。
  • 模型是从数据里学出来的。agent 是靠评估一轮一轮改出来的。评估指拿一批任务去测、给结果打分，每次改动之后都要评估一遍，才知道是变好还是变坏。越来越多的软件是 agent 生成的。这三层都在变成归纳式，所以评估成了开发的中心：开发流程从定目标和做评估开始，模型和 agent 实际会做什么，最后也以评估的结果为准。
  • 对 agent 来说，训练数据和测试数据是同一种格式的东西：一个个任务。每个任务有任务说明、一个可以动手的环境，和一个判断结果的验证器。

写程序的三个阶段：人要写的细节越来越少

今天用 agent 写软件，人写的是一段任务说明，代码由 agent 生成。在这之前，写程序的方式已经经过三个阶段。每往后一个阶段，人要亲手写的细节就少一些，交给工具去翻译的部分就多一些。用 agent 写软件是朝同一个方向又走了一步。下表用同一件事「把一个数加 5」在三个年代的三种写法来说明。

用 agent 写软件这一步，和前三个阶段有一个根本的区别。前三个阶段里，规则始终是人写的，程序对不对可以靠读代码来判断。用 agent 写软件之后，代码是生成出来的，对不对越来越靠测量来判断。

下一节先用一个小例子看「靠读」和「靠测」差在哪里，例子里只换掉一个函数的写法。再往后的两节给这两种办法起名字，叫演绎式和归纳式。「三层都在变成归纳式」一节再回到 agent 生成的软件。

+
延伸：前几次换阶段时有人抵触。高级语言 FORTRAN 的主要设计者 John Backus 在 1976 年回忆 1950 年代时说，当时很多程序员把自己看作掌握着一门技艺的神职人员，认为这门技艺复杂到普通人学不会。凡是想让更多人也能编程的系统，他们都敌视和嘲笑。出处：Backus 的演讲《Programming in America in the 1950s》的摘录。
+
延伸：也有人过分乐观。IBM 在 1954 年写的 FORTRAN 初步报告里有一句话：FORTRAN 应该能基本消除写代码和调试这两件事，所以解决一个问题的成本可以降到原来的一半以下。七十多年过去，写代码的方式变了很多次，调试一直都在。

两个版本各有各的错法。规则的版本会漏掉规则没写到的格式，或者只取出号码的一部分。模型的版本可能在某些输入上取错，或者在号码之外多输出一些文字。区别在于怎么发现这些错：前一种可以靠读，后一种只能靠测。

从适用的范围看，调用模型的版本更好用：它能认出更多种写法，输入的格式稍有不同也不容易失效。它的代价是可预测性变差。同一段输入跑一百万次，规则的版本每次输出什么，事先就能说出来。模型的版本在这样简单的任务上很可能几乎每次都一样，但没有人能保证。交给模型的任务越难，它的输出越难预料。

演绎式：人写规则，对不对可以读出来

机器码、汇编语言、高级语言这三个阶段，和上面例子里用规则写的版本，有一个共同点：规则是人写的。程序做的事是把这些规则用到新的输入上，得到输出。这种做软件的办法可以叫演绎式。

演绎式的软件有一个很强的性质。计算机科学家 Tony Hoare 在 1969 年的论文《An Axiomatic Basis for Computer Programming》开头这样说：计算机编程是一门精确的科学，一个程序的所有性质，以及它在任何给定环境里运行的所有后果，原则上都可以只凭程序的文本，用纯粹的演绎推理得出来。

换成日常的话：原则上，想知道一段代码会做什么，读它就能推出来，不必运行。代码评审、静态检查和形式化验证都建立在这一点上。代码评审是人读代码，静态检查是让工具在不运行程序的情况下检查代码，形式化验证是用数学方法证明程序符合写明的要求。

传统的软件开发流程也是按这个性质排的：先写规格说明（specification，用文字或文档写明软件应该做什么），再实现，再测试，再上线。写代码的人读得懂自己写的东西，每一步都知道自己做了什么，代码对不对主要靠读和推理来判断。测试排在实现之后，起的是确认的作用：确认代码做到了规格说明写的事。实际的软件开发里，读代码和跑测试是一起用的。

在这个流程里，规格说明是起点。软件实际会做什么，最后以代码为准。

归纳式：人给例子，对不对只能测出来

演绎式由人写规则，机器学习的做法相反。人提供的是例子，也就是输入和期望的输出，在机器学习里叫数据和标注。规则由训练过程从例子里找出来，找出来的规则就是模型。这种办法可以叫归纳式。上面例子里被调用的语言模型就是这样来的。

这一页说一样东西是用归纳式做出来的，指的是两点同时成立。第一，规则是照着例子找出来的，没有人逐条去写。第二，找出来的规则对不对，读不出来，只能再拿例子去测量。机器学习的训练是照着例子找规则最常见的办法。

改一处、测一遍、留下更好的那一种，这样一轮一轮地改，也是照着例子找规则。后面讲 agent 时说的归纳式就是这一种：例子是评估用的那一批任务，找出来的规则是改到最后留下的那个 agent。本节后面先用取电话号码的函数举一个这样改的例子。

对这种靠数据找规则的办法，有过一个很绝对的说法：数据足够多的时候，可以不要理论。它出自《连线》杂志的 Chris Anderson 在 2008 年 6 月发表的文章，题目就叫《The End of Theory: The Data Deluge Makes the Scientific Method Obsolete》。文章说的理论，也包括人们为了解释现象而事先提出的模型。这里的模型指一种解释现象的理论，和机器学习里训练出来的模型是两回事。文章举的例子是 Google：它给网页排序，不需要知道一个网页为什么比另一个好，只要链接的统计数据显示它更好就够了，给内容配广告也是同样的做法。文章把这种做法概括成一句话：有相关性就够了，不必追问因果。

题目的说法很绝对，但它说中了后来确实发生的一个变化：在图像识别、语音识别、机器翻译这些问题上，从数据里学出来的系统后来都比人写规则的系统做得好。

下表把演绎式和归纳式并排比较，归纳式一列写的是机器学习的情形。最后一行是两种开发流程，表后的图画的就是这两种流程。

{{fig 22 | 上面一行是传统的软件开发流程，四步依次是规格说明、实现、测试、上线，标注为演绎式。下面一行是模型、agent 和软件现在的开发流程，四步是目标、评估、实验、优化，标注为归纳式，并且从优化有一条线回到评估，表示这几步要反复做。}}

下面一行的四步里没有写「训练」，它仍然是归纳式。评估这一步准备的例子就是人提供的例子。实验和优化两步照着在这些例子上测出的结果，一轮一轮地改。改出来的东西对不对，也靠在例子上测量。

两行流程里，测试和评估的位置不同。上面一行里，测试排在实现之后，是用来确认的。下面一行里，评估排在实验之前：要先准备好一批用来测的例子和给结果打分的办法，才谈得上做实验和优化。没有评估，后面两步无从下手。

下面一行的四步可以这样理解。

  • 目标是想让要做的模型、agent 或软件做到什么。
  • 评估是拿一批例子去测、给结果打分。做这一步要先准备好两样东西：一批用来测的例子，和给结果打分的办法。对 agent 来说，这批例子是一个个任务，「agent 的训练数据和测试数据是什么」一节会讲到。
  • 实验是试一种改法，看它有没有用。实验通常是对照试验，也就是只改一处、其余不变，比较改动前后的结果，例如消融实验（ablation，去掉或改动一个部分，看结果变化多少）。
  • 优化是按实验的结果，把正式的版本真正改掉。它相当于上面一行的实现，因为正式的版本是在这一步被改动的。

拿前面取电话号码的函数举一个例子，四步可以这样对应。目标是从各种写法的文字里取对号码。评估要准备的是一批有代表性的输入和正确答案，打分的办法是数取对了多少，跑一遍就得到取对的比例。实验是另写一种 prompt 试跑一遍，看取对的比例变了多少，这时正式用的 prompt 还没有换。优化是把正式用的 prompt 换成取对比例更高的那一种，然后回到评估再来一轮。

两行的走法也不同。上面一行大体上从前往后走一遍，写的人读得懂代码，每一步都知道自己做了什么。下面一行要一轮一轮地试，靠试错逐步得到更好的结果。

三层都在变成归纳式

从传统软件到机器学习，再到语言模型和 agent，归纳式的范围一步步扩大。到今天，模型、agent 和软件这三层都越来越多地用归纳式的办法做出来。三层各是怎么来的，人还读不读得出它会做什么，各不相同。下面先说模型和 agent 这两层是怎么来的，再用一张表把三层放在一起。

语言模型是用机器学习的办法训练出来的一类模型。它的输入和输出都是文字，训练的目标是预测下一个 token（模型处理文字的基本单位）。互联网上的大量文字因此成了现成的带标注数据：前面的文字是输入，紧跟着的文字是标注。

agent 让模型能在计算机上动手做事。模型按约定的格式输出一段文字，运行框架把它转成对另一个程序的调用，或者直接当作代码去执行。运行框架（agent harness）是包在模型外面、给它工具并管理多轮对话的程序。

到这一步，在计算机上执行哪些操作也由模型来决定。模型的行为没有人逐条编写，是从大量数据里学出来的。这一页讲到了传统软件、调用模型的函数和 agent，三者当中，agent 由人写的规则决定的事情最少。

运行框架仍然是人写的，但它改得好不好，读代码看不出来。agent 实际怎么做由模型决定，同一个任务跑两次，过程和结果都可能不同，所以运行框架的每次改动都要靠评估来判断，见下表的第二行。

软件这一层和另外两层有一处不同。上一节说归纳式要两点同时成立，其中第二点是找出来的规则对不对读不出来。模型和 agent 这两层读不出来。agent 生成的代码原则上读得出来，逐行读过的代码，对不对仍然可以靠读来判断。把这一层也算作归纳式，说的是实际的做法：生成的量太大，越来越少有人逐行去读，代码被当成读不出来的东西，靠运行和测试来判断。

深度学习库 Keras 的作者 François Chollet 在 2026 年 2 月的一条帖子里把第三层说得很直接：用足够强的 agent 来写代码，本质上就是在做机器学习。

他把用 agent 写代码这件事和机器学习逐项对应起来，见下表。左列是机器学习里的东西，先说明其中几个词。优化目标是训练要让它变好的那个指标。搜索空间的约束（constraints on the search space）限定训练可以在什么范围里找答案。优化过程是一步步调整、直到达到目标的过程。黑盒模型是只看得到输入和输出的模型。

在这个对应里，规格说明和测试一起成了 agent 反复尝试时要达到的目标：规格说明用文字写明想做到什么，测试用来判断做到了没有。下一节会讲到，开发流程的起点从写规格说明换成了定目标和做评估。那里说的变化，是怎样才算做到改由评估来确定，想做到什么仍然要用文字写下来。

他接着指出，机器学习里的老问题也会跟着来。一个是对规格说明过拟合，也就是只对写明的那些要求有效，换一种情况就不行。一个是只在测试范围内有效的捷径。还有一个是数据泄漏，也就是答案提前漏给了被测的一方。

Chollet 说的「只在测试范围内有效的捷径」，在 agent 的评估里属于钻空子（reward hacking）的一种。钻空子指 agent 没有按本意完成任务，却靠漏洞拿到分数。漏洞可能出在环境里，也可能出在验证器里，还可能出在运行评估用的那套程序和服务里。环境是 agent 动手的地方，里面放着它要用的文件和软件。验证器是任务里给结果打分的程序。第三部分会专门讲钻空子的几种做法和对付它的办法。

规格说明原来的位置，现在归评估

把上面几节合起来，从传统软件到现在的模型、agent 和 agent 生成的软件，有两处换成了评估。这两处说的是两件事，要分开看。

第一处是流程的起点。以前开发流程从写规格说明开始，现在从定目标和做评估开始，也就是归纳式一节的流程图里下面一行的头两步。目标说的是想做到什么。怎样才算做到，要靠评估来确定，所以原来由规格说明承担的工作，现在主要由评估承担。这一节的标题说的就是这一处。

第二处是最终依据。例子一节说过，最终依据指想确认做出来的东西实际会做什么，最后以什么为准。在传统软件里，代码是最终依据。现在，评估的结果是最终依据。

这一点在三层上的程度不同。模型和 agent 这两层，人读不出它们会做什么，只能以评估的结果为准。agent 生成的软件，代码仍然可以读，但上一节的表说过，实际上越来越多地靠运行和测试来判断，不同团队的做法差别很大。

下表的前两行是这两处变化，后三行是跟着一起变的另外三件事。右列说的是现在的模型、agent 和 agent 生成的软件这三层。

流程的起点换了，这份工作由谁来做也成了问题。以前写规格说明的人是软件工程师。现在做评估的人是谁，这个角色要会什么，目前没有现成的答案。它可能是一种新的职业，也可能是现有的职业换一套开发方法，合适的工具和分工都还在形成当中。

这个角色要做什么，Harbor 的团队有过一个说法。Harbor 是一套用来做评估和运行评估的开源工具，它的团队在 2026 年 10 月的一篇文章里说：开发流程从设计和实现转向评估和优化之后，人的工作越来越多地是设计给结果打分的办法。出处：Cracking down on reward hacking。

要达到什么目标，仍然要用文字写下来。评估用的每个任务都有一段任务说明，也就是交给 agent 的那段文字，要做成什么就写在里面，由验证器（给结果打分的程序）逐条检查。任务说明写明要做成什么，验证器确定怎样才算做成。上一节说规格说明用文字写明想做到什么，测试用来判断做到了没有，按这个说法，任务说明和验证器的分工与规格说明和测试的分工相同。这一句是对照两处的内容得出的，见资料说明。第三部分会讲到，任务说明和验证器要一一对应。

agent 的训练数据和测试数据是什么

先比较两个目标。训练一个预测房价的模型，训练数据和测试数据是什么样子很容易想到：一张数字表格，每一行是一套房子的各项特征和成交价。把目标换成「让 agent 接手牙科诊所前台的日常工作」，训练数据和测试数据是什么样子，就不容易想出来了。

机器学习里，训练数据和测试数据是一条条「输入加标注」。agent 要做的是在一个环境里分很多步完成一件事，一条「输入加标注」描述不了这样一件事。对应的东西是任务。

下表左列是机器学习里的几个词，右列是它们在 agent 开发里对应的东西。左列的权重是模型里在训练时被调整的大量数值参数。损失函数给模型的输出打分，衡量它离正确答案有多远。优化器按这个分数去调整权重。测试集和验证集是不拿来训练、专门用来检查模型的例子。

右列有两处要说明。技能文档（skills）是写给 agent 看的说明，告诉它某一类事情该怎么做。改 prompt 的优化算法是一类自动改写 prompt 的程序：它读运行的记录和评估的反馈，提出对 prompt 的修改，再评估一遍，看得分有没有提高。

表里最要紧的是前两行：训练用的和测试用的是同一种格式的东西。同一个任务，拿来算分，它是评估用的任务。拿 agent 在它上面的得分去改进 agent，或者去训练模型，它就是训练数据。按得分的高低来训练模型的做法叫强化学习，第四部分会讲到。所以把任务的格式定好、把任务写对，两头都受益。

Terminal-Bench 的作者说，agent 的训练数据和测试数据很相似，就像机器学习里划分出来的训练集和测试集。上面那张对应表依据的演讲整理稿还提醒了一点：在熟悉的任务上反复改进，仍然可能过拟合，也就是表里的最后一行。

机器学习里，测试集是没有拿来训练的例子。照这个类比推下来，拿来训练模型或者反复改 agent 的那批任务，和最后用来检验成绩的那批任务也要分开。这一句是按作者的那句话和整理稿的提醒推出来的，两处都没有直接这样说。

这一讲后面三部分，讲的就是做评估这份工作的具体内容：评估用的一批任务长什么样，一个任务怎么写，写完之后怎么运行和维护。下一部分先用 Terminal-Bench 做例子，看这样一批任务实际长什么样。Terminal-Bench 这个基准测试的题目，是让 agent 在命令行环境里完成真实的技术工作。

资料说明

这一节记录核对资料时发现的出入和没有查到的地方。前面各节的结论已经按核对的结果来写。

  • 对应表里「任务」这个名字。「agent 的训练数据和测试数据是什么」一节的对应表，依据的是 Alex Shaw 的演讲的第三方文字整理稿。演讲把任务说明、沙箱（sandbox，隔离的运行环境）和验证器合在一起叫作环境（environment）。其中的沙箱就是正文说的「一个可以动手的环境」。Harbor 的文档把这三样合在一起叫任务，表里统一写成任务。整理稿里和损失函数对应的是「Environment rewards and feedback」，其中的 environment 同样指这三样合起来的整体，所以表里写成运行一个任务得到的得分和反馈。出处：Everything Is a Rollout。
  • 任务说明和验证器的分工，对照规格说明和测试的分工。「规格说明原来的位置，现在归评估」一节最后一段说两对的分工相同，这是把两处的内容放在一起读出来的。Chollet 的帖子把规格说明和测试合在一起，对应机器学习里的优化目标和搜索空间的约束，没有分开说两者各管什么。出处：Chollet 的帖子。
