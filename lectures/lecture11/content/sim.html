先看结论

  • 语言模型可以顶替用户，可以顶替环境，也可以两样都顶替，这一页的三个例子各顶替了其中一样。这样 agent 练习时不用等真人来提要求，也不用每一步都去操作真实的系统，练习的次数没有上限。agent 指能自己调用工具、分很多步去完成任务的语言模型系统。
  • 模拟用户：τ-bench 让一个语言模型扮演来找客服的顾客，agent 用工具办事，最后检查数据库的状态和回复的内容。APIGen-MT 在同样的环境里，先由几个语言模型把任务和标准答案审好，再让模拟的用户和 agent 按任务对话。结果和标准答案一致的对话留下来，成为一条多轮的运行轨迹，也就是一次解题过程的完整记录。
  • 模拟环境：DreamGym 训练一个语言模型来预测「这个动作之后，下一个状态是什么、奖励是多少」，用它代替真实环境来做强化学习。状态指 agent 做完一个动作之后环境的样子，比如操作之后的网页。强化学习是让 agent 自己去做任务，做完之后得到一个分数，这个分数叫奖励，再按奖励更新模型。
  • 真实的数据没有全部省掉：τ-bench 的任务由人工编写和核对，DreamGym 里预测状态和奖励的那个模型要先用从真实环境里收集的轨迹来训练。
  • 风险是模拟器的错误也可能被学进去，模拟器指扮演用户或环境的那个语言模型。模拟的用户会说错话，模拟的环境会预测错，agent 分不出哪些是真实世界的规律，哪些是模拟器的错误。
  • 这一讲把数据的来源分成五种：人工演示、从现成的材料里提取、合成运行轨迹、合成任务和环境、模拟的用户和环境，这一页讲最后一种。五种来源放在一起看：越便宜、越容易做大的来源，离真实的人和真实的系统越远。这说的是大致的走向：人工演示最贵、离真实最近，后四种的花费都低，这一页的汇总表没有给这四种的花费排出高低。实际的系统通常把几种组合起来用。

让语言模型顶替用户或环境

agent 是能自己调用工具、分很多步完成任务的语言模型系统。它做任务时要和两方打交道：向它提要求的用户，和它动手操作的环境。前面讲过四种数据来源：人工演示、从现成的材料里提取、合成运行轨迹、合成任务和环境。它们大多至少保留了一样真的东西：真人的操作，或者真实的网站和代码仓库。第五种来源叫模拟的用户和环境，它把用户或者环境换成语言模型来扮演。

这样得到的仍是这一讲说的两种数据。在这一页的例子里，模拟的用户和 agent 对话，产生拿来模仿的运行轨迹，模拟的环境让 agent 在里面练习。

这一页说的环境，指 agent 动手操作、并给它返回结果的那个系统。第二部分把环境定义成三样合在一起：任务，沙盒（一个隔离的运行空间，agent 在里面动手），验证器（判断任务做成没有的程序或评分办法）。这一页指的主要是其中的沙盒。DreamGym 的模型除了返回操作的结果还给出奖励，也就是把验证器的事也做了。

τ-bench：让语言模型扮演来找客服的顾客

τ-bench（Yao 等，2024，发表于 ICLR 2025）本身是一个基准测试（benchmark，一套固定的题目，用来给模型打分）。论文把它当作评估工具来做，任务数量有意做得很少，全部由人工编写和核对。它出现在这里，是因为它定下的这套做法后来被直接拿去造训练数据：用语言模型扮演用户，工具是可以真正执行的程序，读写一个专门造出来的数据库，最后检查数据库的最终状态和 agent 回复的内容。这样的数据库不连接真实的业务系统，上一部分把它叫作模拟的数据库。下面的 APIGen-MT 就是用 τ-bench 的工具和数据库来生成数据的。上一部分的 AgentScaler 成批地合成工具调用的环境，也沿用了同样的设计。

τ-bench 模拟的是客服场景，任务分零售和航空两类。agent 是客服，可以使用一组 API 工具，要遵守一份业务规定。顾客由一个语言模型扮演。背后是一个数据库，里面有用户、订单或者航班。

{{fig 54 | 左：τ-bench 的三个部分，从上到下是工具、agent 和用户。工具读写背后的数据库，由 agent 来调用。agent 的系统 prompt 里是业务规定，比如基础经济舱不能改签。用户由语言模型扮演，它的系统 prompt 里写着这个顾客是谁、想办什么、办不成的时候怎么办。右：航空任务里的一段对话。顾客要改航班，agent 查了订单，发现是基础经济舱不能改，但订票不满 24 小时可以取消，问顾客要不要取消重订，顾客同意后 agent 调用工具取消了订单，数据库被改写。图片来源：Yao 等，2024。}}

τ-bench 还提出了一个衡量稳定性的指标 pass^k：同一个任务独立跑 k 次，k 次全部成功的概率，再对所有任务取平均。它和常见的 pass@k 相反，pass@k 是 k 次里有一次成功就算。

需要这个指标，是因为用户是语言模型扮演的，每次说的话不完全一样，同一个任务跑几次的结果会不同。gpt-4o 在零售任务上单次成功率超过 60%，但 8 次全部成功的比例不到 25%。

模拟的用户会出什么错

τ-bench 的论文列了模拟的用户的几种问题：给它的指令里可能有错字或歧义，指令里不一定包含办这件事需要的全部知识，扮演用户的模型在推理、计算、记住长对话、严格照指令行事这些方面能力有限。

在作者检查过的失败例子里，原因出在模拟的用户这一边的是少数。作者人工检查了 gpt-4o 在零售任务上失败的 40 个例子，其中 4 个的原因是用户指令里的错字或歧义，其余 36 个都归为 agent 自己的问题。

i
评分办法里后来也查出了问题。拿 τ-bench 这样的环境直接做训练，「什么都不做」在相当一部分任务上也能拿到奖励。这是从 Zhu 等人 2025 年论文的发现推出来的：一个什么都不做、只返回空回答的 agent，在航空任务上的成功率是 38%。原因是航空任务里有 38% 是有意设计成办不成的，比如改签一张不能改的票，这些任务的成功标准就是数据库没有被改动。第 13 讲会讲到这件事。出处：Zhu 等，2025。

APIGen-MT：先把任务审好，再让模拟的用户和 agent 按任务对话

APIGen-MT（Prabhakar 等，NeurIPS 2025）要造的是多轮对话的训练数据。让语言模型一次生成整段对话很容易出错。中间任何一步出了差错，整段对话就不能用了。每一轮说什么，又取决于前面调用了什么工具、返回了什么。所以它分成两个阶段：先把任务和标准答案审好，再让模拟的用户和 agent 按这个任务进行一段对话。

{{fig 55 | 第一阶段：生成任务和标准答案。数据生成器根据 API、规定和业务数据提出一个任务；先过格式和执行检查，再由评审委员会的几个模型投票；不通过的，由反馈生成器汇总原因、写出改进计划，交回生成器重做。通过的任务，图上分成 Task Intent 和 Groundtruth 两块，对应下面说的给用户的指令和标准答案。图片来源：Prabhakar 等，2025。}}

第一阶段：生成并审核任务和标准答案

这一阶段的产出，论文叫任务蓝图（task blueprint）。一份蓝图包含三样：给用户的指令，一串可以验证的标准动作，以及预期的最终输出。后两样合起来是这个任务的标准答案。这一节说的「任务和标准答案」，指的就是这样一份蓝图。

  1. 先抽样，再生成。抽样的第一样是一串 API：在 API 的依赖关系图上沿着边随机走几步，把经过的 API 连成一串。这张图把每个 API 当成一个节点，一个 API 的输入要用到另一个 API 的输出时，就从后者到前者连一条边。同时抽出的还有业务规定、业务数据和用户人设（给模拟的用户设定的身份和背景）。然后一个语言模型根据抽样出来的这些材料提出一个任务，写出蓝图的三样，其中的标准动作围绕那一串里会改写数据库的 API 来构造。
  2. 规则检查：动作的格式要对，要能在环境里真的执行。业务规定被写成了 Python 的单元测试，标准动作不能违反。
  3. 评审委员会：几个语言模型从正确、完整、合理等方面给任务打分，按多数票决定通过与否。
  4. 不通过的任务，由一个反馈生成器汇总失败的原因和评审意见，写成一份改进计划，交回第 1 步重做。

论文给出了这一阶段的成功率：有这个反馈循环时是 70%，没有时是 28%。重做的轮数有上限，零售任务最多 3 轮，航空任务最多 5 轮。这个成功率是按什么算出来的，论文没有写明。

第二阶段：模拟的用户和 agent 按蓝图对话

蓝图审好之后，模拟的用户和 agent 按它进行一段对话，过程见下图。

{{fig 56 | 第二阶段：模拟的用户拿着给用户的指令（图上叫 Task Intent），一点一点地向 agent 提要求。agent 在环境里调用工具，这些工具是可以真的执行的 API。最后把这次交互的结果和标准动作、预期的最终输出比较，一致的才算成功的轨迹。图上把模拟的用户叫 Simulated Human，把 agent 叫 Test Agent，把这个环境叫 Simulation Environments，它指 τ-bench 那种工具真的执行、数据库专门造出来的环境。图片来源：Prabhakar 等，2025。}}

一个语言模型扮演用户，把指令里的要求一点一点说出来。agent 这一边是 gpt-4o，它理解用户的意图，调用工具把事情办完。只有环境的最终状态和标准动作的结果一致、agent 最后的回复和预期的最终输出一致的轨迹才留下。每个任务最多试三次。论文给出这一阶段的成功率是 67%，没有写明是按任务算还是按每次尝试算。

为了让模拟的用户更稳定，每一轮让它生成 4 个候选的回复，再让模型自己找出这些候选的问题，选出一个。

DreamGym：让语言模型来预测下一个状态和奖励

强化学习是让 agent 反复做任务：每做一步看到环境的新状态，任务做成了得到奖励，再按奖励更新模型。在真实环境里做强化学习很贵：每一步都要真的打开网页、真的执行动作，环境不容易重置。

真实环境里的奖励还常常稀少而且不稳定。稀少是说一个任务要做很多步，只有做成了才在最后得到奖励，中间的步骤没有分数。不稳定是说网页这类环境经常变动，给出的奖励有时是错的。

DreamGym（Chen 等，2025，发表于 ICLR 2026）的做法是训练一个语言模型来充当环境。agent 发出一个动作，这个「经验模型」用文字写出下一个状态和奖励，agent 再根据它继续。被它代替的那个环境里，动作会真的执行，这一节把它叫真实环境。

{{fig 57 | 左上：传统的做法，agent 在真实环境里行动，任务稀少而且昂贵，真实环境难以扩大规模，奖励稀少而且不稳定。左下：用经验模型代替真实环境。右：系统的结构。agent 的动作交给经验模型，经验模型先推理，再给出下一个状态和奖励；它可以从经验回放缓冲区（一个存放过往交互记录的库）里检索相似的经验；任务生成器挑出 agent 有时成功、有时失败的任务，生成更难的变体。图片来源：Chen 等，2025。}}

这个设计背后的判断是：训练 agent 要的是足够多样、信息量足够、因果关系说得通的交互数据，环境不必完全逼真。

经验模型给的奖励同样稀少，只在任务做成的最后一步给 1。agent 和经验模型交互得到的记录，这一节叫合成的经验。

论文说合成的经验给出的反馈比真实环境里更密、更稳定。按上面的规则，一条轨迹最多只在最后一步得到奖励，「更密」量的是什么，论文没有写明。论文把更密这一点归因于任务生成器按难度安排任务：它挑的是 agent 有时成功、有时失败的任务，理由是同一个任务做几次，成功和失败各占一半时，给训练提供的信息最多。

它并没有完全离开真实数据

经验模型本身要用真实的轨迹来训练。WebArena 是一个网页任务的基准测试，agent 要在几个专门部署的网站上把整个任务做完。以它为例，论文用了 4,800 条从真实环境里收集的轨迹，由一个强的语言模型给每一步补上「为什么这个动作会导致这个结果」的推理，再拿来微调经验模型。

训练 agent 时也可以再接上一段真实的交互。论文用了三个基准测试：WebArena、WebShop 和 ALFWorld。WebShop 是一个仿照购物网站搭建的环境，agent 要搜索并找到符合要求的商品。ALFWorld 是一个用文字操作的家居任务环境。对下表里的这个 agent（Llama-3.1-8B）来说，在 WebShop 和 ALFWorld 上成绩最好的版本，是先在合成的经验上训练，再用 5 千步真实的交互接着训练。WebArena 没有列在这句话里，是因为论文的整张表里，同一个 agent 换用另一种强化学习算法训练的各组中，有两组在 WebArena 上的成功率是 10.9%，比这个版本的 9.7% 高。下面的表里有 WebArena 和 WebShop 两列，没有 ALFWorld，也没有换用另一种算法的各组。

经验模型预测错了怎么办

对这个问题，论文给出的是一个理论上的保证和两样间接的证据。

理论上的保证在论文附录里，是一个下界，也就是「至少有这么多」的保证。它保证的是 agent 的进步，进步指模型更新一次之后，agent 预期拿到的累计奖励比更新之前多出的部分。保证成立的条件是训练算法限制了每次更新的幅度，这个限制在下面讲第一项时说明。在这个条件下，agent 在真实环境里的进步，至少是它在经验模型充当的环境里的进步减去两项。

第一项和每次更新的幅度有关。训练算法规定了模型的行为每次更新最多能改变多少，这是一个上限。按论文的公式，这一项和这个上限成正比：上限放得越宽，要减掉的就越多。

第二项和经验模型的误差有关，这个误差由两部分组成：奖励预测的误差，和状态转移的误差。状态转移的误差指经验模型预测的下一个状态和真实环境会给出的下一个状态之间的差别。

在经验模型充当的环境里的进步超过这两项之和，真实环境里的表现才有保证不变差。

作者认为第二项里奖励和状态转移这两部分误差可以做得很小。论文里和它有关的证据有两样：GPT-4o 给生成的轨迹打的分，以及最后的任务成功率。

GPT-4o 的打分是这样做的。随机抽 100 条轨迹，让 GPT-4o 看操作前的状态、agent 的动作和经验模型预测的下一个状态，从四个方面各打 0、1 或 2 分。四个方面是：下一个状态和上一个状态、和动作是否对得上，状态有没有实质的变化，内容是否充实，以及有没有凭空编造。论文说，和拿来对照的另外三个版本相比，完整的 DreamGym 在四个方面都是最好或接近最好。分数画在一张图里，正文没有列出数值。

这两样都是间接的证据。GPT-4o 打分时看到的只有经验模型自己的预测，没有真实环境给出的下一个状态可以对照。经验模型预测的状态和奖励同真实环境不一致的比例有多高，论文没有直接的数。

论文也写了适用范围的限制，说的是把在一个环境的合成经验上训练出的 agent 拿到另一个环境里去用。在 WebShop 和 WebArena 这两个网页环境之间这样换，论文说成绩比直接在目标环境上做监督微调（让模型模仿现成的示范）的模型还高。从这两个网页环境换到差别很大的家居任务环境 ALFWorld，论文说成绩明显下降。这两组结果画在一张图里，正文没有给出数值。

这和前面说的 ALFWorld 上成绩最好的版本是两件事。那个版本是在 ALFWorld 自己的任务上训练的，这里说的是在网页环境上训练、拿到 ALFWorld 上去用。

五种来源放在一起

对每种来源，都可以问三个问题：花多少钱，离真实多近，能做到多大。能做到多大，问的是数据的规模，也就是能得到多少任务、运行轨迹或单步样本。单步样本是只教下一步该做什么的一个例子，一条运行轨迹有很多步，可以拆成很多个这样的例子。

下面把第三到第五部分的内容汇总成一张表。表里的验证器，指判断任务做成没有的程序或评分办法。每种来源的名字下面列了例子。第五种的三个例子就是这一页讲的，前四种的例子出自第三部分和第四部分，各是什么如下。

  • 人工演示：Mind2Web 是网页任务的人工演示数据集，OpenCUA 是一项收集桌面操作人工演示的工作。
  • 从现成的材料里提取：SWE-rebench 从 GitHub 自动提取编程任务，AgentTrek 照着网上的教程把操作重放一遍，VideoAgentTrek 从录屏视频里还原出动作。
  • 合成运行轨迹：Synatra 让语言模型把教程和网页改写成单步样本，只写步骤，不真正执行。OS-Genesis 和 NNetNav 先在环境里探索，再根据探索写出指令。
  • 合成任务和环境：SWE-smith 和 R2E-Gym 成批地造编程任务，AgentScaler 成批地合成工具调用的环境。

不同领域的任务适合不同的来源，这里的领域指代码、网页、操作电脑、工具调用这四类 agent 任务。代码有测试和版本历史，天然适合从 GitHub 提取和注入 bug。网页和操作电脑的任务没有现成的验证器，所以大量依赖语言模型来判断轨迹的好坏。客服这类工具调用的任务离不开用户，所以要模拟用户。

实际的系统往往把几种来源接在一起，下面是三个例子。VideoAgentTrek 用逆动力学模型（inverse dynamics model，看着前后画面的变化反推出鼠标和键盘动作的模型）从视频里标出动作，而训练这个模型要用人工录制的数据：用 OpenCUA 的录制工具录下的、同时带有真实鼠标和键盘记录的视频。AgentScaler 合成了环境，又用模拟的用户来产生对话。SWE-smith 造出环境之后，要让一个强的模型在里面跑，才得到训练用的运行轨迹。

+
五种来源之外：产品上线之后的使用记录。这一讲讲的是训练模型用的数据，五种来源都是为训练模型准备的。对用现成模型搭应用的人来说，最容易拿到的数据是自己产品的运行记录，它主要用来改进应用本身，所以没有算在五种里。Shreya Shankar 2024 年的文章《Data Flywheels for LLM Applications》讲的就是怎样用这些记录。她的出发点是很多团队用的是模型的 API，不去微调，所以改进主要靠把修正过的记录当作示例放进 prompt。文章里的 data flywheel 指这样一个循环：应用在真实使用中产生记录，人和程序给这些记录打分，分数低的被修正，修正过的例子再放回 prompt 或用来改进系统，这样每一条使用记录都可以用来改进应用。她把这个循环分成三部分：定义评估指标，持续监控这些指标是否还和人的判断一致，以及用评估的结果不断改进。出处：Shankar，2024。
+
延伸阅读：用语言模型标注和合成数据的综述。Tan 等人 2024 年的综述《Large Language Models for Data Annotation and Synthesis: A Survey》梳理了怎样用语言模型来标注和合成数据、怎样评估这些标注的质量、怎样使用它们。它和这一讲的关系可以这样看。上面的表里，第二到第五种来源都让语言模型来做事，包括改写材料、写指令、给轨迹打分、扮演用户、预测状态和奖励，做的也是用语言模型标注和合成数据。出处：Tan 等，EMNLP 2024。

这一部分的小结

  • 模拟的用户让多轮对话的任务可以大规模地生成和验证。它的前提是工具是会真的执行的程序，每次调用都真的读写数据库，所以最后的状态可以检查。
  • 模拟的环境可以把强化学习阶段的真实交互省掉，经验模型本身仍要用真实的轨迹来训练。在 WebShop 和 ALFWorld 上成绩最好的版本，强化学习阶段还接了 5 千步真实交互。换来的是无限的练习，付出的是预测可能不准。
  • 五种来源各有适合的领域，实际中常常组合使用。
