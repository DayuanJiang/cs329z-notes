先看结论

  • agent 数据有两种。运行轨迹（trajectory，也叫 trace）是一次解题过程的完整记录，模型照着它模仿，这种训练叫监督微调。环境（environment）是一个任务加一个可以动手的沙盒，再加一个判断做成没有的验证器。模型在里面反复练习，每次按验证器给的分数（奖励）来更新，这种训练叫强化学习。
  • 拿运行轨迹训练时，只有 agent 自己写的那几段（想法和动作）计入训练目标。系统 prompt、任务和工具返回的结果只作为上下文。轨迹的格式由包在模型外面的程序决定。
  • 环境的奖励有四种来源：代码测试、评分细则、用语言模型当评审、真人的偏好。排在前面的可靠但适用面窄，排在后面的适用面广但不精确。
  • 环境可以产出运行轨迹：让模型在环境里跑很多次，挑出好的拿去模仿，或者给每一次打分再按分数更新模型。反过来，只有轨迹是造不出环境的：轨迹只是一次过程的记录，里面没有可以重新动手的沙盒，也没有判断做成没有的验证器。
  • 各阶段的数据量很少有公司公开。DeepSeek 公开过的数字是：V3 预训练用 14.8 万亿个 token，监督微调用 150 万条样本；一年后的 V3.2 在强化学习里用了大约 8.5 万个 agent 任务，后训练的算力超过了预训练的 10%。后训练（post-training）指预训练之后再用少量专门的数据继续训练的阶段，监督微调和强化学习都属于它。

两种数据各是什么

上一部分说，agent 数据通常指对话和环境。放到 agent 任务上，对话就是运行轨迹：它在格式上仍是一段对话，轮流出现的是任务、agent 的想法和动作、工具返回的结果。运行轨迹和环境的样子、用法和教给模型的东西都不一样。

i
trajectory 和 trace 是一回事。这一讲里这两个词可以互换，都指一次运行的完整记录，下面统一叫运行轨迹。一次运行本身叫 rollout：把模型放进环境，让它从头做到提交或者用完步数。每一次 rollout 留下一条运行轨迹。

一条运行轨迹里，哪些部分算进训练

一条运行轨迹是几种角色轮流出现的一长串文字。训练时，模型要学着预测的只有 agent 自己写的那几段。

这样做的理由很直接。系统 prompt 和任务是别人给的，工具的输出是环境产生的，模型将来用不着自己去生成它们。模型要学会的是：看到前面这些内容之后，下一步该想什么、做什么。

{{fig 14 | 一条修 bug 的运行轨迹。左边一列是角色，中间是内容，右边一列方块标出这一段是否计入训练的损失：深红色的计入，白色的不计入。}}

下表按角色写出图里这条轨迹的内容，以及每种角色的文字是否计入训练目标。

具体的做法是这样的。语言模型的训练目标是预测下一个 token（模型处理文字的最小单位，大致是一个词或半个词）。把整条轨迹交给模型，让它在每个位置预测下一个 token，但只在 agent 的那几段上计算损失（预测和实际内容的差距），其余位置的损失被屏蔽掉。图右边那一列方块就是这张屏蔽表，英文叫 loss mask。

轨迹的格式由运行框架决定

同一个动作可以写成几种样子：一次工具调用（tool call，模型按固定的结构写出要调用的工具名和参数），一段 ReAct 式的文字，或者一段可以直接执行的代码。用哪一种，由运行框架（harness，也叫 scaffold，指包在模型外面、给它工具并管理多轮对话的程序）决定，模型本身不决定。

三种写法的实例和这件事的后果都在第七部分讲：一批轨迹如果都来自同一个运行框架，模型会把这个框架的格式和解题的能力一起学进去。

一个环境里有什么

用于后训练的一个环境由三样东西组成：任务、沙盒、验证器。

这和基准测试里一道题的结构完全一样。基准测试（benchmark）是一套固定的题目，用来给模型打分，第 13 讲会再讲到这三样。区别只在用途：拿来打分的时候它是基准测试的一道题，拿来训练的时候它是一个训练环境。Andrej Karpathy 2025 年 8 月 27 日发在 X 上的一篇帖子里也说，环境既可以用来训练模型，也可以用来评估模型。

环境还能产出运行轨迹。让一个语言模型在环境里解题，把它解题的过程录下来，就是一条轨迹。所以后面几部分讲数据来源时，有的办法直接造轨迹，有的办法先造环境，再从环境里得到轨迹。

反过来不行，只有轨迹是造不出环境的。轨迹只是一次过程的记录，里面没有可以重新动手的沙盒，也没有判断做成没有的验证器。

环境的奖励从哪里来

拿运行轨迹做监督微调时，学习的信号来自「下一步动作预测得对不对」。在环境里做强化学习时，信号来自验证器给的奖励。奖励有四种常见的来源，可以排在一条轴上：一头可靠但适用面窄，另一头适用面广但不精确。

后面几部分里的环境，大多数选的是轴左端的办法，也就是测试或者检查数据库的最终状态，因为大规模训练需要便宜、自动、每次结果一致的奖励。检查数据库的最终状态用在工具调用类的任务上：agent 调用工具会改动一个数据库，做完之后由程序比较数据库里的内容和预期是否一致。它和代码测试一样由程序判定，所以也在轴的左端，例子见第五部分的 τ-bench。

每个阶段用多少数据

这一节看各个训练阶段用多少数据和算力。能看到的趋势有两个：越靠后的阶段，数据的条数越少；后训练占的算力在一年里涨了很多。

各家公司通常不公开每个训练阶段的数据量。DeepSeek 是少数写出过具体数字的：2024 年 12 月的 DeepSeek-V3 技术报告和 2025 年 12 月的 DeepSeek-V3.2 论文各给了一部分。

这一节的阶段按训练的先后来分。语言模型的训练常被分成预训练（pre-training）、中期训练（mid-training）和后训练（post-training）三段，Stanford CS336 的数据一讲用的就是这个分法。按它的说法，中期训练是预训练之后，再拿质量更高的数据接着训练一段，用来加强模型的能力。监督微调和强化学习都属于后训练。第一部分的三个阶段是照 Karpathy 的说法、按每个时期最看重的数据来分的，那里的后两个阶段在这里都算后训练。

V3.2 的 8.5 万个任务是怎么来的

V3.2 论文里的表把强化学习用的 agent 任务分成四类，每一类的来源都能在后面几部分要讲的数据来源里找到。这一讲把 agent 数据的来源分成五种：请人演示，从现成的材料里提取，让模型合成运行轨迹，让模型合成任务和环境，用模拟的用户和环境。下表最后一列写的是每一类任务对应其中哪一种。四类任务只用到了五种里的两种：从现成的材料里提取，合成任务和环境。

表里的「代码 agent」和「代码解释器」是两类不同的任务。代码 agent 要修改一个代码仓库，把 issue 里的问题解决掉。代码解释器这一类是解一道数学、逻辑或数据科学的题：模型可以在 Jupyter Notebook 里写代码并运行，用运行的结果来得出答案。Jupyter Notebook 是一种可以一段一段写代码、马上看到运行结果的工具。

论文对通用 agent 那一类有一句概括：这些任务很难解，但很容易验证。例子是按一组约束条件规划三天的行程。城市、酒店、景点和餐馆可以组合出的方案数量极多，论文把它叫作很大的组合空间，要从里面找到一个满足全部约束的方案很难。检查一个给定的方案是否满足约束却很简单。

容易验证这一半，和前面讲奖励时的要求是一回事：奖励要能便宜、自动、每次结果一致地给出。很难解这一半，论文没有说明理由，只写了造任务时会一轮一轮地加大任务的难度。

这一部分的小结

  • 运行轨迹是示范，用监督微调来学，只在 agent 的想法和动作上计算损失。
  • 环境是练习的地方，由任务、沙盒和验证器三样组成，用强化学习来学，信号来自验证器给的奖励。
  • 环境可以产出轨迹，所以造环境的办法也是造轨迹的办法。
  • 越靠后的训练阶段，数据的条数越少，质量要求越高。DeepSeek 公开的数字显示，后训练的算力相对预训练的比例在一年里升了很多。
