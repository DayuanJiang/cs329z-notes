先看结论

语言模型有三类事做不好：算不准的，训练时没见过的，自己接触不到的（比如数据库这类接口、物理世界、随时在变的状态）。这些事交给模型外面的程序去做，模型只负责写出「调用哪个工具、传什么参数」。

这里的工具，指在模型外部运行的程序的函数接口，比如计算器、搜索、数据库查询。agent 指能自己调用工具、分很多步去完成任务的语言模型系统。

让模型会用工具有两个方向：训练模型去认识一批具体的工具，或者给工具定一个任何模型都能读的标准接口。现在通行的是后一个。

后一个方向有一个前提：模型要有「读描述、写调用」的通用能力。这种能力也是训练出来的，模型厂商一般专门为这件事训练过自己的模型。这种训练不针对哪一批工具，所以新增工具时不用再训练，具体的工具放到运行时再给。

下表对照这两个方向。表头用的是这两个方向的另一种说法：前一个方向是改模型去适应工具，后一个方向是改工具的描述方式。「代表」一行里，左栏是四篇论文提出的方法，右栏是三种接口。

左栏的四种方法都靠训练让模型学会用工具。Toolformer 让模型自己给文本加上工具调用，筛选之后用来微调，微调是在已经训练好的模型上用新数据继续训练。ToolkenGPT 把每个工具做成一个新的 token（模型处理文字的最小单位），原模型不动，只训练模型给这个 token 准备的一串数字。ToolLLM 是 Qin 等人 2023 年提出的方法：用 ChatGPT 生成的数据微调一个开源模型，让它会调用 RapidAPI 这个平台上的真实 API。API（应用程序接口）是一个程序提供给别的程序调用的入口。Gorilla 是 Patil 等人 2023 年提出的模型，在 1,645 个机器学习 API 上微调出来。这一讲把训练出它的做法也叫 Gorilla，和前三种方法并列。

这一讲的顺序是：先把上一讲留下的 RAG 的问题讲完，然后依次讲为什么需要工具、模型怎样学会调用工具、工具多到上千个怎么办、工具怎样接到任何模型上、怎样评估。

资料说明

这一节记录核对资料时发现的出入和没有查到的地方。前面各节的结论已经按核对的结果来写。

  • GPT-3 的参数量约为 Toolformer 的 25 倍。这个倍数是 Toolformer 的论文自己的说法。论文介绍用来对比的模型时写道，1,750 亿参数的 GPT-3 的大小约是论文里其他对比模型的 25 倍（原文是 about 25 times larger）。其他对比模型都是 67 亿参数的 GPT-J，或者由它微调得到的模型，Toolformer 也在其中。按两个参数量直接相除，1,750 亿约是 67 亿的 26 倍。出处：Schick 等，2023 的 4.1 节。
  • 第一张表里，新增一个工具时 ToolLLM 为什么单独写。第五部分对照两个方向的配图上，「改模型去适应工具」一栏只写了 Toolformer、ToolkenGPT、Gorilla 三个名字，后面跟着「每个新 API 都要再训练一次」，没有列 ToolLLM。ToolLLM 的论文报告，它微调出的模型只靠 API 文档就能用上训练时没见过的 API。所以第一张表把「重新造数据、重新训练」只写在 Toolformer、ToolkenGPT 和 Gorilla 这三种方法上，ToolLLM 单独写。依据和核对的经过见第四部分的资料说明。
