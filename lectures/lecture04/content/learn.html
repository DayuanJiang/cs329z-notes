先看结论

  • 用工具要做四个决定：什么时候调用，调用哪个工具，传什么参数，怎么把结果用进后面的文字。这四个决定都可以通过训练让模型学会。
  • Toolformer（2023 年 2 月）不需要人工标注。它让模型自己在普通文本里试着插入工具调用，真的去执行，只留下「看了结果之后，后面的文字更好预测」的那些调用，再用这些文本微调模型（微调是在已经训练好的模型上用新数据继续训练）。
  • 学会 5 个工具之后，67 亿参数的 Toolformer 在填事实、算术和日期推算上超过了 1,750 亿参数的 GPT-3，在开放问答上仍然不如 GPT-3。
  • ToolkenGPT 把每个工具当成词表里的一个新 token（token 是模型处理文字的最小单位，大致是一个词或半个词），原模型的参数完全不动，只训练新 token 的向量，所以能接入两百多个工具。
  • 两种做法都是在生成文字的中途触发一次调用，连续调用几个工具都做不好。Toolformer 不能把一个工具的输出交给另一个工具，论文自己把这一点列为局限。ToolkenGPT 能做需要连续调用的题，但只做对 15%。

把「会用工具」当成一个学习问题

站在模型的角度，用工具要做一连串决定。写到一句话的哪个位置时该停下来调用工具？该用问答系统还是翻译系统？参数怎么写？结果回来之后怎么接着往下写？

遇到「要不要做、选哪一个」这类决定，机器学习的常规做法是准备带答案的数据，让模型从数据里学。难处在于数据从哪里来：没有人会在写文章的时候，顺手标出「这里应该调用一次计算器」。下面两种方法各自给出了一个答案。

Toolformer：模型自己教自己用工具

Toolformer 出自 Meta AI 的 Schick 等人 2023 年 2 月的论文。它训练语言模型来决定四件事：调用哪些 API（应用程序接口，一个程序提供给别的程序调用的入口），什么时候调用，传什么参数，以及怎样把结果用到后面的生成里。训练是自监督的（训练用的答案由数据和模型自己产生，不需要人工标注），每个 API 只需要人写几个示范。

{{fig 22 | 右边是 Toolformer 生成的四段文字，彩色部分是它自己插入的工具调用。从上到下用的是问答系统、计算器、翻译系统和维基百科搜索。图片来源：Schick 等，2023。}}

一次调用写在方括号里，依次是工具名、括号里的输入、一个表示「后面是结果」的特殊记号，最后是结果。以图里第二段为例：

  • 原文是「1,400 名参加者里有 400 人（即 29%）通过了测试」。
  • 要写出 29% 这个数，得先算 400 除以 1,400。Toolformer 在 29% 的前面插入一次调用：工具是 Calculator，输入是 400 / 1400。
  • 计算器返回 0.29，这个结果也写进方括号里。模型接着往下写时已经看到了 0.29，于是写出 29%。

图里第一段同理：写到「《新英格兰医学杂志》是谁的注册商标」时，模型先问问答系统「这本杂志的出版方是谁」，得到 Massachusetts Medical Society，再接着写出它的缩写 MMS。要学的就是：为什么在这个位置调用，为什么用问答系统、不用翻译系统。

它用的五个工具

Toolformer 只用了五个工具。现在的 agent（能自己调用工具、分很多步去完成任务的语言模型系统）能用上千个工具，这在当时是一个很早的尝试。对工具只有两条要求：输入和输出都能写成文字，并且能找到几个示范。

{{fig 23 | 五个工具各一个例子，上面是输入，下面是返回的结果。日历不需要输入，所以输入是空的。}}

方法：三步造出带工具调用的训练数据

思路是把问题转成造数据。拿一个普通的文本数据集，给其中合适的句子在合适的位置插入工具调用，得到一个新的数据集。再用新数据集微调（fine-tuning，在已经训练好的模型上用新数据继续训练）模型。模型见多了「这种上下文后面跟着一次调用」的例子，推理时就会在类似的位置自己写出调用。

{{fig 24 | 从左到右：普通的文本数据集，经过采样、执行、筛选三步，变成带 API 调用的数据集。下面一行用「Pittsburgh is also known as the Steel City」这句话演示每一步。}}

被微调的模型是 GPT-J，有 67 亿参数。文本数据集是网页语料 CCNet 的一个子集。下面三步里，采样和筛选由 GPT-J 自己来做，执行交给工具，全程不需要人工标注。

第一步：采样，找出可能需要调用的位置和内容

给模型一段 prompt（交给模型的输入文字），里面说明任务，并给出几个人写的示范，例如「你的任务是给一段文字加上对问答 API 的调用」。然后把要处理的句子交给它。

{{fig 25 | 右上的方框是 prompt 的样子。下面是模型的输出：在「Pittsburgh is known as」后面插入了一次对问答系统的调用。最下面是用来挑位置的公式。}}
  • 挑位置。对句子里的每个位置，算出模型在这里开始一次调用的概率。默认的设置是：概率超过阈值 0.05 的位置留下，最多留 5 个。
  • 生成候选调用。在每个留下的位置上，让模型续写出调用的内容，默认最多采样 5 个候选。同一个位置可能得到「匹兹堡还有什么别称」和「匹兹堡在哪个国家」两个不同的问题。
  • 两个工具的设置不同。计算器和翻译只在语料的一小部分文本上生成调用，候选少。论文给这两个工具放宽了设置：阈值是 0，最多留 20 个位置，每个位置最多采样 10 个候选。

第二步：执行

把所有候选调用真的执行一遍，拿到结果。执行发生在模型外面：可能是调用另一个神经网络，可能是跑一段 Python 脚本，也可能是在语料里检索。

{{fig 26 | 两个候选问题各得到一个答案：「钢铁之城」和「美国」。}}

执行有可能失败。工具可能没有返回，调用的格式可能写错，返回的内容也可能是错的。这些情况下拿到什么就用什么，由下一步来决定留不留。

第三步：筛选，只留下真的有帮助的调用

判断一次调用有没有帮助，标准是：模型看到这次调用和它的结果之后，预测原文后面的 token（模型处理文字的最小单位，大致是一个词或半个词）是不是更容易了。「容易」用损失来量，损失越低表示预测得越准。

{{figs 27 28 | 左：筛选用的损失和两个要比较的量。右：一个算例，三种情况下预测「the Steel City」的损失。右图里的 2.5、2.1、0.8 是示意用的数，论文里没有。}}

有三个细节。

  • 为什么要和「加调用但不给结果」比。光是那个问题的文字，就可能给后文提供线索。把它也作为对照，才能确认帮助来自工具返回的结果。
  • 损失只看调用位置后面的几个 token。损失是加权的交叉熵（交叉熵按模型给正确 token 的概率来算，概率越低损失越大），权重随距离递减：紧跟在调用后面的 token 权重最大，每远一个减少 0.2，从第 6 个开始权重是 0。这样可以保证调用被插在真正用得上它的地方。
  • 阈值按工具调整。默认要求损失至少降低 1.0。计算器和翻译的候选太少，阈值放宽到 0.5。

下面是论文里的真实例子和它们的有用程度。

{{fig 29 | 三段文本和各自的分数。分数越高，说明工具的结果对预测后文的帮助越大。}}

筛选之后，把留下的调用连同结果插回原文，就得到了新的数据集。阈值取 1.0 时，留下约 6.1 万条带维基百科搜索的例子、约 2.1 万条带日历的、约 1.9 万条带问答的。计算器和翻译按放宽后的阈值 0.5，分别留下 3,680 条和 3,156 条。训练时每个工具最多用 2.5 万条。除了多出来的调用，新数据集的文字和原来完全相同。论文检查了加入调用会不会损害模型预测普通文本的能力：在 WikiText 和 CCNet 两个文本数据集上，关掉工具调用时，用新数据集微调的模型和用原数据集微调的模型，预测普通文本的准确程度相同。在 CCNet 上微调这件事本身会带来变化：两个微调过的模型在 WikiText 上都比原来的 GPT-J 略差，下面的多语言问答里也有几种语言的成绩下降。

用的时候怎么运行

微调之后，模型照常一个 token 一个 token 地往下写。当它写出那个表示「后面是结果」的特殊记号时，外面的程序暂停生成，取出方括号里的工具名和输入，调用对应的工具，把结果和方括号的结束标记接在后面，再让模型继续写。

论文在这里加了两条规则。第一，只要「开始调用」这个 token 排在最可能的前 10 个 token 里，就让模型开始调用，目的是让它更愿意用工具。第二，每个输入最多调用一次，免得模型陷入不停调用工具、一直不给出回答的循环。

i
这和现在的 agent 不一样。Toolformer 是在一段文字生成到一半时触发调用，结果直接嵌进这段文字。现在的 agent 是以一轮为单位：模型在一轮里决定要调用工具，外面的程序执行，结果作为下一轮的输入交回来；一个工具不行就换另一个，一条任务可以调用很多次。这种做法靠的是第五部分的标准接口。

结果：小模型加工具，和大 25 倍的模型比

评测用了五类任务，全部不给例子（zero-shot），也不告诉模型该用哪个工具。对比的是没有微调的 GPT-J，以及 1,750 亿参数的 GPT-3。

「小模型加工具，全面超过了 GPT-3」这个说法要加条件。常见的说法是 Toolformer 在各类任务上都比大得多的 GPT-3 好。实际上要分开看。补全事实、算术、日期推算这三类，它确实超过了 GPT-3，算术上差距最大。开放问答的三个数据集上它都不如 GPT-3，论文认为原因是搜索工具太简单，而且模型不能在结果不好时换一个查询重搜。多语言问答上它没有稳定地超过原来的 GPT-J，论文的解释是在 CCNet 上微调让模型在某些语言上变差了。TEMPLAMA 上的提高也不来自日历工具。

模型要多大才学得会用工具

论文把同样的方法用在四个更小的 GPT-2 模型上，参数量分别是 1.24 亿、3.55 亿、7.75 亿和 16 亿。

{{fig 31 | 三类任务上成绩随模型大小的变化。蓝线是允许调用工具，红线是同一个模型但禁用工具，虚线是 GPT-3。横轴的单位是百万参数，最右边的点是 GPT-J。图片来源：Schick 等，2023。}}

最小的两个模型，蓝线和红线几乎重合：给了工具也用不好。用好工具的能力大约在 7.75 亿参数时才出现。之后模型越大，不用工具的成绩在涨，用工具的成绩涨得更多，两条线之间的差距一直很大。

Toolformer 的局限

论文自己列出了五条。

还有一条更根本的局限，第五部分会展开：工具是训练进模型里的。想加第六个工具，就要重新造数据、重新微调。

ToolkenGPT：把工具当成一个词

Toolformer 的调用是在生成 token 的过程中触发的。顺着这个思路再走一步：既然调用是由某个 token 触发的，能不能干脆把每个工具做成词表里的一个 token？Hao 等人的 ToolkenGPT（发表在 NeurIPS 2023）就是这样做的。这种代表工具的 token 叫 toolken。

{{fig 32 | 左边是词表：上面是普通的词，下面是三组 toolken，分别代表知识库查询、数学运算和机器人动作。右边是一道几何题的求解过程，模型在三种状态之间切换。图片来源：Hao 等，2023。}}

语言模型每一步都要从词表里选下一个 token。它给每个 token 准备了一个向量（embedding，一串数字），拿当前的内部状态和所有向量比较，得出每个 token 的概率。ToolkenGPT 在这张向量表后面给每个工具加一行。于是模型每一步既可能选出一个普通的词，也可能选出一个工具。

{{figs 33 34 | 左：一次调用的五个步骤。右：训练数据的样子和损失函数。右图的红字写着损失只在 toolken 的位置上算，这和图上的公式、论文的原文对不上：公式只排除了标成 N/A 的位置。}}

运行时的五步

  1. 选出了一个 toolken。模型平时处在推理状态，照常生成文字。某一步选出的是一个 toolken，比如 square（求平方）。
  2. 暂停生成。把已经生成的内容搬到另一段 prompt 里。
  3. 进入工具状态。这段 prompt 里放的是这一个工具的若干使用示范。
  4. 填参数。模型照着示范，把这次调用的参数补全，例如 16。填参数是比较容易的事，靠看示范就能做。
  5. 执行并回到推理状态。外面的程序执行工具，把返回值 256 填回原来的文字，模型继续往下写。

只训练新加的向量

原来的语言模型完全不动，要训练的只有新加的那几行向量。训练数据是成对的两个序列。以「the area is 256 square feet」为例：

  • 原序列是 the、area、is、2、5、6、square、feet。
  • 配对的序列把 2 换成 toolken square，把 5 和 6 标成「跳过」。意思是：在该出现结果的第一个位置，应该选出求平方这个工具；结果的其余部分由工具填，不用模型预测。
  • 损失在所有没有标成跳过的位置上算，普通词的位置和 toolken 的位置都包括在内。可以这样理解：普通词位置上的损失让新加的向量学到，在该接着写文字的位置上不要选出工具。能被更新的参数只有新加的那几行向量。

训练数据有两个来源：本来就标了工具调用的数据集，或者让语言模型合成的数据。因为原模型不动，接入一个新工具只要在向量表后面再加一行，用这个工具的示范数据训练这一行。

ToolkenGPT 的结果，和多步调用的难处

{{fig 35 | 左：两个数学数据集上的准确率，括号里是可用工具的个数，红框标出的是需要多步调用的那一列。右：知识库问答，横轴是可用工具的个数，从 30 个到 234 个。图片来源：Hao 等，2023。}}

这张表和右边的图有两点值得注意。

  • 多步题的成绩都很低。只需要调用一次工具的题，ToolkenGPT 做对 73%。需要连续调用几个工具的题，它只做对 15%，其他方法在 3% 到 9% 之间。很可能的原因有两个：每一步都有很多种选择，几步连起来，可能的调用序列数量很大；现成的训练数据里大多是单次调用，连续调用的例子很少。ToolkenGPT 的向量就是只用一步题的合成数据训练的。
  • 工具一多，靠 prompt 就不行了。右图里，把所有工具的说明和示范都写进 prompt 的做法（绿线和红线），工具数超过 30 个之后准确率明显下降，因为 prompt 的长度有限，放不下。从图上读，用标注数据训练的 ToolkenGPT（蓝线）到 234 个工具时仍然在 0.9 以上。只用合成数据训练的版本（橙线）也高于其他基线，但随着工具增多而下降。

这一部分的小结

  • Toolformer 用模型自己的损失来筛选工具调用，不需要人工标注，学会了 5 个工具。
  • ToolkenGPT 把工具做成 token，只训练向量，学会了两百多个工具。
  • 两者留下了两个问题。一是规模：真实世界里的工具成千上万。二是连续调用：一条任务常常要用好几个工具。
