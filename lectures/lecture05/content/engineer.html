先看结论

  • 一个 AI 系统有三根支柱：数据、系统（或模型）、评估和度量。其中的「系统」指要由你来搭的那个程序本身。度量（metric）是给系统的输出打分的函数，评估是用度量在一批数据上给系统打分。只有系统这一样，也能搭出一个能跑的 agent（能自己调用工具、分很多步完成任务的语言模型系统）。把它当工程来做，三样都要有。
  • 按「下一步做什么由谁决定」，可以把系统排成一条线：单个模型，workflow（步骤由程序写定的多次模型调用），agent。越往右，交给模型决定的事越多。
  • 这条线的每一段都有现成的框架或工具。调用模型有厂商的接口，写 workflow 有 DSPy、LangGraph 这类框架（framework，写程序时调用的库），agent 有已经搭好的运行框架（harness，包在模型外面、给它工具并管理多轮对话的程序）。
  • 另外还有两类工具跨在整条线上：一类管可靠性，一类管可观测性（observability，能从外面看到系统内部每一步发生了什么）。
  • 框架把底层的细节包起来，换成几个更容易使用的概念，让人不必每次都从头写。这些概念叫作抽象。这一讲学的是这些抽象，抽象底下的系统细节是这门课其他各讲的内容。

框架是什么：从 PyTorch 说起

框架替人做了什么，可以拿 PyTorch 来看。PyTorch 是一个用来训练神经网络的 Python 框架。

训练模型时要反复做一件事。先算损失（loss），它是一个数，衡量模型的预测离正确答案有多远。再算出损失对每个参数的导数，也就是这个参数稍微变一点时损失会跟着变多少，然后按导数调整参数，让损失变小。算导数的这一步叫反向传播。

下面的图用一个最简单的线性模型，把训练的两种写法放在一起。

{{fig 4 | 同一件事的两种写法。左：只用 Python 和 NumPy，手工写出反向传播。先算预测值和损失，再按公式算出损失对预测值的导数，进而算出对 w 和 b 这两个参数的导数，最后更新参数。右：用 PyTorch。只写出从输入算出预测值和损失的那两行，这一步叫前向的计算，然后调用 loss.backward()，导数由框架自动算出。}}

右边的代码里，求导的数学照样全部要做，现在由 PyTorch 在底下替你做。这些数学仍然值得理解，但没有人愿意每次都手写一遍。

框架做的就是这件事：把底层系统的一部分细节包起来，换成几个更容易使用的概念。这些概念叫作抽象。

写 agent 的程序也有这样的框架。这一讲的目标有三个。

  • 认识 agent 工程里常用的框架。
  • 把这些框架引入的抽象，和它们底下的系统设计对应起来。
  • 判断不同的工具在编排和可靠性上各有什么用。

编排（orchestration）指安排多个步骤按什么顺序执行、中途出错怎么办。可靠性指系统出了错还能把任务做完，它要靠编排来保证。

i
两个容易混的词。这一讲里「框架」指 DSPy、LangGraph 这类给你写程序用的库。「运行框架」（harness，也叫 scaffold）是另一个东西：包在模型外面、给它工具并管理多轮对话的那层程序，比如 Claude Code。用框架可以写出一个运行框架，也可以完全不用框架、从头写一个。运行框架在第五部分讲。

三根支柱：数据、系统、评估

搭一个 agent，可以完全没有数据，也没有评估，后面会看到只用一行代码就能搭出来。但那样搭出来的东西，你不知道它好不好，也没有办法系统地改进它。

workflow 和 agent 的分法。这里的分法和 Anthropic 2024 年 12 月的文章一致。文章说，workflow 是通过预先写好的代码路径来编排模型和工具的系统，agent 是由模型自己随时决定下一步做什么、用哪个工具的系统。出处：Building effective agents。

这一部分的小结

  • AI 系统的工程需要三样核心的东西：数据、系统、评估。
  • 按模型的自主程度，系统排成一条线：模型，workflow，agent。区别在于决定权在你的代码里，还是在模型手里。
  • 线上的每个位置都有现成的框架或工具。
  • 还有一些工具专门用来提高 agent 的可靠性和可观测性。
