一句话的结论

有了框架，搭出一个能跑的 agent 只要一两行代码。把它当工程来做，要的是另外几样东西：数据，评估，可靠的运行，和看得见的运行记录。框架在这几样上各提供了一套抽象，用的时候要知道抽象底下实际发生了什么。

这里的 agent，指能自己调用工具、分很多步去完成一个任务的语言模型系统。「框架」（framework）指 DSPy、LangGraph 这类写程序时调用的库。它和「运行框架」（harness，包在模型外面、给它工具并管理多轮对话的程序）是两个东西，这一讲两样都会讲到。

抽象（abstraction）指框架把底层的细节包起来之后，留给写程序的人用的那几个概念。

下表把「搭出一个能跑的 agent」和「把它当工程来做」放在一起比较。表里有两个词先说明一下。度量（metric）是一个给程序的输出打分的函数。可观测性（observability）就是上面说的「看得见的运行记录」：能从外面看到系统内部每一步发生了什么。

七个问题

这一讲分七个部分，每个部分回答一个问题。下表每一行给出问题、答案和一个依据或例子。

表里有四个名字先说明一下。控制流指程序里「接下来执行哪一步」的决定。基准测试（benchmark）是一组题目加一个打分的办法。Terminal-Bench 2.0 是一个基准测试，题目是让 agent 在命令行环境里完成任务。HarnessTax 是 Pan 等六人 2026 年发表在 arena.ai 博客上的一篇文章，它测量换一个运行框架对成功率和花费有多大影响。

这一讲最后把 agent 的工程归纳成一个循环：搭建，运行，评估，改进，然后再来一遍。七个问题可以按这四步大致归类，有的部分涉及不止一步。

  • 搭建：第二、四、五个问题。DSPy 和 LangGraph 是用来写程序的框架，第五个问题里的运行框架是别人已经搭好、装上就能用的 agent 程序。
  • 运行：第六个问题。它讲怎样让 agent 稳定地跑很久，怎样查看每次调用。
  • 评估和改进：第三个问题。有了数据和度量才量得出好坏，优化器靠它们来改 prompt。
  • 第一个问题给出后面要用的概念，第七个问题汇总各步的做法。
