一句话的结论

搭一个 agent 系统要做三组设计决定：控制流在谁手里，模型怎样推理和行动，每次调用模型时上下文里放什么。每一组都有几种现成的设计模式。模式给的只是大致的解法，真实的系统是把几种模式组合起来，再按自己的情况改出来的。

这里的 agent，指能自己决定下一步调用什么工具、分很多步去完成任务的语言模型系统。包在模型外面、给它工具并管理多轮对话的程序叫运行框架（harness，也叫 scaffold）。这一讲讲的就是设计运行框架时有哪些现成的思路可以用。

七个问题

这一讲分七个部分，每一部分回答一个问题。下面的表列出每个问题的答案，和一条依据或例子。

表里有五个词先说明一下。基准测试（benchmark）是一组题目加一个打分的办法。token 是模型处理文字的最小单位。o1 是 OpenAI 的一个推理模型，这类模型在给出答案之前，先在内部写出一段思考过程。system prompt 是每次调用模型时放在输入最前面的那段固定指令。工具调用是模型发出的一次使用工具的请求，通常写成一个 JSON 对象或一行文字，里面是工具的名字和参数。
