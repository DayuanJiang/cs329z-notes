先看结论

搭一个 agent 系统要做三组设计决定：控制流在谁手里，模型怎样推理和行动，每次调用模型时上下文里放什么。每一组都有几种现成的设计模式，也就是对常见解法的总结。模式给的只是大致的解法，真实的系统是把几种模式组合起来，再按自己的情况改出来的。

控制流指的是「下一步执行什么」由谁来决定。「agent 系统」在这一讲里是统称：下一步由程序定的 workflow 和下一步由模型定的 agent 都算在内。其中的 agent，指由语言模型自己决定下一步、在循环里调用工具的系统。工具是模型可以调用的外部功能，比如搜索和运行代码。模型发出的一次使用工具的请求叫工具调用，通常写成一个 JSON 对象或一行文字，里面是工具的名字和参数。

上下文是每次调用模型时发给它的全部输入，上下文窗口是模型一次调用能接受的输入加输出的总长度。包在模型外面、给它工具并管理多轮对话的程序叫运行框架（harness，也叫 scaffold）。

表里有四个词先说明一下。基准测试（benchmark）是一组题目加一个打分的办法。token 是模型处理文字的最小单位。o1 是 OpenAI 的一个推理模型，这类模型在给出答案之前，先在内部写出一段思考过程。system prompt 是每次调用模型时放在输入最前面的那段固定指令。

第三行的 Archon 搜索的是 workflow 的结构：用哪些模型，用生成、评审、排序、融合这类零件里的哪几种，分几层连接。融合指读几个候选回答，合并成一个回答。分几层连接，指零件排成几层，上一层的输出交给下一层。论文把这样组合出来的 workflow 叫架构。Archon 提出一个候选架构，在基准测试上测一下，再根据结果提出下一个。

 第二部分workflow 的五种模式

prompt chaining、routing、parallelization、orchestrator-workers、evaluator-optimizer 各是什么，什么时候用，怎样分清。

 第三部分真实的 workflow 是怎样组合出来的

STORM 这个写作系统的流程和效果，以及 Archon 怎样自动搜索 workflow 的结构。

 第四部分agent 怎样推理

ReAct 和 Reflexion 两个推理模式，自我纠正（没有外部反馈时让模型自己检查并改正答案）的局限，给负责检查的一方配上工具的 CRITIC，以及 ReAct 和 Reflexion 今天变成了什么样。

 第五部分动作用什么形式

用代码当动作的 CodeAct，先计划再执行的 ReWOO 和 LLMCompiler，以及这些想法今天留在 agent 里的两种形式：直接生成代码，和并行的工具调用。

 第六部分上下文窗口里放什么

为什么要管理上下文。两条原则：只放当前需要的东西，改动时保持连续。一个实际的限制：改动旧内容会让缓存失效，缓存指服务商把上一次请求里开头相同的那部分计算结果留下来复用。然后是五种模式，以及另一套把这些办法分成写、选、压缩、隔离四类的分法。

 第七部分案例：Pi 这个运行框架做了哪些选择

Pi 故意不做的功能，它的工具、循环和树形的会话、上下文管理和安全，最后是整讲的小结。
